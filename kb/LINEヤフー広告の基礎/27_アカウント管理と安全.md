## 0. 先に結論（この章で一番効く 10 点）

1. **器は「企業 ＞ ルート MCC ＞ MCC ＞ 広告アカウント」の木**。企業を作るとルート MCC が 1 つでき、操作できるのはルート MCC の**管理権限**の人だけ。MCC はルート MCC を含めて **5 階層**、MCC の直下に MCC 400・広告アカウント 200、ルート MCC 配下の MCC は合計 2,000 まで ✅〔仕様〕（H:000044414）
2. **権限は 3 つ（管理・登録更新・参照）で、付けるのは「アカウント単位」**。そして**実際に効く権限は「ベースアカウント」に付いた権限**。MCC に権限を持つ人が、その MCC をベースアカウントに選ぶと、配下の**すべての階層**のアカウントにその権限で触れる。ルート MCC の管理権限の人がルート MCC を選べば、企業の全アカウントを管理権限で操作できる ✅〔仕様〕（H:000044371、H:000047564）
3. **お金と人を触れるのは管理権限だけ**。ユーザーの招待、アカウントリンクの申請・承諾・解除、お支払い方法の設定、入金、リストの共有設定は管理権限だけ ○ で、登録更新・参照は × ✅〔仕様〕（H:000044310）。さらに、**広告アカウントの作成・名前の変更、本人確認書類の提出、請求先の設定、前払金の移動、アカウント移管の申請、契約の承継の手続きはルート MCC の管理権限だけ** ✅（H:000044258、H:000044655、H:000052238、H:000044628、H:000044431、H:000053390）
4. **操作履歴は管理権限か登録更新権限の人しか見られない**（参照権限では見られない）。さかのぼれるのは**今日を含めて 366 日前まで**。画面表示は最大 10 万件、絞り込みのダウンロードは 1 万件、履歴ファイルは 1 本 100 万件。人の操作は**ビジネス ID**、システムの操作は更新者「LINEヤフー株式会社」・更新ソース「SYSTEM」か「自動運用ルール」で出る ✅〔仕様〕（H:000044760、H:000044150）
5. **支払いは 3 方式で、アカウントを作るときの「契約プラン」で決まる**。前払い（銀行振込かクレジットカード）、クレジットカード後払い、売掛取引（請求書払い、一部の代理店だけ）。**クレジットカード後払いは、作るときにしか選べず、あとから他の方式に変えられず、アカウント移管もできない** ✅〔仕様〕（H:000044258、H:000055577、H:000044501）
6. 前払いは**残高がゼロになると全部の広告が止まる**。銀行振込は反映まで約 3 営業日・振込手数料は自分持ち・自動入金なし。クレジットカードは即時で、自動入金（残高ゼロか平均クリックコストの約 5 日分を下回ったとき、**1 日最大 3 回**、3,000 円以上 1,000 円単位）か、**月定額一括入金**（毎月 1 日に 1 回だけ）を選べる ✅〔仕様〕（H:000045000、H:000044583）
7. **税は「税込みで引き落とし・残高は税抜きで表示」**。入金・決済のときに消費税を足して引き落とし、残高には入金額から**見込み消費税**を引いた額が出る。**インボイス（適格請求書）として使える書類は、前払い・クレジットカード後払いなら月次利用明細、売掛取引なら請求書**。月次利用明細は前月分が月初 5 営業日までに出て、**過去 10 年分**取れる ✅〔仕様〕（H:000044994、H:000045396）
8. 「止まる」は 6 種類あり、原因も戻し方も違う: ①自分の配信オフ ②残高ゼロ・決済失敗・月額予算の到達・与信限度額の超過 ③広告の掲載停止（審査）④アカウントの停止（アカウント審査基準）⑤**取引の停止**（本人確認書類を 14 日出さない）⑥契約の解除（12 か月配信が無い、支払いの不履行、**3 日以上連絡が取れない**など規定§19 の 20 項目）。**解約したアカウントは復活できない** ✅（H:000044655、H:000044250、規定§9・§15・§19・§20）
9. **乗っ取り対策の公式の道具は少ない**。Google の複数人承認や Meta のピア承認・セキュリティセンターに当たるものは見つからない ❓。あるのは、ビジネスアカウントの **2 段階認証（2026-04-30 からオフにできない、2026-06-30 に未設定の人へメール認証を自動で有効化）**、パスキー、招待はビジネス ID の登録メールと一致しないと承諾できない、招待の承諾・辞退と権限の変化が管理権限の人全員にメールで届く、操作履歴。そして規定は「**ツールで行われた設定はお客様が行ったものとみなす**」「ID が漏れたら直ちに書面で知らせる」と定める ✅（N:20260317、H:000045039、H:000044364、規定§5）
10. **引き継ぎは 2 つの道**: 会社をまたぐ「**アクティブアカウント移管**」（毎月 1 日に切り替え、5 日前までに移管先のルート MCC 管理権限が申請、移管元が前日 23 時までに承諾。入稿・実績・操作履歴は移るが、**権限はシステムが変えないので前の人が残る**、MCC は移せない、前払いの残高は移管元に返金）と、代理店だけを替える「**代理店の変更**」（規定の別紙 1。変更希望月の前月末で締める）✅〔仕様〕（H:000044431、H:000044501、規定 別紙 1）

### 2-1. 何がどこに属すか ✅〔仕様〕

| 器 | 何か | 何が入るか・何をするか | 出典 |

### 3-1. 広告アカウント・MCC に付ける 3 つの権限 ✅〔仕様〕（H:000044371、H:000045396、H:000045398）

### 3-2. ルート MCC 管理権限 ✅〔仕様〕（H:000044414、H:000045396）

- ルート MCC の管理権限のユーザーは、ルート MCC をベースアカウントに選ぶと、ルート MCC 配下の**すべての階層**を管理権限で操作できる
- 用語集の定義: 保有する全アカウントに対して**登録更新、支払い情報の登録、入金手続き**の権限を持つ。**法人管理権限**を持つ場合は**受取口座の登録**もできる
- 広告アカウントの**管理権限があれば**できること（ルート MCC が要らない）: **入金手続き、クレジットカード取引明細のダウンロード、解約時の返金の受取口座の表示** ✅（H:000044414 のヒント）
- △ 名前の揺れ: 2024 年の公式コラム（C:権限）と 2024-08-29 のお知らせ（N:20240829）は「**ツール管理権限（ツール管理者）**」と書き、「保有する全アカウントで支払い情報の登録・入金・ツール利用者の追加ができる、法人管理権限があれば受取口座も、1 企業 999 名まで、他企業のビジネス ID には付けられない」と説明する。今のヘルプは同じ中身を「ルート MCC 管理権限」と書き、承継の手続きもヘルプは「ルート MCC 管理権限のユーザーのみ」、お知らせは「ツール管理権限を持つユーザーのみ」。**同じものの改称と読める**が、改称の日付と「999 名」が今も効くかは ❓
- 「法人管理権限」の定義・付け方は、読んだヘルプに無い ❓

### 3-3. ベースアカウントと「効く権限」の決まり方 ✅〔仕様〕（H:000047564）

1. ログインすると最初に「ベースアカウント選択」画面が出る。一覧は**直接権限を持つアカウント**だけ（1 件だけなら一定時間で自動で選ばれる）
2. 選んだベースアカウントと、**その配下の全階層**のアカウントを操作できる
3. 操作できる全アカウントに、**ベースアカウントに付いた権限と同じ権限**が効く
4. だから、MCC の権限を持ち、その MCC をベースアカウントに選べば、**直接の権限が無い配下のアカウントも**その権限で操作できる
5. ルート MCC 管理権限の人がルート MCC を選べば、全階層を管理権限で操作できる

- ルート MCC 管理権限もアカウントの権限も無いビジネス ID では、アカウント選択画面そのものが出ない（招待を受けるか、申し込む）✅（H:000045039）
- 「ご注意」として、MCC の操作の可否表（3-4）も「ベースアカウントに付いた権限が、そのアカウントと配下の全階層の操作に効く」と書く ✅（H:000044310）

### 3-5. 招待・変更・削除・棚卸し ✅〔仕様〕（H:000044364、H:000044509、H:000044525）

- **招待できるのはアカウントの管理権限の人**。手順: アカウントを選ぶ →「ツール」→「権限管理（ユーザー）」→「ユーザー」→「アカウントに招待」→ 権限とメールアドレス →「招待メールを送信」
- **メールアドレスは大文字・小文字を区別**。招待先のビジネス ID の登録メールアドレスと一致しないと招待できず、承諾もできない（統合済みビジネス ID にメールが無ければ、統合前の Yahoo! JAPAN ビジネス ID のメールと一致が要る）
- 1 つのビジネス ID に、一度に複数アカウントの権限は付けられない。権限の種類ごとに招待をやり直す
- **招待メールは再送できない**。届かなければ取り消して招待し直す。「辞退」した人は一覧に出ない
- 自動メールの送り先: 招待したとき → 招待された人だけ。**承諾・辞退したとき → 招待された人＋そのアカウントの管理権限の人全員＋連絡先利用者**（アカウントが MCC に関連付いていれば、その MCC の管理権限の人全員にも）
- 責任: **招待と、招待された人の操作で起きた問題の責任は、招待した側が負う**。承諾すると、問い合わせのときにその人にも情報が開示される。招待された側は、そのアカウントの管理・運用・参照の目的以外に使えない。他企業の MCC・広告アカウントへの招待を承諾すると、招待元から自分のビジネス ID の登録情報が見えることがある ✅
- 権限の変更: 「招待済みユーザー」欄で鉛筆アイコン → 権限を選んで「適用」。削除: チェックを入れて「一括操作」→「権限削除」
- **棚卸し**: MCC を選んで「権限管理（ユーザー）」の「アカウントごとの権限情報ダウンロード」で、**配下の全アカウントの招待済みユーザーの権限**を 1 回で落とせる ✅（H:000044525）
- 社員を足す流れ: 本人がビジネス ID を作る → 管理権限の人にメールアドレスを伝える → 招待 ✅（H:000062048）

### 3-6. 他企業（代理店・パートナー）と組むときの形 ✅〔仕様〕

| 形 | 何が起きるか | 向く場面〔推測〕 |
|---|---|---|
| 他企業のビジネス ID を広告アカウントに**招待** | その人に、付けた権限がそのアカウントだけに効く | 少人数の外部の運用者に 1 アカウントだけ任せる |

### 5-1. 契約当事者の統一と「承継等の手続き」✅〔仕様〕（N:20240829、H:000053390）

- 2024-10-01 に、「Connect One」構想の一環として、契約形態にかかわらず**契約当事者を「広告主」に統一**し、広告取扱基本規定を改めた。代理店と広告主の利用範囲は変えない、と公式
- 代理店契約で使っていた広告アカウントは、各広告主への「承継」が要った。手続きの期間は **2025-09-30 で終了**し、**未完了のアカウントは 2025-10-01 から順次配信停止**。期限後も手続きはでき、配信の再開には手続きが要る
- 手続き: 「ツール」→「企業」の「広告アカウントの承継等の手続き」→ アカウントを選ぶ（「全てのアカウント」も可）→ 同意事項 → 「承継する」。**手続きの後は取り消せない**。代理店は広告主から必要な権限をもらって代理で行う
- 検索広告（ショッピング）は 2024-12-04 から。手続きすると「商品情報掲載利用約款」にも同意したことになる
- 代理店を介さず広告主が作ったアカウントは対象外

### 5-2. 規定上の代理店の位置 ✅〔仕様〕（規定§2、§9、§10、§19）

- 代理店は、申し込みの時点で広告主から必要な権限をもらったうえで、広告主を代理して申し込む。LINEヤフーが承諾すると、**利用契約は広告主との間で**、代理利用契約は代理店との間で成り立つ
- **代理店の行為（事実上の操作を含む）は広告主が責任を負う**
- **利用契約が終わると代理利用契約も終わる**
- **LINEヤフーが代理利用契約を止める・解除するときは、その代理店を代理人にしている広告主の広告アカウントを止められる**（規定§9 2）。代理店の不払い・倒産・違反で、広告主のアカウントが止まりうる
- 売掛取引の一部のアカウントでは、LINEヤフーの広告主への債権を代理店に売り、**代理店が LINEヤフーに払う**形がある（規定§10 5）。代理店が払わないと代理利用契約の停止・解除の理由になる（規定§19 5(1)）

### 5-3. 運用の判断への効き方

- **小さな会社・個人の事業主がオンラインサインアップで始めると、支払いは前払いかクレジットカード後払いの 2 択**。請求書払いが要るなら代理店経由〔仕様〕
- **代理店経由でも、アカウントの契約当事者は広告主**（2024-10-01〜）。代理店をやめても、アカウントは広告主のもの。ただし代理店の MCC とのリンクと、代理店の社員の招待は自分で外す〔仕様＋推測〕
- **代理店の経営状態は広告主のリスク**。規定§9 2 で代理店の契約が止まると広告主のアカウントも止まりうる〔仕様＋推測〕

## 6. 支払い

### 6-1. 3 つの方式 ✅〔仕様〕（H:000044258、H:000045000、H:000055577、規定§10）

### 6-6. 運用の判断への効き方

- **前払い＋自動入金は「止まらない」が、使いすぎの歯止めが弱い**（1 日最大 3 回、繰り返し引き落とし）。**月の予算を守りたいなら月定額一括入金**（公式も「使いすぎを防ぎたい」人に勧める）。ただし月の途中で残高が尽きると止まる〔公式の推奨＋推測〕
- **前払いの銀行振込は 3 営業日のずれ**。残高が尽きる日の 3 営業日前に振り込む。週末・連休をまたぐなら更に前〔仕様＋推測〕
- **クレジットカード後払いは「作るときの一択」で、後戻りできず移管もできない**。将来、会社をまたいで引き継ぐ可能性があるアカウント（代理店から自社へ、事業の売却）では前払いを選ぶ〔仕様＋推測〕
- **カードの期限切れ・限度額**: 月定額一括入金は失敗しても自動で再入金しない。後払いは決済失敗で止まる。カードの更新月を暦に入れ、バックアップカードを登録する〔仕様＋推測〕
- **検索とディスプレイの残高・振込先は別**。片方だけ尽きて止まることがある。前払金の移動（7-2）で寄せられる〔仕様〕

## 7. 残高・明細・税

### 7-1. アカウント残高と見込み消費税 ✅〔仕様〕（H:000045396、H:000045000）

- **アカウント残高** ＝ 入金額から広告のクリック料金を引いた額
- **見込み消費税** ＝ クリック料金の消費税として**先に預かる**額。**残高には入金額から見込み消費税を引いた額が出る**。契約終了のときに使われなかった見込み消費税は返金の対象
- 自動入金・手動入金のクレジットカードの引き落としは「アカウント残高に追加する金額」＋消費税（つまり、残高に 10,000 円足したいなら、引き落としは税込みの額）
- **掲載終了までの予想日数**: 残高で掲載できる日数の予測値（検索の用語集）。**平均コスト（日）**: インプレッションのあった直近 3 日のコストの平均（用語集）。自動入金の「平均クリックコスト」も実績のあった直近 3 日の平均（H:000045000）

### 7-2. 前払金の移動 ✅〔仕様〕（H:000044628）

| 項目 | 中身 |

| 誰が | **ルート MCC 管理権限だけ**。**正規代理店は使えない**（画面も出ない）|

### 7-8. 不課金のクリック（無効なクリック）✅〔仕様〕（規定§11、H:000045396）

- LINEヤフーが課金すべきでないと判断したクリックなど（**不課金クリック**）は請求しない。**判定の条件は営業秘密で開示しない** ✅（規定§11 1）
- 特定のクリックの調査を申告できるのは、**そのクリックの日から 60 日以内** ✅（規定§11 2）。調べて不課金と判断し、すでに受け取っていれば、その額を上限に返金することがある。判断と返金額に異議を言わないことを規定は求める（§11 3）
- 用語集の言い方: 既知の不正プログラム・特定の重複クリック・その他の異常なクリックなど、悪意があると判断したクリックを「**無効なクリック**」か「無効な疑いがあるクリック」とし課金から除く。**無効なクリック率** ＝ 無効なクリック数 ÷（無効＋有効のクリック数）× 100 ✅（H:000045396）
- 明細には「不正な広告利用による調整金（調整額）」として出る（7-3）

### 7-9. 運用の判断への効き方

- **毎月 6 営業日目に月次利用明細を落として経理へ**（インボイスの書類。前月分は 5 営業日までに出る）〔仕様＋推測〕
- **「予算どおりに使ったのに残高の減りが多い」は消費税**。残高は税抜きで減り、入金は税込み。月の広告費を税込みで組む〔推測〕
- **不正クリックの申告は 60 日の期限**。週次の点検で異常なクリックの山（特定の時間・地域）を見つけたら、すぐ申告する〔仕様＋推測〕
- **解約は月初 5 営業日を避け、後払いは月末 3 日も避ける**〔仕様〕

### 8-6. 回復の順序〔推測。各段の根拠は括弧内〕

1. **どの「止まる」かを決める**（8-1 の表）。管理画面の通知（ベル）、登録メールアドレスへのメール（規定§22: 通知はメール送信の時点で届いたとみなす）、配信状況、残高を見る

3. ③なら: 34 の手順（直して保存＝再審査の依頼）
4. ④なら: アカウント審査基準のどれに当たるかを通知から読み、問い合わせ（34§5-3）。**否認された広告を残さない**（34§6-3）
5. ⑤なら: ルート MCC 管理権限の人が書類をアップロードし、連絡（H:000044655）
6. ⑥なら: 復活できない。新しい広告アカウントを作る前に、**違反アカウントの繰り返し作成**（アカウント審査基準）に当たらないかを確かめる（34§6-1）

- **代理店の MCC に多くの広告主がぶら下がる形は、他社の違反の巻き込みのリスクがある**（別紙 2）。大きな予算のアカウントは、自社のルート MCC に置き、代理店とは招待かリンクで組む〔推測〕

### 9-4. 被害に遭ったときの手順〔推測。各段の根拠は括弧内〕

1. **配信を止める**: アカウントの配信設定をオフ（H:000044960）。前払いなら**自動入金を解除**（H:000044935）、カードセットの解除も検討（解除すると自動入金も外れる）
2. **人を外す**: 「権限管理（ユーザー）」で知らない人の権限を削除（H:000044509）。知らないアカウントリンクを解除（H:000044398）
3. **自分のビジネス ID を守る**: パスワードの変更、2 段階認証の手段の見直し（N:20260317）
4. **報告**: 規定§5 4 により、直ちに書面で LINEヤフーへ（窓口はお客様専用の問い合わせ）。移管の申請が出ていれば、**移管日の前日 23 時までに取り下げを申請**（移管元・移管先どちらからでも、H:000044431）
5. **記録を残す**: 操作履歴のファイルを作って保存（366 日で消える、H:000044760）、入金/返金/カード明細を落とす
6. **不正なクリック・入金**: 不課金の申告は 60 日以内（規定§11 2）。不正な広告利用の調整金は明細で確かめる（H:000044180）

### 9-5. 運用の判断への効き方

- **守りは「管理権限を絞る」と「通知を読む」の 2 つに尽きる**。公式に承認の段が無いので、管理権限の人が 1 人乗っ取られると、人の追加・リンク・入金まで一気に触られる〔仕様からの推測〕
- **ルート MCC 管理権限の人は全員、認証アプリかパスキーにする**〔推測〕
- **自動入金の額を大きくしすぎない**。乗っ取りで予算を上げられると、1 日最大 3 回の自動入金で被害が広がる。上限を決めたいなら月定額一括入金〔仕様＋推測〕

## 10. 引き継ぎで確かめること

### 10-1. 2 つの道（会社が替わるか、代理店だけが替わるか）

| | アクティブアカウント移管 | 代理店の変更 |
|---|---|---|
| 何が替わるか | アカウントの**所有者（企業）**| 広告アカウントの**代理店**（契約当事者の広告主は同じ）|
| 根拠 | H:000044431、H:000044501 | 規定§2 4、別紙 1 |
| 誰が申請 | **移管先**のルート MCC 管理権限の担当者 | 広告主か、変更前の代理店（「申請者」）|
| いつ替わるか | **毎月 1 日**（土日祝でも）。任意の日は不可 | 審査を通ると、**変更希望月の前月末日で締めて**清算し、承諾の通知の日に替わる |
| 期限 | **移管日の 5 日前**まで（例: 12/1 なら 11/26 23:59）。移管元の承諾は**前日 23 時**まで（直前だと一時的に配信が止まりうる）| LINEヤフーが別に指定する期限まで。取り下げは締日まで |
| 審査 | あり（否認なら再申請。余裕を持って）| あり（基準は非公開、拒否の理由も開示の義務なし）|

### 10-2. アクティブアカウント移管の細目 ✅〔仕様〕（H:000044431、H:000044501）

**できる条件**（どれかに当たらないと不可。当たっても総合判断で断ることがある）:
- 移管先が LINEヤフー広告の契約企業、**国内の企業間**
- 一部の企業だけの機能（オーディエンスリスト、リストのアカウント間共有、予約型など）の利用状況が移管元と移管先で同じ
- 移管後に移管先の**年間売上の上限**を超えない
- 申請が重複していない、API のテスト用アカウントではない、利用状況に問題が無い
- **お支払い方法が売掛取引か前払い**（**クレジットカード後払いは移管できない**）
- 契約状況が「サービス中」か、「終了」から **13 か月以内**。終了から 13 か月以上で検索のオーディエンスリストグループに関連付いたアカウントが混ざると、**同時に申請した全部が不可**

**移るもの・移らないもの**:

| 移る | 移らない |
|---|---|
| 入稿アイテム、リスト・タグ、パフォーマンスデータ、レポート・テンプレートの設定、スクリプトの設定、**操作履歴**（操作した人のビジネス ID と日時を含む）、一部の広告主: 効果測定ツールの設定・共有オーディエンスリスト・月額予算（売掛取引のみ）| **請求先など移管元の企業に属する情報**、**MCC アカウント**、月次利用明細・入金/返金明細・クレジットカードの取引明細・アカウント情報のダウンロード（検索のアカウント別の設定情報と実績値）|

**落とし穴**:
- **権限はシステムが変えない**。移管アカウントに権限を持つビジネス ID はそのまま残るので、**移管元の社員・代理店が見たり編集したりできる状態が続きうる**。事前に自分で確かめて変える ✅
- **MCC のリンクも自動では外れない**。リンクを続けると、MCC の持ち主の企業から一部の情報が見え続ける。続けるか外すかは移管先の責任で判断 ✅
- MCC の配下へ移したいなら、**移管の前に**移管先の MCC とアカウントリンクする。しなければ移管先のルート MCC の配下に入る ✅
- **前払いの残高は移管元に返金**（移管後の月末に自動）。移管先が前払いでカードセットが未登録なら、**移管日の 0:00 から入金するまで配信できない**。移管先のルート MCC／MCC にカードセットがあり、両方とも前払いで移管元の自動入金がオンなら、移管後に自動入金されて再開 ✅
- 移管先がクレジットカード後払いなら、支払い設定をするまで配信されない。カードセットが登録済みなら自動で再開するが、システムの月額予算が付くので直す ✅
- **移管日の 0:00 から移管完了までのコストは移管先に請求**。移管前のコストへの返金・補填は、返金のときの所有者へ ✅
- 売掛取引 → 前払いなら移管後に入金が要る。前払い → 売掛取引なら月額予算に最低の 3,000 円が自動で入る（直す）✅
- 検索のオーディエンスリストグループに関連付いたアカウントは**全部まとめて**移す（一部だけは不可）。ディスプレイのリスト共有は一部だけ移せる ✅
- 予約型: 移管日が予約型の配信期間に入る、キャンセル料が未確定、移管先が予約型を使えない、などは不可 ✅
- 検索広告（ショッピング）: BM 商品管理ならつながりは維持。LINE Merchant System で移管元と移管先のショップが違うと、再登録・再申請・再連携まで配信停止 ✅

## 14. 少額・少量のアカウントでの注意〔推測。根拠は各節〕

- **オンラインサインアップの小さな広告主は、支払いが前払いか後払いの 2 択**。月の予算を固く守るなら「前払い＋月定額一括入金」、止まらないことを優先するなら「前払い＋自動入金」か後払い（6 章）
- **後払いの月額予算は最低 10,000 円**（検索・ディスプレイ）。売掛取引の月額予算は 3,000 円から（6-3、6-4）
- **前払いの検索とディスプレイで残高が分かれる**ので、両方を少額で回すと片方が先に尽きる。前払金の移動で寄せる（7-2）
- **1 人で運用していても、ルート MCC 管理権限のビジネス ID を 2 つ目（家族・共同経営者・信頼できる人）に持たせておく**。ID を失うと、入金・本人確認・移管の全部が止まる（3-2、4-3）
- **年に数回しか出さない商材は 12 か月の休眠ルールに注意**（2-4）

## 15. 判断の型

| 場面 | 先に確かめる | 決め方 |
|---|---|---|
| 新しく始める（自社）| 請求書払いが要るか、将来移管しうるか | 請求書払いが要る → 代理店経由。移管しうる → 前払い。どちらでもない → 前払い＋月定額一括入金か後払い |
| 代理店と組む | 代理店の MCC に入れるか、招待か | 担当の入れ替わりが多い・複数人 → アカウントリンク（アカウント管理）。少人数 → 登録更新権限で招待。**ルート MCC 管理権限は渡さない** |
| 代理店をやめる | 代理店を替えるのか、自社運用に戻すのか | 別の代理店へ → 代理店の変更（別紙 1）。自社へ → リンク解除と招待の削除（契約当事者は広告主のまま）|
| 会社が替わる（事業譲渡・グループ内）| 支払い方式、契約状況、リスト共有 | アクティブアカウント移管。後払いなら移管できない → 新規作成で実績は持ち越せない |
| 配信が止まった | 8-1 のどれか | 8-6 の順 |
| 乗っ取りが疑わしい | 9-3 の兆候 | 9-4 の順。移管の申請があれば前日 23 時までに取り下げ |
| 経理・監査 | インボイスの書類、履歴の期間 | 月次利用明細（前払い・後払い）か請求書（売掛）を毎月保存。操作履歴を四半期ごとに保存 |
