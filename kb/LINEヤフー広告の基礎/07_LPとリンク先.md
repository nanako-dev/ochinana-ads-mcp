## 0. 先に結論（10 行）

1. **LP の「内容」と「ドメイン」に、公式のはっきりした決まりがある。** 最終リンク先 URL・スマートフォン向け URL・クリック後に表示されるページは**同一の内容**、表示 URL を含む 4 つの URL の**ドメインは一致**（検索 H000044815、ディスプレイ H000044231）✅〔仕様〕
2. **計測のためのリダイレクトは「トラッキング URL」に置き、最終リンク先 URL には着地のページを入れる。** ディスプレイのヘルプは、計測用の URL から別のドメインの LP へ飛ぶ例（パターン 3・4）を、この形で示す ✅〔仕様〕（H000044231）
3. **トラッキング URL は審査される。** ディスプレイの運用型では、上位の階層（アカウント・キャンペーン・広告グループ）のトラッキング URL に不備があると、**配下の広告がまとめて否認**されうる ✅（H000044231）。検索の上位階層の URL オプションは**再審査の依頼ができない**（直して設定し直す）✅（H000044782）
4. **`{lpurl}` は、アカウント・キャンペーン・広告グループのトラッキング URL では必須。** 検索の動的検索連動型広告の広告にも必須。キーワード・クイックリンクと、検索のそのほかの広告では任意 ✅（H000044782、H000044231）
5. **同じ名前のパラメーターでも、検索とディスプレイで返す値が違う。** `{device}` は検索が m／t／c、ディスプレイは DESKTOP／SMARTPHONE／TABLET／CTV（NONE）。`{campaignid}` は検索が「トラッキング用の ID（キャンペーン ID とは異なる）」、ディスプレイは「キャンペーン ID」✅（H000045007、H000044463）
6. **広告のトラッキング URL は、キーワードの最終リンク先 URL より優先される。** キーワード単位で LP を変えたいなら、キーワードにもトラッキング URL を置くか、広告のトラッキング URL を外す ✅（H000044782 の表）
7. **表示速度の数字の基準は、公式に見当たらない ❓。** 公式が言うのは「LP のコンテンツと検索クエリーの関連性」「ページの操作性」（品質インデックスの LP の要素）、スマートフォンへの最適化、導線の見直しまで（`01§4-2`、H000045074、H000044184）
8. **LP そのものを比べる専用の機能は無い ❓。** 検索とディスプレイの A/B テストは「キャンペーン」を 2 つに分けて配信機会を半分ずつにする仕組みで、公式の例は入札・広告文・マッチタイプ・クリエイティブなど。LP の比較は例に無いが、テスト側の広告の最終リンク先 URL を変えれば作れる〔推測〕（§9）
9. **LINE の面での見え方で公式に書いてあるのは、配信先・形式・角丸・9:16 のトリミングまで。** 広告をタップした後に LINE の中のブラウザで開くか、外のブラウザで開くかは、LINEヤフー広告のヘルプに**記載なし ❓**（§10）
10. **LP の主体者（会社名・氏名）はアカウント名と一致が必要。** 別の会社のサイトは同じアカウントで出せない（新しいアカウントが要る）✅（H000044448）

## 3. リンク先の要件の全体像（審査と表示）

### 3-1. どの決まりが LP にかかるか ✅〔仕様〕

LP にかかる決まりは 3 層ある。どれも LINEヤフー広告の公式（ヘルプの「アカウント審査基準」「広告掲載基準」と入稿の説明）に書かれている。

| 層 | 中身 | 出典 | 詳しくは |
|---|---|---|---|
| アカウント審査基準 第 2 章「サイトの表示」 | 運営サイトが下の 6 つのどれかに当たると**アカウントを開設できない** | H000044188 | §3-2 |
| 広告掲載基準 第 9 章（形式ごと） | 検索: 表示 URL の 4 条件、入稿 URL とページの 2 条件。ディスプレイ: URL の一致と同一の内容 | H000044815、H000044819 | §4 |
| 広告掲載基準 第 2〜8 章 | 主体者の明示、関連性・有用性、定期購入の表示、業種の表示事項、LINE への誘導の制限 | 34 が引いたヘルプ | `34§2-13` |
| 入稿の説明（URL 項目） | トラッキング URL の遷移と一致、上位階層の審査 | H000044231、H000044782 | §5 |

### 3-2. アカウント審査基準「サイトの表示」の 6 項目 ✅〔仕様〕（H000044188、2026-11-24 本文）

運営サイトが次のどれかに当たる場合は、**アカウントを開設できない**。

| # | 決まり | 本文の解説（要点） |
|---|---|---|
| (1) | 作成中など通常の環境で表示できないもの | 作成中・リンク切れ、表示が大きく崩れる、**表示に ID・パスワードが要る**、使う環境によって見られない。**PDF のように閲覧に特定のソフトやアプリが要るページは登録できない**（サイトの中から PDF へのリンクは可） |
| (2) | ブラウザのバックボタンなどで直前のページへ戻れないもの | — |
| (3) | 広告主以外の第三者のポップアップ・アンダーウィンドウ・別画面を出すもの | — |
| (4) | ブラウザのウィンドウの大きさや位置を強制的に変えるもの | — |
| (5) | ユーザーの意思の確認なく、ソフトのダウンロードを始めたり、アプリを起動したりするもの | リンクの上で**ユーザーの意思を確かめてから**ダウンロード・起動するものは登録できる |
| (6) | その他、ユーザーの意に反する動きのあるもの | — |

- 本文は「審査観点およびユーザーの利便性から本基準を定めています」と書く。基準は変わることがある、とも書く ✅
- ID・パスワードが要るページの審査の通し方（「審査用認証情報」）は `34§2-13` ✅（H000045001）

### 3-3. 主体者とアカウント名、別ドメインのサイト ✅〔仕様〕（H000044448、2026-11-24 本文）

- 広告の主体者情報（会社名・氏名）は**「アカウント名」と一致**する必要がある
- 今のサイトと**同じ主体者**の別ドメインのサイトなら、同じアカウントで出せる。キャンペーンの設定（配信設定・1 日の予算など）を同じにするなら、**ドメインごとに広告グループを作る**ことを公式は勧める。同じ広告グループに別ドメインのサイトを入れることもできるが、サイトとキーワード・クリエイティブ・最終リンク先 URL の関連性が低いと掲載できない
- キャンペーンの設定を変えるなら、新しいキャンペーンと広告グループを作って登録する
- **主体者が違う**サイトは、同じアカウントでは出せない。新しいアカウントを足す（問い合わせが要る）

### 運用の判断への効き方
- **LP を PDF にしない**。資料請求の着地を PDF のダウンロードにしたいときも、PDF へのリンクを置いた HTML のページを LP にする（H000044188 の (1)）
- **ポップアップ型の離脱防止・アプリ起動の自動化は入れない**。「戻れない」「意思の確認なく起動」はアカウントの開設の段階で断られる決まり（H000044188 の (2)・(5)）。開設後の広告の否認は `34§2-13`
- **ブランドごとに会社が違うグループ企業は、LP の運営会社に合わせてアカウントを分ける**。代理店がまとめて運用していても、主体者がアカウント名と一致しない LP は同じアカウントに入れられない（H000044448）
- 同じ会社の複数サイトは、**ドメインごとに広告グループを分ける**（公式の推奨）。品質インデックスの「広告の関連性」「LP の利便性」もキーワード × 広告文 × LP で見られるので、混ぜると原因を切り分けにくい〔推測〕

## 4. URL の組み立て（最終リンク先・スマートフォン向け・表示 URL・ドメインの一致）

### 4-1. 検索広告の URL 項目 ✅〔仕様〕（H000044782、2026-11-24 本文）

| 項目 | 何を入れるか | 置ける階層 | 必須か | 注意（本文） |
|---|---|---|---|---|
| 最終リンク先 URL | ユーザーが**最終的に到達する**ページ | 広告・キーワード・クイックリンクアセット | 広告とクイックリンクは必須 | トラッキング URL があると、最終リンク先 URL より**トラッキング URL が優先**される。表示 URL に日本語 URL を入れたときは、Punycode の URL を日本語に直した状態も考えて審査する |
| スマートフォン向け URL | PC とスマートフォンで着地のページが違うときのスマホのページ | 広告・キーワード・クイックリンク | 任意 | **最終リンク先 URL・表示 URL とドメインの一致が必要**。PC 用とスマホ用は同じドメインの中に作る（例 `http://example.com/pc` と `/sp`）。スマホのページしか無いなら最終リンク先 URL に入れ、この項目は空にする |
| トラッキング URL | 計測用の URL | アカウント・キャンペーン・広告グループ・広告・キーワード・クイックリンク | 任意（管理ツールだけで測るなら不要） | 1,024 バイト（半角 1・全角 3）、日本語 URL 可。§6-6 |
| カスタムパラメーター | `{_key}=value` の識別子 | キャンペーン・広告グループ・広告・キーワード・クイックリンク | 任意 | 最大 3 つ。§6-5 |
| 表示 URL | 広告に出る URL | （RSA はドメインが自動、ディレクトリ 1・2 を入れる） | — | 文字数は `05§3-4` |

- PC とスマホのページが**別ドメイン**のときの公式の 2 案: ①PC 向けとスマホ向けで**別々の広告**を作る（例 `http://example.com/` と `http://example-sp.com/`）、②トラッキング用パラメーター `{ifmobile}` を使う ✅
- アプリ訴求キャンペーン（Android）で置けるのは**広告の最終リンク先 URL だけ**。アカウントのトラッキング URL も効かない ✅
- 階層ごとに置ける項目は「標準キャンペーン」「アプリ訴求（iOS）」「アプリ訴求（Android）」で違う（本文は表を画像で示す）✅

### 4-2. ディスプレイ広告の URL 項目 ✅〔仕様〕（H000044231、2026-11-24 本文）

| 項目 | 置ける階層 | 必須か | 注意（本文） |
|---|---|---|---|
| 最終リンク先 URL | **広告だけ** | 必須 | ディープリンク（アプリに直接移る URL）を入れられる |
| スマートフォン向け URL | 広告 | 任意 | キャンペーン目的「アプリ訴求」、広告タイプ「予約型専用広告」では置けない |
| 表示 URL | — | 入稿不要 | 最終リンク先 URL から自動で作られる |
| トラッキング URL | 広告。運用型はアカウント・キャンペーン・広告グループにも | 任意 | 運用型で上位の階層に置くときは `{lpurl}` が必須。ディープリンク可。§5-2 |
| カスタムパラメーター | 広告。運用型はキャンペーン・広告グループにも（**アカウントには無い**） | 任意 | 目的「商品リスト訴求」ではロゴの最終リンク先・スマホ向けとトラッキング URL だけに効く |

- 目的「商品リスト訴求」では、データフィードの Tracking URL・Landing Page URL・Smartphone Landing Page URL・Image URL と、キャンペーンバナーのリンク先 URL に、上位の階層（アカウント〜広告）の設定は**効かない** ✅
- ディスプレイの URL は日本語不可（`05§3-4`）。検索で日本語 URL を使っているなら、ディスプレイ用にエンコードした URL を用意する（`05§3-4` の運用の判断）

### 4-3. ドメインの一致と「同一の内容」✅〔仕様〕

| 広告 | 決まり | 出典 |
|---|---|---|
| 検索（動的検索連動型広告を除く） | 最終リンク先 URL のページ・スマホ向け URL のページ・**ユーザーが広告をクリックすると表示されるページ**は**同一の内容**。表示 URL・最終リンク先 URL・スマホ向け URL・クリック後のページの URL の**ドメインは一致** | H000044815（広告掲載基準 第 9 章 1） |
| 検索の表示 URL | リンク先のサイトの内容を正確に反映／サイトの所有者について誤解を招きやすい表現を使わない／タイトル・説明文の代わりやメールアドレスに使わない／入稿規定に準拠 | H000044815 |
| ディスプレイ | 最終リンク先 URL・スマホ向け URL・クリック後に表示されるページの URL のドメインは一致 | H000044231 |
| ディスプレイ（トラッキング URL） | トラッキング URL に個別のパラメーターが付いていても、**遷移先のページの内容が最終リンク先 URL のページと一致していれば**入稿上は問題ない | H000044231 |

- 検索の「第 9 章 1」の基準は**動的検索連動型広告には適用しない**、と本文は書く（動的検索連動型広告の LP は対象ページの決まり `05§4-3`）✅

### 4-4. ディスプレイのヘルプが示す 4 つの組み方 ✅〔仕様〕（H000044231）

| パターン | 広告に設定する URL → 最終的に表示されるページ | リダイレクト | パラメーター | 最終リンク先 URL | トラッキング URL |
|---|---|---|---|---|---|
| 1 | `https://example.com` → `https://example.com`（ドメイン一致） | なし | なし | `https://example.com` | （なし） |
| 2 | `https://example.com?param=1` → `https://example.com`（一致） | なし | あり | `https://example.com?param=1` | （なし） |
| 3 | `https://tracking.example.com` → `https://example.com`（一致しない） | あり | なし | `https://example.com` | `https://tracking.example.com` |
| 4 | `https://tracking.example.com?param=1` → `https://example.com`（一致しない） | あり | あり | `https://example.com` | `https://tracking.example.com?param=1` |

- 表示 URL はどれも最終リンク先 URL から自動で `example.com` になる ✅
- つまり「**計測のサーバーを通すなら、その URL はトラッキング URL に入れ、最終リンク先 URL は着地のページ**」が公式の形。パラメーターを付けるだけ（リダイレクトしない）なら最終リンク先 URL に直接付けてよい（パターン 2）

### 4-5. スマートフォン対応 ✅〔公式の推奨〕と ❓

- 公式の言い方: 「スマートフォンのユーザーを狙うならサイトをスマートフォンに最適化し、スマートフォン向けの広告とページを使う。**別サイトは必須ではない**が、見つけやすく直感的に操作できることが重要」（広告の品質のヘルプ H000045074、`01§5-1`）✅
- 品質インデックスの LP の要素は「ページの操作性」も考える（H000044956、`01§4-2`）✅
- スマホで「何秒以内に表示」「文字の大きさ」「タップの大きさ」などの数字の基準は、ヘルプに見当たらない ❓

### 運用の判断への効き方
- **1 つのレスポンシブなページで PC とスマホを兼ねるのが、URL の管理がいちばん簡単**。スマホ向け URL は空にでき、ドメイン不一致の心配も無い〔推測。根拠は H000044782 の「スマホ向けページが無い、または同じ URL なら設定不要」〕
- PC とスマホでドメインを分けている古いサイトは、**広告を分ける**か `{ifmobile}` で出し分ける（§6-1 の入稿の可否の表）。スマホ向け URL に別ドメインを入れると入稿できない
- **LPO ツールで同じ URL のまま中身を出し分ける**場合、「最終リンク先 URL のページとクリック後に表示されるページは同一の内容」という基準との関係は公式に書かれていない ❓。審査の時に見えるページと、ユーザーに出すページが大きく違う作り（訴求する商品が変わるなど）は避け、見出し・画像・並びの違いにとどめる〔推測〕
- 計測のツールの URL（別ドメイン）は**トラッキング URL**に置く。最終リンク先 URL に入れると、表示 URL が計測ツールのドメインになり、ドメイン一致の基準に当たる〔推測。根拠は H000044231 のパターン 3・4 と H000044815〕

## 5. リダイレクトとトラッキング URL の審査

### 5-1. トラッキング URL の審査 ✅〔仕様〕

| 広告 | 決まり | 出典 |
|---|---|---|
| ディスプレイ（共通） | 審査の時に**トラッキング URL からリンク先へ正しく移れない**と、否認の可能性がある | H000044231 |
| ディスプレイ（運用型） | トラッキング URL は**どの階層に置いても掲載後の審査**がある | H000044231 |
| ディスプレイ（運用型） | 上位の階層のトラッキング URL を新しく置く・変えると審査がある。そのトラッキング URL を**配下の広告に当てはめて**、主に「広告の URL が機能しているか」「URL の移動先が最終リンク先 URL と一致するか」を見る | H000044231 |
| ディスプレイ（運用型） | 不備があると、トラッキング URL を置いた・変えた上位の階層の**配下のすべての広告**が否認される場合がある | H000044231 |
| ディスプレイ（運用型） | 審査のタイミングで、上位の階層のトラッキング URL と配下の結果が違うことがある。上位が承認でも、配下の広告がガイドラインに当たれば否認 | H000044231 |
| ディスプレイ（運用型） | 上位の階層のトラッキング URL・カスタムパラメーターも審査され、否認なら**配信停止**の可能性 | H000044231 |
| 検索 | アカウント・キャンペーン・広告グループのトラッキング URL・カスタムパラメーターの審査状況は、各一覧の「**URL オプション審査状況**」列で見る（表示項目の編集で足す） | H000044782 |
| 検索 | 上位の階層の URL オプションには**再審査の依頼の機能が無い**。状況を見て設定し直す | H000044782 |
| 検索 | トラッキング URL を使うと、**配信の時に配信できる URL へ変えられることがある** | H000044782 |
| 共通 | 承認済みの URL などを編集すると「編集内容審査中」になり、その間は**編集前の内容で配信が続く**（否認でも編集前で続く） | `34`・`94`（H000045072） |

### 5-2. URL のテスト機能（ディスプレイ）✅〔仕様〕（H000044342、2026-11-24 本文）

- 最終リンク先 URL かトラッキング URL を置くときに「**URL をテストする**」で、正しく移れるか、最終リンク先 URL とトラッキング URL の移動先が一致するかを先に確かめられる
- 見られるのは**ページの移動の可否だけ**。ガイドラインに当たるかは見ない
- 運用型: アカウント・キャンペーン・広告グループ・広告の設定画面と、キャンペーン・広告グループ・広告の作成画面で使える。**上位の階層で使うと、配下の最終リンク先 URL とトラッキング URL を一度に最大 10 件**まで確かめられる
- 予約型: 広告の作成・設定画面だけ
- 目的「アプリ訴求」で iOS のとき、最終リンク先 URL に `https://itunes.apple.com/` を入れてテストすると「トラッキング URL の接続先が最終リンク先 URL と異なります」と出るが、**入稿上は問題ない**（直さなくてよい）
- 検索広告に同じテストの機能があるかは、今回のヘルプでは見ていない ❓

### 5-3. リダイレクトで落ちるもの（参照）

- 自動タグ設定が付ける `yclid` などは、他社のトラッキングツールでリダイレクトすると **LP のアドレスバーに残らないことがある**、と公式は書く。残らないと、検索の成果はタグの補完機能でもコンバージョン API でも戻せない（`06§3-3`、B-04）
- 公式は、広告管理ツールではパラメーター付きの URL を見られないので、**実際にクリックして確かめる**よう勧める（`06§3-3`）

### 5-4. 2022 年の「リンク先 URL 形式」から「最終リンク先 URL 形式」への強制変換（歴史）✅〔公式の発表〕（lycbiz.com `yahoo-ads/20220615`）

- 対象: ディスプレイ広告（運用型）で、2021 年 1 月以降に 1 インプレッション以上の実績があるアカウントの、リンク先 URL 形式の広告。**検索広告は対象外**
- ドメインが同じ広告: 最終リンク先 URL に元のリンク先 URL を入れ、表示 URL は自動
- ドメインが違う広告: 公式が**サイトをクロールして最終的に表示されるページの URL を最終リンク先 URL に**入れ、元のリンク先 URL は**トラッキング URL** に移す
- 2022-06-15 に変換を開始。2022 年 11 月からリンク先 URL 形式の広告は「掲載不可」で配信停止の予定、と告知
- 今の設計の考え方（§4-4 のパターン 3・4）と同じ向き: 「着地 = 最終リンク先 URL、計測の経由 = トラッキング URL」

### 運用の判断への効き方
- **上位の階層にトラッキング URL を置く前に、必ず URL のテスト機能で配下を確かめる**（ディスプレイ）。上位の 1 か所の誤りで配下の広告がまとめて否認されうる（H000044231）。テストは 1 回 10 件までなので、広告が多いなら代表の広告グループで先に試し、問題が無ければ広げる〔推測〕
- 検索の上位の URL オプションが否認されたら、**再審査の依頼ではなく設定のやり直し**（H000044782）
- 計測ツールを変える・リダイレクトを足すときは、**変える前に 1 本の広告で yclid が LP に残るかを実機で見る**（`06§3-3`）。残らないなら、トラッキング URL のリダイレクト先に `{lpurl}` を正しく入れているか（§6）、計測ツール側がパラメーターを渡しているかを確かめる〔推測〕
- 「編集中も前の内容で配信が続く」ので、**LP の URL を変えたつもりでも、承認まで古い URL に人が流れる**。古い LP を消すのは新しい URL の承認を見てから（`34`・`94` の H000045072）〔推測〕

### 6-4. `{lpurl}` の入れ方と「?」の変換 ✅〔仕様〕（H000045007、H000044463 の表）

- 公式は `{lpurl}` の後に「`?`」を付けることを勧める。配信の時に、システムが「`?`」をアンパサンド（`&`）など適切な文字に変えることがある
- 本文の例（検索・ディスプレイで同じ表）:

| ケース | 最終リンク先 URL | トラッキング URL | クリック後の URL |
|---|---|---|---|
| 最終リンク先に「?」なし・`{lpurl}` が先頭 | `http://www.example.com/` | `{lpurl}?param=xxx` | `http://www.example.com/?param=xxx` |
| 最終リンク先に「?」なし・`{lpurl}` が先頭以外 | 同上 | `http://rd.example.com/?lp={lpurl}%3F&param=xxx` | `http://rd.example.com/?lp=http://www.example.com/%3F&param=xxx` |
| 最終リンク先に「?」あり・先頭 | `http://www.example.com/?` | `{lpurl}?param=xxx` | `http://www.example.com/?&param=xxx` |
| 最終リンク先に「?」あり・先頭以外 | 同上 | `http://rd.example.com/?lp={lpurl}%3F&param=xxx` | `http://rd.example.com/?lp=http://www.example.com/%3F%26&param=xxx` |

- 検索の本文の別の例: 最終リンク先 `http://www.example.com/?param=1`、トラッキング URL `http://www.example.com/?lp={lpurl}` → クリック後 `http://www.example.com/?lp=http://www.example.com/%3Fparam%3D1`
- `{escapedlpurl}` の例: `?lp=http%3A%2F%2Fwww.example.com%2F%3Fparam%3D1`（`:` と `/` もエンコード）。`+2`・`+3` は `%25` が重なる

| 使い方 | 最終リンク先 URL やトラッキング URL に `{_key}` を書き、クリックの時に値へ置き換わる。例: トラッキング URL `{lpurl}?campaign={_mycampaign}`、カスタムパラメーター `{_mycampaign}=キャンペーンA` | 同じ |

### 6-6. 階層と優先順位 ✅〔仕様〕（H000044782、H000044231）

- **上の階層の設定は下の階層にも効き、下の階層に設定があればそちらが優先**（検索: アカウント → キャンペーン → 広告グループ → 広告 → キーワード。ディスプレイの運用型: アカウント → キャンペーン → 広告グループ → 広告）
- 検索のクイックリンクアセット: アカウント〜キーワードのトラッキング URL・カスタムパラメーターが反映される。クイックリンクそのものに設定があればそちらが優先。**クイックリンクを関連付けた階層（キャンペーンか広告グループ）の設定は影響しない**
- 検索のアカウントのトラッキング URL は、**アカウントの作成時には置けない**。作ってからアカウントの編集画面で置く
- 最終リンク先 URL に直接移る広告は、効果測定をしていてもトラッキング URL は要らない
- **検索: 広告のトラッキング URL は、キーワードの最終リンク先 URL より優先される**（本文の表）:

| 設定 | 配信される URL |
|---|---|
| キーワードに最終リンク先 URL、広告にトラッキング URL と最終リンク先 URL | **広告のトラッキング URL** |
| キーワードにトラッキング URL と最終リンク先 URL、広告に最終リンク先 URL | キーワードのトラッキング URL |

- 検索で `{lpurl}` が必須なのは、アカウント・キャンペーン・広告グループのトラッキング URL と、動的検索連動型広告の広告のトラッキング URL。キーワード・クイックリンクと、ほかの広告タイプでは任意
- 検索のトラッキング用パラメーターには、置ける階層の制限があるものがある（例 `{yclid}` はキャンペーンだけ）

### 6-7. データの使い方の制限 ✅〔仕様〕（H000045007、H000044463）
- トラッキング用パラメーターで取ったデータは、**自社の効果測定で一次利用する場合に限り**使える。取ったデータを顧客に直接提供・譲渡・転売するなどの**二次利用はできない**（検索・ディスプレイとも）

### 運用の判断への効き方
- **検索とディスプレイで同じ計測の URL の型を使い回さない**。とくに `{device}` の値の違い（m と SMARTPHONE）と、`{campaignid}` が検索ではトラッキング ID であること。分析ツール側で媒体ごとに対応表を持つ〔推測。根拠は §6-3〕
- 検索の `{campaignid}` を管理画面のキャンペーン ID と突き合わせても一致しない。**キャンペーンの識別は、カスタムパラメーター（`{_cp}=名前`）を自分で置く**ほうが確実〔推測〕
- **キーワードごとに LP を変える設計なら、広告にトラッキング URL を置かない**か、キーワードにもトラッキング URL を置く（§6-6 の表）。置き忘れると、キーワードの最終リンク先 URL が無視されて広告の URL に流れる
- 計測のサーバーへリダイレクトするなら `{lpurl}` を先頭以外に置き、計測側が 1 回デコードして転送する前提で組む。2 段以上のリダイレクトなら `{lpurl+2}`（ディスプレイの本文は「複数回リダイレクトする場合に有用」と書く）
- UTM などの固定の値は、上位の階層のトラッキング URL（`{lpurl}?utm_source=yahoo&...`）に 1 つ置けば配下にすべて効く。ただし上位の誤りは配下全体に広がる（§5-1）。**変える前に URL のテスト機能**（ディスプレイ）
- 取ったデータを広告主以外へ渡す使い方（再販・データ提供）はしない（§6-7）

### 9-4. LP の比較で、媒体のテストと LPO ツールのどちらを使うか〔推測〕

| 比べたいもの | 媒体の A/B テスト | LPO ツール（同じ URL で出し分け） |

| 審査 | URL を変えた広告は審査に入る | 媒体の URL は変わらない。ただし「クリック後のページは同一の内容」の基準との関係は ❓（§4-5） |
| 少ない件数 | 配信機会を半分にするので、片側の件数は半分になる | 同じ |
| 判定 | 画面の有意性の表示は書かれていない ❓ | ツールしだい |

- Google 側の注意（同期型のテストタグの表示速度、クローラーへの B 案の出し方）は G07§3・§7 にある。LINEヤフーのクローラーの扱いは公式に記載なし ❓

### 運用の判断への効き方
- **LP の比較を媒体の中でやるなら、検索はテストキャンペーンの URL だけを変える、ディスプレイは B キャンペーンの URL だけを変える**。ほかの要素を同時に変えない（公式の PDF の「比較対象以外の条件はできる限り違わないように」p12）
- **件数で先に決める**。配信機会を半分にするので、月のコンバージョンが少ないキャンペーンでは片側が数件になる。公式は「比較に必要なデータ量が集まっていない場合は検証の延長も」と書く（PDF p13）。少ない件数で言えることは G07§5-6 の考え方で読む〔推測〕
- **自動入札のまま LP を比べるなら、学習が落ち着くまでの期間を評価から外す**。テストキャンペーンは新しいキャンペーンなので学習の引き金になる（`36§1-2`）〔推測〕
- LP の差し替えを「A/B テストなしの前後比較」で判定するときは、季節・入札の学習・審査待ちの日（古い URL で配信が続く、§5-1）が混ざる。少なくとも**審査の承認日を切り替えの日**として記録する〔推測〕

### 10-2. タップした後、どのブラウザで LP が開くか ❓

- LINEヤフー広告のヘルプには、**LINE の面の広告をタップした後に、LINE の中のブラウザで開くのか、端末の既定のブラウザで開くのかの記載が見当たらない** ❓（H000044287 と、「LINE アプリ」「ブラウザ」でのヘルプ検索の結果を 2026-11-24 に確認）
- LINE Developers（LINE ヤフーの開発者向けの公式文書）に書いてあること ✅〔仕様〕:
  - 「LINE 内ブラウザ」は LINE のアプリ内専用のブラウザ。LIFF では LINE 内ブラウザを外部ブラウザの一種として扱う（`liff.getContext()` の `type` が `external`）（differences-between-liff-browser-and-line-in-app-browser）
  - クエリパラメーター `?openExternalBrowser=1` で、LINE 内ブラウザの代わりに**外部ブラウザで開く**。`?openInAppBrowser=0` は Chrome カスタムタブで開く（**Android 版 LINE だけ**）。これらは「**LINE アプリからアクセスするすべての URL で機能**」し、LIFF の URL では機能しない（using-line-url-scheme）
  - 文書に更新日の記載は無く、LINE 内ブラウザの Cookie・ストレージの扱いの説明もこの 2 本には無い ❓
- **広告の最終リンク先 URL に `openExternalBrowser=1` を付けたとき、広告のクリックにも効くか**は、どちらの公式にも書かれていない ❓

### 10-3. LP の作りで気をつけること〔推測〕（部品は公式）

| 気をつけること | 理由 | 根拠 |
|---|---|---|
| LINE の面の広告のクリックを、検索や Yahoo! JAPAN の面と分けて読む | 配信先 URL レポートで `ad.line.me` を分けられる | H000044287 |
| LINE の中のブラウザで開いたとき、ほかのブラウザのログインや Cookie が引き継がれない前提で作る（会員ログインを前提にしたフォーム・カート） | LINE 内ブラウザは「アプリ内専用のブラウザ」 | LINE Developers（挙動の細部は ❓） |
| 外部ブラウザへ移すパラメーターを広告の URL に付けるなら、審査・ドメイン一致・yclid の受け渡しを 1 本で試してから広げる | 広告での扱いは記載なし。URL を変えると審査に入る | §4-3、§5-1、`06§3-3` |
| 角丸と 9:16 のトリミングで、画像の端の文字・ロゴが欠けない | LINE の面の加工 | H000044287 |
| LINE 公式アカウントへ誘導する LP は、未認証の LINE 公式アカウント・個人の LINE アカウントへのディープリンクにしない | 掲載基準 | `34§2-13`（H000044788） |

### 運用の判断への効き方
- **LINE の面の CVR が低いとき、まず「LP が LINE の中で正しく動くか」を実機で見る**（フォーム・決済・ログイン・電話発信）。公式に挙動の記載が無いので、iOS と Android の LINE で広告をタップして確かめるのが唯一の確かめ方〔推測〕
- LINE の面を止めたいだけなら、プレイスメントで `ad.line.me` を除外する（H000044287）。LP の問題が直るまでの止血に使える〔推測〕
- LINE の面と Yahoo! JAPAN の面の成果を比べるときは、**配信先 URL レポートで面を分けてから**比べる。LINEヤフー広告ネットワーク経由は判別できないので、「LINE アプリ」と「それ以外」の 2 つに分ける（H000044287）

## 13. よくある思い込みと実際

| 思い込み | 実際 | 根拠 |
|---|---|---|
| 計測ツールの URL を最終リンク先 URL に入れてよい | 計測の経由はトラッキング URL、着地は最終リンク先 URL。表示 URL は最終リンク先 URL から作られるので、計測ツールのドメインが表示 URL になってしまう | H000044231 のパターン 3・4、H000044815 |
| Google の ValueTrack の型をそのまま使える | `{device}` の値、`{campaignid}` の意味（検索はトラッキング ID）、`{yclid}` の置ける所（キャンペーンのトラッキング URL だけ）が違う | H000045007、H000044463 |
| 検索とディスプレイで同じ計測の URL を使い回せる | `{device}` の値・`{ifmobile}` の置ける所・日本語 URL の可否が違う | §6-3、`05§3-4` |
| キーワードの最終リンク先 URL を入れれば、その LP で出る | 広告にトラッキング URL があると、広告のトラッキング URL が優先される | H000044782 の表 |
| トラッキング URL は審査されない | ディスプレイは掲載後の審査があり、上位の誤りで配下の広告がまとめて否認されうる。検索の上位の URL オプションは再審査の依頼ができない | H000044231、H000044782 |
| URL のテスト機能で通ったら審査も通る | テストが見るのは遷移の可否と一致だけ。ガイドラインは見ない | H000044342 |
| スマホ専用のサイトを別ドメインで持てばよい | スマホ向け URL は最終リンク先・表示 URL とドメイン一致が必要。別ドメインなら広告を分けるか `{ifmobile}` | H000044782 |
| 表示速度は品質インデックスの要素だと公式が言っている | 公式は「ページの操作性」まで。速度の言葉・基準は見当たらない | H000044956、§7-2 |
| LINEヤフー広告には LP の A/B テストの機能がある | LP 専用の機能は無い。キャンペーンの A/B テストで、片方の広告の URL を変えて作る〔推測〕 | H000053491、PDF |
| A/B テストならクリックが半分ずつになる | 分けるのは配信機会。表示・クリックが均等になる保証は無い | PDF（検索 p3、ディスプレイ p26） |
| LINE の面の広告は LINE 内ブラウザで開く（と公式が書いている） | LINEヤフー広告のヘルプに記載なし。外部ブラウザで開く指定は LINE Developers にあるが、広告での扱いは記載なし | H000044287、LINE Developers |
| PDF の資料を LP にできる | PDF だけのページは登録できない。HTML のページから PDF へリンクする | H000044188 |
| 同じ代理店が運用すれば、グループ会社のサイトを 1 つのアカウントで出せる | 主体者がアカウント名と一致しないサイトは同じアカウントで出せない | H000044448 |

## 14. 判断の型

| 状況 | まず確かめる | 次の手 |
|---|---|---|
| 「リンク先」系の否認が出た | §11 の 1〜6、`34§2-13` の否認理由 | 直して再審査（`34§5`）。上位の URL オプションなら設定し直し（§5-1） |
| ディスプレイの広告が一斉に否認された | 直前に上位の階層のトラッキング URL を変えていないか | URL のテスト機能で配下を確かめ、トラッキング URL を直す（§5-1・§5-2） |
| 計測ツールの成果だけ急に減った | トラッキング URL の変更、`{lpurl}` の位置、リダイレクトで yclid が落ちていないか | 実機でクリック（`06§3-3`）。§6-4 の例で組み直す |
| キーワード別の LP に人が来ない | 広告にトラッキング URL があるか | キーワードにトラッキング URL を足すか、広告の分を外す（§6-6） |
| LP の要素が「平均より下」 | 語の意図と LP の中身、スマホの操作 | LP の見出し・中身を語に合わせる。語ごとに LP を分けるかを検討（§8） |
| LP の改善の効果を確かめたい | 月のコンバージョンの件数（片側で足りるか） | 足りれば A/B テスト（§9）、足りなければ手前の指標と前後比較（承認日を切り替え日に） |
| LINE の面だけ CVR が低い | iOS・Android の LINE で LP が動くか | 動かなければ LP を直すまで `ad.line.me` を除外（§10） |
