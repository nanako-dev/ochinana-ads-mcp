## 0. 共通の前提

### 0-1. 指標どうしの関係

```
【クリック】（L2）       【表示】（L1）
   │ × クリック後 CVR        │ （ビュー 1 日の窓）
   ▼                          ▼
【クリックスルーの成果】 ＋ 【ビュースルーの成果】（クリックに手柄が無い成果だけ）
   │                          │
   └────────┬─────────┘
            ▼
【コンバージョン数】（キャンペーンに付けたイベントだけ。付けた時点から先だけ。モデルの推計が入ることがある）
            │
            ├── CPA ＝ 支出 ÷ コンバージョン数（ビュー込み）
            ├── クリック後 CVR ＝ クリックスルーの成果 ÷ クリック（ビューを含まない）
            └── ROAS ＝ order_created の売上 ÷ 支出（購入だけ）
```

- **CPA と クリック後 CVR から成果の数を逆算すると合わない**（分子にビューが入るかどうかが違う）✅（65§4-3）
- 窓が効くのは コンバージョン・売上・CPA・ROAS・クリック後 CVR。表示・クリック・費用は変わらない ✅（06§11-1）

### 0-2. 分解式

| 指標 | 式・定義 | 読み方 | 出典 |
|---|---|---|---|
| コンバージョン数 | 選んだ窓の中のクリックとビューの目標の成果（クリック 3＋ビュー 2＝5） | ビュー 0 日にすればクリックだけ | ✅ 06§11-3、D:Ads |
| CPA | 支出 ÷ コンバージョン数。null は 0 ではない | 既定ではビュー込みで、Google より安く見える | ✅ 65§4-1・4-3 |
| クリック後 CVR | クリックスルーの成果 ÷ クリック（比） | LP と計測の健康を見るのに向く〔推測〕 | ✅ 65§4-1 |
| ROAS | `order_created_roas`（売上 ÷ 支出）。4 は「費用 1 に売上 4」 | 購入だけ。廃止予定の `roas`・`attributed_sales_amount` は購入とサブスクの合計で中身が違う | ✅ 65§4-1 |

### 0-3. まず疑う見かけ

| 見かけ | 何が起きるか | 確かめ方 | 出典 |
|---|---|---|---|
| 成果の遅れ | 反映は 24〜48 時間 | 直近 2 日を外す | ✅ 06§12-2 |
| 窓の設定 | クリック 7／14／30 日、ビュー 0／1 日。表示している全部のコンバージョンの列に効く | 「列を編集」>「コンバージョンイベント」>「アトリビューション期間」 | ✅ 06§11-1、62#8 |
| 計上日の基準 | 広告に触れた日か、成果の日か。日別の合計が違う | レポートの設定 | ✅ H:20001217、06§11-1 |
| 2026-09-30 の API の既定 | Insights の成果の既定がクリック 30 日＋ビュー 1 日＋広告に触れた日に。旧来の数え方のモードは無い | API で窓を明示して取っているか | ✅ D:Ads（Changelog）、06§11-3 |
| イベントを付けた日 | 目標の成果は、キャンペーンにイベントを付けた時点から先だけ数える（さかのぼらない） | イベントの設定の日 | ✅ 65§4-2 |
| モデル化 | 計測できる場合はモデルで推計した成果が合計に入ることがある | ❓ 推計の分を抜き出す列は記載なし | ✅ 06§8-3 |
| 費用の遅れ | 費用は約 7〜8 時間遅れ。直近の CPA は分子と分母の両方が未確定 | 直近 2 日を外す | ✅ H:20001217 |

### 0-4. 切り分けの順（計測を先に）

1. **見かけを外す**（§0-3）: 遅れ・窓・計上日・API の既定・イベントを付けた日
2. **計測が動いているか**: 実際のイベントが、キャンペーンにつないだデータソースに届いているか。「設定しただけでは、使えるシグナルが届いている証拠にならない」 ✅（H:20001634）
3. **EQS の警告**: 照合の情報の欠け・遅れ・重複 ✅（H:20001634、06§10-2）
4. **配信と課金**: 表示とクリックの量（L1・L2）、oCPC か oCPM か
5. **LP と事業の側**: LP の変更、オファー、季節

- 公式の手順（数字が合わないとき）: 同じアカウント・キャンペーン・イベント・絞り込み・期間・時間帯・計上日の基準・窓・列にそろえる → 加工していない CSV を残す → UTM の流入が解析に無いなら、LP の URL とパラメータを、実際に観測した着地 URL とリダイレクト後の最終 URL と比べる（**このために有料のクリックを新しく起こす必要は無い**）→ 最終の LP で解析のタグが読み込まれているか → 直したら新しい流入で確かめる（過去の欠けは戻らない）✅（06§13-2）

## 1. コンバージョン数（CV）

### 1-1. 定義と分解式

- コンバージョン数 ＝ クリックスルーの成果 ＋（ビューの窓が 1 日なら）ビュースルーの成果。クリックとビューの両方に当たる成果はクリックが取る ✅（06§11-1）
- 対象はキャンペーンに付けた 1 つの標準イベント（コンバージョン目的）。カスタム イベントは最適化の目標にできない ✅（H:20001412）

### 1-2. まず切り分ける順番（CV に特有の点）

1. クリックスルーとビュースルーの列を分けて、どちらが動いたか
2. コンバージョンの画面で、実際のイベントが届いているか（直近のイベントの確認は、直近約 15 分の最新 50 件）✅（`C-API-005`）
3. EQS の警告
4. クリック数（L2）と クリック後 CVR のどちらが動いたか

### 1-3. 「減った」の木（CV-下）

- ⓪ 見かけ
  - CV-下-01 成果の反映の遅れ（直近 2 日）
  - CV-下-02 窓を狭めた（ビューを 0 日にした・クリックを 7 日にした）
  - CV-下-03 計上日の基準を変えた・比べる表で基準が違う
- ① 計測
  - CV-下-04 ピクセルが外れた・LP の変更で読み込まれない
  - CV-下-05 `oppref` がリダイレクトで落ちた・コンバージョン API に渡していない
  - CV-下-06 同意の拒否で送られていない
  - CV-下-07 コンバージョン API の送信が遅い・7 日を過ぎた・1 件の不正で全体が失敗
  - CV-下-08 日本のアカウントで自動詳細マッチング（AAM）をオフにしている・照合の情報が少ない
  - CV-下-09 イベント名・データソースのつなぎが合っていない
- ② 配信と課金
  - CV-下-10 表示・クリックが減った
  - CV-下-11 コンバージョン目的をクリック課金（oCPC）で作った
- ③ LP と外
  - CV-下-12 LP・オファー・季節

## 2. コンバージョン単価（CPA）

### 2-1. 定義と分解式

- CPA ＝ 支出 ÷ コンバージョン数（ビュー込み）✅（65§4-1）。目標 CPA は**平均の目標**で、1 件の料金でも上限でもない ✅（H:20001634）
- 分解〔推測〕: CPA ＝ CPC ÷ クリック後 CVR（クリックスルーだけのとき）。ビューが入ると、この式より低く出る

### 2-2. まず切り分ける順番（CPA に特有の点）

1. 直近 2 日を外す（費用と成果の両方が遅れる）
2. 窓・計上日をそろえる
3. 分母（成果）か分子（費用）か: CV が減ったなら §1、費用が増えたなら L1・L2
4. 目標・倍率・戦略の変更（変更履歴）

### 2-3. 「上がったとき」の木（CPA-上）

- ⓪ 見かけ
  - CPA-上-01 直近の成果がまだ出そろっていない
  - CPA-上-02 窓を狭めた（ビューを外した）
- ③ 入札
  - CPA-上-03 目標 CPA を上げた・倍率を上げた
  - CPA-上-04 インテリジェント入札で目標の単価が無い（量を優先）
  - CPA-上-05 上限入札から目標 CPA へ移した・API の旧欄で値を送った
- ① ② 成果と費用
  - CPA-上-06 クリック後 CVR が下がった（計測か LP）
  - CPA-上-07 CPC が上がった（L2）

## 3. ROAS と売上（ROAS）

### 3-1. 定義と分解式

- ROAS（`order_created_roas`）＝ 帰属した `order_created` の売上 ÷ 支出。売上の列（`order_created_attributed_sales`）は**購入だけ**で、ほかのイベントの値は入らない ✅（65§4-1）
- 画面の名前は「注文完了に基づく ROAS」「成立注文の売上額」 〔画面〕62#7
- **価値（売上）に最適化する戦略（目標 ROAS に当たるもの）は記載なし** ❓（02§3-1）

### 3-2. まず切り分ける順番（ROAS に特有の点）

1. どの列を見ているか（`order_created_roas` か、廃止予定の `roas`）
2. 窓・計上日・遅れ（§0-3）
3. 件数（CV）か 1 件の売上か

### 3-3. 「下がったとき」の木（ROAS-下）と詳細

| 番号 | 要因 | なぜそうなるか | 確かめ方 | 直し方 | 印 | 出典 |
|---|---|---|---|---|---|---|
| ROAS-下-01 | 購入以外の成果を見込んでいた | 売上・ROAS は `order_created` だけ。リード・サブスクの値は入らない | 付けたイベントと売上の列 | 購入の値を送る。リードの価値は台帳で別に見る | ✅ | 65§4-1・4-3 |
| ROAS-下-02 | 廃止予定の `roas`・`attributed_sales_amount` と比べている | 廃止予定の列は購入とサブスク開始の合計で、中身が違う | API の項目名 | `order_created_*` だけを使う | ✅ | 65§4-1 |
| ROAS-下-03 | 値の付け方（税・送料・割引・通貨） | 値の違いは数字が合わない公式の理由の 1 つ | 送っている値の定義と台帳 | 値の定義をそろえる | ✅ | 06§13-1 |
| ROAS-下-04 | 購入の件数が減った | §1 の CV-下 | §1 | §1 の打ち手 | ✅ | §1 |
| ROAS-下-05 | 窓・遅れ | §0-3 | §0-3 | そろえる・待つ | ✅ | 06§11・§12 |
| ROAS-下-06 | 単価の低い商品の購入が増えた | 件数は保たれても 1 件の売上が下がる〔推測〕 | 商品の内訳（商品フィードのキャンペーンは商品の列、約 30 日まで） | 商品ごとの売上を台帳で見る | 〔推測〕 | 06§12-3 |

## 4. GA4・Google 広告・自社の台帳とのずれ（GAP）

### 4-1. 定義

- 公式の言い方: **「差があることは、必ずしもエラーを示さない」** ✅（06§13-1）。CRM はすべての購入を数え、広告のレポートはその媒体に帰属した購入を数える ✅（06§13-1）
- GA4 の接続（ベータ）で取り込んだ数字は、**プロパティの全流入元の合計**で、OpenAI の広告に帰属した成果でも ROAS でもない ✅（06§13-3）

### 4-2. まず切り分ける順番（GAP に特有の点）

1. 同じアカウント・期間・時間帯・絞り込みにそろえる（画面はアカウントの時間帯、請求は UTC）✅（H:20001217、62#12）
2. 窓と計上日をそろえる（ChatGPT をビュー 0 日にする）
3. 加工していない CSV を残し、どちらが多いかで木を選ぶ

### 4-3. 「管理画面のほうが多い」の木と詳細（GAP-上）

| 番号 | 要因 | 確かめ方 | 直し方 | 印 | 出典 |
|---|---|---|---|---|---|
| GAP-上-01 | ビュースルーが入っている（GA4 にビュースルーは無い） | ビュースルーの列 | ビュー 0 日の列で比べる | ✅ | 06§11-3、06§13-4 |
| GAP-上-02 | モデルで推計した成果が入っている | ❓ 抜き出す列は記載なし | 差の残りとして説明する | ✅／❓ | 06§13-1 |
| GAP-上-03 | ラストタッチの手柄の付け方の違い（広告を押した人が後で直接来て買うと、ある道具は「直接」、別の道具は広告の手柄） | 台帳の流入元 | 二重計上ではない。媒体ごとの合計を足さない | ✅ | 06§13-1 |
| GAP-上-04 | ピクセルと API の重複が除かれていない | CV-上-04 | 3 つの鍵をそろえる | ✅ | 06§6 |
| GAP-上-05 | 計上日・時間帯の違い | 計上日の基準、時間帯 | そろえる | ✅ | H:20001217 |

### 4-4. 「管理画面のほうが少ない」の木と詳細（GAP-下）

| 番号 | 要因 | 確かめ方 | 直し方 | 印 | 出典 |
|---|---|---|---|---|---|
| GAP-下-01 | GA4 の「有料の流入」に審査のクローラーの訪問が入っている（管理画面のクリックより多い） | 入稿・修正の直後の UTM 付きの訪問 | 課金されるクリックではない。比べる期間から外す | ✅ | H:20001207、68§0 |
| GAP-下-02 | 台帳（CRM）はすべての購入を数える | 台帳の流入元の内訳 | 正常。広告の帰属の数と比べる | ✅ | 06§13-1 |
| GAP-下-03 | `oppref` が落ちて広告に帰属できない | EQS の「クリックの情報が無い」 | CV-下-05 | ✅ | 06§7 |
| GAP-下-04 | 同意の拒否・ブロック | 同意の率 | CV-下-06 | ✅ | 06§3-3 |
| GAP-下-05 | 窓が短い（クリック 7 日）、ビュー 0 日 | 窓の設定 | 比べる道具の窓に合わせる | ✅ | 06§11-1 |
| GAP-下-06 | UTM が外れて GA4 で別の流入に見える（逆に GA4 では ChatGPT の流入が少ない） | 着地 URL とリダイレクト後の最終 URL | UTM を付け直す。新しい流入で確かめる（過去は戻らない） | ✅ | 06§13-2 |

### 4-5. 判断の型（GAP）〔推測。根拠は各行〕

- ずれの大きさに「正常の幅」の公式の数字は無い ❓。**差の向きと、§4-2 の 3 つをそろえた後に残る差**で判断する
- 社内・顧客への報告では、ChatGPT の成果を「ビュー 0 日・クリック 30 日・広告に触れた日」と書き添える（65§4-3 の案）

## 6. よくある思い込みと実際
