## 0. 先に結論（この章で一番効く 10 点）

1. **OpenAI の仕組みで審査・評価できない LP は配信の対象にならない** ✅〔仕様〕（P§4「当社のシステムで審査又は評価できない広告やランディングページは、配信対象にはなりません」、2026-11-20 の v1.7 でも同じ）。却下のよくある原因として、ヘルプは「OpenAI のユーザー エージェントか IP アドレスを弾く LP」を名指しする ✅（H:20001217、2026-11-12 ごろ更新）
2. 広告の LP に要るのは **OAI-AdsBot（必須）**。OAI-SearchBot は推奨。商品フィードは、**商品画像の URL に OAI-SearchBot が届くこと**も要る（画像のホストが 403 を返すとフィードの処理が止まりうる）✅〔仕様〕（H:20001243）
3. **OAI-AdsBot は広告として出されたページだけを訪れ、集めたデータを生成 AI の基盤モデルの学習に使わない** ✅〔仕様〕（D:Bots）。学習を断りたいなら GPTBot を止めればよく、**OAI-AdsBot を止める理由にはならない**〔推測〕。各クローラーの設定は互いに独立 ✅（D:Bots）
4. **robots.txt だけでは足りない**。WAF・CDN・bot 対策・JavaScript の確認画面・CAPTCHA・認証・**地域の規則（geo rules）**・レート制限が、別々に自動のアクセスを止める。リダイレクトの途中のホスト・サブドメイン・外部の行き先もそれぞれ見る ✅〔公式の推奨〕（H:20001243）
5. **「ブラウザで開ける」「HTTP 200 が返る」は、クローラーが中身を読めた証拠にならない**。空白・不完全・ログイン・確認画面は不可 ✅（H:20001243）。**トップページが開くことは、広告のリンクが動く証拠にならない**。パラメータ込みの完全な URL で、端末・地域ごとの行き先まで確かめる ✅（H:20001243）
6. **Cloudflare は OAI-AdsBot を確認済みの bot として許可している** ✅（H:20001243）。IP の固定の一覧（openai.com/adsbot.json）は公開されているが、公式は**ログで見た IP だけに頼らず、名乗り・確認済み bot の仕組み・許可リスト・robots.txt・提供元の bot 確認を組み合わせる**よう勧める ✅（H:20001243）。2026-11-24 に取った adsbot.json の範囲は **IPv4 の /25 が 2 つ**（作成時刻 2026-05-12）✅（§3-2）
7. **ChatGPT のクラウド ブラウザは広告の審査とは別の仕組み**。利用者の頼みで ChatGPT がサイトを操作するためのブラウザで、**使えるのは有料プラン（無料版と Go を除く）** ✅（H:20001280、2026-10-28 ごろ更新）。広告が出るのは無料版と Go なので、**クラウド ブラウザを許可しても広告の審査は通らないし、止めても審査には響かない**〔推測。両方の本文から〕。許可の手順は Akamai・Cloudflare・HUMAN・Vercel ごとにあり、それ以外は Web Bot Auth（RFC 9421 の署名）で確かめる ✅（D:Commerce）
8. ポリシー v1.7（2026-11-20）で**「欺瞞的なリダイレクトを使う、ポリシー違反の中身を審査から隠す」ことの禁止と、「広告からメッセージングのチャットやグループへ直接リンクできない」**ことが明文になった ✅〔仕様〕（P§3「リンク先の健全性」）。△ 34§6-3・§14 の「クローキングを名指しした規定は ❓」は、この文で一部が埋まった（§2-4）
9. **審査のクローラーは、トラッキング パラメータ付きの LP を訪れることがある。第三者の解析ツールはそれを有料の流入と数えることがあるが、課金されるクリックではない** ✅（H:20001207、2026-11-15 ごろ更新）。GA4 などで「入稿・修正の直後に、クリック数より多い UTM 付きの訪問」が出たら、まずこれを疑う〔推測〕
10. **直しても承認は保証されない。サポートの手動の回避に頼らない**。直したら同じ URL とリダイレクトで試し直し、状態が自動で変わらなければ再入稿か再審査 ✅（H:20001243）。大量の入稿で 429 が出るなら、小分けにして時間をかける ✅（H:20001243）

## 2. LP の審査の仕組み（なぜクローラーが要るか）

### 2-1. 審査の 3 レベルと LP ✅〔仕様〕（P§4、2026-11-20 更新の v1.7。日本語版の本文）

| レベル | 何を見るか | LP との関係 |
|---|---|---|
| 広告主 | 正当な事業者か、資格要件を満たすか。認証、アカウントの質、詐欺・不正・悪用・欺瞞の兆候 | 「審査可能で、自社の事業と提供内容を明確に示すウェブサイトか公開プロフィール」を出すこと（P§3、§2-4） |
| 広告クリエイティブと LP | **タイトル・コピー・メディア・LP** がポリシーに合うか。許可されていない区分（武器・酒・欺瞞など）を宣伝・実質的に言及していれば却下 | LP も審査の対象そのもの |
| 掲載 | 承認された広告が、掲載ポリシーに合う関連のある会話にだけ出るようにする | LP の中身は「いつ出すか」の判断にも使われうる（§2-2） |

- ほとんどの審査は、人の監督のもとで自動の仕組み（LLM や分類器を含む機械学習）が行い、**広告が配信可能になる前に**、広告・LP・広告主の兆候を審査する。一部は重大度・確信度・リスクで人の審査に回る ✅（P§4）
- **「当社のシステムで審査又は評価できない広告やランディングページは、配信対象にはなりません」** ✅（P§4）
- **承認の後も審査は続く**。利用者の報告、自動の指標、継続的な品質評価で広告と広告主の活動を見る ✅（P§4）。〔推測〕承認の後に LP を変えたり、WAF の設定を強めたりして読めなくなれば、後から配信が止まりうる。ヘルプも「LP・トラッキング リンク・リダイレクト・ホスティング・セキュリティ設定を変えたら点検をやり直す」と書く ✅（H:20001243）
- 開発者文書の点検の順（アカウント → キャンペーン → 広告グループ → 広告）の最後は「広告が有効で承認済みか。**クリエイティブと LP にアクセスできるか**」✅（D:Ads「Check the hierarchy」）

### 2-2. LP の中身は審査だけでなく「いつ出すか」と「文面の書き換え」にも使われる ✅

- **OAI-AdsBot**: 広告として出されたページの安全を確かめるために訪れる。**利用者にその広告を出す最も適切なタイミングを決めるために、LP の中身を使うこともある** ✅〔仕様〕（H:20001243、D:Bots）
- 広告の選ばれ方の信号に **「広告の LP」** が入っている（今の会話の文脈と意図、LP、タイトル、コピー、文脈ヒント、ターゲティング、パーソナライズがオンなら広い経験の一部の信号）✅（H:20001047、H:20001207）
- **クリエイティブの強化**（2026-10-30 から既定でオン、05§6）は「既存の広告と**ランディングページのコンテンツ**」を使って見出し・説明文を作り直し、翻訳し、画像の大きさを変え、**リンク先 URL を最適化して、ウェブサイト内の関連ページに誘導することがある** ✅（H:20001614 日本語版、2026-11-06 ごろ更新）。公式は「価格、プロモーション、商品詳細、在庫状況など、広告とランディングページの情報を最新に保つ」よう勧める ✅〔公式の推奨〕
- **運用の判断への効き方**:
  - LP が読めないと、審査に落ちるだけでなく、**承認された後も「どの会話に合う広告か」の材料が痩せる**〔推測。LP がタイミングの判断に使われるという本文から〕。文脈ヒントで補えるのは一部（23§6）
  - クリエイティブの強化がオンなら、**広告に入れた LP 以外の、同じサイトの別ページに送られることがある**。〔推測〕そのページもクローラーと人に読める状態にしておく（ログインの壁・地域の遮断・在庫切れのページを残さない）。どのページに送ったかを広告主が前もって知る手段は記載なし ❓。止めたいならクリエイティブの強化をオフにする（05§6-2）

### 2-3. 「LP が読めない」は却下のよくある原因として公式に挙がっている ✅（H:20001217、2026-11-12 ごろ更新）

- ヘルプの「広告が却下された」の節: Ads Manager の Ads タブで状態を見て、「Not serving」ならカーソルを当てて理由を読む。**よくある原因は、広告のコピーか LP がポリシーに合わないこと、または LP が OpenAI のユーザー エージェントか IP アドレスを弾いていること**。直して出し直すか、誤りだと思えば再審査を求める
- サポートに伝えるもの（同じ節）: 広告のタイトルとコピー、不承認のコードかメッセージ、LP の URL、通知を受けた時刻
- **運用の判断への効き方**: 「Not serving」の理由に LP が出たら、文面を直す前に、まず §10 の点検でクローラーに何が返っているかを確かめる。文面を直しても LP が読めなければ同じ結果になる〔推測〕

### 2-4. リンク先の健全性（ポリシー v1.7 の明文）✅〔仕様〕（P§3、2026-11-20。英語版の本文で文を確かめた）

| 決まり | 中身（本文の要約） | 34 との関係 |
|---|---|---|
| 審査できるサイト | 広告主は、**審査可能で、自社の事業と提供内容を明確に示すウェブサイトか公開プロフィール**を出す | 34§2-4 の C17・C18 と同じ向き |
| 正確な行き先 | 広告の行き先は、広告主と宣伝するオファー・商品・サービスを正確に表す | C17 |
| **欺瞞的なリダイレクトと「審査から隠す」ことの禁止** | 「Advertisers may not use deceptive redirects or hide policy-violating content from reviewers」（欺瞞的なリダイレクトを使ったり、ポリシーに違反する中身を審査担当から隠したりしてはならない） | △ 34§6-3・§14 は「クローキングを名指しした規定は ❓」と書く。v1.7 の文は「クローキング」の語は使わないが、**審査と人に違う中身を見せることの禁止**として読める〔推測〕 |

| 高リスクの行き先 | フィッシング・タイポスクワットのドメイン・**確認されていないメッセージのチャネル**など、高リスクか欺瞞的な行き先へ送る広告は詐欺として禁止（P§2「詐欺及び不正行為」） | 34§2-2 |
| 紹介・リード獲得 | 第三者の事業者に送る広告主は、個人情報を集める前に、その役割と別の事業者が提供することをはっきり目立つ形で示す（P§3） | 34§2-5 |

- v1.7 の変更ログは「既存の掲載ポリシー及び広告主向けポリシーについて明確化し、詳細を追加しました」だけで、**どの文が足されたかは書かれていない** ❓。上の 2 つ（隠すことの禁止、メッセージングへの直リンク）は、既存の 34（v1.6 で書いた章）に無い文なので v1.7 で足されたと読める〔推測〕

### 2-5. リンク先の URL の仕様 ✅〔仕様〕（D:Ads、2026-11-24 取得）

| 項目 | 中身 |
|---|---|
| 形式 | HTTP か HTTPS の URL |
| 長さ | **2,048 字まで** |
| 届くこと | **OpenAI の広告のクローラーがアクセスできること**（「accessible to OpenAI's ad crawlers」） |
| パラメータ | `landing_page_configuration.query_string_template` をキャンペーン・広告グループ・広告で指定。アカウントのトラッキング設定が既定。優先は「フィード < アカウント < キャンペーン < 広告グループ < 広告」。同じキーなら優先の高い値が勝つ（`utm_*` 以外のキーも同じ） |

## 4. robots.txt の設定

### 4-1. 公式が言っていること ✅（H:20001243、D:Bots）

- OAI-AdsBot（必須）と OAI-SearchBot（推奨）を robots.txt で許す。**LP だけでなく、必要な素材（画像・CSS・JavaScript など〔推測〕）にかかる規則も**確かめる
- **リダイレクトに関わるホストごとに**確かめる（サブドメイン・外部の行き先も）。robots.txt はホスト（サブドメイン）ごとのファイルなので、計測リンクのドメイン、LP のサブドメイン、画像の CDN のそれぞれに置かれたものが効く〔推測〕
- **robots.txt の規則だけでは足りないことがある**。ファイアウォール・CDN・bot 対策が別の制限をかける（§5）
- エンジニアが最初に確かめること（FAQ）: LP が OAI-AdsBot に成功の応答を返すか、**robots.txt がその道筋（パス）を許しているか**、WAF・CDN・bot 対策・JavaScript の確認画面・CAPTCHA・認証・地域の規則が自動のアクセスを止めていないか
- OAI-SearchBot: robots.txt を変えてから、検索の仕組みが合わせるまで**約 24 時間** ✅（D:Bots）。OAI-AdsBot に同じ時間の記載は無い ❓

### 4-2. 書き方の例〔推測。公式に robots.txt の例文は無い ❓〕

```
# 広告の審査（必須）と ChatGPT の検索（推奨）を許す
User-agent: OAI-AdsBot
Allow: /

User-agent: OAI-SearchBot
Allow: /

# 生成 AI の学習には使わせない（任意。広告には影響しない）
User-agent: GPTBot
Disallow: /
```

- 〔推測〕`User-agent: *` で `Disallow: /lp/` のように LP の道筋を全部の bot に閉じていると、名指しの許可が無い限り OAI-AdsBot も止まる（robots.txt の一般の読み方。OAI-AdsBot が robots.txt に従うかの明文は ❓ なので、**止まらない保証も無い**）
- 〔推測〕Google の AdsBot は全体指定（`*`）を無視するので、Google では「`*` で閉じても広告の審査は通る」ことがある（`../Google広告の基礎/43_LPのテストと出し分け.md` §6-2）。**同じ設定で ChatGPT の審査が通るとは限らない**

### 4-3. 運用の判断への効き方

- robots.txt は「許していない」ことの点検用。**直しても WAF で止まっていれば通らない**ので、robots.txt の次に必ず §5 を見る
- robots.txt を直したのに状態が変わらないときは、§11 の手順で出し直す（OAI-AdsBot がいつ取り直すかは ❓）

## 5. WAF・CDN・bot 対策の設定

### 5-1. 公式の 5 段の点検 ✅〔公式の推奨〕（H:20001243 英語版・日本語版、2026-11-07 ごろ更新）

| 段 | 何をするか | 落とし穴 |
|---|---|---|
| 1. 広告の正確なリンクを確かめる | **トラッキング パラメータを含む完全な URL** を開き、リダイレクトをたどって、最後のページに広告の商品・サービスが出るか確かめる。計測リンクなら、**端末や地域で行き先が変わるか**も | **トップページが開くことは、広告のリンクが動く証拠にならない** |
| 2. OpenAI のクローラーを許す | OAI-AdsBot（必須）・OAI-SearchBot（推奨）。robots.txt を LP と素材について、**リダイレクトのホストごとに**（サブドメイン・外部の行き先を含む）。今のクローラーの文書と、公開された IP の範囲を使う | — |
| 3. セキュリティの設定を確かめる | 確認済みの OpenAI のクローラーの要求が、**ログイン・CAPTCHA・ブラウザの確認（browser challenge）なしで** LP と必要な中身に届くか。**最初のドメインだけでなく行き先のホストも**。拒否されたら、失敗した要求の時刻と要求 ID（あれば）で、サイトかセキュリティのログから該当の出来事を探す | robots.txt の規則だけでは足りない |
| 4. クローラーが受け取るページを確かめる | ブラウザで開けても、クローラーが同じ中身を受け取るとは限らない。**クローラーの要求への応答**をサイトの担当に確かめてもらう（§5-2 の表） | HTTP の成功だけでは、中身が読み込まれたことにならない |
| 5. 変えたら試し直す | 何をいつ変えたかを記録し、実際の広告の URL とリダイレクトでもう一度試す。広告が多いなら、**代表の URL 数本で試してから広げる**。直ったら Ads Manager で該当の広告を確かめ、状態が変わらなければ再提出・再審査の手順へ | 直しても承認は保証されない。LP・計測リンク・リダイレクト・ホスティング・セキュリティの設定を変えるたびにやり直す |

- サイトを他の人が管理しているなら、この点検の一覧をウェブの開発者・ホスティングの提供元・セキュリティの担当に渡す ✅〔公式の推奨〕（H:20001243）

### 5-2. 応答ごとの直し方 ✅〔仕様〕（H:20001243）

| クローラーへの応答 | 確かめること・直すこと |
|---|---|
| 403／アクセス拒否 | 拒否したホストのセキュリティの規則。**元のサイトではなく、リダイレクト先のサブドメインのことがある** |
| 404／見つからない | ページかリダイレクト先を直す。計測リンクは、端末・地域ごとに選ばれる行き先を確かめる |
| 429／要求が多すぎる | レート制限と bot 対策の出来事。大量の入稿は、小さく分けて出すと役立つことがある |
| 空白・不完全・ログイン・確認画面 | 意図したページの中身と必要な素材にクローラーが届くか。**HTTP の成功の応答だけでは、中身が読み込まれたことにならない** |

- ❓ OAI-AdsBot が **JavaScript を実行して描画後の中身を読むか**は記載なし。〔推測〕「空白・不完全なページは不可」「中身と必要な素材が届くか」と書くことから、**最初の HTML に商品の名前・価格・説明が入っていない作り（中身を JavaScript だけで後から差し込むページ）は危うい**。Google の AdsBot も同じ点が ❓（`../Google広告の基礎/43_LPのテストと出し分け.md` §6-2）

### 5-4. 固定の IP 範囲で許可するとき ✅〔公式の推奨〕（H:20001243）

- 一部のセキュリティの仕組みは、許可リストに入れるのに「公開された固定の IP 範囲から来ること」を求める。クローラーの基盤は変わりうるので、**ログで短い期間に見た IP だけに頼らない**
- 代わりに、**名乗り（ユーザー エージェント）、対応していれば確認済み bot の仕組み、ファイアウォールの許可リスト、robots.txt の振る舞い、提供元の bot 確認**を組み合わせて確かめる
- どうしても固定の一覧が要るなら https://openai.com/searchbot.json と https://openai.com/adsbot.json を使う
- 〔推測〕名乗りだけで許すと、OAI-AdsBot を名乗る別の bot も通る。名乗りと IP の範囲の両方が合うときだけ通す、が守りの強さと審査の通りやすさの釣り合いがよい

### 5-5. 地域の規則（geo rules）と日本のサイト

- FAQ は、自動のアクセスを止めるものとして**地域の規則（geo rules）**を名指しする。行き先の種類でも「**地域限定のアクセス（region-specific access）**」を要る行き先は、審査に十分な中身を渡せないことがある、と書く ✅（H:20001243）
- 計測リンクの点検でも「**地域によって行き先が変わるか**」を確かめるよう書く ✅（H:20001243）
- ❓ **OAI-AdsBot がどの国の IP から来るか**は記載なし（adsbot.json に地域の情報は無い）。Google は「AdsBot は主に米国から」と書く（G43§6-2）が、OpenAI は書いていない
- **運用の判断への効き方**〔推測〕: 日本のサイトに多い「海外の IP を全部弾く」「日本からだけ見せる」設定は、OAI-AdsBot が日本の外から来れば止める。34§0-1 も同じ指摘。①海外遮断があるかをサイトの担当に聞く ②あれば adsbot.json の範囲を例外にする ③地域で LP の中身を変えていないか（日本から見ると日本語、海外から見ると英語のトップへ転送、など）を確かめる

### 5-6. レート制限と大量の入稿 ✅〔公式の推奨〕（H:20001243）

- 大量の一括入稿や、クローラーの急な増加は、自動のレート制限や bot 対策を作動させることがある
- 疑わしいときは、HTTP の応答コード（とくに **429**）、ファイアウォール・CDN のログ、bot 対策の出来事、要求の絞り込みの規則、クローラーが来た時間帯の流入を、エンジニアに見てもらう
- **小分けにして、長めの時間をかけて入稿する**ことも考える。一括入稿の広告も、直したことを確かめる間は小さい束で出すと、レート制限や bot 対策に当たりにくい
- 〔推測〕一括入稿（05§10、02）で数百本の広告を一度に入れると、同じ LP に OAI-AdsBot が短時間に集中しうる。LP が同じなら束を分けても訪問の数は減らないかもしれないが、公式の勧めは「分ける」

## 6. ChatGPT のクラウド ブラウザ（広告の審査とは別の仕組み）

### 6-1. 何か・誰が使うか ✅〔仕様〕（H:20001280、2026-10-28 ごろ更新）

- クラウド ブラウザは、**ChatGPT Work に、クラウドの別のコンピューターの上の専用ブラウザ**を持たせる仕組み。ページを読み、ボタンを押し、フォームに入力し、公開のサイトとログインの要るサイトで手順を進める。頼みによって、つないだアプリ・プラグイン・クラウド ブラウザのどれか、または両方を使う
- **提供: 対応地域の有料プランの ChatGPT Work。無料版と Go は除く**（「excluding Free and Go」）。展開中は変わりうる。ワークスペースの権限にもよる
- 利用者は、新しいサイトへのアクセスのたびに許可を求められる（既定）。設定で「毎回聞く」「自動で承認（危うそうなときだけ止まる）」「常に許可（勧めない）」を選べ、サイトごとに許可・拒否もできる。予約の確定や支払いなど取り消しにくい操作の前には、チャットで確認を求める
- サイトの側で止めることもある: 「自動のブラウザ エージェントからのアクセスを制限するセキュリティの仕組みを使うサイトがある。…この制限はサイトが決めるもので ChatGPT ではない。…クラウド ブラウザの流入を許すかは、最後はそれぞれのサイトが決める」✅（H:20001280）
- クラウド ブラウザは端末のブラウザと別で、自分の Cookie・ログインを持つ。利用者の手元のブラウザのタブ・履歴・保存したパスワード・Cookie は使わない ✅（H:20001280）

### 6-2. 許可の仕方（開発者文書の「Help ensure cloud browser access to your site」）✅〔仕様〕（D:Commerce、2026-11-24 取得）

- サイトのファイアウォールが、利用者が頼んだ訪問を止めたり途中で切ったりすると、購入などの目的を果たせない。**ChatGPT の agent profile をファイアウォールの許可リストに入れる**。他のセキュリティの制御はそのままでよい
- **Akamai・Cloudflare・HUMAN・Vercel は、ChatGPT の要求の署名を自動で確かめる**。設定の手順は §5-3 の表の右の列
- FAQ:
  - 決済など特定の操作の前に人の確認を必須にできるか → サイトの持ち主が操作を制御する機能は**まだ無い**。ただし全利用者について、重大な操作の前に人の確認を求めている
  - 特定のページや商品だけエージェントに見せないことはできるか → 例外はサイト全体に効く。**既存のページ単位のアクセス制御はそのまま残す**
  - 他の bot に影響するか → しない。確認済みのクラウド ブラウザの訪問を許す規則は、他の流入の扱いを変えない。**この訪問は利用者の代わりのもので、OAI-SearchBot を含む OpenAI のウェブ クローラーとは別**
  - 商品フィードとの関係 → 独立しているが補い合う。フィードは商品の発見に、クラウド ブラウザは加盟店のサイトでの次の操作に。**フィードを設定していなくても**、確認済みの利用者はクラウド ブラウザでサイトを使える
  - プラグインとの関係 → 独立しているが補い合う。プラグイン（MCP）があると速く使えることがあり、作って公開することを勧める
  - 支払いや注文の誤りは誰が扱うか → 操作の責任は最後は顧客にある。顧客が自分で操作したときと同じように対応する

### 6-3. 署名の確かめ方（Web Bot Auth）✅〔仕様〕（D:Commerce）

- ChatGPT は **Web Bot Auth** で一部の自動のブラウザの要求を名乗る。これは**署名つきのクラウド ブラウザの要求の話で、ウェブ クローラーの話ではない**。仕組みは HTTP Message Signatures（**RFC 9421**）
- 署名つきの要求には `Signature`、`Signature-Input`、`Signature-Agent`（値は `"https://chatgpt.com"`）の 3 つのヘッダーが付く
- 公開鍵: https://chatgpt.com/.well-known/http-message-signatures-directory
- 自分で確かめる手順: ①`Signature-Agent` が引用符も含めて `"https://chatgpt.com"` と完全に一致するか ②公開鍵を取る ③RFC 9421 に沿って `Signature` と `Signature-Input` を検証 ④許可の例外は**署名を検証してから**かける

### 6-4. 運用の判断への効き方

- **クラウド ブラウザの許可は ChatGPT の広告の審査の点検項目ではない**〔推測。H:20001243 は OAI-AdsBot と OAI-SearchBot しか挙げず、D:Commerce はクラウド ブラウザをクローラーと別と書く〕。広告を出すために必要なのは OAI-AdsBot
- 逆に、**広告が出る利用者（無料版・Go）は、クラウド ブラウザを使えない**（H:20001280）。広告から LP に来る人は、ふつうは自分のブラウザか ChatGPT の中のブラウザで開く〔推測。広告のクリックでどのブラウザが開くかは記載なし ❓〕
- それでも EC・予約のサイトは、**有料プランの利用者が ChatGPT に「このサイトで予約して」と頼む場面**のために、クラウド ブラウザを止めていないかを点検する価値がある（00§9-2「広告以外の手」）。これは広告の運用とは別の判断として、サイトの担当と決める〔推測〕
- 00§9-2 は「クラウド ブラウザを弾かない」を加盟店の手に挙げ、国の制限は記載なし〔推測: 使える〕と書く。今回の本文で、**使える利用者の側は「対応地域の有料プラン」**と分かった（地域の一覧は記載なし ❓）

## 7. 商品フィードと画像のホスト

### 7-1. 決まり ✅〔仕様〕

| 項目 | 中身 | 出典 |
|---|---|---|
| 画像の URL を読む bot | **OAI-SearchBot が商品画像の URL を巡回できること**。画像のホストのファイアウォール・CDN・bot 対策の規則を確かめる。**403 の応答でフィードの処理が止まりうる** | H:20001243 |
| 一括入稿の画像 | 画像の URL は**画像そのものを返す**こと。プレビューやログインのページは不可 | H:20001217 |
| 画像の形と置き場 | PNG か JPG、正方形、1200×1200 以下。公開で、ブラウザで画像に直接開けること。置き場の例: 公開の Google ドライブのリンク、AWS（S3・CloudFront）、広告主のドメインか CDN の自前のリンク | H:20001217 |
| ホテルのフィード（限定ベータ） | LP と画像は公開でアクセスできること。ホテルのキャンペーンは国単位だけで、地域の除外・細かい地域・**絞り込んだプラットフォームの指定は使えない** | D:Ads（Hotel feeds） |

### 7-2. 運用の判断への効き方

- 〔推測〕「Google ドライブの公開リンク」を勧める文があるが、ドライブの共有リンクはふつうプレビューのページを返す。**画像そのものを返す直接のリンク**かを、ブラウザで開いて確かめる（H:20001217 の「画像そのものを返す」と合わせる）
- 商品フィードの広告が日本で使えるかは ❓（00§2-3、05§8-3）

## 8. 行き先の種類ごとの可否

### 8-1. 公式が挙げる「審査に十分な中身を渡せないことがある」行き先 ✅〔仕様〕（H:20001243 FAQ）

| 行き先 | 公式の扱い | 代わりの手〔推測〕 |
|---|---|---|
| アプリストアのリンク | 審査に十分な巡回できる中身を渡せないことがある | アプリの紹介ページ（Web）を LP にし、そこからストアへ |
| ディープ リンク | 同上 | 同上 |
| 文書（PDF など〔推測〕） | 同上 | 中身を HTML のページにする |
| アプリやログインが要る行き先 | 同上 | ログインの前の公開ページ |
| 地域限定のアクセスが要る行き先 | 同上 | 地域の規則の例外（§5-5） |
| 対応していないリダイレクト | 同上（どのリダイレクトが対応していないかは記載なし ❓） | 計測リンクを挟まず、LP に直接パラメータを付ける（06§14-3） |
| **メッセージングのチャット・グループへの直リンク** | **不可**（P§3、v1.7） | 自社サイトの LP に連絡手段として置く |

- 公式の勧め: **できるかぎり直接届く Web の LP を使う** ✅（H:20001243）

### 8-2. 年齢確認の画面・会員だけのページ・確認画面〔推測を含む〕

- 「ログイン・CAPTCHA・ブラウザの確認」はクローラーを止める ✅（H:20001243）。〔推測〕年齢確認の画面（「20 歳以上ですか」の入口）も、クローラーには「確認画面」に見える。もっとも、酒の広告はそもそも禁止（P§2）
- 〔推測〕会員限定の価格・クーポンの LP は、ログインの前の公開ページに広告の商品が出るようにする

### 8-3. LP の出し分け（A/B テスト・LPO の道具）〔推測を含む〕

- ✅ v1.7 は「欺瞞的なリダイレクト」と「ポリシー違反の中身を審査から隠す」ことを禁じる（P§3）
- 〔推測〕**A/B テストそのものは禁止されていない**（禁止なのは違反の中身を隠すこと）。ただし、クローラーには案 A、人には案 B が出る作りだと、案 B がポリシーに合わなければ「隠した」と見なされうる。**どの案もポリシーに合うこと**、**クローラーに何が見えるか**（名乗り・IP で案が固定されるか、毎回ランダムか）を確かめる
- 〔推測〕クリエイティブの強化の「リンク先 URL の最適化」（§2-2）も、LP の出し分けと重なると、どのページのどの案に送られたかが追いにくくなる。テストの期間は強化をオフにする選択肢がある（05§6-2）
- ❓ OAI-AdsBot が JavaScript を動かして出し分けの後の中身を見るかは記載なし（§5-2）。Google でも ❓（G43§6-2）

## 9. クローラーの訪問が有料の流入に見える件（計測）

### 9-1. 公式の文 ✅〔仕様〕（H:20001207 英語版、2026-11-15 ごろ更新）

- 「Ad-review crawlers may visit submitted landing pages with tracking parameters. Third-party analytics may classify these visits as paid traffic, but crawler visits are not billable ad clicks and do not incur click charges.」（審査のクローラーは、提出された LP をトラッキング パラメータ付きで訪れることがある。第三者の解析ツールはそれを有料の流入と分類することがあるが、クローラーの訪問は課金されるクリックではなく、クリックの料金はかからない）
- 同じページ: UTM などの**固定のパラメータはクリックで保たれ**、既存の解析ツールで ChatGPT の広告からの流入を見るのに使える
- 2026-11-22 ごろに更新された「Why conversion totals differ between platforms」（H:20001632）は、媒体ごとに数字が合わない理由として、数えるものの違い・帰属の違い・日付・反映の遅れ（24〜48 時間）・同意やブラウザの制限・推計を挙げる。**クローラーの訪問は挙げていない**（2026-11-24 時点）

### 9-2. どう見分けるか〔推測。公式に見分け方の手順は無い ❓〕

| 見る場所 | 手がかり |
|---|---|
| サーバーのアクセス ログ・CDN のログ | 名乗りに `OAI-AdsBot` を含む訪問。IP が adsbot.json の範囲か（§3-2） |
| GA4 などの解析ツール | 入稿・広告の編集の直後に、Ads Manager のクリック数より多い UTM 付きの訪問。滞在がごく短い・直帰。〔推測〕GA4 が OAI-AdsBot を既知の bot として自動で除くかは ❓（Google の公式も OpenAI の公式も書いていない。このメモでは調べていない） |
| Ads Manager | クローラーの訪問はクリックに数えられない（課金されない）ので、**Ads Manager のクリック数には出ない** ✅（H:20001207 の「not billable ad clicks」から） |
| `oppref` | ❓ クローラーの訪問に `oppref`（クリックのたびに付く参照、06§7）が付くかは記載なし。〔推測〕`oppref` はクリックで付くものなので、**UTM はあるが `oppref` が無い訪問**はクローラーか、パラメータの付け方の誤りを疑う手がかりになりうる |

### 9-3. 運用の判断への効き方

- **広告を入稿・編集した日を台帳に書き**、その日と翌日の UTM 付きの流入を割り引いて読む〔推測〕。06§14-1 と同じ
- GA4 の「ChatGPT の広告からの流入」と Ads Manager のクリック数を比べるとき、**GA4 が多すぎる日があればクローラーの訪問を先に疑う**。逆に GA4 が少ないのは、同意・ブラウザの制限・`oppref` や UTM の欠け（06§7-2）を疑う〔推測〕
- コンバージョンには響きにくい〔推測〕: クローラーは購入・申込をしない。ただし「LP 到達」「ページ閲覧」を成果にしていると、クローラーの訪問で数字が膨らみうる（ピクセルが動くかは ❓）。**ページ閲覧を成果の目標にしない**（06§9）

## 10. 点検の手順（入稿前・変更後・落ちたとき）

### 10-1. 入稿前（サイトの担当と一緒に）

1. 広告に入れる**完全な URL**（パラメータ込み）を決める（§2-5）。計測リンクを挟むなら、端末・地域ごとの行き先を全部書き出す
2. リダイレクトをたどり、**関わるホスト**（計測リンクのドメイン、LP のドメインとサブドメイン、画像の CDN、外部の行き先）を一覧にする
3. 各ホストで robots.txt を見る: OAI-AdsBot（必須）・OAI-SearchBot（推奨）を止めていないか（§4）
4. 各ホストで WAF・CDN・bot 対策を見る: 「AI の bot の一括遮断」「海外の IP の遮断」「JavaScript の確認画面」「CAPTCHA」「レート制限」（§5）
5. サーバーに、OAI-AdsBot の名乗りで LP を取らせたときの応答を見てもらう: 200 か、中身（商品名・価格・説明）が最初の HTML にあるか（§5-2）。〔推測〕手元で名乗りを変えて取るのは「OpenAI の IP から来た」ことにならないので、IP で絞る規則の確認にはならない
6. 商品フィードなら、画像のホストで OAI-SearchBot を確かめる（§7）
7. LP の中身: 広告の商品が最初の画面にある、禁止の商品が並ばない（P§2 の一貫性、34§2-4）、メッセージングへの直リンクでない（§2-4）

### 10-2. 変更のあと

- LP・計測リンク・リダイレクト・ホスティング・セキュリティの設定を変えたら、**10-1 の 1〜5 をやり直す** ✅〔公式の推奨〕（H:20001243）
- 〔推測〕サイトの改修・CDN の乗り換え・WAF の規則の更新の予定を、広告の運用の側にも知らせてもらう約束をしておく（承認後も審査は続く、§2-1）

### 10-3. 「Not serving」で LP が理由のとき

1. 状態にカーソルを当てて理由を読む（H:20001217）
2. §5-1 の 5 段で原因を探す。失敗の時刻と要求 ID がサポートから伝えられたら、サイトの担当に渡してログを探してもらう（H:20001243）
3. 直したら、同じ URL とリダイレクトで試す → Ads Manager で状態を見る → 変わらなければ再提出か再審査（§11）

## 11. 直したあとの流れ・サポートに伝えること ✅（H:20001243、H:20001217）

- 直ったら、Ads Manager で該当の広告を確かめる。**状態が自動で変わらなければ、再アップロードか再提出・再審査**の手順に従う。一括入稿の広告は、直したことを確かめる間は小さい束で出す
- **サポートの手動の回避に頼らない**。robots.txt・WAF・CDN・bot 対策・認証・レート制限を直して、OAI-AdsBot が読めるようにする。LP が読めるようになった後に、広告の再アップロードか再提出が要ることがある
- **直しても承認は保証されない**。広告は引き続き審査を通る必要がある
- サポート（ads-support@openai.com か、ヘルプの右下の窓口。H:20001217）に伝えるもの（H:20001243）:
  - 影響のある広告アカウントと広告の ID（分かれば）
  - 広告に使った正確な URL と、最後の行き先
  - エラーのメッセージか画面の写し
  - 失敗した時刻（時間帯を含む）
  - サイトの担当が何をいつ確かめ・変えたか
- サポートへの連絡にパスワードや支払いの情報を入れない（H:20001217）

| 思い込み | 実際 | 根拠 |

| ブラウザで LP が開けるから審査は大丈夫 | ブラウザで開けても、クローラーが同じ中身を受け取るとは限らない。HTTP の成功の応答だけでは中身が読み込まれたことにならない | ✅ H:20001243 |
| トップページが開くから広告のリンクも動く | トップの成功は広告のリンクが動く証拠にならない。パラメータ込みの完全な URL で、端末・地域ごとの行き先まで確かめる | ✅ H:20001243 |
| robots.txt で OAI-AdsBot を許したから通る | robots.txt だけでは足りない。WAF・CDN・bot 対策・JavaScript の確認画面・CAPTCHA・認証・地域の規則が別に止める | ✅ H:20001243 |
| 「AI に学習させたくない」から OpenAI の bot は全部止める | 学習の bot は GPTBot。OAI-AdsBot は広告として出されたページだけ訪れ、学習に使わない。止めると広告の審査が通らない。設定は互いに独立 | ✅ D:Bots |
| Google の AdsBot を通しているから OAI-AdsBot も通る | 名前も仕組みも別。Google の AdsBot は robots.txt の `*` を無視するが、OAI-AdsBot の扱いは記載なし | ✅ D:Bots、G43§6-2／❓ |
| Cloudflare なら何もしなくてよい | Cloudflare は OAI-AdsBot を確認済みの bot として許可している。ただしサイト側の独自の規則・AI の bot の遮断は別〔推測〕。点検は省かない | ✅ H:20001243＋〔推測〕 |
| クラウド ブラウザを許可すれば広告の審査も通る | クラウド ブラウザは利用者の代わりにサイトを操作するもので、クローラーとは別。広告に要るのは OAI-AdsBot。しかもクラウド ブラウザは有料プランだけで、広告が出る無料版・Go の利用者は使えない | ✅ D:Commerce、H:20001280 |
| サポートに頼めば LP の確認を手で通してもらえる | 手動の回避に頼らない。LP を読めるようにして出し直す | ✅ H:20001243 |
| 直したのだから承認される | 直しても承認は保証されない。審査は続く | ✅ H:20001243 |
| GA4 の ChatGPT 広告の流入がクリック数より多いのは、計測の誤り | 審査のクローラーがパラメータ付きで LP を訪れ、解析ツールで有料の流入に見えることがある（課金はされない） | ✅ H:20001207 |
| LINE の友だち追加やオープンチャットに直接飛ばせば早い | 広告からメッセージングのチャット・グループへ直接リンクできない（v1.7）。自社サイトの中で連絡手段として置くのは可 | ✅ P§3 |
| 商品画像は LP と同じ許可で済む | 商品画像の URL には OAI-SearchBot が要る。画像のホストが別なら、そちらの設定も見る。403 でフィードの処理が止まりうる | ✅ H:20001243 |

## 15. 公式に記載なし ❓ と確かめ方

| 項目 | 確かめ方〔推測〕 |
|---|---|
| OAI-AdsBot が robots.txt に従うか（名指しが要るか、`*` に従うか） | D:Bots・H:20001243 の更新を見張る。サポートに聞く |
| OAI-AdsBot がどの国・地域の IP から来るか | adsbot.json の範囲の持ち主を調べる（第三者の情報になる）。サポートに聞く |
| OAI-AdsBot が JavaScript を実行して描画後の中身を読むか | サーバーのログで、OAI-AdsBot が CSS・JavaScript・画像も取りに来るかを見る（取りに来ても実行の証拠にはならない） |
| OAI-AdsBot の名乗りの版の番号が変わるか | D:Bots の RSS を見張る |
| robots.txt や WAF を直してから OAI-AdsBot が取り直すまでの時間 | 直した時刻と状態が変わった時刻を台帳に書く |
| どのリダイレクトが「対応していないリダイレクト」か | — |
| クリエイティブの強化の「リンク先 URL の最適化」がどのページに送るか、事前に知る手段 | レポートで LP 別の数字が取れるかを見る（取れるかも ❓） |
| GA4 が OAI-AdsBot の訪問を既知の bot として自動で除くか | Google の GA4 の公式で取り直す（この章では調べていない） |
| クローラーの訪問に `oppref` が付くか | サーバーのログで、OAI-AdsBot の訪問の URL を見る |
| 商品フィードの旧方式のパラメータの移行期限（2026-11-05）を過ぎたアカウントの扱い | D:Ads の更新を見る |
| クラウド ブラウザが使える地域の一覧 | H:20001280 の更新を見る |
| 広告のクリックで LP がどのブラウザで開くか（ChatGPT のアプリの中か、端末のブラウザか） | 実機で確かめる（運用者の判断。広告をクリックすると課金されるので、自社の広告ではしない） |
