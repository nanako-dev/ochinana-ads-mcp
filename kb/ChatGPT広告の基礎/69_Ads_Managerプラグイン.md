## 0. 先に結論（この章で一番効く 10 点）

1. **プラグインは「ChatGPT Ads Manager」というアプリ（MCP の道具）と、十数個のスキルの束**。開発者は OpenAI、機能の表示は「Interactive, Read, Write」。紹介ページの手順は「ChatGPT Work または Codex で新しいチャットを始め、プラグインを使うよう頼む」✅〔仕様〕（A-02）
2. **使えるかは、プラグイン・プラン・ワークスペースの設定で決まる**。一部の接続は管理者の設定か承認が要る。ブロックされていたらワークスペースの管理者に聞く ✅（A-02、h11487775）。**国の制限は書かれていない** ❓
3. **触れるのは、つないだ Ads Manager の利用者が触れるアカウントと資源だけ**。できる操作はその人の役割とアカウントで有効な機能で決まる ✅〔仕様〕（S-50）。プラグイン専用の権限の段は無い（Ads の役割がそのまま効く）〔推測〕
4. できることは 6 つ: ①サイトか依頼文から広告の下書き（見出し・説明文・画像）②商品フィードからのキャンペーン ③キャンペーン・広告グループ・広告の管理（作成・設定の更新・停止・再開・アーカイブ・画像の差し替え）④成果と成果の計測の分析 ⑤配信の診断 ⑥1 回か**日次・週次の予約の点検**。ほかにアカウントの作成の手伝いと利用者の管理 ✅（S-50）
5. **読む・分析・診断・点検はアカウントを変えない**。下書きとプレビューは上げない・公開しない。**上げる・作る・変える（アカウント・キャンペーン・広告グループ・広告・ロゴ・利用者のアクセス）は、その操作をそのまま確かめてから**。変える前に「アカウント・今の状態・変えた後・変わる値」を見せ、変えた後に読み直して確かめる。承認の後に中身が変われば、もう一度聞く ✅〔仕様〕（S-50）
6. **予約の点検は提案だけで、自動では何も変えない**。準備・配信・計測を見て、予算・入札・ターゲティング・文面・画像の順位づけした改善点を、根拠と次の手つきで出す。予約の前に中身を下見できる ✅（S-50）
7. 期間を言わなければ「**アカウントの時間帯で、終わった直近 7 日**」。数字は Ads Manager にいまある分で、ふつうのレポートとアトリビューションの遅れがそのまま入る ✅（S-50）
8. **売上と ROAS は出さない**（成果の値を受け取らない）。直近の生の成果のイベントは「直前 15 分の最新 50 件」だけで、過去のレポートではない ✅〔仕様〕（S-50）
9. **請求・支払い方法・税・法人の身元の情報・異議申し立ては Ads Manager で直接**。ビジネス エージェントの広告は作れない（△ 紹介ページのスキルの一覧に「Business Agent Setup」がある。§7）。まとめて作れる標準の広告は 1 回 50 本まで（同じ画像・切り抜き・リンク先）。確認・審査・資格・配信の判断は覆せない ✅（S-50）
10. **Claude（運用 MCP）からはこのプラグインを使えない**。Claude から日次の数字を取るのは Advertiser API と Ads API キー（65§1-1）。プラグインは「ChatGPT の中で見る・下書きを作る・点検の提案を受ける」道具、API は「自分の道具で毎日決まった数字を取る」道具 〔推測: 65§1-1 と同じ〕

## 3. 入れ方・つなぎ方・外し方

### 3-1. 入れる・つなぐ ✅〔仕様〕（A-02、L-01、h11487775）

1. プラグインの一覧（Plugins）で「ChatGPT Ads Manager」を探す（紹介ページの「プラグインをインストール」からも開く）
2. ＋ で入れる。MCP サーバーの接続が要るなら、促されたときにつなぐ（入れるときに認証するものと、初めて使うときまで待つものがある）
3. 「プロンプトに従って権限を確認し、必要なアプリを接続」する（A-02）。アプリが個別の認可を求めるなら、使いたい情報にアクセスできるアカウント（ここでは Ads Manager の利用者）でログインし、求められる範囲を見てから認可する（h11487775）
4. 新しいチャットを始め、プラグインを使うよう頼む。「@」でプラグインかスキルを名指しして呼ぶこともできる（L-01）
- **プラグインを入れても、アプリに要るアカウントの認可やワークスペースの承認の代わりにはならない** ✅（h11487775）
- 入れた後のスキルは、新しいチャットから使える ✅（L-01）

### 3-2. ワークスペースの管理者の側 ✅〔仕様〕（h11487775、L-01、A-02）

- ChatGPT Business では多くのアプリが既定で有効で、管理者がワークスペースのアクセスを変えられる。新しい Enterprise・Edu のワークスペースは選ばれたアプリだけが有効で始まる
- 管理されたワークスペースでアプリが「Disabled by admin」と出たら、管理者に見直してもらう（管理者は Admin Console → 対象の ChatGPT のワークスペース → Plugins）。管理者・所有者はワークスペースの設定からアプリを無効にできる
- **プラグインが使えること、アプリのアクセス、役割の権限、提供元のアカウントの認可は、別々の管理** ✅（h11487775）
- 個人のアカウントで管理者がいないなら、アプリの要件を見て、表示が続くなら OpenAI のサポートへ ✅（h11487775）
- 運用の判断への効き方: 会社の ChatGPT のワークスペースで使うなら、**ワークスペースの管理者（情シス）**と**広告アカウントの管理者（マーケ）**の両方の許可が要る〔推測: 権限が別々の管理という書き方から〕

### 3-3. 外す ✅〔仕様〕（L-01、h11487775）

- 対応するプラグインの一覧で開き「Uninstall plugin」（あるとき）。ワークスペースが入れたプラグイン・既定のプラグインは、この操作が無く管理者が管理することがある
- **プラグインを外しても、別につないだ MCP サーバーの連携は ChatGPT の中でつながったまま**。外すなら別に切る（L-01）
- アプリのアクセスをなくすには、切る（Settings > Plugins）か、管理者に無効にしてもらう。「アプリの権限」の設定を変えても、アプリが持つアクセスは減らない（いつ確認を求めるかが変わるだけ）（h11487775）
- 運用の判断への効き方: 担当が替わったら、**プラグインを外すだけでなく接続も切る**。広告アカウントの側でもその人の役割を外す（27§4-2）〔推測〕

## 4. できること ✅〔仕様〕（S-50、last month の更新。A-02）

| 分野 | できること | 確認の要否 |

| **サイトか依頼文から広告を作る** | 公開のサイトか商品のページを渡すか、宣伝したいものを書く → 見出しと説明文を下書き。画像は ①サイトから合うものを探す ②渡した画像を使う ③条件を満たす既存のクリエイティブを使い回す ④**選んだときだけ新しい画像を生成**。1 本か、同じ承認済みの画像・切り抜き・リンク先を使う**標準の広告のまとまり**を作る。**上げる・保存する前にプレビュー**。既存のキャンペーンと広告グループに足すか、足りない構成を作る。承認したクリエイティブを上げ、確認した状態で広告を作る。作る前に LP・画像・文面・キャンペーンの設定・予算・ターゲティングなどを見せて承認を求める | 下書き・プレビューは不要。上げる・作るは要る |
| **商品フィードから作る** | 条件を満たす商品フィードがあれば、商品フィードのキャンペーン・広告グループ・広告のテンプレートを作る。画像はフィードから。**商品フィードの広告グループはアーカイブしていないテンプレートを 1 つだけ** | 要る |
| **管理する** | 名前でアカウント・キャンペーン・広告グループ・広告を探す。今の設定と状態を見る。キャンペーン・広告グループを直接作る。既存の広告のプレビュー。対応する設定の更新。**停止・再開・アーカイブ**。既存の広告の画像の差し替え。変更は 1 つの資源に限り、アカウント・今の状態・提案の状態・変わる値を見せて承認を求め、**成功の後に読み直して確かめる** | 読むのは不要。変えるのは要る |
| **成果と成果の計測を分析する** | アカウント全体か、キャンペーン・広告グループ・広告の中で、比べる・順位をつける。表示・クリック・費用・CTR・平均 CPC・平均 CPM。計測があればアトリビューションした成果。選んだ期間の推移。時間・端末・国・下の階層での内訳。成果の計測元と設定の見直し、診断のための直近の生の成果のイベントの確認。紹介ページは「変更履歴の分析」も挙げる（A-02） | 不要 |

## 5. 確認の仕組みと、ChatGPT の「アプリの権限」の設定

### 5-1. プラグインの確認 ✅〔仕様〕（S-50）

| 操作 | アカウントが変わるか | 確認 |
|---|---|---|
| アカウントのデータを読む、成果を分析する、配信を診断する、推奨の見直し | 変わらない | 不要 |
| 広告の下書き・プレビュー | 変わらない（上げない・公開しない） | 不要 |
| クリエイティブを上げる、アカウント・キャンペーン・広告グループ・広告・ロゴ・利用者のアクセスを作る・変える | 変わる | **その操作をそのまま確かめてから** |
| アカウントの作成 | 変わる | 上に加え、**広告規約とプライバシー ポリシーへの明示の同意** |
| 承認の後に提案の中身が変わった | — | 新しい提案を見せて**もう一度聞く** |

- FAQ: 「プラグインは聞かずに変えるか」→「いいえ。クリエイティブを上げる、Ads Manager の資源を作る・変える前に、提案の全体を見せて確認を求める」✅（S-50）
- FAQ: 「予約の見直しは自動で最適化するか」→「いいえ。1 回も予約も読むだけ。推奨を出し、対応する変更は別に承認を求めて示す」✅（S-50）

### 5-2. ChatGPT の「アプリの権限」の設定との関係 ✅〔仕様〕（h11487775、一昨日の更新）・△

- ChatGPT のアプリ一般には、いつ確認を求めるかを決める「アプリの権限」の設定がある。選べるものは「Always ask」「Allow read actions」「Allow low-risk actions」「Allow all actions」（条件を満たすアプリ・アカウントだけ）など
- 「Allow all actions」は「対応する操作が、ほかの確認なしに動きうる」ので**危険が高い**、と公式は書く。アカウント全体・ワークスペース全体の標準の選択肢にはこれが無い。機微な操作は承認が要るか、断られることがある
- 「アプリの権限」は新しいアクセスを与えない（アプリが持つアクセスに対して、いつ聞くかを変えるだけ）
- △〔推測を含む〕**プラグインのヘルプは「聞かずに変えない」と書き、ChatGPT のアプリ一般のヘルプは「Allow all actions ではほかの確認なしに動きうる」と書く**。Ads Manager のアプリで「Allow all actions」を選べるか、選んだときにプラグイン自身の確認（提案を見せて承認を求める）が残るかは、公式に書かれていない ❓。**広告アカウントを変えうるので、Ads Manager のアプリは「Always ask」か「Allow read actions」のままにする**〔推測〕

### 5-3. 下書きにアカウントは要るか ✅（S-50 FAQ）

- 「広告の下書きに Ads Manager のアカウントは要るか」→「いいえ。アカウントを選ぶ前に、クリエイティブを下書きしプレビューできる。**クリエイティブを上げる・広告を保存するには、書き込みのできる条件を満たす Ads Manager のアカウントが要る**」

### 5-4. 運用の判断への効き方

- プラグインの確認は「人が毎回承認する」形で、Google の自動化ルールや Meta の自動ルールのような**条件で自動に動く仕組みは無い** ✅（S-50: 予約の見直しは変えない）
- 変更を承認する前に、**見せられた「変わる値」をそのまま記録**しておく（監査ログと突き合わせられるように）〔推測〕
- 「Allow all actions」を許さないことを、ワークスペースの決まりにしておく〔推測〕

## 6. 権限（誰のどの権限で動くか）

### 6-1. 公式に書かれていること ✅〔仕様〕（S-50、S-40、A-02、h11487775）

- 「プラグインは、**つないだ Ads Manager の利用者**が使えるアカウントと資源だけにアクセスできる。**できる操作は、その人の役割とアカウントで有効な機能による**」（S-50）
- Ads の役割（27§4-1）: 管理者（アカウントと利用者のアクセスの管理）、メンバー（広告の資源を使い・更新する）、閲覧者（見るだけ。書き込みもアカウントの管理もできない）（S-40）
- 上げる・保存するには「**書き込みのできる**」アカウントが要る（S-50）
- ChatGPT の側の権限: プラグインが使えること、アプリのアクセス、役割の権限、提供元のアカウントの認可は別々の管理（h11487775）。Codex の中で動くときは、Codex の砂場（sandbox）と承認の方針が効き、外のサービスへの接続はそのサービスの認証とアクセスの管理を使う（L-01）
- 一部の接続は管理者の設定か承認が要る（A-02）

### 6-2. 役割ごとに何ができそうか〔推測。根拠は 6-1〕

| Ads の役割 | 読む・分析・診断・点検 | 下書き・プレビュー | 作る・変える・停止 | 利用者の管理・ロゴ |
|---|---|---|---|---|
| 管理者 | できる | できる | できる（確認つき） | できる（確認つき） |
| メンバー | できる | できる | できる（確認つき） | ❓（メンバーは「アカウントの管理の権限が無い」ので、できないと読める） |
| 閲覧者 | できる | できる（アカウントが無くても下書きはできる） | できない（書き込みの権限が無い） | できない |

- ❓ 公式はプラグインの操作ごとに要る役割の表を出していない。上の表は Ads の役割の説明とプラグインの「役割による」から組んだもの

### 6-3. 運用の判断への効き方

- **外注先・代理店の担当にプラグインで分析だけを頼むなら、広告アカウントの閲覧者で招き、その人のプラグインでつないでもらう**。Ads API キーを渡すより、規約（27§9-2）と権限の両面で安全〔推測〕
- 自分のプラグインは自分の役割（管理者なら全部）で動く。**ふだん分析だけに使うなら、分析用に閲覧者の別の利用者を用意する手もある**が、利用者を増やすと所属の数・管理の手間が増える（27§3-5）〔推測〕

## 8. 点検の予約（推奨だけの見直し）

### 8-1. 公式に書かれていること ✅〔仕様〕（S-50）

- 1 回だけの見直し（有効なキャンペーン）か、**日次・週次の見直しの予約**
- 見るもの: **準備（readiness）・配信（delivery）・計測（measurement）**
- 出すもの: **予算・入札・ターゲティング・文面・クリエイティブ**にわたる機会の優先順位。**根拠と、はっきりした次の手**つき
- **アカウントは決して変えない**。対応する追いかけの変更は、別に承認を求めて示す
- 予約の前に、予約する見直しを**下見**できる
- 例: 「推奨だけの週次の見直しを設定して」「有効なキャンペーンを CMO の目線で見直して」
- 紹介ページのスキルの名前に「Ads Manager Actionable Review」がある（A-02）

### 8-2. 書かれていないこと ❓

- 点検の**基準**（何を「問題」とみなすかのしきい値）、点検の結果がどこに届くか（ChatGPT の中のタスクか通知か、メールか）、時刻を選べるか、予約をいくつ持てるか、点検が使う期間（既定の 7 日か）
- ChatGPT のタスク一般: 予約のタスクは、つないだアカウントと既存のアプリの権限で許された情報だけに触れ、ワークスペースのアプリの設定・役割の権限・承認の要件も効く。承認が要る操作があると、見直すまでタスクは止まる ✅（h11487775。Ads Manager のプラグインに限った記述ではない）

### 8-3. 運用の判断への効き方〔推測〕

- ads-mcp の `get_anomalies`＋朝の定例に近い（65§1-2）。ただし基準が公開されておらず、売上・ROAS が無い。**点検の推奨は、28§1・36§5 の点検の型と公式の推奨（28§12-2）で裏を取ってから使う**
- 予約の点検の推奨に「予算を上げる」「入札を上げる」が出ても、運用の型の順（計測 → 成果の定義 → 絞る → 素材 → 構成 → 入札・予算）で上流が片づいているかを先に見る（28 の順）
- 日次の点検は気づきの補助。**日次の数字の記録（シート）の出どころにはしない**（65§1-2）

## 10. 分析の既定と数字の扱い ✅〔仕様〕（S-50、A-02）

| 項目 | 中身 |

| 期間の既定 | 期間を言わなければ**アカウントの時間帯で、終わった直近 7 日**（trailing seven completed days） |

## 11. データの扱いと責任（規約・ChatGPT の設定）

### 11-1. ChatGPT の側 ✅〔仕様〕（h11487775、L-01。アプリ一般の記述で、Ads Manager に限った記述ではない）

| 項目 | 中身 |
|---|---|
| モデルの学習 | **ChatGPT Business・Enterprise・Edu**: アプリから得た情報を既定ではモデルの学習に使わない。**Free・Plus・Go・Pro**: 「Improve the model for everyone」の設定がオンなら、アプリから得た情報を学習に使うことがある |
| メモリ | メモリがオンなら、アプリが応答するときに関係するメモリを使うことがあり、ChatGPT はアプリから得た関係する情報を覚えることがある（アプリや接続元が保存を制限する場合を除く） |
| Web の検索 | アプリから得た関係する情報を、Web の検索の問いに使うことがある |
| 規約 | アプリと共有するデータは、各アプリの利用規約とプライバシー ポリシーに従う。MCP サーバーを通じてデータを送るときは、そのサービスの規約とプライバシー ポリシーが効く（L-01） |
| 利用の枠 | アプリの利用は ChatGPT のプランの上限や機能ごとの枠に数えられることがある |

- 運用の判断への効き方〔推測〕: 広告アカウントの数字・予算・顧客の情報を扱うので、**個人の Free・Plus で使うなら「Improve the model for everyone」をオフにする**か、Business 以上のワークスペースで使う。顧客の数字を扱う代理店は、社内の情報の扱いの決まりに照らす

### 11-2. 広告規約・広告ツール規約の側 ✅〔仕様〕（T-01、S-20）

- 広告規約の「広告マネージャー」は、広告サービスの管理に使う**インターフェース・API・ツール・関連機能**を指す（T-01 第 12 条）。プラグインがここに含まれると明記はされていない ❓ が、Ads Manager のアカウントを操作する以上、広告規約の義務（アカウントと認証情報の安全、認定ユーザーの作為・不作為への責任、漏洩の通知）は同じく効く〔推測〕（27§9-2）
- **AI が作った文面・画像の責任は広告主**: 広告規約は、AI が生成した出力を含むすべての推奨・設定・出力について、広告主が単独で責任を負うと定める（第 5.3 条）。広告ツール規約は、AI のクリエイティブのツールが生成したクリエイティブを、承認・使用・適用したら「広告」とみなし、価格・在庫・推薦・資格・期待される結果などの重要な表示の正確さ・裏づけと、法令やポリシーが求める AI 生成の開示に広告主が責任を負うと定める（S-20 第 3.1・3.2 条）。生成物の正確さ・権利の非侵害・法令の遵守は保証しない（第 3.3 条）
- プラグインの画像の生成・文面の下書きが広告ツール規約の「AI クリエイティブツール」に当たるかは書かれていない ❓。当たるものとして扱い、**下書きは薬機法・景品表示法などの日本の法規の目で見てから承認する**（31）〔推測〕
- レポートのデータは頻度・リーチ・効果の測定の目的だけに使い、自然人の特定や OpenAI の利用者を識別するセグメント作りに使わない（T-01 第 5.4 条）

## 13. 運用での使いどころ（28§11-6 を土台に）〔推測〕

1. **引き継ぎの初日**: 「アカウントの構成を一覧にして」で、キャンペーン・広告グループ・広告・状態・予算を書き出してもらい、27§12 の点検表と突き合わせる
2. **配信が止まったとき**: プラグインの診断で最初の制約を出し、27§8-4 の順で裏を取る。請求・確認の問題なら管理画面へ
3. **下書き**: 商品ページから角度の違う見出し・説明文を作り、法規（31）とブランドの言い回しで直してから承認。画像の切り口は別に作る
4. **週次の推奨だけの見直し**: 予約して、推奨を 28§1・36§5 の型と公式の推奨（28§12-2）で裏を取ってから採る。**推奨をそのまま一括で承認しない**
5. **やらないこと**: 売上・ROAS の報告、日次のシートの数字の出どころ、「Allow all actions」での利用、規約を読まずのアカウントの作成
