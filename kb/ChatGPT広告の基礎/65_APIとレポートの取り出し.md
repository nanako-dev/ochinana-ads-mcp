## 0. Google 広告 API との対比表

Google 側は `../../ads-mcp/README.md`（いまの作り）と `../Google広告の基礎/27_アカウント管理と安全.md` §5-6、`06_コンバージョン計測.md`、`26_効果測定の実務.md` に合わせた。

| 観点 | Google 広告 API（いまの ads-mcp） | ChatGPT の広告（Advertiser API） | 運用の判断への効き方 |
|---|---|---|---|
| 入口 | OAuth クライアントを持つ Google Cloud プロジェクトの段階（エクスプローラー以上）＋ OAuth の更新トークン。開発者トークンは 2026-09-09 に廃止（G27）。認証ファイル `google-ads.yaml` | **Ads Manager の「設定 > 一般 > API キー」で作る API キー 1 本**を `Authorization: Bearer` で送るだけ ✅〔公式〕S-01、S-62。アプリの登録・開発者の審査・申請は、文書に**出てこない** | 準備は Google よりずっと軽い。|
| 鍵の効く範囲 | 認可したユーザーが触れるアカウント（MCC 配下も）。ads-mcp は許可リストで 2 つに絞る | **キー 1 本 ＝ 広告アカウント 1 つ** ✅〔公式〕S-01 Authentication。複数のアカウントを読むなら、アカウントごとにキーを作る | 許可リストは「キーとアカウント ID の組」で持つ〔推測〕 |

| アトリビューションの窓 | コンバージョン アクションの設定。入札にも効く（G06） | **呼び出しごとに指定するレポートの設定**で、最適化・入札・課金は変わらない ✅〔公式〕S-01、S-45 | API で取るときは窓を毎回明示する。省略すると既定が入る |

| アカウントの中で動くスクリプト | Google 広告スクリプト、自動ルール（メール送信あり） | ❓ 記載なし。代わりに ChatGPT の中のプラグインが「日次・週次の点検」を予約できる（提案だけ）✅〔公式〕S-50 | 定期の実行は自分の側（MCP・スクリプト）で持つ |
| 定期レポート・メール | 予約レポートのメール送信がある（Google 側の詳細はこのメモの範囲外） | ❓ 記載なし（S-45 の CSV の節にも、ヘルプの検索にも出ない） | 毎日の数字は API か手の CSV で取る |

### 1-1. 運用の判断への効き方

- **Claude Code（ads-mcp）からつなぐなら、Advertiser API ＋ API キーが今すぐ使える唯一の道**。パートナーの OAuth は読み取りだけに絞れて理想的だが、自分で登録する手順が公開されていない ❓
- **ChatGPT の中から見るだけなら、プラグインが一番手軽**。ただし Claude からは使えない。両方を並べて使うなら、プラグインの「直近 7 日」の既定と、こちらの道具の期間をそろえる
- 外部のデータ連携サービスにキーを渡すのは、運用の原則 5（鍵を AI に渡さない、手元のファイルに置く）と、キーが書き込みもできる点から勧めない〔推測〕

### 1-2. プラグインでできること・できないこと ✅〔公式〕本文（S-50、28 日前の更新。A-02）

| できる | 中身 |
|---|---|
| 読む・分析する | アカウント全体かキャンペーン・広告グループ・広告の中で比べる・順位を付ける。表示・クリック・費用・CTR・平均 CPC・平均 CPM、計測があればコンバージョン。期間の推移。時間・端末・国・下の階層での内訳。計測の設定と直近の生のイベントの点検。A-02 は「変更履歴の分析」も挙げる |
| 期間の既定 | 期間を言わないと、**アカウントの時間帯で、終わった直近 7 日**。数字は Ads Manager にいまある分（遅れはそのまま） |
| 点検 | 1 回だけ、または**日次・週次の予約**。準備・配信・計測を見て、予算・入札・ターゲティング・文面・画像の改善点を順に出す。**アカウントは変えない**（予約の点検も提案だけ）。予約の前に中身を確かめられる |
| 配信の詰まりの診断 | アカウント → キャンペーン → 広告グループ → 広告 → 計測の順にたどり、最初の制約を示す。読むだけ |
| 作る・変える | ウェブサイトや依頼文から見出しと説明文を下書き、画像を選ぶ・生成する、プレビュー、確認してからアップロードと作成。1 回の依頼で標準の広告を 50 本まで（同じ画像・切り抜き・リンク先）。設定の更新、停止・再開・アーカイブ、画像の差し替え。変更の前に「アカウント・今の状態・変えた後・変わる値」を見せて承認を求め、変えた後に読み直して確かめる |
| アカウントの管理 | 利用者と招待中の一覧、招待、役割の変更、削除、ロゴの差し替え（審査が終わるまで今のロゴのまま）。セルフサーブで自社のアカウントを作る手伝い（規約の同意は本人が明示） |

| できない・限られる | 中身 |
|---|---|
| 権限 | つないだ利用者が触れるアカウントだけ。できる操作は役割とアカウントの機能による |
| 売上・ROAS | **プラグインは成果の値を受け取らないので、売上と ROAS は出さない** |

## 2. 「自分の広告アカウントの日次の実績を読むだけ」に要る最小の準備

**要らないもの**（公開の文書に出てこない）: 開発者の登録、アプリの作成・審査、利用の申請、Cloud プロジェクト、OAuth の同意画面、利用料（記載なし ❓）。**Google のような段階（エクスプローラー・ベーシック）も無い** ✅〔公式〕S-01（Getting Started は「広告アカウントと Advertiser API キーが要る」だけ）

### 2-1. 手順（番号順。AI はどれも代わりにしない）

1. **自分の役割を確かめる**: Ads Manager の「設定 > ユーザー」で、自分がその広告アカウントの**管理者**（Admin）か見る。パートナーの手順は「キーを作る前に管理者の権限があることを確かめる」と書く ✅〔公式〕S-62（Fospha の項）。メンバー・閲覧者でキーを作れるかは ❓
   - 役割は広告アカウントごとに 管理者／メンバー／閲覧者。閲覧者は書き込みも管理もできない。ChatGPT のワークスペースや API Platform の組織の役割は、広告の権限にならない ✅〔公式〕S-40（本文）、S-39
2. **キーを作る**: 「設定 > 一般 > API キー」→「Create New Key」（新しいキーを作成）✅〔公式〕S-62、〔画面〕62 #16。名前は用途が分かるもの（例: 「ochinana-ads-mcp 読み取り用」）。**名前を付けても権限は絞れない**〔推測: A-01 の入力は名前だけ〕
   - 画面に権限・期限を選ぶ欄があれば、読み取りだけ・短い期限を選ぶ（欄があるかは ❓。あれば 62 に記録する）
3. **キーをその場で手元のファイルに保存する**: 例 `~/.config/ochinana-ads/openai-ads.key`（中身はキー 1 行だけ）。`chmod 600` で自分だけが読めるようにする。**チャットに貼らない、ads-mcp のフォルダや git の中に置かない**（運用の原則 5）。キーが作成時に 1 回しか表示されないかは ❓（第三者の解説はそう書く）
   - 公式も「サーバーに安全に保存する」「秘密の管理の仕組みに置き、ブラウザのコード・ログ・ソース管理に入れない」と書く ✅〔公式〕S-01（Getting Started、Conversion Setup）
4. **1 回だけ動作を確かめる**:
   ```bash
   curl -sS -G "https://api.ads.openai.com/v1/ad_account" -H "Authorization: Bearer $(cat ~/.config/ochinana-ads/openai-ads.key)"
   ```
   返ってきた `id`（`adacct_…`）・`timezone`（`Asia/Tokyo` のはず）・`currency_code`（`JPY` のはず）・`status`・`review` を見る。公式も最初にこれで確かめると書く ✅〔公式〕S-01。**この呼び出しは読むだけで、広告費はかからない**
5. **Claude に渡すのは 2 つだけ**: キーのファイルの**場所**と、広告アカウントの `id`（許可リストに入れる）。キーの中身は渡さない
6. **もう 1 つのアカウントも読むなら**、そのアカウントに切り替えて 1〜5 を繰り返す（キーはアカウントごと）✅〔公式〕S-01
7. **止めるとき・漏れたとき**: 「設定 > 一般 > API キー」で消す〔推測〕。削除・失効の手順と、キーの期限・本数の上限は公開の文書に無い ❓

### 2-2. 間違えやすい点

- **コンバージョン API キーは別物**。計測の「コンバージョン」の画面か API で作るキーで、サーバーから成果を送るためだけのもの。送り先も別（`bzr.openai.com`）。レポートの読み取りには使わない ✅〔公式〕S-01（Conversion Setup、Troubleshooting の API Errors）
- **ChatGPT や API Platform（platform.openai.com）のキーでは呼べない**〔第三者: 検索結果の解説。公式の明文は ❓〕。公式は「Ads API キーは 1 つの広告アカウントに紐づく」とだけ書く
- **請求の上限（アカウントの支出の上限）の API は、読むだけでも「請求を管理する権限」が要る** ✅〔公式〕S-01（Account spending limits）。日次のシートには使わない

### 2-3. 運用の判断への効き方

- 準備は 10 分ほどの手作業で終わる〔推測〕。Google のような審査待ちは無い
- いちばんの危険は**キーが書き込みもできること**〔推測〕。だから、①管理者がキーを作るが、②キーを使う道具は読むだけの呼び出ししか持たない（§6）、③漏れたらすぐ消す、の 3 点で守る

### 3-5. 運用の判断への効き方

- **日次のシートは「毎朝、直近 3 日分を取り直して上書き」する**〔推測〕。ただし成果はクリックの窓（既定 30 日）の中で後から付くので、成果の列は**直近 30 日分**を取り直す（費用・表示・クリックは 3 日で足りる）。`_他媒体の共通/02_日次の実績の列の対応表.md` に合わせた。費用は 7〜8 時間、成果は 24〜48 時間遅れるので、前日の行だけを足していくと、後から増えた分を取りこぼす
- **窓と基準は毎回明示して送る**。2026-09-30 より前に作った仕組みは「クリックだけ」で数えていたかもしれず、今は既定が「クリック 30 日＋ビュー 1 日＋広告に触れた日」に変わった（旧来のモードは無い）✅〔公式〕S-01 Changelog・Reporting
- **1 日 2 回の呼び出しで足りる**〔推測〕: ① GET（キャンペーン × 日、配信と成果の合計）、② POST（キャンペーン × 日、クリックスルー・ビュースルーの内訳）。広告単位まで取るなら GET をもう 1 回
- 画面と数字を合わせるときは、同じ日付・同じ基準・同じ窓にする ✅〔公式〕S-01

| ビュースルーの扱い | ビューの窓が 1 日なら「コンバージョン」の合計に入る。両方に当たる成果はクリックが取る |

### 4-3. 運用の判断への効き方（Google と意味が違う列）

1. **「コンバージョン」**: 既定ではビュースルー込み。Google の「コンバージョン」はビュースルーを含まない。**媒体を並べるシートでは、ChatGPT を `view_through_attribution_window_days=0` で取った列を使う**。ビュー込みの数字は別の列で持つ
2. **CPA**: 合計にビューが入るので、既定のままだと Google より安く見える
3. **クリック後の CVR**: クリックスルーだけで割る。CPA と CVR から成果の数を逆算すると合わない
4. **売上・ROAS**: 購入だけ。リードやサブスクの値は入らない
5. **費用**: マイクロではなく通貨の単位。直近は 7〜8 時間遅れで、0 円でも課金が無いとは限らない
6. **窓**: Google は設定が入札にも効くが、ChatGPT は取るたびに選べるレポートの設定。シートには「どの窓で取ったか」を列か注記で残す〔推測〕
7. **日の区切り**: レポートはアカウントの時間帯（日本のアカウントは日本標準時）、請求は UTC（62 #12）。請求書と日次のシートは日の区切りがずれる〔推測〕

## 6. 運用 MCP につなぐときの案〔推測〕

ここはすべて設計案。コードは書いていない。いまの ads-mcp（Google 広告の読み取りの道具、許可リスト、認証の置き方）に合わせた。

### 6-1. 読むだけに絞れるか

- **キーそのものは絞れない**（§0）。だから**道具のコードで絞る**。Google の版と同じく「アカウントを変える呼び出しはコードのどこにも無い」をテストで確かめる
  - 呼んでよい端点の許可リスト: `GET /v1/ad_account`、`GET /v1/campaigns`・`/v1/ad_groups`・`/v1/ads`（一覧と取得、`include[]=serving_issues`）、`GET /v1/ad_account/insights` とキャンペーン・広告グループ・広告の Insights、`GET /v1/audit_logs`、`GET /v1/ads/{ad_id}/landing_page_crawl`（審査のクローラーが LP を取った記録。読むだけで、新しく取りには行かない。画面の写しの URL は最長 24 時間 ✅〔公式〕A-01）、そして **POST は `POST /v1/conversions/insights` の 1 本だけ**（読むだけの POST）
  - それ以外の POST・PATCH・DELETE（`/activate`・`/pause`・`/archive`・`/api_keys`・`/upload` など）は、送る前に道具が断る。テストで「許可リスト外の道を組み立てられない」ことを確かめる
- 将来、パートナーの OAuth（読み取りの `ads.admin.all.read`）を個人でも使えるようになれば、鍵の側でも読むだけにできる。今は登録の手順が公開されていない ❓

### 6-2. 許可リスト（アカウント）

- `config.py` にの ChatGPT の広告アカウントの `adacct_…` を足す（principles.md 版 0.3 の範囲）
- **キーはアカウントに 1 本ずつ**なので、許可リストは「アカウント ID → キーのファイルの場所」の組で持つ
- 毎回、最初に `GET /v1/ad_account` で返る `id` が許可リストと一致するかを確かめ、違えば以後の呼び出しをせずに断る（キーの入れ違いを防ぐ）

### 6-3. 鍵の置き場所

環境変数で**場所だけ**を道具に渡す。Claude Code の設定に入るのも場所だけ
- **Google との違い**: Google はライブラリが認証ファイルを直接読むので道具のコードは中身を開かないが、ChatGPT は道具のコードがファイルを読んでヘッダーに入れる必要がある。原則 5 の「AI が鍵の中身を読まない・出力しない」は守れる（コードは読むが、返答・ログ・CSV・エラーの文に入れない）。テストで「返り値とログにキーの文字列が出ない」を確かめる
- `.gitignore` に `*.key` を足す。キーのファイルを ads-mcp のフォルダの外に置く

### 6-4. Google と同じ形の道具にするなら

| Google の道具 | ChatGPT の版の案 | 呼ぶもの | 注記 |
|---|---|---|---|
| `list_accounts` | `chatgpt_list_accounts` | `GET /v1/ad_account`（許可リストのキーごと） | 時間帯・通貨・状態・審査を返す |
| `get_performance` | `chatgpt_get_performance` | `GET /v1/ad_account/insights`（`aggregation_level` = campaign／ad_group／ad、`limit=2000`、ページ送り） | 窓と基準を引数にし、**既定はクリック 30 日・ビュー 0 日・広告に触れた日**（Google と並べる用）。ビュー込みが要るときだけ 1 を渡す。円、CTR は % に直す。「判定の範囲」に窓・基準・遅れを書く |
| （新） | `chatgpt_get_conversions` | `POST /v1/conversions/insights` | クリックスルー・ビュースルーの内訳、イベント別、国・端末の内訳。413 のときは期間を分けて取り直す |
| `get_change_history` | `chatgpt_get_change_history` | `GET /v1/audit_logs` | 変更した人の ID（`actor_id`）は返さない（Google の版と同じく経路だけ）。保存期間は ❓ なので毎日 CSV に残す |
| `get_anomalies`・`measure_effect` | 同じ計算に ChatGPT の日別を渡す | 上の日別 | 成果の遅れの日数は 2 日を置き値に（24〜48 時間）。費用は当日を外す |
| `run_checks` の一部 | `chatgpt_get_serving_issues` | 一覧・取得の `include[]=serving_issues` | 空でも配信の約束ではない |
| `get_search_terms` | **作れない** | — | 会話・話題のレポートは無い |

- 日次のシートのスクリプトは、上の `chatgpt_get_performance`（キャンペーン × 日、費用などは直近 3 日・成果は直近 30 日）と `chatgpt_get_conversions`（同じ範囲の内訳）を毎朝 1 回ずつ呼び、行を「日付 × キャンペーン」で上書きする。窓は「クリック 30・ビュー 0」と「クリック 30・ビュー 1」の 2 列で持つ
- 呼び出しの数は 1 日数回で、毎分 600 の上限から遠い

## 9. 取得できなかった・確認できなかった項目 ❓（2026-11-19 時点）

1. **画面の「API キー」の作成画面に、権限・期限を選ぶ欄があるか**、キーが 1 回しか表示されないか、何本まで作れるか、消し方。

4. 日本のアカウントで API が実際に呼べるか（画面に作成のメニューがあることだけ確認）
5. **CSV の見出しの正確な文字列**（日本語の表示名か、英語の機械名か）。公式に書かれているのはイベントの列の `attributed_event_…` だけ。
6. 監査ログの保存期間
7. `data_status` の意味、予算の欄（`campaign_budget_daily` など）の単位
8. 都道府県・年齢・性別の内訳（API の内訳は国・端末・プラットフォーム・商品だけ）
9. パートナー向け OAuth の登録の仕方（クライアント ID の取り方、個人の広告主が使えるか）
10. プラグインが日本のアカウント・日本のプランで使えるか
