## 0. 先に結論（この章で一番効く 10 点）

1. **層は 4 つで、置き場所が決まっている。** アカウント＝ブランド・通貨・時間帯・権限・費用の上限、キャンペーン＝目的・予算・期間・地域・端末・オーディエンス・最適化のイベント、広告グループ＝入札（課金・戦略・額）・文脈ヒント・オーディエンス別の倍率・商品セット、広告＝クリエイティブ・画像か商品テンプレート・リンク先 ✅〔仕様〕S-01
2. **作成後に変えられないもの**: アカウントの国・通貨・時間帯 ／ キャンペーンの目的 ／ コンバージョン目的の最適化のイベント ／ コンバージョン目的の課金（クリックか表示）／ 予算の種類の「1 日 → 通算」の向き ／ 広告の所属の広告グループ ／ 1 枚の画像 → 複数画像への変更 ／ アーカイブ ✅〔仕様〕S-01・S-34・S-37・h20001215。どれも「新しく作る」か「複製」で対応する
3. **複製（Clone）は「別の目的か、対応する別の課金方法」の新しいキャンペーンを作る機能。** 同じ目的のまま丸ごと写すことはできない（例: クリック → クリック不可）✅ S-34（2026-11-12 ごろ更新）
4. **上限**: 自分で作れる広告アカウントは所属 10 まで ／ キャンペーン・広告グループ・広告はアカウントあたり各 5,000 ／ 文脈ヒントは広告グループあたり 2,000 ／ 地域の ID は 2,500 ✅。広告グループは「キャンペーンあたり 10,000」とするヘルプが残る △（h20001211、2026-11-12 ごろ更新）
5. **キャンペーンを分ける公式の条件は「予算・目的・地域（ターゲティング）・商品カテゴリーが大きく違う」、広告グループを分ける条件は「訴求か LP が違う」「入札の設定・文脈ヒント・商品の選び方が違う」** ✅〔公式の推奨〕S-34・S-55・S-01。Google の「まとめよ」に当たる推奨（細かく分けるとデータが割れる）は ❓ 公式に記載なし
6. **広告は「1 つの訴求でなく、範囲を取りに行く」。** 1 つの商品ごとにタイトル・本文の組を多く・多様に作る、と公式が勧める ✅〔公式の推奨〕S-41。1 広告グループの広告の本数の上限・推奨は ❓
7. **文脈ヒントはキーワードではない。** 「何を・誰に・いつ」を 1 つの考えで自然な文に。完全一致ではなく、配信を保証せず、地域・時間帯・除外を強制できない ✅〔仕様〕S-44（2026-10-28 ごろ更新）。△ API の参照は「説明か**キーワード**の一覧を」と書き、ヘルプは「つながりのないキーワードの羅列でなく」と書く（§6-1）
8. **文脈ヒントの更新は「足す」ではなく「一覧ごと置き換え」。** 画面の一括入稿も API も同じ。空の配列で全部消える ✅〔仕様〕S-01・S-42・h20001215
9. **Negative Phrases は「資格のある広告主」だけ。** 資格の条件・書き方・個数・一致のしかたは公式に記載なし ❓（S-31、2026-11-15 ごろ更新）。**新しく分かったこと**: 開発者文書の Bulk API（限定プレビュー）の広告グループの欄に `exclusion_hints` がある。中身の説明は無く、Negative Phrases と同じものかは ❓（§7-2）
10. **新しい広告グループでは「成果の最大化（インテリジェント入札）」が既定で選ばれる**（対象の広告グループ）✅ h20001425（2026-10-28 ごろ更新）。構成を作るときに入札を見ずに進めると自動入札で始まる。自動化の全体は `13`

## 1. Google との対比（G04 と）

| 観点 | Google 広告（G04） | ChatGPT の広告 | 運用の判断への効き方 |
|---|---|---|---|
| 層 | MCC → アカウント → キャンペーン → 広告グループ → キーワードと広告 | 広告アカウント → キャンペーン → 広告グループ → 広告。**MCC に当たる層は無い**。代理店は広告主ごとに別アカウントを作り、同じ OpenAI のログインで切り替える ✅ S-01・S-39 | 複数の広告主を 1 つの画面でまとめて見る仕組みは ❓ 記載なし。アカウントを切り替えて見る |
| 引き金の置き場所 | キーワード（広告グループ）とマッチタイプ | **文脈ヒント**（広告グループ）。マッチタイプは無い ✅ S-01 | 「キーワードの一覧」を作る作業は無い。代わりに場面の説明文を書く |
| 除外の置き場所 | 除外キーワード（広告グループ・キャンペーン・リスト）。誰でも使える | Negative Phrases（資格のある広告主だけ）✅ S-31。地域・オーディエンスの除外はキャンペーン ✅ S-01 | 「この話題では出さない」を広告主が確実に作れない前提で設計する |
| 入札の置き場所 | キャンペーン（入札戦略）。ポートフォリオで共有 | **広告グループ**（課金・戦略・額）✅ S-01。ポートフォリオは ❓ | 同じキャンペーンの中で広告グループごとに入札を変えられる。目的はキャンペーンで 1 つ |
| 予算の置き場所 | キャンペーン。共有予算あり | キャンペーン。共有予算は ❓。「別の予算が要るならキャンペーンを分ける」✅ S-01 | 予算を分けたいことがキャンペーンを分ける主な理由になる |
| 作成後に変えられないもの | キャンペーンの種類（検索・P-MAX など）。目的はあとから変えられる | **目的・最適化のイベント・コンバージョン目的の課金**。通貨・時間帯・国 ✅ S-34・S-37・S-39 | Google のように「同じキャンペーンを途中で目標 CPA に切り替える」発想は、入札戦略（広告グループ）でしかできない。目的は作り直し |
| 構成の公式の推奨 | 「統合」: 予算・目標を共有するものは同じキャンペーン、テーマの近いものは同じ広告グループ、単一キーワードの広告グループはまとめる | 「目的・取り組みごとにキャンペーン」「訴求か LP が違えば広告グループを分ける」「広告は数と多様さ」✅ S-34・S-55・S-41。**統合を勧める文、細かく分けると学習が割れるという文は ❓ 無い** | Google の「まとめよ」をそのまま持ち込まない。逆に「細かく分けよ」とも書いていない |
| 広告の本数 | 有効な RSA は 1 広告グループ 3 本まで | 広告の本数の上限は「アカウントあたり 5,000」だけ。広告グループごとの上限は ❓。**多く・多様に作る**のが公式の推奨 ✅ S-41・S-42 | Google の「3 本まで」を持ち込まない |
| 何で出たかの報告 | 検索語句レポート | **無い**。会話・話題の列は無い〔画面〕62#7 | 文脈ヒントの効きは、広告グループを分けて数字で比べるしかない |
| 一括編集 | エディタ、一括アップロード、スクリプト | 画面の「Export for edit」→ 表を直して一括入稿 ✅ h20001215。API の Bulk API（限定プレビュー、1 回 1,000 操作）✅ S-01 | 文脈ヒントは一覧ごと置き換えなので、必ず最新の書き出しから直す |

## 2. 層ごとに決めること

### 2-1. 広告アカウント ✅〔仕様〕S-01（開発者文書 Account Management、2026-11-24 取得）、S-39（h20001213、2026-11-23 ごろ更新）

| 決めること | 中身 | 変えられるか |
|---|---|---|
| 3 つの名前 | 法人名（`legal_name`、請求と事業者の確認）・アカウント名（`account_name`、管理画面の中だけ）・ブランド名（`brand_name`、広告に出る名前）。サインアップでは 1 つの名前が 3 つ全部に入る | 変えられる（2026-09-25 から別々に）。ブランド名の変更は審査が通るまで配信が止まる。法人名の変更は事業者の審査をやり直し、「止まることがある（may pause）」。アカウント名は審査なし ✅ S-39。△ 開発者文書は「法人名か公開のブランド名を変えると、アカウントが審査を通るまで配信が止まる（pauses）」と書き、法人名も「止まる」と言い切る（§13） |
| アイコン（ファビコン） | JPEG・PNG・WebP、256×256 以上（開発者文書のアカウントの節）| 差し替えられる。差し替えはブランド審査に入り、通るまで今のアイコンが出続ける（プラグインのページ S-50）。大きさは △（128×128 とする節もある。05§5-2） |
| 国（所在地）・通貨・時間帯 | 作成時に選ぶ | **変えられない**。別の設定には新しいアカウント ✅ S-39、〔画面〕62#11 |
| 権限 | 管理者（すべて）・メンバー（キャンペーンの作成と管理）・閲覧者（見るだけ）| 変えられる ✅ S-39 |
| 状態 | `active`・`paused`。アカウントを止めると全キャンペーンの配信が止まる | 変えられる。**アカウントを再開しても、子のキャンペーン・広告が有効になったわけではない** ✅ S-01 |
| 審査の状態 | ブランド審査（`review.status`）と、別のアカウントの審査（`account_integrity_review`）は別の欄。欄が返らないことは「承認」でも「却下」でもない ✅ S-01 | — |
| 費用の上限 | 期間を区切った上限（一部のアカウントだけ。重ならない。先の予定は 60 枠まで。開始日は含み終了日は含まない）と、1 日の上限（後払いの請求書のアカウントだけ、2026-09-09 追加）。**キャンペーンに配分はしない** ✅ S-01、S-33 | 変えられる。使った額より下げられない |

- 運用の判断への効き方: アカウントの層で後から直せないのは国・通貨・時間帯だけ。**日本の法人なら JPY・日本標準時で作る**（請求は UTC で区切る、62#12）。ブランド名は広告に出るので最初に決め、公開後に変えない〔推測〕。変えると審査が終わるまで全部の広告が止まる ✅

### 2-2. キャンペーン ✅〔仕様〕S-34（h20001210、2026-11-12 ごろ更新）、S-01（Campaigns の参照）

| 項目（画面のヘルプ）| API の欄（2026-11-24 の開発者文書）| 決まり |
|---|---|---|
| キャンペーンのタイトル | `name` | 3〜1,000 字、空白以外の字を含む ✅ S-01 |
| 説明 | `description` | 任意 |
| 目的 | `bidding_type` | `impressions`・`clicks`・`conversions`。**API で省くと `impressions`（表示）になる** ✅ S-01。作成後に変えられない ✅ |
| コンバージョン イベント（コンバージョン目的のとき）| `conversion_event_setting_ids` | **ちょうど 1 つ**の有効な標準イベントの設定。カスタム イベントは不可。作成後に変えられない ✅ S-01・S-37 |
| 予算 | `budget.daily_spend_limit_micros` か `budget.lifetime_spend_limit_micros` | **どちらか 1 つだけ**。両方は持てない ✅ S-01。日本円の最低の 1 日の予算は 2,500 円 ✅ S-34。△ API の参照の表は `lifetime_spend_limit_micros` を「必須」と書き、入札と予算の節は「1 日か通算のどちらか 1 つ」と書く（§13） |
| 開始日・終了日 | `start_time`・`end_time`（Unix 時刻）| 省くと開始の遅れなし。画面の最初のキャンペーンは、公開前に日付の欄が出ないことがある ✅ S-34。一括入稿では日付は UTC の 0 時、終了日はその日を含まない（10 日まで出すなら 11 日）✅ S-42 |
| 対象の国 | `targeting.locations.include`・`targeting.excluded_locations` | 省くと**利用可能な全地域** ✅ S-01。1 か国だけに出すならその国を明示して含める（除外だけでは絞れない）✅ S-34。くわしくは 23§3 |
| 対象の端末（任意）| `targeting.platforms.included` | 省くか `null` で制限なし ✅ S-01。くわしくは 23§4 |
| 含める・除くカスタム オーディエンス（任意）| `targeting.custom_audiences.ids`・`targeting.excluded_custom_audiences.ids` | 含めるには照合後 25,000 人以上、除外は下限なし。同じオーディエンスを両方に入れられない ✅ S-01。くわしくは 23§5 |
| 商品フィードのキャンペーン | `mode: product_feed`、`product_feed_id` | 新しい商品フィードのキャンペーンは地域が国単位だけ ✅ S-01。くわしくは 05§8 |
| 計測用パラメータ | `landing_page_configuration.query_string_template` | §2-6 |

- 画面のヘルプが挙げるキャンペーンの中身（S-34 の本文）: タイトル、目的、コンバージョン イベント（コンバージョン目的のとき）、予算、開始日・終了日、対象の国、対象の端末（任意）、含める・除くカスタム オーディエンス（任意）
- 運用の判断への効き方: **キャンペーンで決めるものは、どれも「配信の範囲と成果の定義」**。このうち目的とイベントは作り直しでしか変えられないので、計測が届くかを確かめてから決める（28§11-5）。API で作るときは `bidding_type` を必ず書く（省くと表示目的で作られる）✅ S-01

### 2-3. 広告グループ ✅〔仕様〕S-01（Ad Groups の参照、Bidding & Budgets）、S-55（h20001211、2026-11-12 ごろ更新）

| 項目 | API の欄 | 決まり |
|---|---|---|
| 名前 | `name` | 3〜1,000 字 ✅ S-01 |
| 文脈ヒント | `context_hints`（文字列の配列）| 最大 2,000。更新は一覧ごと置き換え ✅ S-01。§6 |
| 課金 | `bidding_config.billing_event_type` | 表示目的は `impression`、クリック目的とコンバージョン目的は `click` ✅ S-01。△ ヘルプはコンバージョン目的に表示課金（oCPM）を書くが、開発者文書の組み合わせの表に無い（02§2-2） |
| 入札戦略 | `bidding_config.strategy` | `fixed_bid`・`maximize_clicks`・`maximize_conversions`（開発者文書）。画面とヘルプでは 2026-11-09 から新規はインテリジェント入札・目標 CPA・目標 CPC ✅ S-36（2026-11-23 更新）。新しい欄の名前は開発者文書にまだ無い ❓（02§3-2） |
| 入札額 | `bidding_config.max_bid_micros` | 固定の入札では必須、最大化では送らない。コンバージョン目的では**CPA の入札**（課金はクリック）✅ S-01 |
| オーディエンス別の倍率 | `bidding_config.custom_audience_bid_multipliers` | 0.1〜10 倍。開発者文書は「固定の入札だけ」と書く ✅ S-01（△ ヘルプは目標 CPA との組み合わせを例に挙げる、02§6）|
| 商品セット（商品フィードのとき）| `product_set` | 省けばキャンペーンのフィード全体。絞り込みの欄は title・body・item_id・offer_id・price・target_url・image_url・product_category・brand・seller_name・external_seller_id・star_rating・condition・age_group。演算は `in`・`gt`・`gte`・`lt`・`lte`（大小は price と star_rating だけ）。同じ欄を 1 つの商品セットで繰り返さない ✅ S-01 |

- 開発者文書の分け方の指示: 「別の入札の設定、文脈ヒント、商品の選び方が要るなら広告グループを分ける。共有する設定が同じ創作のバリエーションは一緒に置く」✅〔公式の推奨〕S-01
- ✅〔仕様〕対象の新しい広告グループでは、画面で「成果の最大化（Maximize results）」が既定で選ばれる。別の戦略にするには広告グループの入札戦略の節で選び直す（h20001425、2026-10-28 ごろ更新）。△ このページは選び直す先を「Manual: Max bid」と書くが、11-09 から新規では上限入札は選べず目標 CPA／CPC になった（S-36）。ページが古い
- 運用の判断への効き方: **入札は広告グループの持ち物。** 同じキャンペーンの中で「固定の入札の広告グループ」と「最大化の広告グループ」を並べられる。ただし最大化には 1 日の予算が要り、予算はキャンペーンの持ち物なので、通算の予算のキャンペーンでは最大化を使えない ✅ S-01

### 2-4. 広告 ✅〔仕様〕S-01（Ads の参照、Campaign Management）、S-41（h20001212、2026-10-29 ごろ更新）

| 項目 | API の欄 | 決まり |
|---|---|---|
| 名前 | `name` | 3〜1,000 字。利用者には出ない ✅ S-01 |
| 種類 | `creative.type` | `chat_card`（標準）か `product_ad_template`（商品フィード）✅ S-01 |
| タイトル | `creative.title` | 3〜50 字（推奨 16〜24 字）。日本の画面の目安は 32 字 ✅ S-01・S-42、〔画面〕62#3。05§3 |
| 本文 | `creative.body` | 100 字まで（推奨 32〜48 字）。日本の画面の目安は 54 字 ✅ 同上 |
| リンク先 | `creative.target_url` | HTTP(S)、2,048 字まで、OpenAI の広告クローラーが読めること ✅ S-01 |
| 画像 | `creative.file_id`（1 枚）か `creative.file_ids`（正方形 4〜6 枚）| 両方は送らない。複数画像はアカウントの有効化が要る。**複数画像は、アカウントが「複数画像＋自動入札」に有効でなければ固定の入札で使う** ✅ S-01 |
| 価格 | `creative.price` | 任意。複数画像とは一緒に使えない ✅ S-01 |

- ✅〔仕様〕広告は**別の広告グループに移せない**。1 枚の画像の広告を複数画像に変えるには新しい広告を作る（S-01）
- ✅〔仕様〕広告の創作を直すと**新しい版が出され、審査がやり直しになる**（S-01）
- ✅〔仕様〕商品フィードの広告グループには、アーカイブしていない商品テンプレートの広告を**1 つだけ**置ける（S-01、S-50）
- 運用の判断への効き方: 広告グループを入れ替えたくなったら「広告を作り直す」しかない。**広告グループの切り方を先に決めてから広告を量産する**〔推測〕。審査のやり直しがあるので、配信中の広告の文を細かく直すより、新しい広告を足して古いものを止めるほうが成績の記録が混ざらない〔推測〕

### 2-5. 状態（有効・一時停止・アーカイブ）✅〔仕様〕S-01

- キャンペーン・広告グループ・広告の状態は `active`・`paused`・`archived`。作成時は `active` か `paused` だけ ✅
- **アーカイブは元に戻せない**。「もう使わないものだけをアーカイブする」✅ S-01
- 親が止まっていれば子は出ない（キャンペーンを止めると子の広告は出ない）。逆に、子が有効でも親の状態・審査・予算・期間が揃わなければ出ない ✅ S-01
- 状態の変更では、却下された広告は承認されず、審査中の広告は審査が終わらない ✅ S-01
- プレビューは見た目だけで、配信の資格を示さない ✅ S-01
- 開発者文書は、新しいものを**一時停止で作ってから**点検して有効にする手順を勧める ✅〔公式の推奨〕S-01
- 運用の判断への効き方: 「使わなくなったキャンペーンはアーカイブ」は Google と同じ感覚で行わない。**アカウントの上限 5,000 はアーカイブしていないものを数える**（§4）ので、上限に近づいたときにだけ、戻さないと決めたものをアーカイブする〔推測〕

### 2-6. 計測用パラメータの置き場所 ✅〔仕様〕S-01

- `landing_page_configuration.query_string_template` をキャンペーン・広告グループ・広告に置ける。アカウントの設定が既定になる
- 優先の順（低い → 高い）: **フィード（あれば）< アカウント < キャンペーン < 広告グループ < 広告**。同じキーは高いほうが勝つ（utm_* 以外のキーも同じ）。合わないキーのフィードのパラメータは残る
- 旧方式（フィードが最優先）のアカウントは 2026-11-05 までに移行（期限は過ぎた）
- 置き換えの記号: `{campaign_id}`・`{ad_group_id}`・`{ad_id}`・`{ad_account_id}`・`{oppref}`〔画面〕62#6
- 運用の判断への効き方: **アカウントに共通の UTM を置き、広告グループで `utm_content` などを上書き**すると、構成をそのまま解析ツールに写せる〔推測〕。審査のクローラーもパラメータ付きで LP を訪れ、解析ツールでは有料の流入に見える（課金されない）✅ S-31

### 3-3. 目的を変えられないことへの備え（28§11-5 の要点）

- 公式は「クリックで始めて、あとでコンバージョンへ」とは勧めていない ❓。公式にあるのは、コンバージョン目的の前提（計測が設定され、標準イベントが届き、最適化するイベントが決まっている）と「十分な頻度のイベントを使う」✅ S-37
- 〔推測〕2 段の立ち上げ: ①クリック目的で計測が届くことを確かめる ②複製でコンバージョン目的のキャンペーンを作る。複製でクリック目的 → コンバージョン目的に移れるかは、§3-2 の △ のとおり課金の選び方の読みが割れる。画面で複製の選択肢を見るまで「移れる」と言い切らない

### 5-3. Google との違い

- Google は「統合」（予算と目標を共有するものは同じキャンペーン、単一キーワードの広告グループはまとめる、デバイス別の分割は外す）を強く勧める（G04§6-2）。**ChatGPT の公式は統合も細分化も勧めていない**。勧めているのは「目的・取り組みごとにキャンペーン」「訴求か LP が違えば広告グループ」と「広告を数多く・多様に」
- Google の分ける理由の多くはキーワードとマッチタイプの扱い（マッチタイプ違いを分けない、など）。ChatGPT にはキーワードが無く、分ける理由は**予算・目的・指定（キャンペーン）と、訴求・LP・入札・ヒント（広告グループ）**に限られる
- Google の「分けると学習が割れる」に当たる説明（ChatGPT の自動入札がキャンペーンをまたいで学ぶか、広告グループごとに学ぶか）は ❓ 記載なし。技術ブログは採点に「過去の実績」を使うと書くだけ（02§9-1）

### 5-4. 構成の型〔推測。§5-1 の公式の推奨から組み立てた〕

| 型 | キャンペーン | 広告グループ | 広告 | 向く場面 |
|---|---|---|---|---|
| 最小 | 1（クリック目的、1 日の予算、日本）| 2〜3（場面ごと。訴求と LP が違うもの）| 各 3 本前後（角度の違う組）| 計測を確かめる立ち上げ（28§11-3）|
| 目的で 2 段 | ①クリック ②計測が安定したら複製でコンバージョン | ①と同じ切り方 | ①から良かった角度を足す | 成果の計測がまだ不安なとき（§3-3）|
| 商品カテゴリー | カテゴリーごと（予算を分けたいとき）| カテゴリーの中の用途ごと | 用途ごとに多様に | 商品の幅が広い EC・小売 |
| 地域 | 地域ごと（都道府県か郵便番号、23§3）| 場面ごと | — | 対応エリアで料金・在庫が違う地域サービス |
| 端末 | アプリと Web で分ける | — | — | アプリの導入が目的、または Web とアプリで LP が違う |

- 判断の芯〔推測〕: **キャンペーンは「お金と成果の定義と配信の範囲」で、広告グループは「場面」で切る。** 場面ごとに文脈ヒント・訴求・LP をそろえると、広告グループ別の数字が「場面ごとの数字」として読める（検索語句レポートの代わり）
- 少額のとき〔推測〕: 2,500 円／日の最低額で広告グループを増やしすぎると、広告グループ 1 つあたりの表示が少なく、比べられない。最初は広告グループを 2〜3 に絞る（28§11-3）

### 5-5. 運用の判断への効き方

- **「この構成はなぜこう切ったか」を 1 行で書けるようにする**〔推測〕。目的・予算・指定のどれで切ったキャンペーンか、場面・訴求・LP・入札のどれで切った広告グループか
- 広告は多く作るのが公式の推奨だが、**クリエイティブの強化がオンだと実際に出る文は入稿した文と違う**（13§3）。広告の本数を増やして比べるより、まず広告グループ（場面）で比べるほうが読み取りやすい〔推測〕
- 構成を途中で大きく組み替えると、目的・イベント・広告の所属を変えられないため、ほぼ作り直しになる。**最初の 2 週間は構成を変えない**（28§11-3 の段 5）

## 6. 文脈ヒント

### 6-1. 何か ✅〔仕様〕S-44（h20001521、2026-10-28 ごろ更新）、S-55、S-31、S-01

- 日本語ヘルプの名前は「コンテキストヒント」、画面の列名は「コンテキストのヒント」（23§6-1、62#15）
- ヘルプの定義: 「事業・商品・サービスについての追加の情報で、ChatGPT の中でどんなときに広告が関係しうるかをシステムが理解するのを助ける。**広告グループの単位**で足し、広告や LP からは分かりにくい役立つ情報を伝える」（S-44）
- 基本のページ: 「広告主は広告グループで、商品・サービスが関係しうる**会話・話題・キーワード**を説明する文脈ヒントを出せる。マッチングの手引きになるが、完全一致のキーワードではなく、特定の会話での配信を保証しない」（S-31、2026-11-15 ごろ更新）
- 開発者文書の案内の節: 「広告グループの広告についての追加の情報。広告や LP が十分に伝えない関係する商品・使い方・ニーズを書く。完全一致のキーワードではなく、地域・端末・オーディエンスの指定の代わりにもならない」（S-01）
- 広告の選ばれ方の中での位置: 選択は「今の会話の文脈と意図、広告の LP・タイトル・本文、広告主の文脈ヒント、（パーソナライズがオンなら）利用者の ChatGPT の体験の一部」を使う（S-31）。**ヒントは材料の 1 つ**で、LP・タイトル・本文と並ぶ
- △ **ヒントにキーワードを書くことの扱いが、公式の中で言い方が違う**:
  - API の参照（Ad Groups）: 欄の説明は「自由な形式のオーディエンスや配置のヒント」、注記は「商品・サービスが役立ちうるときの**説明かキーワード**の一覧を出す」（S-01）
  - ヘルプ（S-44・S-55）: 「つながりのない**キーワードの羅列ではなく**、1 つの考えに絞った自然な句で」
  - 両立させる読み〔推測〕: 書くこと自体は禁じていないが、効く書き方として公式が勧めるのは場面の説明文。**キーワードの一覧を貼る運用はヘルプの推奨に反する**

### 6-2. 書き方 ✅〔公式の推奨〕S-44（英語版の本文、2026-11-24 に読み直した）

**3 つの問い**: 「商品について、誰の役に立つか、いつ役立つかについて、ほかに何を知っておくべきか」

| 問い | 書く中身 |
|---|---|
| 何（What）| 関係する製品の機能、サービス、料金、提供状況（在庫）、対応地域 |
| 誰（Who）| 合う顧客のニーズ・好み・事情 |
| いつ（When）| 役立つ状況・決める場面 |

- 一番合う顧客と、事業の成果が良くなる場面を使って、満たせるニーズを書く
- **1 つの考えに絞った、はっきりした自然な句**にする。1 つのヒントで 3 つの問い全部に答えなくてよい

**4 つの条件**:

| 条件 | 中身 |
|---|---|
| 追加（Additional）| 広告や LP で明らかなこと以上を足す |
| 具体（Specific）| 具体的な機能・サービスの詳細・顧客のニーズ・場面 |
| 関連（Relevant）| 提供するものと使い道の本当のつながり |
| 正確（Accurate）| 実際の提供内容。機能・料金・特典・提供状況・対応地域が変わったら更新する |

- LP に書いてある中身でも、顧客のニーズと結べば役立つ（公式の例「暖かい日の練習に向く、通気のよいランニングシューズ」は、機能がなぜ大事かを説明している）
- 別の本当の使い道も書ける（例: 支えのある運動靴は、長時間立ち仕事の人にも合う。商品がそれを支えるなら）。**「この客層に届けたい」というだけでは、商品がその層に関係することにはならない**
- 人がヒントと同じ言葉を使わなくても、根っこのニーズや場面が関係すればよい

**公式の例**（S-44。「例示で、自社の実際に合う中身を使う」と注記）:

| 事業・商品 | ヒント（和訳）|
|---|---|
| ランニングシューズ | 初めての 5 km に向けて練習する初心者のための、普段使いのクッションのあるランニングシューズ |
| 地域の水道業者 | 〔市〕で営業時間外も受ける住宅の水道修理。急ぎの修理の出張料は 89 ドル |
| 会計ソフト | ネットと店舗の売上を突き合わせる必要がある、伸び盛りの小売店向けの帳簿のソフト |

| 開発者文書の例（S-01）| あまり役立たない → より役立つ |
|---|---|
| 靴 | → 岩場向けの軽いトレイル ランニング シューズ |
| アウトドア | → 雨の日のハイキング向けの、水に強い靴 |
| カリフォルニアの顧客 | → 地域の指定でカリフォルニアを選び、ヒントには商品の使い方を書く |

- 開発者文書の注記: 「例は書き方の見本で、特定の会話で広告が出る保証ではない」（S-01）

### 6-3. できないこと ✅〔仕様〕S-44、S-01、S-56

- 「ヒントは**ターゲティングの規則でも配信の指示でもない**。特定の会話・オーディエンス・状況で出ることを保証せず、**地域の制限・配信の時間帯・除外を強制できない**」（S-44）
- 例: 「シカゴで提供する住宅の配管サービス」は事業の説明。「シカゴの人にだけこの広告を出す」は配信の指示（効かない）。配信の制限は製品の設定（地域・端末・オーディエンス）で（S-44）
- 広告グループが扱う商品を書いて範囲をはっきりさせてよい。ただし**特定の人や会話を除くことにはならない**（S-44）
- 配信が細いときの点検でも「ヒントは文脈を足すもので、キーワードのような厳しい資格の条件ではない。地域やオーディエンスの制限を調べるなら明示の指定の欄を見る」（S-01 Troubleshooting）

### 6-4. 置き場所・件数・更新 ✅〔仕様〕

| 決まり | 中身 | 出典 |
|---|---|---|
| 置き場所 | 広告グループ（キャンペーン・アカウント・広告には無い）| S-01、S-44 |
| 件数 | 広告グループあたり 2,000。埋める必要はない。広告を正確に説明する情報を入れる | S-01 |
| 画面での入れ方 | 広告グループの作成で入れる | S-55 |
| 一括入稿の書き方 | JSON の配列 `["hint1", "hint2"]` | S-42、S-59 |
| 一括入稿で直す | **既存の一覧に足されず、上げた値で置き換わる**。足したいときも全部の一覧を書く | S-42、h20001215 |
| API で直す | `context_hints` は今の一覧を置き換える。1 つ足すときは読んで足して全部送る。空の配列で消える。欄を省けばそのまま | S-01 |
| 直したあと | 広告グループを読み直して保存された一覧を確かめる | S-01 |
| 1 つのヒントの字数・言語 | ❓ 記載なし | — |
| ヒントの効きの報告 | ❓ 記載なし（会話・話題の列は無い、62#7）| — |
| 低入札の警告との関係 | 広告グループを更新すると 24 時間は低入札の警告が出ない（ヒントの変更も広告グループの更新）| S-01〔ヒントの変更が当たるかは推測〕|

### 6-5. 日本語での書き方の型〔推測。§6-2 の公式の推奨を日本語の例にした。28§11-1 と同じ形〕

| よくない | よい | どの条件を満たすか |
|---|---|---|
| 「ランニングシューズ, 靴, スニーカー, 運動」| 「初めてフルマラソンに出る人の、30 km 走の練習に向く厚底のシューズ」| 具体・誰・いつ |
| 「東京の人だけに」| （ヒントには書かない。地域の設定で東京都を選ぶ）／ヒントは「平日夜と土日も受け付ける、出張費込み 8,800 円の水まわりの修理（東京 23 区）」| 配信の指示を外し、事業の説明にした |
| 「30 代女性に届けたい」| 「産休明けで時短勤務に戻る人の、朝 10 分で作れる作り置きの献立の宅配」| 「届けたい」をやめ、ニーズと場面に |
| LP の見出しを写す | LP の機能を「なぜ役立つか」と結ぶ: 「梅雨どきの通勤でも足が濡れにくい、防水の革靴」| 追加 |
| 「今だけ 20% オフ」（終わったあとも残す）| 特典が続く間だけ書き、終わったら消す | 正確 |
| 1 つのヒントに 3 つの場面を詰める | 場面ごとに 1 ヒント。訴求か LP が違う場面は広告グループを分ける | 1 つの考え |

- ヒントの本数〔推測〕: 公式は「埋めなくてよい」と書くだけで、数の推奨は ❓。**場面ごとに 1 本、広告グループに数本〜十数本**で始め、数字を見て足す
- 言語〔推測〕: 日本語の会話に出すなら日本語で書く。英語で書いた場合に日本語の会話へどう効くかは ❓

### 6-6. Google のキーワード・AI Max との違い

| 観点 | Google | ChatGPT |
|---|---|---|
| 性質 | キーワードは「この語で出す」の指定。マッチタイプで広さを決める | ヒントは関連性の材料。広さを決める仕組みは無い ✅ S-01・S-44 |
| 数 | 増やすほど届く範囲が広がる | 「埋めなくてよい」。数より具体性 ✅ S-01 |
| 除外 | 除外キーワードで外せる | ヒントで除外はできない ✅ S-44 |
| 地域・時間帯 | キーワードには書かないのは同じ。地域・スケジュールは設定 | 同じ。ヒントに書いても効かない ✅ S-44 |
| 報告 | 検索語句レポートで実際の語が見える | 実際の会話は見えない（62#7）|
| 一番近い Google の機能 | — | AI Max の「キーワードを外した検索語句のマッチング」に LP・広告文から関連を読む形が近い〔推測〕（23§1）|

### 6-7. 運用の判断への効き方

- **Google のキーワード表を貼らない。** 公式が避けるよう書く「つながりのないキーワードの羅列」になる
- **1 ヒント＝1 場面**で、「誰が・どんなときに・何に困って・どう役立つか」を書く。料金・対応エリア・営業時間など、LP の奥にある条件も書く（公式の例が料金を書いている）
- **効きを比べるなら広告グループを分けて**、ヒントの書き方だけを変える〔推測〕。会話のレポートが無いので、広告グループ別の表示・CTR・成果で比べるしかない
- **直すときは必ず最新の一覧から**（置き換えなので、古い書き出しから上げると他の人が足したヒントが消える）✅ h20001215
- 料金・特典・在庫・対応地域が変わったら、広告・LP と一緒にヒントも直す（「正確」）✅ S-44

## 7. Negative Phrases と、出したくない場面を外す手段

### 7-1. 公式の本文（全部）✅〔仕様〕S-31（2026-11-15 ごろ更新、2026-11-24 に読み直した）

- 「OpenAI の方針は、安全で適切で、利用者の信頼とブランドの安全に沿うチャットの近くにだけ広告を置くこと。安全の仕組みは、敏感な利用者の文脈やブランドにとって安全でない場面（広告ポリシーに挙げた文脈を含む）に広告が出ないよう設計している」
- 「**資格のある広告主は、ブランド独自の方針に基づく狭い掲載の条件のために Negative Phrases を使える。この選択肢は資格のある広告主向けで、すべての広告主が使えるとは限らない**」
- help.openai.com の検索で「negative phrases」を引いても、専用のページは出なかった（2026-11-24）

### 7-2. 開発者文書の `exclusion_hints`（新しく分かったこと、2026-11-24）

- ✅〔仕様〕Bulk API（限定プレビュー、アカウントごとに有効化）の操作の表で、`ad_group.create` と `ad_group.update` の任意の欄に **`context_hints` と並んで `exclusion_hints`** がある（S-01 Bulk API「Supported operations」）
- ❓ `exclusion_hints` の意味・形式・件数・一致のしかたの説明は、開発者文書のどこにも無い。ふつうの Ad Groups の参照（`POST /ad_groups`）の欄の表には無い
- ❓ これがヘルプの Negative Phrases と同じものか、どの広告主が使えるかは公式に記載なし。**「Negative Phrases ＝ exclusion_hints」と言い切らない**〔推測では、同じ「除外のヒント」の API 側の名前の可能性がある〕
- 既存の章（23§7）は「画面のどこにあるか ❓」と書いている。API に欄の名前が出ていることは 23 に無い（§13）

### 7-3. Negative Phrases の書き方 ❓

- 資格の条件、日本で使えるか、画面のどこにあるか（62 の確認では見当たらない）、何語・何個まで、一致のしかた（言葉の一致か意味の一致か）、どの層に置くか — **すべて公式に記載なし**（2026-11-24）
- 公式の言葉から言えるのは「**狭い**掲載の条件」「**ブランド独自の方針**」のためのもの、ということだけ。広く外す道具（Google の除外キーワードのような使い方）として説明されてはいない
- 〔推測〕書くなら、ブランドの方針で避ける具体的な場面（例: 自社の製品の事故の話題）を短い句で。**公式の書き方の説明が出るまで、この推測で設計を固めない**

### 7-4. 広告主が使える除外の手段（一覧）✅

| 手段 | 置き場所 | 外せるもの | 外せないもの | 出典 |
|---|---|---|---|---|
| 地域の除外 | キャンペーン | 地域（国・都道府県・郵便番号など）| 話題・会話 | S-01、S-34 |
| カスタム オーディエンスの除外 | キャンペーン | 顧客リストの人（下限なし）| 話題・会話 | S-01、h20001346 |
| 端末の指定 | キャンペーン | アプリ・Web の面 | 話題・会話 | S-01、S-34 |
| Negative Phrases | ❓ | ブランド独自の狭い掲載の条件 | — | S-31（資格のある広告主だけ）|
| `exclusion_hints` | 広告グループ（Bulk API）| ❓ | ❓ | S-01 |
| 文脈ヒント | 広告グループ | **何も外せない** | — | S-44 |
| OpenAI 側の安全の仕組み | （広告主は設定しない）| 敏感な利用者の文脈・ブランドに安全でない場面（ポリシーの文脈 19 種など）| 広告主ごとの細かい希望 | S-31、S-19（23§8-2）|

### 7-5. 運用の判断への効き方

- 「この話題では出したくない」という要望には、**今は広告主の側で確実に外せない**と説明する。資格の確認は営業の窓口かサポートに問い合わせる〔推測〕
- 外したい場面が多い商材は、**出す前に「その場面で出ても困らない広告と LP か」**を確かめる（ヒントで外す・LP で外す、はできない）〔推測〕
- 既存顧客を外したいなら、Negative Phrases ではなく**カスタム オーディエンスの除外**（下限なし）を最初から入れる ✅ S-01

## 9. 判断の型

### 9-1. 作る前の 6 つの問い〔推測。§2〜§8 の仕様から組んだ〕

1. **何を成果とするか、計測は届いているか** → 目的とイベントが決まる（後から変えられない）
2. **予算を分けたいものはあるか** → キャンペーンの数が決まる
3. **地域・端末・顧客リストで範囲を分けたいか** → キャンペーンの数が決まる
4. **訴求か LP が違う場面はいくつあるか** → 広告グループの数が決まる
5. **場面ごとに、LP にない何を伝えるか** → 文脈ヒントが決まる
6. **1 つの商品について、別の角度の広告を何本作れるか** → 広告の数が決まる

## 11. よくある思い込みと実際

| 思い込み | 実際 | 根拠 |
|---|---|---|
| Google と同じく MCC でまとめて管理できる | MCC に当たる層は無い。広告主ごとに別アカウント、同じログインで切り替え | ✅ S-39 |
| 入札戦略はキャンペーンで決める | 広告グループで決める。目的と予算はキャンペーン | ✅ S-01 |
| 目的は途中で変えられる | 変えられない。複製は別の目的・別の課金のときだけ | ✅ S-34 |
| 同じ設定のキャンペーンは複製で増やせる | 同じ目的のままは複製できない | ✅ S-34 |
| 予算の種類はいつでも切り替えられる | 通算 → 1 日の片道だけ（Google の合計予算とは向きが逆）| ✅ S-34、G02 |
| 1 広告グループの広告は 3 本まで | それは Google の RSA。ChatGPT は「多く・多様に」が推奨、広告グループごとの上限は記載なし | ✅ S-41 ／ ❓ |
| 文脈ヒントはキーワード。多いほど届く | 完全一致のキーワードではない。埋めなくてよい。数より具体性 | ✅ S-01、S-44 |

| アーカイブしても後で戻せる | 戻せない | ✅ S-01 |
| API で目的を書かなくてもクリック目的になる | 省くと表示目的 | ✅ S-01 |

- **02§2-3・05**: 「成果の最大化が既定で選ばれる」は商品フィードのキャンペーン（h20001268）だけを根拠にしている。h20001425（2026-10-28 ごろ更新）は**対象の新しい広告グループ全般**で既定と書く。ただし同じページは選び直す先を「Manual: Max bid」と書き、11-09 の変更（S-36）が反映されていない △

- **S-01 の内部**: Campaigns の参照の表は `budget.lifetime_spend_limit_micros` を「必須」と書き、Bidding & Budgets は「1 日か通算のどちらか 1 つ」と書く。Ad Groups の参照は `max_bid_micros` を「必須」と書き、最大化では送らないと別の節に書く。どちらも参照の表が古いと読める〔推測〕

- **S-36（2026-11-23 更新）**: 冒頭に「ChatGPT Ads は既定でより賢く（intelligent by default）なりつつある」という文が足された。中身（11-09・11-18・2027-01-01 の日付、払う額の決まり）は 02§3 の記述と変わっていない
