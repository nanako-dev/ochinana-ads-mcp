## 0. 先に結論（この章で一番効く 10 点）

1. **ChatGPT の買い物の調べものに出る商品は広告ではない**。広告は別枠（「スポンサー」）✅〔仕様〕H:11128490（2026-11-16 ごろ更新）
2. 商品の選ばれ方は、利用者の問いと文脈（メモリー・カスタム指示）、第一者・第三者の提供元の構造化された商品データ、OpenAI の安全の基準。販売者の並び順は在庫・価格・品質・作り手か主な売り手か ✅ H:11128490
3. **広告は ChatGPT の独立した回答に影響しない**。Business Hub で事業者として登録しても、表示が増える保証は無い ✅〔仕様〕H:20001635（2026-11-24 更新）、B:登録
4. **広告マネージャーの商品フィードの商品は、ベータの間は広告だけで、自然な商品表示に出ない** ✅ H:20001268（21§2-3）。自然な表示に載せたいなら、**Business Hub の商品フィード**など別の道
5. 公式の「広告以外の手」は 6 つ: 商品フィードの提出・クラウド ブラウザを弾かない・ChatGPT Wallet の支払い・プラグイン（MCP）・Sign in with ChatGPT・Business Hub での事業者の登録 ✅〔仕様〕D:Com「Partner Playbook Overview」
6. **Business Hub の登録は広告アカウントが無くてもできる**。ただし本人確認（Persona）が済まないと、情報の公開・インサイト・**商品フィードの接続**・エージェントができない ✅ H:20001635
7. **Business Hub のビジネス エージェント（広告ではない）は米国の対象の EC・オンライン サービスだけ**（日本語版のヘルプと事業者向けページ）✅ B:登録、H:20001635 日本語版。英語版は国の名前を書かず「所在地の条件」とだけ書く △
8. **ChatGPT Wallet は米国の Pro の利用者だけ**に段階的に提供（18 歳以上・米国の住所・米国発行のカード）✅ H:20001654（2026-11-22 ごろ更新）。加盟店の側は専用の組み込みが要らない ✅ D:Com「Accept payments」
9. **Instant Checkout と Agentic Commerce Protocol（ACP）**は 2025-09-29 に公式発表（米国の Etsy の出店者から、Shopify の加盟店は「まもなく」）✅ B:購入。2026-11 の公式の開発者文書とヘルプには **Instant Checkout の語が無く**、購入はクラウド ブラウザ・プラグイン・Wallet で説明している。縮小の報道はあるが、廃止の公式発表は見当たらない ❓
10. 日本の事業者が今すぐできて費用がかからないのは、①クラウド ブラウザと OAI-SearchBot を弾いていないかの点検（68）②商品ページの価格・在庫・レビューを正確に保つ ③Business Hub で登録できるかを試す（日本で通るかは ❓）〔推測〕

## 2. 全体の地図

### 2-1. 公式が描く買い物の流れ ✅〔仕様〕D:Com「Partner Playbook Overview」（要約）

1. 利用者が欲しいものを話す（例: 座席の下に入る機内持ち込みのかばん）
2. ChatGPT が候補を探す。情報源は頼みごとと連携しだいで、公開のウェブ・非公開の API の連携・（小売では）加盟店の商品フィード
3. 利用者が比べる（出品・時間などを選び、買うか予約するかを決める）
4. ブラウザの操作かプラグインに進む。ブラウザの操作は今のサイトの流れを使い、大きな開発は要らない。プラグインは開発が要るが、構造化した操作を公開し、自社の裏側で確かめて実行できる。アカウントと支払いの段では、使える所で Sign in with ChatGPT と ChatGPT Wallet が支える。**結果は事業者が確定する**

### 2-2. 公式の 6 つの手 ✅〔仕様〕D:Com「Support the commerce journey」

| 手 | 公式の説明（要約） | 誰向け | この章の節 |
|---|---|---|---|
| 商品フィードの提出 | 商品・画像・価格・在庫の最新のフィードで検索の索引を強める | 物を売る事業者 | §6 |
| クラウド ブラウザのアクセス | CDN・ファイアウォールが確認済みの ChatGPT のブラウザの訪問を止めていないか確かめる | サイトを持つ事業者 | §7 |
| 支払いを受ける | 今のサイトで ChatGPT Wallet の支払いを受ける | 決済のあるサイト | §8 |
| プラグインを作る | 在庫の確認・購入や予約の準備などを構造化した道具として公開 | 開発の力がある事業者 | §9-1 |
| Sign in with ChatGPT | サイト・購入手続きにアカウントが要るとき、ChatGPT でログイン | 一部の商取引のパートナー | §9-2 |
| 事業者の登録 | Business Hub で事業者として登録し、プロフィールを管理 | 事業者全般 | §5 |

- 公式の順番の案内は、商品フィード → クラウド ブラウザ → 支払い → プラグイン → Sign in with ChatGPT → 事業者の登録（各ページの「次の手順」のつながり）✅ D:Com。**重要度の順とは書いていない**

### 2-3. 運用の判断への効き方

- 6 つのうち、**開発がほぼ要らないのはクラウド ブラウザの点検と事業者の登録**。商品フィードは仕様どおりのファイル、プラグインと Sign in with ChatGPT は開発が要る〔推測: 各節の手順から〕
- 広告の担当の仕事として扱えるのは、クラウド ブラウザ・クローラーの点検（広告の審査にも効く、68）と、Business Hub の情報の正しさ〔推測〕

## 3. 自然な商品表示（広告ではない）✅〔仕様〕H:11128490（2026-11-16 ごろ更新、英語版の本文）

### 3-1. いつ出るか

- 問いに買い物の意図があるとき（例「犬の仮装の衣装を探して」）、ChatGPT は画像と商品の詳細を見せ、買える手段を見せることがある
- **商品の結果は広告ではない**。広告は商品の結果と別 ✅
- モバイルとウェブの ChatGPT で使える。利用者のプランの限定は書かれていない ❓（広告は無料版と Go だけ、00§8）

### 3-2. 選ばれ方

| 何を見るか | 公式の説明（要約） |
|---|---|
| 問いと文脈 | 問いと、メモリー・カスタム指示などの文脈。例: 道化が嫌いと言っていれば道化の衣装を外すことがある |
| 構造化されたデータ | 第一者・第三者の提供元の構造化されたメタデータ（価格・商品の説明など）と、その他の第三者のコンテンツ |
| モデルの回答 | 新しい検索の結果を見る前に生成したモデルの回答 |
| 安全の基準 | OpenAI の安全の基準と製品の方針 |

- どれが効くかは頼みごとしだい（予算を言えば価格を重く見る）✅
- 全部の商品が出るわけではない ✅
- モデルは意図を読み違えることがあり、利用者が言い直して直す ✅

### 3-3. 表示の中身

| 要素 | 公式の説明（要約） |
|---|---|
| タイトル・説明 | 第三者の提供元の情報をもとに、**ChatGPT が簡略にしたタイトル・説明を作ることがある**（加盟店ごとに同じ商品の書き方が違うため） |
| ラベル | 「Budget-friendly」「Most popular」のようなラベルを ChatGPT が作ることがある。保証や確かめた主張ではない（例: 手頃さのラベルは、最安ではなく、レビューで値頃と言われることが多いという意味のことがある） |
| レビューの要約 | 公開のウェブのレビューをもとにモデルが作る。レビューと評価は OpenAI が確かめていない |
| 価格 | 第三者の提供元から受け取る。最初の回答の価格は、ふつう最初に並ぶ販売者の価格で、**最安とは限らない**。商品の詳細では、知っている最安の選択肢を目立たせる。複数の販売者があれば「Best price」のラベルがつくことがある |
| 反映の遅れ | 販売者が価格・送料を変えてから反映まで遅れがある。速くする方法を開発中 |
| 試着 | 服・小物に「Try on」のボタン。自撮りを上げると ChatGPT Images で試着の画像を作る。参照の写真は保存され、設定で変えられる |
| 保存 | 商品をライブラリのお気に入り・フォルダに保存できる |

### 3-4. 販売者の選ばれ方と並び順

- 商品を選ぶと、その商品を売る販売者の一覧が出ることがある。一覧は第三者の提供元か**販売者から直接**の販売者・商品のメタデータで作る ✅
- 並び順の要因: **在庫・価格・品質・その商品の作り手か主な売り手か**。好みに合わせた並べ方を今後増やす予定 ✅
- Shopify の加盟店: 商品データは Shopify Catalog を通じてすでに ChatGPT に連携。個々の加盟店の追加の作業は要らない ✅
- 直接の商品フィードを出したい加盟店は、開発者サイトの商品フィードの文書を読み、**直接のフィードのアクセスを申請**できる ✅（申請の窓口は Business Hub、§6）

### 3-5. 誤りの報告

- 利用者は商品の高評価・低評価のボタン、商品のメニューからの誤り・方針違反の報告、コンテンツの報告の様式で知らせられる ✅
- **事業者が誤りを直す公式の窓口**は Business Hub の情報の更新と商品フィード（§5・§6）〔推測: H:11128490 は利用者の報告の道だけを書く〕

### 3-6. 運用の判断への効き方

- 商品ページと構造化データ（価格・在庫・説明・レビュー）が、第三者の提供元を通じて選ばれ方に入る。**商品ページの情報を正確に・機械が読める形に保つ**ことが、費用のかからない対策〔推測〕
- 「主な売り手か」が並び順の要因なので、メーカーの直販サイトは、自社が作り手であることを商品ページで明らかにしておく〔推測〕
- ChatGPT が商品のタイトル・説明を作り直し、ラベルも付ける。**表示される文言を事業者が決められない**。薬機法・景表法で気をつける表現（効能・最上級）を ChatGPT が付ける可能性は ❓（31 と関係）

## 4. 広告と回答の関係（回答に影響しない原則）

- 利用者向けヘルプの並び順の要因（在庫・価格・品質・作り手か主な売り手か）にも、広告・提携の語は無い ✅

### 4-2. 運用の判断への効き方

- 「ChatGPT の広告を出すと、回答の中で自社が薦められやすくなる」は**公式に否定されている**（#2）。提案書でも「回答の中の推薦を買う広告」と書かない（61§4 のやらないこと 1）
- 逆に「回答に出たいから広告をやめる」も根拠が無い。自然な表示と広告は**別の経路**として、別々に評価する〔推測〕
- 自然な表示で自社が出ているかは、Business Hub のインサイト（言及・クリック、§5-6）でしか公式には見られない

## 5. Business Hub（事業者の登録）✅〔仕様〕H:20001635（英語版・日本語版、2026-11-24 更新）、B:登録（日本語版）

### 5-1. 何ができるか

- ChatGPT の中で自社を「事業者として登録（claim）」し、事業の詳細・商品の情報を出し、利用者の関わり方（インサイト）を見る
- 対象の EC・オンライン サービスの事業者は、出した情報で客の質問に答える**ビジネス エージェント**を作れる（§5-7）
- 登録が承認され Persona の本人確認が承認されると、プロフィールに**青いチェック（確認済みの印）**がつく。**登録だけでは印はつかない**

### 5-2. 誰が登録できるか

| 条件 | 中身 |
|---|---|
| 人 | 事業の所有者か、代表する権限のある人。関係を確かめる手続きと承認が要る |
| 広告 | **広告アカウントも ChatGPT Enterprise の契約も要らない** |
| 地域・業種 | 「ChatGPT が使え、必要な確認の手続きに対応している地域」で、既存の事業の登録か新しい追加ができる。**所在地と事業の形で使えるかが変わる**。登録の可否は業種・所在地・OpenAI の認証や信頼性の確認で判断（B:登録） |
| 種類 | EC とオンライン サービスの事業者は、登録とエージェントの公開の対象 |
| 方針 | Business Agents Policy の業種の要件も満たす |
| 店舗・飲食店 | **実店舗とレストランは、今は米国の既存の掲載情報だけ**登録できる |
| 見つからないとき | 対象のオンラインの事業なら、追加の選択肢が出ることがある |

- **日本の事業者が登録できるか**: 日本語版のページと日本語のヘルプがあり、「ChatGPT が提供されている地域」と書くが、**国の一覧は無く、日本の名前も無い** ❓。実店舗は米国だけ ✅（日本の店舗・飲食店は今は登録できないと読める）

### 5-3. 登録の手順

1. ChatGPT にログインし、サイドバーから Business Hub を開き、事業の名前で探す
2. 合う掲載を選び、管理に使う ChatGPT のアカウントを確かめる
3. 出ている確かめ方を選ぶ

| 確かめ方 | 中身 |
|---|---|
| 事業の電話 | SMS か自動の音声通話でコード |
| 事業のメール | 事業のメールにコード |
| ウェブサイトのドメイン | ChatGPT に出る TXT レコードを DNS に足す（種類・名前・値をそのまま）。反映に時間がかかる |
| Shopify のストア | Shopify の管理画面の ChatGPT のアプリか、Business Hub から接続 |

- 掲載ごとに使える方法が違う。公開の電話でコードを受けられないなら、ドメインの方法を探す ✅
- 広告アカウントがあるか OpenAI の担当者がいる事業者は、ワークスペースの管理者に**個人あての登録のリンク**が届いているはず ✅ D:Com「Submit product feeds」。その招待は送られたメールのアドレスでログインして使い、**転送して他人に使わせない** ✅ H:20001635
- 掲載が組織の管理者（ChatGPT Enterprise のワークスペースの管理者）を要するときは、その人が自分のアカウントで始める。広告アカウントの管理者・サイトの管理者とは別の人のことがある ✅
- 申請は審査の依頼で、アクセスの付与ではない。結果はメールで来る。審査中は取り消せる ✅
- 掲載がロックされていたら「サポートに連絡」✅
- 既に他人が登録していたら、「•••」から所有の異議（Dispute ownership）を出し、Persona で権限を確かめる。登録や異議でプロフィールの見え方は変わらない ✅

### 5-4. Persona の本人確認

- 登録の確かめ（事業との関係）と、Persona（本人の確認）は別。**ドメインや Shopify で確かめても、Persona の承認が要る**: 情報の変更の公開・インサイトの閲覧・**商品フィードの接続**・エージェントの設定 ✅
- 用意するもの: 政府の発行の身分証、事業の登記の情報、代表する権限の証明が要ることがある ✅
- **法人名は登記の書類どおり**（屋号は別の欄）。住所・登録番号・税番号も記録と合わせる ✅
- Persona で新しいプロフィールを作ると、OpenAI の承認で**自動で公開**される（公開の別の手順は無い）。準備ができてから進める ✅
- 提出しただけでは承認ではない。失敗・期限切れはメールの指示に従い、「再試行」があれば直して出し直す ✅

### 5-5. 情報の更新と下書き

- 承認の後、サイト・事業の説明・商品やサービスの分類・ロゴ・配送の方針・返品の方針・カバー写真などを更新できる。Businesses in ChatGPT のポリシーに従う ✅
- 変更は OpenAI が審査して公開。**掲載や回答に出るまで時間がかかる**。ChatGPT は他の情報源も使う ✅
- 消せるのは未公開の下書きだけ。**公開済みのプロフィールはサポートでも消す・非公開にする・隠すことができない** ✅
- 複数のブランドは**ブランドごとに別のプロフィール**。全ブランドをまとめる親のプロフィールは無い ✅
- チーム: 登録した管理者が、Business Hub で仲間を足し、**代理店に事業やエージェントの管理の権限**を渡せる。各人は自分の ChatGPT のアカウントを使う ✅

## 6. 商品フィードの提出（買い物用）✅〔仕様〕D:Com「Submit product feeds」「Product feed schema」、H:20001635「Connect a product feed」

### 6-1. 何に使われるか

- ChatGPT は商品フィードと、その他の小売・公開のウェブの情報源を、**商品の発見**に使える。フィードは構造化したカタログのデータ ✅
- フィードは**カートを更新せず、購入を確定しない**。客が動くときは、今のサイトかプラグインが今の出品を確かめる ✅
- ブラウザの操作は別の機能（§7）✅

### 6-2. 手順（開発者文書）

1. Business Hub（https://chatgpt.com/business-hub/ ）から始める。広告アカウントがあるか担当者がいれば、ワークスペースの管理者に個人の登録のリンクが届いている。登録がまだなら事業者向けページの手順で登録
2. Business Hub の商品の欄で**本人確認**を選ぶ（商品を上げるのに必須）
3. 確認が済んだら商品の欄に戻り、商品のアップロードを選ぶ
4. **商品を売る国と通貨を選ぶ**
5. 仕様（Product feed schema、21§3）どおりにフィードを作る。全行に必須の項目、`item_id` を変えない
6. 送り方を 1 つ選ぶ: 手動のアップロード・ホストした HTTPS の URL・SFTP（販売者の窓口で、全体の写しを送る）。上げた後に誤りを直す

### 6-3. 手順（Business Hub のヘルプ）

- CSV を仕様どおりに上げるか、ホストしたフィードの URL（ファイルそのものを開く URL）を入れる。ホストした URL を取り込めないときは CSV のアップロードを使える。処理が成功すると、カタログはそのファイルの商品になる。以後の自動の取り込みにはホストした URL が働いている必要がある ✅
- フィードの商品は **Commerce policies（商取引の方針）**に従う ✅（方針の中身はこの章では読んでいない ❓）
- 上げたときに商品の URL で失敗したら: 上げ先のプロフィールのサイトと、失敗した商品の URL のドメインを比べる。違うプロフィールなら切り替え、商品の URL が誤りなら直す。同じなら Persona の状態（保留なら待つ）。ドメインの方法なら TXT レコードを照らす ✅
- **Shopify の加盟店は、Business Hub でストアを接続すれば、既存の Shopify のカタログを使える**。別のフィードは要らない ✅
- **Shopify のアプリを入れなくても、Shopify Catalog の対象の商品はすでに ChatGPT に出うる** ✅

### 6-4. 項目の既定（広告との関係）✅ D:Com

- 検索（`is_eligible_search`）は既定で有効、購入手続き（`is_eligible_checkout`）は既定で無効、広告（`is_ads_eligible`）は**フィードに広告の既定が無ければ無効**（21§3-7）
- 購入手続きは「別に有効にする連携」が要る。旗を立てるだけでは購入手続きの導入は終わらない。売り手のプライバシーの方針と利用規約の URL が条件つきで必須 ✅

### 6-5. 国の制約

- **OpenAI 形式の標準のアップロードは今は米国向け**。共通の形式は US・CA・MX、他の市場は OpenAI が連携と国・通貨を確認してから ✅ D:Com「Geo tagging」（21§3-3）
- 手順 4 の「売る国と通貨を選ぶ」に日本があるかは ❓
- **運用の判断への効き方**: 日本の EC が日本の利用者向けに直接のフィードを出せるかは分からない。Shopify を使う店は、Shopify Catalog の連携で何もしなくても載りうる（日本の店に効くかは ❓）〔推測〕

## 7. クラウド ブラウザを弾かない ✅〔仕様〕D:Com「Help ensure cloud browser access to your site」

### 7-1. 何か

- 利用者は ChatGPT にサイトを訪ねて用事を済ませるよう頼める（商品探し・比較・様式の入力）。一部の用事で ChatGPT は**クラウドのコンピューターで動くブラウザ**を使い、利用者の代わりにページを読み、ボタンを押す ✅
- ファイアウォールがその訪問を止めると、購入などの用事が終わらない。**ChatGPT のエージェントの身元（agent profile）を許可の一覧に足す**よう勧める。他のセキュリティの制御は保ったままでよい ✅〔公式の推奨〕
- クラウド ブラウザは有料プランの利用者だけ（無料版と Go を除く）✅ 68§3（H:20001280）

### 7-2. 確かめ方

| 提供元 | 扱い |
|---|---|
| Akamai・Cloudflare・HUMAN・Vercel | **ChatGPT の要求の署名を自動で確かめる**（それぞれの手順がある） |
| その他の CDN・ファイアウォール | 手で確かめる: ①`Signature-Agent` ヘッダーが `"https://chatgpt.com"`（引用符を含めて）と完全に一致 ②公開鍵を https://chatgpt.com/.well-known/http-message-signatures-directory から取る ③`Signature` と `Signature-Input` を RFC 9421 で確かめる ④署名を確かめた要求にだけ例外を当てる |

- 仕組みは Web Bot Auth（HTTP Message Signatures、RFC 9421）。**署名つきのクラウド ブラウザの要求の話で、ウェブのクローラーの話ではない** ✅

### 7-3. よくある質問（公式）

| 問い | 答え（要約） |
|---|---|
| 購入などで人の確認を必須にできるか | 個々のサイトが操作を制御する機能はまだ無い。全利用者について、**重い操作の前には人の確認を求めている** |
| 一部のページ・商品だけ止められるか | 例外はサイト全体に当たりうる。今のページ単位のアクセス制御は保つ |
| 他の bot に影響するか | しない。クラウド ブラウザの訪問は利用者の代わりで、OAI-SearchBot などのクローラーとは別（クローラーの制御は 68） |
| 商品フィードとの関係 | 独立だが補い合う。フィードは商品の在庫の理解（発見）を助け、ブラウザは加盟店のサイトでの次の操作を助ける。**フィードを出していなくても、確認済みの利用者はブラウザでサイトを使える** |
| プラグインとの関係 | 独立だが補い合う。プラグインが無くてもブラウザで使える。プラグインがあると速く楽になりうるので、作って公開することを勧める |
| 支払い・注文の誤りは誰が扱うか | 操作の責任は客にある。客が自分で操作したときと同じように対応する |
| 客との関係はどうなるか | 弾くサイトは、他の情報源に移る利用者・客を失うかもしれない |

### 7-4. 運用の判断への効き方

- 広告の審査のクローラー（OAI-AdsBot）・検索のクローラー（OAI-SearchBot）・クラウド ブラウザの 3 つは別の仕組み。**3 つとも弾いていないかを一度に点検する**（68§10 の手順）〔推測〕
- 日本の EC が今すぐできる、費用ゼロの手の 1 つ（00§9-2、61§4 のやれること 1）

## 8. 支払い: ChatGPT Wallet

### 8-1. 加盟店の側 ✅〔仕様〕D:Com「Accept payments」

- 客は ChatGPT Wallet か保存した支払い方法で、**加盟店のサイトで**払う。客が ChatGPT で確かめて承認し、**加盟店の購入手続きが決済を処理**する。注文・発送・客の対応・不正の判断は加盟店 ✅
- **Wallet は今の購入手続きのページ・支払いの様式でそのまま動く。Wallet 専用の組み込みは要らない**。ブラウザのアクセスの点検などは任意 ✅
- 不正の判定: ChatGPT のクラウド ブラウザが bot の検知に当たり、購入が失敗することがある。OpenAI は利用者の信号を `Forwarded` ヘッダーで送る対応を広げている（送られる項目: `asn`・`for`〔利用者の IP〕・`ip-country`・`ip-prefix`・`locale`・`tz`・`user-agent`）。外部の不正の判定の会社を使うなら、その会社に取り込みの設定を確かめる ✅
- 定期の課金: 今の購入手続きが対応していれば使える。客の同意を取る ✅
- 別の購入に使い回さない（同意はその取引だけ）✅
- カードの番号の全体は受け取らず、ネットワークのトークン（PAR で元の口座に結びつける）✅
- 既に保存したカードの流れはそのまま使える（Wallet は別の支払い手段）✅

### 8-2. 利用者の側 ✅〔仕様〕H:20001654（2026-11-22 ごろ更新）

## 9. プラグイン（MCP）と Sign in with ChatGPT

### 9-1. プラグイン ✅〔仕様〕D:Com「Build a plugin」

- 開発の力があれば、次は**プラグイン（MCP のサーバー＋スキル）**。ChatGPT がページと様式をブラウザで操作する代わりに、事業者のサービスを直接呼ぶ ✅
- ブラウザに比べた利点（公式）: 確かさ（画面の配置に頼らない）、続くログイン（トークンの期限・取り消し・方針の範囲で）、速さ（1 回の呼び出しで何ページ分も。ただし実際の流れを測る。**自動で速くなるとは限らない**）✅
- 作り方の決まり: **画面を持たない（headless）プラグイン**にする。iframe の MCP の画面は Dots で使えず、商取引の推奨の道ではない。在庫・価格・取引の状態・確定は MCP のサーバーが持つ ✅（「Dots」が何かは ❓）
- 小売の道具の例（必須の名前でも共通の形式でもない）: 商品の照会（ID・今の価格・在庫・画像・受け取り方）、カートの操作（カートの ID・明細・合計）、購入手続き（対応するなら。合計と要る手順、続きの URL か確定の結果）、注文の履歴と再注文（ログインした客）✅
- 購入手続きを会話から出ずに終えられるよう作る。終えられない段では、ブラウザでサイトに続ける URL（`continue_url`）を返す ✅
- **ゲストのまま**（加盟店のアカウントにログインせずに）商品の照会とカートの作成・更新ができるようにし、購入手続きでログインしたときにカートを引き継ぐ ✅〔公式の推奨〕
- サーバー間の認証が要るなら、MCP のサーバーの相互 TLS（mTLS）に対応（OpenAI が管理する証明書を ChatGPT が出す）✅
- 日本の事業者が公開できるかは ❓

### 9-2. Sign in with ChatGPT ✅〔仕様〕D:Com「Integrate Sign in with ChatGPT」

- サイト・購入手続きにログインが要るとき、客が ChatGPT でログインできる。商取引の連携では、訪問をまたいでログインを保つときや、購入手続き・注文の追跡・返金・割引で本人を確かめるときに**強く勧める** ✅
- **一部の商取引のパートナーだけ**。許可の一覧への追加は siwc-partners-inbox@openai.com に「商取引のパートナー」と書いて申請。許可の後、本人確認だけの連携は自分で設定でき、公開の前に手動の審査に出す ✅
- 決まり: 既存の加盟店のアカウントは重複を作らずに結びつける。**メールの一致だけではアカウントの持ち主の証明にならない**。ChatGPT の本人確認は購入の承認ではない。受け取る本人の情報の通知と同意は事業者の責任 ✅
- 公開の前に、新規・既存の客、結びつけ、同意の拒否、期限切れ、取り消しを試す ✅

| 何か | Stripe と共同で作った **Agentic Commerce Protocol** を土台にした **Instant Checkout** を始める |
| 誰が | **米国**の ChatGPT の Plus・Pro・無料版の利用者が、チャットの中で**米国の Etsy の出店者**から直接買える。Shopify の 100 万超の加盟店（例として 4 ブランドの名前）に「まもなく」対応 |
| 範囲 | 単品の購入だけ。複数の商品のカート、販売者・地域の拡大は今後 |
| 流れ | 商品が対応していれば「Buy」を押し、注文・配送・支払いを確かめ、チャットを離れずに買う。注文・支払い・発送は**販売者が既存の仕組みで処理** |
| 手数料 | **販売者が成立した取引ごとに少額の手数料**を払う。利用者は無料。価格と表示に影響しない |
| 並び順 | 表示される商品はスポンサーの影響を受けず関連性だけで順位づけ。同じ商品の販売者が複数なら、在庫・価格・品質・主な売り手か・Instant Checkout の対応などで並べる（§4-1 の △） |
| ACP | AI のエージェント・人・事業者が購入を完了するためのオープンな標準。**オープンソースで公開**。Stripe を使う販売者は「1 行のコード」でエージェントの決済を有効にできる、Stripe 以外は Stripe の Shared Payment Token API か ACP の Delegated Payments Spec で参加できる、と書く |
| 信頼 | 各段の明示の確認、暗号化した支払いトークン（許した額と販売者だけ）、必要な情報だけを販売者に渡す |
| 申請 | 販売の準備ができた販売者は申請する（発表のリンク） |

### 10-2. ACP の公開の仕様 〔公式の関係先〕https://www.agenticcommerce.dev/ （2026-11-24、WebFetch の要約）

## 11. Shopify の加盟店 ✅〔仕様〕H:20001241（2026-10 更新）、H:11128490、H:20001635、B:登録

- 日本の Shopify の店が Shopify Catalog で ChatGPT に出るかは ❓（Shopify の側の対象の条件。この章では Shopify のヘルプを読んでいない）
