## 0. 先に結論（10 行）

1. 権限は 5 段階（管理者／標準／読み取り専用／お支払いとご請求／メール専用）。**標準ではユーザーの追加も、お支払い方法の追加も、管理者アカウントとのリンク操作もできない** ✅
2. 管理者アカウント（MCC）にリンクしただけでは「オーナー（所有権）」は付かない。オーナーの MCC の管理者だけが、子アカウントのユーザー・リンクを編集できる ✅
3. **毎月の請求書で払っているアカウントを、支払いを担う MCC からリンク解除すると、その場で配信が止まる** ✅
4. 2026-09-09 で **開発者トークンは廃止**。API のアクセスの段階は Google Cloud プロジェクトに付くようになった（ヘッダーに送っても無視される）✅
5. 管理者が 3 人を超えるアカウントでは、ユーザーの追加・削除・権限変更に別の管理者の承認（複数人承認）が要る。期限は 20 日 ✅（人数の書き方は △）
6. 乗っ取りの典型は「Google 広告のログイン画面を装った検索広告」から認証情報を盗み、管理者を足して予算を使う手口〔第三者: Malwarebytes 2025-01〕
7. 無効なクリックは課金前に除かれ、課金後に見つかった分は翌月以降のクレジット。キャンペーンの指標は遡って直らない（16 の 4-4）✅
8. IP の除外はキャンペーン単位で 500 件まで。**アカウント単位の IP 除外は P-MAX にも効く** ✅
9. 2026-06-01 から、時間別・日別・週別のデータは **37 か月**しか取れない（月・四半期・年は 11 年）。API は古い日付で `DateRangeError.INVALID_DATE` ✅
10. 変更履歴は管理画面で **2 年**、API の `change_event` は **30 日** しかさかのぼれない ✅

### 1-3. 所有権（オーナー）✅

- MCC がオーナーになっていると、その MCC の管理者は子アカウントの **ユーザーのアクセス・管理者・サービス間のリンク** を編集できる。オーナーでない MCC はキャンペーンの管理はできるが、ログイン情報などの所有者側の設定は変えられない（9978556、6139186）
- オーナーにするのは子アカウントの管理者。［管理者］→［アクセスとセキュリティ］→［管理者］で MCC が「オーナー」と表示されればよい（6139186）
- **毎月の請求書や与信枠の申し込みには、MCC のオーナー設定が必要**（9978556）
- 既存のアカウントをリンクしても、オーナーは自動では付かない（7456530 の要約経由。〔第三者〕Relevant Audience も同旨）

### 1-4. リンク解除で起きること ✅（7458428）

| 影響 | 中身 |
|---|---|
| アクセス | MCC は子アカウントに入れなくなる。子アカウントは自分のキャンペーン履歴と機能を保持する |
| 解除できる条件 | MCC 側から解除できるのは、子アカウントにアクセスできるユーザーが 1 人以上いるか、別のオーナー MCC にリンクされているとき |
| 共有のリマーケティング リスト | MCC のタグ・共有リストは子アカウントで増えなくなり、使えなくなる。**そのリストをターゲットにした広告グループや、除外に使っていたキャンペーンは止まる** |
| アカウント間のコンバージョン計測 | 解除後のクリックは MCC のタグで記録されない。解除前のクリックは計測期間（通常 30 日）の間は記録される。子アカウント独自のタグがあれば、そちらに戻る |
| 毎月の請求書 | 支払いを担う MCC（paying manager）から外すと **配信が止まる**。外す前に、移る先の MCC の下で請求の設定を作り直す |
| MCC 所有の入札戦略 | 外れるとキャンペーンの入札が変わる → 14 の 74 |

- ✅ お支払いプロファイルを MCC から外すと、そのプロファイルを使う全アカウントの請求設定が無効になり配信が止まる（14169584 の要約経由）
- ❓ ラベル・共有の除外リスト・共有予算の扱いはこのページにない → 確かめ方: テスト用の子アカウントで MCC の共有リストを付けた状態で解除し、キャンペーンの状態を見る

### 1-5. 代理店の切り替え（支払う側の移管）✅（14200924、ベータ）

- 前の代理店（現在の支払いを担う MCC）が「支払い元の変更（Change Who Pays）」要求を出し、新しい代理店が承認する。サポートが 48 時間以内に審査（追加情報が要るときを除く）
- 新しい代理店は支払いを担う MCC と請求の設定、移管日を選ぶ。アカウント予算の開始日は移管日以降
- **移管後 7 日以内に子アカウントを新しい MCC にリンクしないと配信が止まる**
- 要求には期限があり、過ぎると自動で取り消し。ベータの間は自動のリンク解除がなく、手で付け外しする

### 1-6. 代理店と広告主の関係での注意〔推測。根拠は上の公式の決まり〕

- 広告主が自社のアカウントに **自社ドメインの管理者を最低 1 人** 置く（オーナー MCC がユーザー管理を握るため）。代理店の MCC をオーナーにするかは契約で決める
- 終了時の段取り（新しい請求設定 → リンク解除 → 共有リスト・アカウント間計測の付け替え）を契約書に書く（リンク解除で即停止・リスト停止があるため。T6 の 10-4 も参照）
- MCC の「セキュリティの必須設定」は階層全体に効く（2375456）。代理店側の 2 段階認証の強制が広告主のアカウントに及ぶことを双方で確認する

### 2-2. 日本での消費税 ✅❓

- ✅ 会社の住所が日本のアカウントは、月別明細書を **グーグル合同会社がリセラーとして発行** し、Google 広告の売り上げに **10% の消費税** が課される（2375370、ja）
- ✅ 会計書類は「個人事業主」か「ビジネス」として作ったアカウントにだけ出る。**この選択はあとから変えられない**（2375370 の要約経由）
- ❓ 予算（日予算・アカウント予算）に消費税が含まれるか、税抜きか → 日本の項目に記載なし。〔推測〕予算・費用列は税抜きで、請求時に 10% が上乗せされる。確かめ方: 月別明細書の「消費税」行と、管理画面の当月費用を突き合わせる
- ❓ 適格請求書（インボイス制度）の登録番号の記載 → 取得したヘルプに記載なし。確かめ方: ［料金］→［書類］の月別明細書を開いて「登録番号」を確認、国税庁の公表サイトで照合
- ✅ Google は税の助言をしない。税理士に相談するよう案内している（2375370）

### 2-4. 支払いの失敗で止まるとき ✅

### 2-5. クーポン（プロモーション コード）✅（日本の規約）

- 対象は新規の広告主で、**初めて作ったアカウントの最初の広告表示から 14 日以内** にコードを入力した人。条件は定められた額以上の広告費（額はコードの媒体に記載）と問題のない請求、請求先住所は日本。自動支払いに限る場合がある
- 条件達成から通常 35 日以内に反映、**反映から 60 日で失効**。1 広告主 1 回。税・手数料には使えない。**残高が尽きても通知されない**。コード自体は媒体の発行から 3 か月
- クーポン由来の残高は解約時の払い戻しの対象外（business.google.com/jp）。乱用は請求関連の停止理由（9841640）

## 3. 広告主の適格性確認（本人確認）

細目（対象・期限の通知・反映 5 営業日・開示内容・再確認のきっかけ）は **15 の 7-22〜7-26**。ここでは「済んでいないと何ができないか」に絞る。

| 済んでいないと / 関係する場面 | 中身 | 印 | 出典 |
|---|---|---|---|

### 6-5. 被害に遭ったときの手順 ✅（9355975）

1. **乗っ取りの報告フォーム** で報告（不審な変更の時系列、漏れたと思う認証情報、不正な時刻、知らない MCC の ID、予算やルールの不審な変更、現在の IP アドレス）
2. Google が不正を確認すると、アカウントを一時停止し、**侵入者が変えたキャンペーンだけ** を止め、不正なユーザーを外し、不正な MCC のリンクを解除し、不正な子アカウントの利用上限を 0 にする
3. 管理者が 2 段階認証で再認証し、パスワードを変える（判断の前に必須）
4. 変更の記録を確認して判断を 1 回だけ出す（**変更できない**）。判断できるのは **乗っ取りの確定日より前から権限を持っていた管理者だけ**。選択肢: 「このアカウントをクリーンアップ」／「現状のまま復元」（正当な変更だった場合。**払い戻しの権利を失う**）／「追加の調査が必要」
5. ユーザーとキャンペーンだけの被害なら確保後すぐ停止解除。構造が変えられていれば、判断を出すまで停止のまま
6. 回復後: 端末のマルウェア確認 → パスワード変更、許可ドメイン・ユーザー・MCC リンク・お支払いプロファイルの点検、覚えのないキャンペーンの停止。ポリシー停止への申し立ては、これらを直してから
7. 払い戻し: 回復と 2 段階認証を済ませてから請求。調査に **10〜15 営業日**、認められると次の請求書に「サービス調整」として出る

### 6-6. 不審な変更の監視〔推測〕

毎日: スクリプトで費用の急増をメール、`change_event` で新しいユーザー・MCC リンク・予算の変更を拾う。毎週: 変更履歴を「ユーザー」列で並べる。毎月: ユーザー一覧と最終ログイン、MCC リンク、お支払いプロファイルのユーザー。人が抜けたら権限を外し、ルール・スクリプトの所有者を移す。

## 9. 審査とアカウントの停止

### 9-1. 不承認の主な理由と対処

- 審査の流れ・ステータス → **05 の 10**、**15 の 7-01〜7-09**
- 主な理由と直し方: 編集基準（記号・繰り返し・電話番号の直書き）、商標、不実表示、リンク先（エラー・リダイレクト・AdsBot の遮断）、電話番号 → **15 の 7-17〜7-33**
- 再審査請求: **1 広告 3 回まで・24 時間以上あける・6 か月より前の決定は管理画面から不可** → **15 の 7-10〜7-14**

### 9-2. アカウントの停止の種類 ✅（9841640）

| 種類 | 中身 |
|---|---|
| 重大な違反（予告なし）| 回避行為（システムの回避）、組織的な欺瞞行為、偽造品、悪意のあるソフトウェア、処方オピオイド、無許可の薬局、**不正なビジネス慣行**、制裁違反、性的に露骨なコンテンツ、児童の性的虐待。**Google 広告で二度と広告を出せない** |
| 繰り返しの違反（違反警告）| 初回は警告のみ。1 回目と 2 回目の警告で **3 日・7 日** の一時保留、3 回目で停止。停止の **7 日以上前** に通知（15 の 7-15・7-16 と一致）|
| 請求と支払い | **クーポンの乱用、チャージバックの請求、不審な支払い、未払い** |
| 不正なアクセス | 権限のない人が入ろうとしたときの一時停止（6 章）|
| 年齢の要件 | Google アカウントに自分ではなく事業の年数を入れた |
| Ad Grants | 非営利向けの要件違反 |

### 9-3. 回避行為（システムの回避）ポリシー ✅（P:15938075）

- 不承認の広告・ドメインの言い換え版を作る、**停止後に新しいアカウントを作る**、機能の悪用で違反コンテンツを出す、**確認プログラムに虚偽の情報**、違反広告を複数アカウントに分散、**クローキング**（Google には適合ページ、利用者には別の中身。同じドメイン内のリダイレクトや操作を妨げるポップアップでの遮断も例）
- 見つかり次第、予告なしに停止。編集基準（書式・つづり）の不承認ではこのポリシーで停止しない

### 9-4. 停止中にできること・申し立て ✅（9841640）

- 停止中は全地域で全広告が止まり、読み取り専用になる（レポート閲覧・支払い・セキュリティ設定・申し立て・解約と払い戻しの請求はできる）。**関連アカウントや新しく作ったアカウントも停止されうる** ので、既存の停止を解くのが先
- 申し立ては停止から **少なくとも 6 か月** の間に、1 アカウント 1 件ずつ。出しすぎると処理されず、**乱用で 7 日間止まる**。却下されても同じ手順で再申し立てできる
- 選ばれた広告主は適格性確認が必要（3 回失敗で申し立て不可）。請求関連の停止では支払い方法の確認（30 日以内）を求められることがある
- 復帰は誤りなどのやむを得ない事情があるときだけ。同じ本人確認書類の別アカウントの停止が原因なら、そちらが通れば自動で復帰
- 審査中は「申し立て中」と表示され、結果はメール。審査の日数は記載なし ❓

## 15. 判断の型

1. **権限を付けるとき**: 「この人は何をする必要があるか」→ 入稿・入札だけなら標準、レポートだけなら読み取り専用、経理ならお支払いとご請求。管理者は社内の 2 人以上に限る
2. **代理店と組むとき**: (a) アカウントは広告主の名義で作る、(b) 広告主側に管理者を残す、(c) オーナーを MCC に渡すかを契約で決める、(d) 終了時の手順（新しい請求設定 → リンク解除 → 共有リストと計測の付け替え）を先に書く
3. **配信が急に止まったとき（アカウント側の原因の順）**: 支払い（拒否・未払い・与信枠・アカウント予算の終了）→ 停止の通知（ポリシー・請求・不正アクセス）→ 適格性確認の期限 → MCC のリンク解除・移管 → それでもなければ 01・02 の配信の問題へ（品質が先、入札は後）
4. **知らない変更を見つけたとき**: 変更履歴の「ユーザー」列と経路を見る → 自動適用・ルール・スクリプトなら設定を見直す → 知らない人・知らない MCC なら 6-5 の手順で即報告。「現状のまま復元」は選ばない
5. **無効なクリックを疑ったとき**: 「無効なクリック」列と率 → 時間帯・地域・配信面（プレースメント、検索パートナー）の偏り → IP 除外とプレースメント除外 → 60 日以内に調査依頼 → それでも足りないときに第三者ツール
6. **ブランド セーフティ**: アカウント単位のインベントリ タイプを決める → 除外テーマ・コンテンツの除外キーワード → MCC の共有除外リスト → 必要なら第三者（DV・IAS・Zefr）
7. **停止されたとき**: 理由の種類を確かめる → 重大な違反なら申し立ての根拠を集める（新しいアカウントは作らない）→ 適格性確認と支払い方法の確認を済ませる → 1 件ずつ申し立て
8. **API・スクリプトを使うとき**: 今の段階（Cloud Console）→ 1 日の操作数で足りるか（エクスプローラーは本番 2,880）→ 古いデータは月の分割で取る
