# Google広告の基礎 23: オーディエンスとターゲティング（キャンペーンの種類をまたいだまとめ）

- 確認日: 2026-11-17（公式ヘルプ・ポリシーヘルプ・API ドキュメントを取得して確認）
- 位置づけ: 10（P-MAX）4 章、11（動画）4 章、12（DG）4 章、15（ルール表）3 章、16（ディスプレイ）3〜4 章の断片を、キャンペーンの種類をまたいで 1 本にしたもの。**細目はそちらを番号で参照し、繰り返さない**
- 使い方: 「誰に・どこに出すか」「どう絞るか」に答える前に読む。確認日から 30 日を過ぎたら出典を取り直す
- 凡例: ✅ 公式で確認 ／ △ 公式の中で食い違う ／ ❓ 公式に記載なし（確かめ方を併記）。〔推測〕＝書き手の判断、〔第三者〕＝Google 以外の主張

## 0. 先に結論

1. 「誰に出すか」は 3 系統。**自社データ**（サイト訪問者・アプリ・YouTube・顧客リスト・リードフォーム）、**Google のセグメント**（アフィニティ・購買意向・ライフイベント・詳しいユーザー属性）、**自分で作るもの**（カスタム セグメント・組み合わせ）。旧「類似セグメント」は 2023 年に終了し、DG 専用の「類似セグメント」だけが残る ✅
2. 同じセグメントでも効き方が種類で 3 通り。検索・ショッピング＝「モニタリング」（絞らず、入札の材料）、P-MAX＝「シグナル」（ヒント）、DG・動画・ディスプレイ＝「ターゲティング」（絞る）だが最適化されたターゲティングが既定オンで外に広がる ✅
3. カスタマー マッチで**絞り込むには利用 90 日以上・累計 5 万米ドル超**が要る。モニタリングと除外は誰でも使える ✅
4. 地域は「所在地やインタレスト」（既定・推奨）と「所在地」。**除外は所在地基準だけ**。判定は「最善の努力」で 100% は保証しない。日本の精度を示す数字は公式にない ✅❓
5. ユーザー属性の「不明」は既定で含まれ、外すと届くべき人まで落ちる ✅
6. P-MAX のプレースメント除外と IP 除外は**アカウント単位だけ** ✅
7. Chrome のサードパーティ Cookie は残ることになり、プライバシー サンドボックスの主要技術は 2025-10-17 に廃止発表 ✅。EEA の顧客データは同意の信号が両方ないと使えない（2024-03〜）✅

## 1. オーディエンスの全種類と元になるデータ ✅（2497941 en・ja、2453998、9066029）

日本語ヘルプは「Your data（自社データ）」を「**データ セグメント**」（旧称 リマーケティング）と書く。

| 系統 | 種類（日本語ヘルプの表記） | 元になるデータ |
|---|---|---|
| 自社データ | ウェブサイトやアプリを過去に利用したユーザー | Google タグ（または GA4 連携）のサイト訪問、アプリのデータ収集 |
| 自社データ | YouTube ユーザー | 連携したチャンネル・動画を見た・操作した人 |
| 自社データ | カスタマー マッチ | 広告主の顧客情報を Google アカウントと突き合わせたもの（3 章） |
| 自社データ | リードフォームのセグメント | Google 広告のリードフォームを送信した人 |
| 自社データ | Google 経由のオーディエンス | Google 検索・YouTube などから広告主のサイトを訪れた人。自動作成 |
| 自社データ由来 | 類似セグメント | 自社データ（シード）に似た人。DG 専用（12 の 4-2） |
| Google | アフィニティ セグメント | 生活様式・関心・習慣。Google のサービスやサードパーティのサイトでの行動、閲覧内容から推定 |
| Google | 購買意向 | 商品を調べ比較している最近の行動 |
| Google | ライフイベント | 卒業・引っ越し・結婚などの節目 |
| Google | 詳しいユーザー属性 | 長期的な事実（大学生、住宅所有者、新しい親など） |
| 自作 | カスタム セグメント | 入力したキーワード・URL・アプリ名（解釈の仕方は 16 の 3-1） |
| 自作 | 組み合わせセグメント | 上の各種を交差・和・除外で組む。詳しいユーザー属性・ライフイベント・自社データも混ぜられる |
| 終了 | 旧 類似セグメント | 2023-08 に全キャンペーンから除去。API でも対象・除外とも不可（16 の 3-1、15 の 3-64） |

- ✅ セグメントを作るデータ（閲覧履歴・過去の検索）は**入札と精度の改善にも使われうる**（2497941）
- ✅ 18 歳未満、広告のカスタマイズをオフにした人などには、セグメントに入っていても個人に合わせた広告は出ない。健康・人種・宗教などのセンシティブな情報は使わない（2497941）
- 自社データの最小人数・有効期間・溜まるまでの時間は 16 の 3-2、15 の 3-57〜58 を参照

### 2-3. 検索でオーディエンスを使う意味

- ✅ 日本語ヘルプ 7365594: スマート自動入札のキャンペーンでは、「モニタリング」で追加した**ファースト パーティ オーディエンス セグメント**がシグナルとして使われる
- ✅ スマート自動入札はデバイスの -100% 以外の入札単価調整を使わない（14 の 145）。何も足さなくても、リストに入ってからの経過時間などはシグナルに使われる（00 の 4-2）
- 〔推測〕よって自動入札の検索でオーディエンスを足す意味は「調整」ではなく、**自社データを明示的にシグナルに渡すこと**と**レポートで差を見えるようにすること**。手動入札なら調整（-90%〜+900%）、RLSA の絞り込みならターゲティング
- △ **アフィニティを検索に足せるか**: 2497941 の対応表は「○」。API には `CANNOT_ADD_USER_INTERESTS_TO_SEARCH_CAMPAIGNS`（検索のみのキャンペーンにユーザーの興味・関心を足せない）がある（15 の 3-28）
- △ **組み合わせセグメント**: 9066030 は「ディスプレイと検索を含めて使える」、API はディスプレイを許可制、DG は不可 ✅（17051545 の機能表に「Not supported in Demand Gen」。9066030 は DG に触れていないだけで、DG については食い違いなし）。〔第三者〕Jyll Saskin Gales のポッドキャスト（2024 年ごろ、要約のみ）は動画で使えなくなったと言う

## 3. カスタマー マッチ

### 3-1. 利用要件 ✅（adspolicy 6299717）

| 機能 | ポリシーを守る全アカウント | 利用 90 日以上・累計 5 万米ドル超 |
|---|---|---|
| ターゲティング／個別の入札単価調整 | × | ○ |
| モニタリング／除外 | ○ | ○ |

- 前提はポリシー遵守と支払いの実績が良好なこと。ドル以外は月平均レートで換算
- 〔推測〕1 ドル 150 円で約 750 万円。**少額アカウントは実質「モニタリングと除外だけ」**

### 3-2. アップロードできる項目 ✅（7659867、7474263）

- 列: Email、Phone（E.164）、First Name、Last Name、Country（ISO 2 文字）、Zip、User IP address、User interaction timestamp。**Mobile Device ID は単独のファイル**。住所での一致は姓・名・国・郵便番号の 4 列がそろったときだけ
- 形式・ハッシュの細目は 11 章（23-11〜23-16）。新しい連携には **Data Manager（データ マネージャー）** を勧めている
- 照合は最大 48 時間。一致しなかった行はポリシー確認以外に使われない

### 3-3. 一致率・最小人数・有効期間 ✅

| 項目 | 中身 | 出典 |
|---|---|---|
| 一致率 | API のアップロードは、一致した一意のユーザー 100 人以上で表示。API の `user_list.match_rate_percentage` | 7659867、手元の API 項目一覧 |
| 一致率の目安 | ❓ 公式に数字なし | 1,000 行程度を上げ 2 日後に見る |
| 最小人数 | 2024-02-01 以降に更新したリストは 100 人（以前は 1,000 人） | 16 の 3-2 |
| 有効期間 | 最大 540 日。540 日以内に 100 人以上の追加・更新がないと有効でなくなる | 6379332、6299717 |
| 配信面 | 検索、ショッピング タブ、YouTube、Gmail、ディスプレイ。第三者配信のクリエイティブ不可 | 6379332 |

### 3-4. 同意 ✅（14546648、6299717）

- 自社がファースト パーティの文脈で直接集めたデータだけ。プライバシー ポリシーに第三者への共有を書く。法令と EU ユーザーの同意ポリシーに沿って同意を取る
- **EEA は 2024-03 から `ad_user_data` と `ad_personalization` が両方 GRANTED** でないと処理されない。欠けていれば「同意なし」。手動アップロードは確認のチェック欄に印を付ける
- EEA・英国・スイス: 2024-03 上旬から第三者の面（Google パートナーの枠・第三者の取引所）では使えない。Google 自身の面では引き続き使える（6379332）。✅ IP とタイムスタンプでの一致は EEA・英国・スイスで不可（ポリシー 6299717 英語版「Ads doesn't support IP and timestamp matching in the EEA, UK, or Switzerland」。2026-11-17 確認。6379332 には記載なし）
- 〔第三者〕API フォーラムの開発者の投稿: 除外だけの用途でも両方 GRANTED が要る（公式文書ではない）
- 禁止: 13 歳未満のデータ、地域と組み合わせた少数への絞り込み、センシティブな商材、個人情報を知っていると匂わせる広告

### 3-5. 自動入札での扱い ✅△（6379332）

- スマート自動入札・最適化されたターゲティングのキャンペーンは、**アカウント内の全カスタマー マッチのリストを自動で取り込み**、効くリストを学ぶ。対象設定は変わらない。オプトアウトか個別に外せる。手動入札では使われない
- △ 同じページが「YouTube と動画アクションで提供中、インフィードと検索は近日」とも書く。〔2026-11-17 取り直し〕英語版も同じ書き方で、**いま自動取り込みが効くのは YouTube と動画アクションのキャンペーン**と読むのが本文に沿う。検索はまだ「近日」
- P-MAX ではシグナルと「データの除外」に使える（10 の 4-1）

## 4. リマーケティング

- 〔推測〕両方作ると同じ人が 2 本に入る。どちらを正にするか決めて寄せる

### 4-2. 除外としての使い方・既存客を除く

- ✅ 除外できるのは**自社データとカスタム セグメントだけ**（2453998）
- ✅ 検索: 購入者リスト・カスタマー マッチを除外に入れる（カスタマー マッチの除外は 5 万ドル条件なし）
- ✅ P-MAX: 「データの除外」か、新規顧客の獲得で「新規顧客にのみ入札」（10 の 2-2・4-1）。DG も新規顧客の獲得あり（12 の 4-4）
- ✅ DG・動画では、顧客データで除外した人に最適化されたターゲティングも出さない（10537509）。ディスプレイは記載なし ❓（16 の 3-7）
- ✅ 除外用のリストを「含める」目的で使ってはいけない（16 の 3-1）
- 〔推測〕除外リストは長め（購入者 540 日）、含めるリストは短めにすると抜けが減る

## 5. 地域

### 5-1. 所在地と関心 ✅（1722038 ja、1722043、API location-targeting）

| 設定（日本語ヘルプ） | API | 中身・使える種類 |
|---|---|---|
| 所在地やインタレスト（既定・推奨） | PRESENCE_OR_INTEREST | いる人・よく訪れる人＋関心を示した人。検索と DG で推奨 |
| 所在地 | PRESENCE | いる人・よく訪れる人だけ。ホテルはこれだけ |
| 検索インタレスト | SEARCH_INTEREST | △ 下記 |
| 除外: 所在地（既定） | PRESENCE（除外） | 除外地域にいそうな人を外す |
| 除外: 所在地やインタレスト | PRESENCE_OR_INTEREST（除外） | 検索・ディスプレイ・P-MAX・ショッピングでは不可 |

- △ 検索インタレスト: 日本語ヘルプは「検索・ディスプレイ・ショッピングで選べなくなった」、API ガイドは「検索と標準ショッピングだけで使える」（14 の 232 は API 側）
- ✅ 公式は「所在地」を、センシティブな業種や、その地域の人だけに出したいときに勧める。切り替えると表示が減る（04 の 8 章）
- ✅ AI Max の「関心対象地域」は広告グループ単位の別機能。キャンペーンで除外した地域は使えない（1722043）

### 5-2. 判定の仕組みと精度 ✅（2453995、1722043）

- 物理的な所在地: IP アドレス（Wi-Fi の IP、**携帯通信会社のプロキシ IP** を含む）。設定により端末の位置（GPS、Wi-Fi、Bluetooth、基地局 ID）
- 関心: 検索語句の地名、過去の検索・所在地、閲覧中のサイトの内容、Google マップの検索。ディスプレイはページの文脈から推定
- 近くの関係の深い地域にも出ることがある。**最善の努力で 100% は保証しない**。ごく狭い範囲は断続的にしか出ないことがある
- **日本の判定精度を数字で示した公式資料は見つからない** ❓。アド マネージャーのヘルプ（ja、要約）は、IP で都市が分からないとき都市は「該当なし」になると書く
- 〔推測〕位置の許可がないスマートフォンは携帯通信会社のプロキシ IP で判定され、市区町村がずれる可能性がある。狭い商圏は地域レポートで外への配信を確かめる

### 5-3. 指定方法・除外・入札

| 方法 | 中身 | 印・出典 |
|---|---|---|
| 国・都道府県など | 種類は国で違う。日本の例で公式に載るのは**都道府県** | ✅ 1722075 |
| 市区町村・郵便番号（日本） | 公式一覧に例なし | ❓ 地域検索で「渋谷区」「150-0001」を試す |
| 半径 | **最小 1 km**、キャンペーン単位、含めるだけ。上限は ❓ | ✅ 1722043、API |
| 地域のまとまり | 主要な場所（空港・大学など）、住所アセット、段階別のユーザー属性。半径は決まった刻み | ✅ 1722043（要約）、API、15 の 3-35 |
| 住所アセットの周りの半径 | 住所アセットが**すべて米国**のときと書かれる | ✅ 2404184（日本は ❓） |
| DG | 新しいターゲティングでは広告グループ単位 | ✅△ 12 の 4-1 |

- ✅ 含める地域と重なれば**除外が優先**。含めていない地域は除外不要（1722040）
- ✅ 地域の入札単価調整はキャンペーン単位、重なれば**いちばん狭い地域の値**だけ。スマート自動入札では無視、P-MAX には調整がない（14 の 135・140・145、10 の 4-1）

## 6. 言語・デバイス・スケジュール・ユーザー属性

### 6-1. 言語・デバイス・スケジュール（細目は 14）

| 項目 | 範囲と注意 | 出典 |

### 6-2. ユーザー属性 ✅（2580383）

- 区分: 年齢（18-24〜65+、不明）、性別（女性・男性・不明）、子供の有無（あり・なし・不明）、世帯収入（上位 10%〜下位 50%、不明。日本は対象国）
- 推定: ログイン中の人は Google アカウントの設定。ほかは Google のサービスやディスプレイ ネットワークでの行動から Cookie・端末 ID で推定。Google 以外のサイトでは主にサードパーティの行動から。**iOS で ATT の同意がない人はサードパーティの行動による推定から外れる**
- 「すべての人の属性は分からない」と公式が明記。組み合わせるほど狭くなる
- **「不明」は既定で含む**。属性を拒むディスプレイのサイトに届くためにも残し、「狭くしたい確信があるときだけ外す」
- 13 歳未満だけ・18 歳未満だけは対象にできない。全区分の除外、「不明」だけ残すのも不可（15 の 3-55）
- △ 「ターゲティング」か「常にモニタリング扱い」かはヘルプと API で書き方が違う（15 の 3-56）
- DG は属性の外にも広がる（12 の 4-3）。動画のフリークエンシー目標設定は世帯収入・子供の有無が外れることがある（11 の 4-4）

| 検索のオーディエンス | モニタリングは配信を変えない | 費用ゼロの観察なので最初から入れる。差が意味を持つまで時間がかかる |
| 最適化されたターゲティング | 既定オン | CV が月数件なら何が効いたか分からなくなる。既存客向けはオフ、新規開拓だけオン |
| 地域 | 狭い範囲は断続的にしか出ない | 地域限定の商売は「所在地」。半径は 1 km 近くまで狭めず、数 km か市区町村から |
| ユーザー属性 | 組み合わせるほど狭い | 絞らずレポートで見て、明らかな対象外だけ除外 |
| 変更 | ターゲティングの変更は学習の引き金にならない（00 の 3-1） | 配信量は急に変わるので 1 つずつ（04 の 11 章の順） |

## 14. 判断の型

### 14-1. 決める順番

1. 種類で効き方を確かめる（検索・ショッピング＝観察とシグナル、P-MAX＝ヒント、DG・動画・ディスプレイ＝絞り込み＋拡張）
2. 既存客を入れるか外すか（新規獲得なら購入者・カスタマー マッチを除外、P-MAX は新規顧客の獲得）
3. 地域（店舗・訪問型は「所在地」、ネット完結は既定のまま）
4. 属性（法律・商材の事情で出せない層だけ除外、「不明」は残す）
5. 自動の拡張（最適化されたターゲティング・属性の拡張・類似の提案モード）を広告グループごとに決める
6. 除外の置き場所をアカウント単位（プレースメント・IP・適合性）とキャンペーン単位に分けて管理する

### 14-2. 広げるか絞るか〔推測。根拠は 9 章〕

| 状況 | 判断 |
|---|---|
| CV が十分にあり計測が整っている | 広く（既定の地域、最適化されたターゲティングをオン、P-MAX のシグナルは出発点だけ） |
| CV が月数件、計測を整えている途中 | モニタリングで差を見る、最適化されたターゲティングはオフで始める |
| 既存客向け（会員、リピート） | 絞る（拡張をオフ、自社データでターゲティング） |
| 地域限定・センシティブな業種 | 「所在地」、地域レポートで外への配信を確かめる。属性・カスタマー マッチの禁止事項を先に確認 |

### 14-3. 数字が悪いときの確認順

1. 地域レポートで対象外の地域への配信（「所在地やインタレスト」の影響）
2. オーディエンス レポートの「合計: ターゲティングの拡大と最適化されたターゲティング」行の比率
3. ユーザー属性レポートの「不明」と除外した区分
4. 「広告が表示された場所」レポートの偏り（16 の 8-1）
5. 除外リストの人数
