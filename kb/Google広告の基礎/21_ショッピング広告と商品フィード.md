# 21 ショッピング広告と商品フィード（Merchant Center）

- 確認日: 2026-11-17（Google 広告ヘルプ、Merchant Center ヘルプ、Google 公式ブログ、Google 開発者向けページを取得して確認。手元の API フィールド一覧 v25〔2026-11-10〕も参照）
- 使い方: ショッピング広告・商品フィード・Merchant Center について答える前にこのメモを読む。P-MAX 全体は 10、入札の種類は 02 と 14、AI Max（検索）は 03 と `../Google_AI最大化設定（AI Max）.md`、AI モードの広告は 13 の 5 章を参照し、ここでは繰り返さない
- 凡例: ✅ 公式で確認 ／ △ 公式の中で記述が食い違う ／ ❓ 公式に記載なし（確かめ方を併記）／〔第三者〕報道・ベンダーの主張 ／〔推測〕筆者の推測
- 用語: **フィード**＝商品の一覧データ（Merchant Center では「データソース」と呼ぶ）。**属性**＝フィードの列（タイトル・価格など）。**商品グループ**＝標準ショッピングで入札の単位になる商品のまとまり（P-MAX では「リスティング グループ」）

## 1. 仕組みの全体像

### 1-1. Merchant Center と Google 広告の役割分担 ✅

| 場所 | 持つもの | 運用者が決めること |
|---|---|---|
| Merchant Center | 商品データ（データソース）、配送・返品の設定、ビジネス情報、審査の結果 | どの商品を、どの属性で、どの国・言語で出すか。属性の中身そのもの |
| Google 広告 | キャンペーン、予算、入札、商品グループ（リスティング グループ）、除外キーワード | どの商品にいくら払うか、どの検索で出さないか |
| 両者の連結 | Merchant Center 1 つに Google 広告アカウント 500 まで（14 の 182） | 連結しないと商品を選べない |

- 標準ショッピングは、作成時に Merchant Center ID が必須で、**作成後に変えられない**。優先度（0〜2）も必須（14 の 258。API の `Campaign.ShoppingSetting.merchant_id`、`campaign_priority`）
- フィード ラベル（`feed_label`）で、同じ Merchant Center のどの商品群を使うかを選ぶ。20 文字まで、旧「販売国」の欄の後継（14 の 260）

出典: support.google.com/google-ads/answer/2454022、6372658／API フィールド一覧 v25

### 1-2. 商品データが広告になるまで ✅（流れは公式の記述を筆者が並べ直した）

| 段階 | 起きること | ここで止まる原因 |
|---|---|---|
| 1. 登録 | ファイル、スプレッドシート、定期取得、Merchant API、サイトの構造化データなどで商品を送る | 必須属性の欠け、形式エラー |
| 2. 審査 | 商品ごとに方針と仕様を確認。ランディング ページも巡回して価格・在庫を照合 | 不承認（商品単位）、アカウントの停止（アカウント単位） |
| 3. 有効な商品 | 無料リスティングと広告の両方で使える状態になる | 30 日更新しないと失効（3-5） |
| 4. キャンペーンに載る | 標準ショッピングの商品グループ、または P-MAX のリスティング グループで対象に入る | 商品グループで除外、フィード ラベルが合わない |
| 5. オークション | 検索語句と商品データの関連で候補になり、広告ランクで並ぶ | 入札・予算・品質（01 を参照） |

### 1-3. キーワードが無い中で何が検索と商品を結びつけるか ✅

- 公式は「キーワードではなく、Merchant Center の既存の商品データ」で、いつどこに出すかを決めると書く。属性（自分で定義したものを含む）と検索語句を照合する
- さらに**着地ページの内容、画像、フィード、その他のシグナル（AI が生成した内容を含む）**で広告を補うことがある。この補完をやめたいときは、**担当者か Google に連絡して申し出る（通常 3〜5 営業日）**。管理画面のスイッチではない（2454022、英語版）
- タイトルについても「着地ページの内容などを使って、検索に合うように調整することがある」と Merchant Center 側に書かれている（6324415）
- 運用者が直接いじれるのは、(1) フィードの中身（どの言葉がタイトル・説明・商品タイプにあるか）と、(2) 除外キーワード（出したくない検索を外す）だけ。「この語句で出す」という指定はない
- 〔推測〕だから「フィードの言葉＝事実上のキーワード」になる。タイトルに無い言葉の検索には出にくい、と考えて設計する（6 章）

### 1-4. 標準ショッピングと P-MAX（フィードあり）✅

| 項目 | 標準ショッピング | P-MAX（フィードあり） |
|---|---|---|
| 配信面 | ショッピング タブ、検索結果の横（テキスト広告とは別枠）、Google 画像検索、検索パートナー（任意） | ショッピング タブ、検索、画像、ディスプレイ、YouTube、Gmail、デマンド ジェネレーション、マップ（ローカル在庫広告） |
| 入札 | 目標広告費用対効果、クリック数の最大化、コンバージョン値の最大化、個別クリック単価（手動）※ヘルプと API の差は 14 の注5 | コンバージョン値の最大化（目標 ROAS 任意）、コンバージョン数の最大化（目標 CPA 任意）。手動は無い |
| 課金 | クリック単価 | 成果（クリックや CPM など） |
| 商品の絞り込み | 商品グループ（7 階層、5-1） | リスティング グループ（アセット グループあたり 1,000、10 を参照） |
| 検索語句の除外 | 除外キーワード | 除外キーワード（検索・ショッピング面だけ。10 の 4-1） |
| 細かい入札の調整 | 商品グループごとの入札、優先度、デバイス等の調整 | 無い（目標値と、商品の切り分けだけ） |

- **同じ商品を両方で出したとき**: 2024-10-23 以降、P-MAX が自動で優先される仕組みは廃止され、**広告ランクの高い方が出る**（15535462。10 の 3-2 と同じ）
- **キャンペーンの優先度は標準ショッピング同士の話**。優先度の記事（6275296）は P-MAX との関係を書いていない ❓ → 確かめ方: 同じ商品を P-MAX と優先度「高」の標準ショッピングに入れ、オークション分析と商品別の表示回数を比べる
- スマート ショッピングは新規作成できない（14 の 221）。比較ショッピング サービス（CSS）に連結した標準ショッピングは一部のネットワークを選べない（14 の 228）

出典: 2454022、15535462、6275296

### 1-5. 無料リスティング ✅

| 項目 | 内容 |
|---|---|
| 出る場所 | ショッピング タブ、Google 検索（リッチリザルト、人気の商品、ショッピングのナレッジパネル）、Google 画像・Lens、YouTube、マップ、**Gemini**、ビジネス プロフィールの商品欄 |
| 日本で出る場所 | ショッピングのナレッジパネルは日本を含む 11 か国。「人気の商品」（衣料）は米国のモバイルだけ |
| 既定 | ほとんどのアカウント（新規はすべて）で**オン** |
| 必須 | 返品ポリシー（Merchant Center で設定を推奨）、配送の設定（**日本は必須の国**）、id・タイトル・リンク・画像・価格・説明・在庫・ブランド、GTIN（無ければ MPN）。衣料は色・サイズ・年齢層・性別 |
| オフにしたとき | 完全には止まらない。サイトから巡回で取られた内容は出ることがある（止めるのはクロールとインデックスの制御） |
| 広告との関係 | 併用。ショッピング タブの広告枠には広告が出続ける |

## 2. 商品データの仕様（主な属性）✅

出典はすべて Merchant Center の商品データ仕様（support.google.com/merchants/answer/7052112、英語版、2026-11-17 取得）。属性名は英語のまま（フィードの列名はこの綴り）。

### 2-1. 基本と画像

| 属性 | 必須度 | 上限・形式 | 注意 |
|---|---|---|---|
| `id` | 必須 | 50 字。一意 | **更新しても変えない**。変えると別商品扱いで学習・実績が切れる〔推測〕 |
| `title`／`structured_title` | 必須 | 150 字 | AI で作ったタイトルは `structured_title` に入れ、`digital_source_type` を `trained_algorithmic_media` にする |
| `description`／`structured_description` | 必須 | 5,000 字 | 同上 |
| `image_link` | 必須 | **最小 500×500 px（2027-01-31 から適用）**。JPEG・WebP・PNG・静止 GIF・BMP・TIFF | 販促の文字、透かし、枠、仮画像、引き伸ばした画像は不可 |
| `additional_image_link` | 任意 | 10 枚、各 2,000 字 | 使用場面の写真・イラストも可 |
| `lifestyle_image_link` | 任意 | 2,000 字 | 「眺める」面（browsy surfaces）だけで使う。AI 生成画像は IPTC の DigitalSourceType を消さない |
| `video_link` | 任意 | 6〜240 秒、500MB 以下、9:16・16:9・1:1、720p 以上 | YouTube 以外は動画ファイルそのものの URL |

### 2-2. 価格と在庫

| 属性 | 必須度 | ルール |
|---|---|---|
| `price` | 必須 | 数値＋ISO 4217 通貨（例 `1980 JPY`）。小数は 2 桁まで。0 は不可（契約付き携帯などを除く）。**米国・カナダは税抜、それ以外（日本を含む）は付加価値税・消費税込み** |
| `sale_price` | 任意 | 通常の `price` と一緒に送る。期間は `sale_price_effective_date`（51 字、開始＜終了） |
| `availability` | 必須 | `in_stock`／`out_of_stock`／`preorder`／`backorder` |
| `availability_date` | 予約・取り寄せで必須 | ISO 8601、1 年先まで |
| `loyalty_program` | 任意 | 会員価格はここ（`price`・`sale_price` に入れない）。**日本を含む 9 か国** |

価格の追加ルール（6324371）:
- 着地ページ・購入手続きの価格と一致させる。**訪問者の IP で価格を変えるのは不可**（地域価格は地域別の仕組みで）
- 送料は価格に入れない（送料の設定で）。最低注文金額も価格ではなく配送の設定で
- 誰でも使える割引・クーポンで、着地ページにその価格がはっきり出ているなら `price` に含めてよい

### 2-3. 分類と識別子

| 属性 | 必須度 | ルール |
|---|---|---|
| `brand` | 新品は必須（映画・書籍・音楽を除く） | 70 字 |
| `gtin` | **強く推奨** | 8・12・13・14 桁（UPC・EAN・JAN・ISBN・ITF-14。JAN は 8 か 13 桁）。GS1 の検査を通ること。GS1 の「制限された範囲」の接頭辞 **02・04・2** と、クーポンの範囲の接頭辞 **05・98・99** で始まる GTIN は送らない（ヘルプはこの書き方だけで、桁数ごとの読み方〔例: 13 桁の「2」が 20〜29 を指すか〕は書いていない）。確かなときだけ送る |
| `mpn` | GTIN が無いときだけ必須 | 70 字 |
| `identifier_exists` | 任意 | 既定 `yes`。GTIN・MPN・ブランドのどれも当てはまらないときだけ `no` |
| `google_product_category` | 任意 | ID か完全なパスのどちらか 1 つ（ID 推奨）。携帯電話 267、時計 201、タブレット 4745、ギフトカード 53 などは指定が必須 |
| `product_type` | 任意 | 750 字。**Google 広告の入札とレポートに使われるのは最初の値だけ** |
| `item_group_id` | バリエーションで必須（日本を含む 6 か国） | 50 字 |
| `condition` | 中古・再生品で必須 | `new`／`refurbished`／`used` |
| `age_group`・`gender`・`color`・`size` | 衣料で必須（日本を含む 6 か国） | `color` は計 100 字、1 色 40 字、数字や色コードは不可 |

### 2-4. 広告と配信先の制御

| 属性 | 上限 | ルール |
|---|---|---|
| `custom_label_0`〜`4` | 各 100 字 | 5 本まで。**1 本のラベルにつきアカウント全体で異なる値は 1,000 種類まで** |
| `promotion_id` | 50 字、1 商品 10 個 | 一部の国で販促に必須（日本は一覧に無い） |
| `short_title` | 150 字（推奨 5〜65） | デマンド ジェネレーションだけで使う |
| `excluded_destination`／`included_destination` | — | 両方あると除外が勝つ |
| `pause` | `ads` か `all` | **14 日以内**の一時停止用。それ以上は不承認。在庫（`availability`）で止めない |

### 2-5. 配送（日本は必須）

| 属性 | ルール |
|---|---|
| `shipping` | **日本を含む一覧の国ではショッピング広告と無料リスティングで必須**（アカウントの配送設定か、この属性）。行政が課す料金は含めない |
| `shipping_label` | 100 字。アカウントの配送設定と結びつける |
| `shipping_weight`・寸法 | 運送会社の料金計算を使うときに必須 |

### 2-6. AI・会話型の買い物向けの属性（任意）

| 属性 | 上限 | 用途 |
|---|---|---|
| `product_highlight` | 2〜100 個、各 150 字 | 箇条書きの特長 |
| `product_detail` | 100 個。節名・属性名 140 字、値 1,000 字 | 仕様表 |
| `question_and_answer` | 30 組、計 10,000 字、問い・答え各 1,000 字 | よくある質問。主に AI モード向け。価格・日付など時間で変わる情報は入れない |
| `related_product` | 30 個 | 関係の種類: セットの一部、必須部品、よく一緒に買われる、代替品、別ブランド、付属品 |

- 会話型属性（conversational attributes）は 6 つ: `question_and_answer`、`document_link`、`related_product`、`item_group_title`、`variant_option`、`popularity_rank`。**任意で、入れても既存商品の承認には影響しない**。補助データソースで足すのが推奨。説明文・`product_highlight`・`product_detail` と重複させない（17085370）
- 提供: 2026-01-11 に「少数の小売から」と発表 → **2026-05-20 に「全世界の小売で利用可能」**（blog.google）
- ❓ これらが**広告**の配信・掲載順位に効くかは公式に記載なし（「AI モードなど AI の面で見つけてもらいやすくする」とだけ）→ 確かめ方: 補助データソースで一部商品だけに入れ、ショッピング広告の表示回数・クリック率を対照の商品と比べる

## 3. フィードの作り方と管理

### 3-1. データソースの種類 ✅

| 種類 | 役割 | 注意 |
|---|---|---|
| メイン（primary）データソース | 商品そのものを登録する | ファイル、Google スプレッドシート、定期取得、API |
| 補助データソース（supplemental） | 既存商品の属性を足す・上書きする | **「高度なデータソース管理」アドオンが必要**（設定 > アドオン）。カスタムラベルや会話型属性を後から足すのに向く |
| 属性ルール（旧 フィードのルール） | 取り込み時に属性を変換・組み立てる | 同じアドオンが必要。2023〜24 年に「フィードのルール」から改名 |
| ローカル在庫・地域在庫・販促・商品レビュー・店舗レビュー | それぞれ別のデータソース | Merchant API で種類ごとに作れる |

- ✅ アドオン「高度なデータソース管理」で使えるのは、属性ルール、補助データソース、インスタント プレビュー、ステージング（14989391、日本語版で名称確認）
- ❓ 補助データソースで**新しい商品を追加できない**こと、結びつけの鍵（id＋フィード ラベル＋言語か）は、今回取得したページに記載なし → 確かめ方: merchants/answer/15157604 などの補助データソースの記事を取得する。〔推測〕従来どおり既存商品の上書き専用

出典: 14994083（属性ルール）、14989391、developers.google.com/merchant/api/guides/compatibility/overview

### 3-2. 自動改善（自動化タブの自動更新）✅

| 項目 | 内容 |
|---|---|
| 対象 | 価格、セール価格、在庫、状態（新品・中古など）。組み合わせて選べる |
| 既定 | **オン**。商品 > 自動化（Automations）タブで個別にオフ |
| 材料 | 着地ページの構造化データ（schema.org）を推奨。無ければ Google の抽出器で読むが、全ドメインには効かない |
| 効かない場合 | 1 日に何度も価格・在庫が変わる商品。不一致が多すぎると Google が更新をやめる。二重取り消し線の価格が複数ある |
| ゆるい照合 | `preorder`・`backorder` は `in_stock` と一致とみなし、値は `in_stock` のまま |
| 位置づけ | 「散発的な問題を直すもの」で、定期更新の代わりではない。読めなければ商品単位の不承認 |

出典: support.google.com/merchants/answer/3246284（英語版・日本語版）

| 警告期間 | 多くの違反は **7 日か 28 日**の警告メールが先に来る。期間中にいつでも 1 回の「お試しの審査」（courtesy review）を依頼でき、期間の終わりに最終審査 |

### 5-2. キャンペーンの優先度 ✅

日本語名「キャンペーンの優先順位」。低・中・高（既定は低）。API では 0〜2。
- 同じ国で**同じ商品**を複数の標準ショッピングが出しているときだけ効く
- 優先度の高いキャンペーンの入札が使われる（優先度の低い側の入札が高くても）
- その予算を使い切ると次の優先度へ。同じ優先度なら入札の高い方
- 予算は 1 日に分散して使われるので、**高優先度が後半のために予算を残して入札しないことがある** → その回は低優先度が入る
- 公式のヒント: セール品など一部の商品だけに絞って高優先度にする（商品フィルタ）

出典: 6275296（英語版・日本語版）

### 5-3. 除外キーワードと「優先度×除外」の段階分け
- 除外キーワードは標準ショッピングで使える（アカウント単位の除外キーワード 1,000 個も効く。04 の表）
- ❓ 「優先度 高＝除外を多く入れて汎用語を拾う／低＝ブランド・型番だけ残す」といった段階分け（いわゆるクエリ スカルプティング）は、**公式ヘルプには書かれていない**。優先度の記事も除外キーワードに触れていない → 第三者の実務手法として扱う。〔推測〕仕組み上は「高優先度側で除外した検索は、低優先度側の入札で取る」ことになるので成立するが、スマート自動入札と組み合わせると各キャンペーンの学習データが薄くなる（02 の学習量の条件を参照）

### 5-4. 入札
- 使える入札: 目標広告費用対効果、クリック数の最大化、コンバージョン値の最大化、個別クリック単価（2454022）。ヘルプと API の食い違いは 14 の注5
- 目標広告費用対効果の開始条件は過去 30 日で 15 件以上（02、14 の 36）

## 6. フィードの最適化

### 6-1. タイトル ✅（要件は公式、型は筆者）
- 公式の要件: 1〜150 字。**最初の 70 字以下しか目に入らないことが多い**ので重要な情報を先頭に。ブランドは差別化になるときに入れる。サイズ・色などバリエーションの違いはタイトルにも専用属性にも入れる。全部大文字・記号・HTML・装飾は不可。**価格・セール日・送料・配送日・社名などの販促文言は入れない**（6324415）
- 公式は「ブランド＋商品の種類＋属性」のような順番は**決めていない**。以下は筆者の型

| 商材 | 型の例（筆者） |
|---|---|
| 型番で探される家電・部品 | ブランド＋商品名＋型番＋主要仕様 |
| ブランドが知られていない商品 | 商品の種類＋用途・悩み＋主要仕様（ブランドは後ろ） |

- 〔推測〕日本語の検索は「商品の一般名詞＋特徴」が多い。社内の商品名（愛称）を先頭にすると、1-3 の照合で一般名詞の検索に出にくくなる
- AI で書き換えたタイトルは `structured_title` で申告する（2-1）。AI Max for Shopping のテキストのカスタマイズはタイトルを書き換えるが、英語フィードだけ（8 章）

### 6-2. 商品タイプとカスタムラベルの設計（筆者の型。仕様の数字は公式）

| 用途 | 入れる属性 | 公式の制約 |
|---|---|---|
| サイトの分類そのまま | `product_type`（「メンズ > トップス > T シャツ」） | 入札・レポートは**最初の 1 つ**だけ。5 段まで |
| 成果での区分け | `custom_label_0` に「主力／普通／不振／新規」など | 1 本 1,000 種類まで。動的に変える値は補助データソースで |
| 利益率 | `custom_label_1` に「粗利 高・中・低」 | 原価が出せるなら `cost_of_goods_sold` |

### 6-3. 商品単位の成果の見方と監査 ✅〔要素〕／〔推測〕〔型〕
- 見られる場所: Google 広告の商品（ショッピング）レポート、API の `shopping_performance_view`（商品属性別の成果）と `shopping_product`（状態・問題）。商品グループを作らなくても、絞り込みで任意の粒度の成果を見られる（2454022）
- 〔推測〕成果での区分けの型（実務でよく使われる考え方を筆者が整理。公式の推奨ではない）

| 区分 | 目安 → 打ち手 |
|---|---|
| 主力 | 費用・売上が大きく目標を満たす → 予算と在庫を守る |
| 伸びしろ | 表示は少ないが CVR・ROAS が良い → タイトル・画像・価格、入札を上げる |
| 浪費 | クリックが多く CV が無い → 検索語句を除外、タイトルの誤解を確認、最後に除外 |
| 眠っている | 表示がほぼ無い → 不承認・属性の欠け・価格を確認 |

- 判断に必要なクリック数の目安は公式に無い ❓ 〔推測〕少量の商品は 1 商品ずつでなく商品タイプ単位にまとめて判断する（9 章）

### 6-4. 画像
- 要件は 2-1。追加画像は 10 枚まで。〔推測〕メイン画像は白背景の商品単体、追加画像・`lifestyle_image_link` で使用場面、の分担

## 12. 少額・少量のアカウントでの注意
- 目標 ROAS は過去 30 日 15 件から（02）。それ未満は個別クリック単価かクリック数の最大化で始め、商品グループは**商品タイプ単位の粗い分け**に留める〔推測〕
- AI Max for Shopping の FUE は目標 ROAS 必須なので、少量では実質使えない（17091277 からの推測）
- 優先度を使った段階分けや商品単位の分割は、各キャンペーンの学習データを薄くする〔推測〕
- まず無料リスティング・不承認ゼロ・価格一致で「出る状態」を作る。費用をかける前にできる（1-5、4 章）
- カスタムラベルの値を増やしすぎない（1,000 種類の上限より、判断できる数が先に尽きる）〔推測〕

## 13. 判断の型
1. **出ていない**: 要対応タブ（商品）→ アカウントの問題 → 配送・返品の設定 → 商品グループの除外 → 入札・予算 の順に見る（品質が先、入札は後）
2. **標準か P-MAX か**: 商品単位の入札・除外を細かく制御したい、計測が薄い → 標準。チャネルをまたいで価値を最大化、CV が十分 → P-MAX。比べるなら PMAX_REPLACEMENT_SHOPPING のテスト（10、14 の 205）
3. **フィードを直す順番**: 不承認 → 価格・在庫の一致 → GTIN・ブランド → タイトルの先頭 70 字 → 商品タイプ・カスタムラベル → 画像 → 会話型属性
4. **AI Max for Shopping**: 日本語フィードなら効果の中心（テキストのカスタマイズ）が使えない前提で、表示されるかの確認だけ先にする
