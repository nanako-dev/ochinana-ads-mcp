## 3. Google が LP を読むクローラー

### 3-1. 種類と役割

| 名前 | 区分 | 役割（公式の説明） | robots.txt | 判定 |
|---|---|---|---|---|
| AdsBot-Google | 特別なクローラー | Google 広告が、パソコン向けページの広告品質を確認する | 全体指定（`*`）を**無視する**。止めるには名指しが必要 | ✅ |
| AdsBot-Google-Mobile | 特別なクローラー | 同じく、モバイル向けページの広告品質を確認する。名乗りは Android 版 Chrome の形 | 同上 | ✅ |
| Googlebot | 共通クローラー | Google 検索。DSA のヘルプは、クロールの問題で不承認になったら Googlebot と AdsBot-Google の両方を通すよう書いている | `*` に従う | ✅ |
| Google-InspectionTool | 共通クローラー | Search Console の URL 検査、リッチリザルト テストなど**検索のテストツール用**。Google 検索やほかのプロダクトには影響しない | Googlebot の指定にも従う | ✅ |
| GoogleOther | 共通クローラー | 特定のプロダクトに結びつかない汎用。社内の研究開発などで使うことがある | 名指しで制御 | ✅ |
| Mediapartners-Google | 特別なクローラー | AdSense・アド マネージャー用。Google 広告の LP 確認とは別 | `*` を無視 | ✅ |
| AdsBot-Google-Mobile（iPhone 版）、AdsBot-Google-Mobile-Apps | 廃止済み | 記録として残っているだけ | — | ✅ |

- 特別なクローラーは、共通クローラーとは別の IP 範囲から来る（`special-crawlers.json` で公開）。逆引きの形は `rate-limited-proxy-***.google.com` ✅
- AdsBot はアメリカから来ることが多い（広告ポリシー 16428223）✅。クローラー全般の説明では、Google のクローラーは主にアメリカの IP から来て、アメリカからの接続が遮断されていると分かれば、ほかの国の IP から試すことがある（overview-google-crawlers）✅。この説明は特別なクローラーを名指ししていない。AdsBot が日本の IP から来る場面があるかは ❓
- リンク先の要件（ポリシー 6368661）は英語版と日本語版で項目の中身が違う。どちらにも「クロールできないリンク先／Destination not crawlable」の項目がある。そのうえで日本語版は「アクセスできないリンク先」にも「Google AdsBot がランディング ページをクロールできない」（AdsBot に 404・403 を返す、robots.txt で止める、サーバー側で拒否する）を含める。英語版の Destination not accessible は「対象地域でアクセスできない」だけで、AdsBot には触れない ✅（2026-11-17 に両方を取得して確認）
- 名乗り（ユーザー エージェント）は偽装できるので、本物かどうかは IP で確かめる ✅

### 3-2. JavaScript を実行して、描画後の内容を読むか

| 対象 | 分かっていること | 判定 |
|---|---|---|
| Google 検索（Googlebot） | 常に新しい Chromium で JavaScript を実行し、描画後の HTML をインデックスに使う。描画は待ち行列に入るので、取得より遅れることがある | ✅ |
| AdsBot（Google 広告） | **JavaScript を実行するかどうか、描画後の内容を文面生成に使うかどうかは、公式のどこにも書かれていない** | ❓ |
| 文面生成がどのクローラーの取得結果を使うか | 記載なし。DSA は「Google のウェブ クロール技術」、P-MAX のページフィードは「インデックス登録の確認に役立つ」と書くだけ | ❓ |

- 手がかり（結論ではない）: AdsBot-Google-Mobile は Chrome の形で名乗り、クローラー一覧は「Chrome の版数は Googlebot が使う Chromium に合わせて上がる」と注記する。広告ポリシーのヘルプ（16431325）は、AdsBot の名乗りでページを開いて「ふだんのブラウザと同じように読み込まれること」を確かめるよう勧める。どちらも「描画後の文面を文面生成に使う」とは言っていない
- 注意: Google 広告のヘルプ（9229701）と広告ポリシーのヘルプ（16428223。Chrome のデベロッパー ツールの Network タブと並べて挙げる）は確認手段に Search Console の URL 検査を挙げるが、URL 検査が使うのは Google-InspectionTool で、公式の説明では検索のテスト用。**URL 検査で B 案が見えても、AdsBot が同じものを見ている証拠にはならない**（このメモの推測）
- 第三者: Prerender（描画サービスの販売会社、2026-08-07 更新の記事）は「AdsBot はブラウザのようには JavaScript を描画しない」と主張するが、Google の資料も自社の検証も示していない。逆に「描画できる」と書く業者ページもあり、どちらも裏づけがない
- AdsBot について公式に書かれていること・いないことの一覧は 94_裏取りの記録_41-44.md の 2-2 にある（AdsBot が JavaScript を実行するかは、そこでも ❓ のまま）

### 3-4. DSA・P-MAX のページ内容の取得

- DSA ✅（2471185）: 見出しはサイトの内容から作る。**見出しを作るための多くのシグナルのうち最も重要なのは、ページの HTML タイトル**。サイトのタイトルやよく使われる語句で LP を選ぶ。HTML タイトルと内容がきちんと書かれたサイトで最もよく働く。大半が画像のサイトや、ログインが必要なサイトは苦手
- DSA のクロール不可 ✅（9229701）: URL を名指しした対象やページフィードは「クロールできません」で不承認になる。それ以外の指定方法では、クロールできなくてもエラーが出ない（気づけない）。リダイレクトは 10 回未満
- P-MAX ✅（14337539）: 設定の変更が行き渡るまで 24〜48 時間かかることがある。複数ドメインや事業が多いサイトでは、見出し・説明文と着地先が食い違うことがある

## 4. ブラウザ側で文面を差し替える A/B テストを、広告システムは読むか

| 観点 | 分かっていること | 判定 |
|---|---|---|
| Google 広告の文面生成が、ブラウザ側で差し替えた文面を読むか | 公式の記述は見つからなかった。検証した第三者の記事も見つからなかった（英語・日本語とも） | ❓ |
| 広告ポリシー上、A/B テストは問題か | クローキングは「ポリシー違反を隠すために、人や Google に違う内容を見せること」。人によって少し違う内容を見せるのは構わないが、宣伝する商品・サービスは全員に同じである必要がある（adspolicy/answer/15938075） | ✅ |

参考: Google 検索（SEO）側の A/B テストの扱い ✅（Search Central「A/B テスト時に Google 検索への影響を最小限に抑える」、最終更新 2025-12-10）

| 項目 | 内容 |
|---|---|
| ブラウザ側の出し分け | URL を変えず、JavaScript でどの案を見せるか決める方法は認められている |
| クローキング | Googlebot にだけ別の URL 群を見せてはいけない。サーバー側の判定でも robots.txt でも同じ |
| Cookie | Googlebot は基本的に Cookie を使わない。Cookie で制御するテストでは「Cookie を受け付けないブラウザに見える版」だけを見る |
| rel=canonical | URL を分けるテストでは、別案の URL から元の URL へ向ける。noindex より canonical |
| 302 | 振り分けのリダイレクトは 302（一時）。301 は使わない。JavaScript でのリダイレクトも可 |
| 期間 | 必要な期間だけ。終わったらテスト用の仕組みをすぐ外す。長すぎると検索エンジンを欺く行為とみなされうる |
| 小さな変更 | ボタンの文言など小さな変更は、クロールされても検索結果への影響はほとんどない |

このメモの推測（公式の裏づけなし）。読む側が B 案を見るには 3 つの関門がある。

1. LP を取得するクローラーが JavaScript を実行する（3-2 のとおり不明）
3. 50:50 の振り分けで B に当たる（Cookie を持たないクローラーは、来るたびに振り分け直される可能性がある）

3 つとも通ったときだけ B 案が材料になりうる。どれか 1 つで止まれば、材料は配信された HTML に書かれた A 案と、共通の title・meta description になる。

## 5. 生成された見出しは、LP のどこから来るか

| 出どころ | 内容 | 種類 |
|---|---|---|
| Google（11259373） | 抜き出しの例として、タイトル・説明・メタタグを挙げる | 公表 ✅ |
| Google（2471185、DSA） | 見出し生成で最も重要なシグナルは HTML タイトル | 公表 ✅ |
| Google（15913066） | AI Max は DSA と P-MAX の生成技術を合わせて広げたもの | 公表 ✅ |
| Foundry CRO（Bradley Jones、2026-04-10） | 「h1・h2 が見出しになりうる」と書くが、根拠の資料も検証も示していない | 第三者の主張（裏づけなし） |
| キーワードマーケティング（小島げん氏、2024-03-04 更新） | 自動作成アセットでは「過去に登録した広告の文言が追加されることが多いと感じる」。件数などのデータはなし | 第三者の印象 |
| インティメート・マージャー（2026-11-11）、援軍（2025-06-27） | 公式ヘルプに基づく解説と確認手順。自社での検証はなし | 第三者の解説 |
| 当てはめ用の状況 | 生成された 2 本はどちらも着地ページの title と同文 | 観察（公表内容と一致） |

- h1・h2・本文のどこから取るかを分けて検証した記事は、英語・日本語とも見つからなかった ❓
- 観察（2026-11-24、1 つのキャンペーンで確認）: Google が足した見出し・説明文は、その広告グループの最終ページの title と同じ文か、title の一部を切り出した文だった。meta description と本文の導入文からは作られていなかった。title の区切りの「｜」は、足された文では「 | 」に変わる（検索語句と広告の組み合わせの見出しでは「｜」のまま出ることがある）。件数が少ないので、一般の決まりとは言えない〔観察〕
- 実務上の読み方（推測）: 内容の少ない小さなサイトでは、まず title がそのまま使われやすい。生成される文面を変えたいなら、最初に手を入れる場所は title と meta description

## 7. 削除と制御

| 手段 | 効き方 | 判定 |
|---|---|---|
| 1 本ずつ削除 | 広告単位のアセット レポートで削除。**元に戻せない**（完全に削除される旨の確認が出る）。管理画面ではまとめて消せず、API とエディタなら一括可 | ✅ |
| テスト中の削除 | カスタムテストは元のキャンペーン側で消す（同期がオンなら介入側にも反映）。AI Max テストは直接消せる | ✅ |
| テキスト ガイドライン（ベータ） | 除外語句は 25 個まで・1 個 30 文字まで、メッセージ制限は 40 個まで・1 個 1〜300 文字（文字数は API 文書）。**すでに生成済みの文面にも効き、合わないものは配信停止・削除済みになる**。効きの悪い指定を入れすぎると良い文面まで消えて成果が落ちる、と公式が注意している | ✅ |
| ブランド設定 | 既存メモ 1 章のとおり（重複のため省略） | ✅ |
| URL の除外 | キャンペーン単位。API では除外の条件に URL のほかページのタイトル・内容なども並ぶ | △（既存メモ 2 章は「タイトル／内容に含むルールは新規作成できない」。管理画面と API で違う可能性） |
| テキストのカスタマイズをオフ | 生成文面はすべて配信停止。最終ページ URL の拡張も一緒にオフ | ✅ |

## 10. よくある思い込みと実際

| 思い込み | 実際 | 根拠 |
|---|---|---|
| 見出しを 15 本入れてあれば、Google の文面は入る余地がない | 上限には数えない。15 本でも生成・配信されうる | 16740321 ✅ |
| 生成されたら必ず配信される | 手入力より上回ると予測されたときだけ。成果が出なければ自動で消える | 11259373、16740321 ✅ |
| LP を直せば 48 時間で必ず広告文に反映される | 「48 時間以内に更新」は公式だが、AdsBot のクロールは約 2 週間ごととも書かれている。両者の関係は不明 | 11259373、9679690 ✅／関係は ❓ |

## 11. 少額・少量のアカウントでの注意

| 注意 | 理由 | 種類 |
|---|---|---|
| 内容の少ない LP は、生成される本数がそもそも少ない | 公式に明記 | 公表 ✅ |
| 表示の実績で生成文面の良し悪しは判断できない | 週 160 回ほどの表示では、生成文面が選ばれる機会自体が少ない。0 回でも異常とは言えない | 推測 |
| 「出ていない」と「作られていない」を分けて見る | 配信は予測で絞られる。作られたかは広告単位のアセット一覧と API の `source` で見る | 公表＋推測 |
| 生成文面を消すのは慎重に | 個別削除は元に戻せない。消したい理由が表現ならテキスト ガイドラインの方が再発を防げる | 公表 ✅ |
| LP を変えてから判断するまで 2〜4 週間みる | 48 時間（文面の更新）と約 2 週間（AdsBot）の両方の記述があるため、長い方に合わせる | 推測 |
| 公表値・第三者の数字をそのまま当てはめない | どれも一定以上の規模・EC や小売以外が前提。国内の 20 日テストでは差がほぼ出ていない | 公表・第三者 |
| プレビューは 0 円で何度でも試せる | オプトイン不要・30 秒以内 | 公表 ✅ |

## 12. 判断の型

| 状況 | 判断 | 根拠 |
|---|---|---|
| 生成される文面を変えたい | まず title と meta description、次に配信される HTML の本文。ブラウザ側の差し替えには頼らない | 1 章・5 章（公表）、4 章（不明のため安全側） |
| 必ず出したい文言がある | 手入力の見出し・説明文に入れる。生成に任せない | 2 章 |
| 出てほしくない言い回しがある | テキスト ガイドライン（除外語句・メッセージ制限）。個別削除は応急処置 | 7 章 |
| 生成文面が 1 本も無い | (1) テキストのカスタマイズが有効か (2) 最終ページ URL が広告単位か (3) LP の内容量、の順に見る。15 本の上限は理由にしない | 1 章・2 章 |
| LP テストの勝ち案を広告にも効かせたい | 勝ち案を HTML に確定させてから（テストを終えてから）。テスト中の B 案が広告文に出ることは期待しない | 4 章（推測）、検索側の指針 |
| 「Google が B を読んだか」を主張したい | 公式に答えが無いので、15 章のテストで自分で確かめた結果だけを根拠にする | 13 章 |

## 15. この問いを確かめられるテストの組み方

問い: LP テストで出し分けた B 案の文面が、AI Max の作る見出し・説明文の材料になるか。

### 15-1. 出典で言えること（組み方の土台）

| 土台にする事実 | 出どころ |
|---|---|
| 生成に使う URL は広告単位の最終ページ URL | 16739013 |
| タイトル・説明・メタタグは抜き出しの対象と明記されている | 11259373 |
| 生成文面は、元にしたソースが変わると自動で消える。LP の変更は 48 時間以内に反映 | 16740321、11259373 |
| AdsBot のクロールは約 2 週間ごと | webmasters 9679690 |
| プレビューは、オプトインなしで URL から最大 10 個の例を作る | 11259373 |
| 生成された文面は `ad_group_ad_asset_view.source = AUTOMATICALLY_CREATED`（`asset.source` は広告主のままのことがある）、画面では［提供者:］＝［Google AI］で見分けられる | API（2026-11-24 に実際に確認）、16739013 |
| 実際に出た見出しは［検索語句と広告の組み合わせ］で見られる | 16470459 |
| AdsBot の名乗りで自分のページを開いて確かめる手順は、公式が案内している | adspolicy 16431325 |
| A/B で少し違う内容を見せることは、広告ポリシー上は問題ない。検索側の指針では、テストは必要な期間だけ | adspolicy 15938075、Search Central |

### 15-2. いまの観察から言えること・言えないこと

- 言える: 生成 2 本が title と同文なのは、公式の作り方どおり
- 言えない: title は A・B 共通なので、「B を読んだ」「読んでいない」のどちらの証拠にもならない。本文は A 案すら使われた形跡がまだ無い。つまり今は「本文が材料になる段階」に達しているかどうかも分からない


### 15-3. テストの組み方（ここからはこのメモの推測。公式の裏づけはない）

考え方: 「どこに書いた言葉が広告文に出てくるか」を、目印の言い回しで追う。目印は、title・meta description・キーワード・既存の広告・もう一方の案のどこにも無い、事実に基づく短い言い回しにする（うその特典や数字は使わない。生成文面は広告主の責任になるため）。

| テスト | やること | 費用・期間 | 読み方 |
|---|---|---|---|
| 0. ツールが AdsBot を対象にするか | Chrome の開発者ツールで、名乗りを AdsBot-Google と AdsBot-Google-Mobile に変え、Cookie を消して LP を数回開く。B 案への差し替えが起きるかを見る | 0 円・10 分 | 差し替えが 1 回も起きなければ、ツールがロボットを対象外にしている可能性が高い。その場合、B 案は材料にならないとほぼ言える（テスト 1〜3 は不要） |
| 1. プレビューで 3 つの URL を比べる | (a) 今の LP（タグあり） (b) B 案を HTML に直接書いた静的な複製ページ (c) A 案だけの静的な複製ページ、をプレビューに入れ、日を変えて各 5 回ほど例を作る。複製ページは公開するがリンクは張らず、canonical を本体へ向ける | 0 円・2〜3 日 | (b) で B の言い回しが出て (a) で 1 回も出ない → 差し替え後は読まれていない可能性が高い。(a) でも出る → 読まれている。(b) でも出ない → 本文がそもそも使われていない（この規模では title 中心） |
| 2. 本番で目印を追う | 目印を 3 か所に置く。M1＝meta description（A・B 共通、静的）、M2＝配信される HTML の A 案の本文、M3＝差し替えで入る B 案の本文だけ。テスト期間中は出し分けを B 100% にして、振り分けの揺れを消す。毎週、`source = AUTOMATICALLY_CREATED` の文面一覧と［検索語句と広告の組み合わせ］の見出しを記録する | 追加費用なし・最低 4 週間（クロール 2 巡ぶん） | 下の判定表 |
| 3. AdsBot が差し替え後の合図を送るか | 差し替えが終わった直後に、自分のサイト内の計測用アドレスへ「どの案を描画したか」を 1 回送る小さな処理を足す。記録から、AdsBot の IP 範囲（公式の一覧で照合）からのアクセスを拾う。外部のサービスへは送らない | 開発 1〜2 時間・4 週間 | AdsBot から合図が届く → JavaScript を実行し、その案を描画している。届かない → 実行していない可能性が高い（ただし、描画はしても合図の送信だけ省くクローラーもありうるので、否定の証拠としては弱い） |

テスト 2 の判定表

| 生成文面に現れた目印 | 読み取れること |
|---|---|
| M3 が現れた | 差し替え後の内容が材料になっている。B 案は材料になる |
| M1 と M2 が現れ、M3 は現れない | 本文は読まれるが、配信された HTML のまま。B 案は材料にならない |
| M1 だけ現れた | 抜き出しは title・meta 止まり。本文は（A も B も）この規模では使われていない。B を読むかどうかは判定できない |
| どれも現れない | 生成自体が進んでいない。配信量か LP の内容量が足りず、結論は出せない |

### 15-4. 進め方と注意

1. テスト 0 → テスト 1 の順に進める。ここまで 0 円で、多くの場合は方向が見える
2. テスト 2・3 は、0 と 1 で決着しなかったときだけ。M1（meta description）は「仕組みが動いているか」を確かめる基準として必ず入れる。これが無いと、何も出なかったときに「読まれていない」のか「生成されていない」のか区別できない
3. 週 160 回ほどの表示では、生成文面が配信されるのを待っても判定できない。**見るのは表示回数ではなく「一覧に現れたか」**。表示 0 回の生成文面が一覧に出るかは未確認（13 章）なので、管理画面と API の両方を見る
4. B 100% の期間は LP テストの計測が止まる。検索側の指針（テストは必要な期間だけ）にも沿うよう、4 週間で切り上げる
5. 期間中は、広告・キーワード・最終ページ URL を変えない。生成文面は文脈が変わると消える（16740321）ため、変えると結果が読めなくなる
6. プレビューと本番が同じ読み方をしている保証はない。テスト 1 だけで「本番でも同じ」とは言い切らない
7. どの結果でも、言えるのは「このサイト・この時点・このツールでは」まで。Google の仕様として一般化しない
