# 30 ローカル・店舗向けの広告（住所アセット・マップ・来店計測・通話）

- 確認日: 2026-11-17（公式ヘルプ・Google の発表・API ドキュメントを取得して確認。第三者は誰の主張か明記）
- 使い方: 店舗・来店・電話・マップ広告の質問に答える前に読む。確認日から 30 日を過ぎていたら、下の出典を取り直してから答える
- 凡例: ✅ 公式で確認 ／ △ 公式の中で記述が食い違う ／ ❓ 公式に記載なし（確かめ方を併記）
- 既存メモとの分担: 住所・電話番号アセットの細かい入稿ルールは 15（2-37〜2-49）、P-MAX 全般は 10、デマンド ジェネレーションは 12、地域ターゲティングの基本は 04 の 8 章と 23、ローカル在庫広告の詳細は 21、コンバージョン計測の基本は 06。ここでは「店舗を持つ事業者が何を使い、何を測れるか」をまとめる

## 1. 仕組みの全体像

### 1-1. 部品の関係 ✅

| 部品 | 役割 | 日本語管理画面での名称 |
|---|---|---|
| Google ビジネス プロフィール（GBP） | 店舗の住所・電話・営業時間・写真・口コミの元データ。Google マップの店舗情報そのもの | Google ビジネス プロフィール |
| 住所アセット（旧 住所表示オプション） | GBP の店舗を広告に結びつける部品。住所・地図・距離・通話ボタンを広告に出し、来店計測・ローカル アクション計測・店舗周辺のターゲティングの前提になる | 住所アセット |
| アフィリエイト住所アセット（旧 アフィリエイト住所表示オプション） | 自社で持たない小売チェーン（家電量販店など）や自動車販売店で売るメーカー向け。Google が持つチェーン店の一覧から選ぶ | アフィリエイト住所アセット |
| 電話番号アセット | 広告に電話番号・通話ボタンを出す | 電話番号アセット |

- データは Google マップと GBP から直接来る（反映・修正のルールは 9 章 L-01〜L-03）。種類は 1 アカウント 1 つ、GBP の所有者か管理者の権限が要る、マップから 10 件まで、休業店は出ない、キャンペーン単位が優先、全部消すと来店計測も止まる、は 15 の 2-44〜2-49 と同じ ✅（2404182）
- GBP の権限がなければメール／ドメインで申請し所有者が承認。既存の GBP があるのに新しく作らない ✅（2404182）
- 地域グループ（GBP のラベルや店舗コードで絞った店舗の集合）でキャンペーンごとに出す店舗を変えられる ✅（2404182）

API で見ると: 住所アセットの種類は `location_ownership_type` = BUSINESS_OWNER／AFFILIATE、チェーンの種類は `chain_location_set.relationship_type` = GENERAL_RETAILERS／AUTO_DEALERS。GBP の店舗の絞り込みは `business_profile_location_set` の名前・ラベル・リスティング ID フィルタ ✅（手元の API フィールド一覧 v25、2026-11-10）

### 1-3. マップ上の広告（ローカル広告）の形と出るキャンペーン ✅（16388390、3246303）

日本語ヘルプでは「ローカル広告について」（3246303）。マップの広告は 4 つの形がある。

| 形 | 出る場所 | 出せるキャンペーン |
|---|---|---|
| プロモート ピン（四角いピン） | 地図を見ているとき、検索中、経路の上、運転ナビ中に時々 | 実店舗の目標に基づく P-MAX、スマート アシスト、旅行（観光スポット）、デマンド ジェネレーション |
| マップ検索の広告 | マップ検索結果の最上部 | 検索、実店舗の目標の P-MAX、スマート アシスト、ショッピング |
| マップのサジェスト広告 | 入力中の候補（Google マップのモバイル アプリだけ） | 実店舗の目標の P-MAX、スマート アシスト、検索 |
| プレイスシート広告 | 店舗の詳細画面（関連する店、近くの観光など） | 旅行、実店舗の目標の P-MAX |

- 出る条件は有効で承認済みの住所アセット。**マップだけに配信はできない**（デマンド ジェネレーションのチャネル選択を除く）。細則は 9 章 L-06〜L-09 ✅
- ピンの見た目: スマート アシストは業種アイコン、実店舗の目標の P-MAX はロゴ ✅（3246303）
- 課金: 検索・P-MAX は見出し・GBP・経路・通話・ピンのどれかのクリックで 1 回分。ロゴ ピンは CPM（L-10、L-11）✅

出典: support.google.com/google-ads/answer/2404182、3246303、16388390、12971048

## 3. 来店・店舗の成果の計測

### 3-1. 来店コンバージョン（推定値）✅（6100636、日本語「来店コンバージョンについて」）

仕組み:
- Google にログインし、ロケーション履歴をオンにしている人の来店を、広告の操作と結びつける。**集計した匿名の統計を、全体の利用者に引き伸ばした推定値**（モデル）であり、1 件ずつの実測ではない
- 1,000 万人以上のアンケート パネル（日本語ヘルプでは「Google アンケート モニター」）で来店を確かめ、モデルを調整する。日本は対象国

利用条件（すべて満たす）:

| 条件 | 内容 |
|---|---|
| 国 | 店舗が来店レポートを提供している国にある |
| 業種 | 宗教・性的関心・子ども・一部の健康に関わる店舗は対象外（センシティブ） |
| 住所アセット | 住所アセットかアフィリエイト住所アセットを使い、有効で、キャンペーン／広告グループで外していない。店舗が多いほど対象になりやすい |
| GBP | 店舗が設定・確認済み |
| 量 | 広告のクリックか表示が十分にあり、店舗への来訪も十分にあり、**プライバシーのしきい値**を超える。しきい値は広告主ごとに違い、数字は公表されていない |
| 単位 | ネットワーク（検索・ディスプレイ・YouTube）ごとに判定。MCC ではなく各子アカウントが単独で満たす必要 |

レポートと入札:
- 対象になると「来店数」のアクションが自動で作られ、「すべてのコンバージョン」列に入る（住所アセットを出すキャンペーンだけ。YouTube・ディスプレイはビュースルー列にも。来店と店舗販売は同時に入札不可）。メインにすれば自動入札に使える
- 「診断」ページで状態・店舗・確認済みの割合・データのしきい値・値の有無を見る
- 入札: 検索（CV 数／値の最大化、目標 CPA・ROAS、拡張 CPC）、P-MAX（目標 ROAS 推奨）、DG（CV 数の最大化、目標 CPA）、ショッピング（目標 ROAS、値の最大化）
- ❓ 計測期間と反映の遅れは記載なし → 確かめ方: リンク先の期間の記事、管理画面のアクション設定

### 3-2. 店舗での販売（店舗販売）✅（15885010）

| 項目 | 内容 |
|---|---|
| 利用開始 | **許可リスト制**。担当者かサポート経由で申請。許可後、しきい値を満たし続ける限りアクションが自動で作られる |
| 件数と既定値のしきい値 | 直近 90 日に約 **30 万回の来店**、アカウント全体で 90 日に **50 万回超の広告の操作**。来店の計測が前提（自動車はアフィリエイト住所アセットが前提） |
| 取引データのアップロード | 90 日に 3 万件以上、直近 30 日に 1 万件以上、毎日〜毎週の定期送信 |
| 自動の動的な値 | 15 か国のみで日本は含まれない |
| 対応業種 | 小売、飲食、自動車メーカー、通信 |
| 対応キャンペーン | 検索、ショッピング（ローカル在庫広告を含む）、P-MAX、ディスプレイ、デマンド ジェネレーション、動画 |

→ 小規模の事業者にはまず届かない水準（推測ではなくしきい値の数字から言える）。

### 3-3. ローカル アクション ✅（9013908、3246303）

住所アセットが有効になると自動で作られる（その種類の成果が 1 件以上あった後、Google がホストする目標として作成）。

| アクション（日本語ヘルプでの名称） | レポート | 入札に使える |
|---|---|---|
| 経路検索 | ○ | P-MAX、検索、ショッピング |
| 通話ボタンをクリック | ○ | **P-MAX だけ** |
| ウェブサイトへのアクセス | ○ | × |
| その他の操作（共有・保存・写真・詳細など） | ○ | × |
| 注文（「注文」ボタンがある業種） | ○ | × |
| メニューの表示（「メニュー」ボタンがある業種） | ○ | × |

### 3-4. 値の付け方 ✅（9462313、13775728）

| 状況 | Google の推奨 |
|---|---|
| オンライン売上を「収益」で測っている | 来店の値 = 店舗での平均購入率 × 店舗の平均購入単価 |
| オンラインの成果に売上の値がない | オンラインの成果との相対比（例: 来店 1、フォーム 0.25） |
| 来店しか測っていない | それでも値を入れる |
| 目標ごと | 来店と通話など目標ごとに値を分ける |
| キャンペーンで変える | 値のルールで、キャンペーンごとに値を上書き・加算・乗算できる |

- 値を使う入札（目標 ROAS・値の最大化）では来店の値が必須で、来店を増やすなら来店の値を相対的に上げる。目標 CPA・CV 数の最大化では値は効かない（L-32）
- 推測: ローカル アクションの「経路」はタップしただけでも数えるので、実際の来店より多い。値は来店率を掛けて割り引くほうが安全（例: 経路→来店の割合が分かれば、来店の値 × その割合）

出典: 6100636（hl=ja・en）、15885010、9013908、9462313、13775728、3246303

## 4. 地域の指定と商圏

基本（「所在地やインタレスト」と「所在地」の違い、除外は所在地基準だけ、上限数）は 04 の 8 章・14 の 164 行・23 を参照。ここでは店舗に関わる点だけ。

### 4-1. 指定のしかた ✅（1722043、2453995、2404184）

| 方法 | 内容 | 注意 |
|---|---|---|
| 国・地域・市区町村・郵便番号 | 国によって使える単位が違う | 小さすぎる地域は指定できないか、表示が途切れる |
| 半径（「特定の地点を中心とした指定半径内」） | 住所を中心に距離で囲む | **最小 1 km**。ホテル キャンペーンでは使えない。上限は記載なし ❓ |
| 住所アセットの周辺 | 住所アセットの店舗を中心に一定範囲。範囲ごとに単価調整比 | 英語版は「全店舗が米国」、日本語版は「全店舗が日本国内」の場合と書く △（L-36） |
| 地域グループ | 関心のある場所、ビジネス拠点、所得層など | API では `location_group`（`enable_customer_level_location_asset_set` でアカウントの住所アセットを使う）|
| P-MAX 店舗目標 | 店舗ごとの半径か、Google が自動で決める。**店舗目標では地域を別に足すことは推奨されない**（店舗から推定されるため） | 半径は ✅ 12971048。「地域を足さない」は公式ヘルプの検索抜粋のみ ❓ |

- 所在地は IP と端末の位置情報、関心は検索語の地名・過去の検索と所在地・マップ検索・サイトの文脈から推定 ✅（2453995）
- 指定地域の**近くの密接に関連する地域**にも出ることがある。精度は 100% ではない ✅（2453995）
- Google は「所在地やインタレスト」を推奨（旅行・不動産・教育で CV 5% 増、2022 年の社内データ）✅（1722043）。来店型では遠方の関心だけの人への配信が無駄になりやすい（推測、04 と同じ）

### 4-2. 商圏の考え方

| 観点 | 内容 | 根拠 |
|---|---|---|
| 「店の場所」ではなく「客のいる場所」 | 対象地域は客がいる場所を基準にする | ✅ 1722043 の助言 |
| 半径は業種・人口密度・競合で変わる | Google 自身が P-MAX の自動半径でこの 3 つを使うと書く | ✅ 12971048 |
| 成果の良い地域を別キャンペーンに分ける | 成果の地域差が大きければキャンペーンを分けて予算と入札を変える | ✅ 2404184 |
| 地域ごとの文・LP | 地域に合わせた広告文と LP | ✅ 2404184 |
| 実測で決める | 既存客の郵便番号の分布から来店の 8 割が入る範囲を商圏にし、外は除外か単価を下げる。地域レポートで答え合わせ | 推測 |

出典: 1722043、2453995、2404184（hl=en・ja）、12971048

|---|---|---|

## 6. 店舗が少ない・予算が少ない事業者での現実的なやり方

### 6-1. 公式の数字から分かること ✅

| 公式の条件 | 1〜数店舗の事業者に当てはめると |
|---|---|
| 店舗目標の P-MAX: 来店・店舗販売は 10 店舗以上、ローカル アクションは 5 店舗以上を推奨（13775728） | 1〜4 店舗は推奨の下限より少ない。禁止ではないが、Google の想定外 |
| 来店コンバージョン: 公表されないプライバシーのしきい値、店舗が多いほど対象になりやすい（6100636） | 小さな店は対象外が多いと考えておく（推測） |

## 7. ローカル在庫広告の概要（詳細は 21）

- 店舗の在庫を Merchant Center のローカル在庫データで出すショッピング系の広告。店舗販売の対象キャンペーンに「ショッピング（ローカル在庫広告を含む）」がある（✅ 15885010）。ショッピングではローカル アクション「経路検索」で入札できる（✅ 9013908）
- 2026-08-31 からショッピングでローカル在庫広告が既定オン、「ローカル商品」設定は廃止し在庫フィルタ（チャネル＝ローカル／オンライン）で管理、と第三者（PPC News Feed、TechWyse）が報道。TechWyse は根拠を 2026-07-20 の Google Ads Developer Blog とし、API v25.1 以降は `enable_local=false` がエラーと書く ❓（一次資料は未取得）
- ローカル顧客の最適化は、Merchant Center の商品を使う P-MAX では効かない（✅ 17198659）。在庫広告と「近くの人を呼ぶ」最適化は別キャンペーンにする

## 11. 少額・少量のアカウントでの注意

- 店舗目標の P-MAX は 5／10 店舗以上を推奨。1〜数店舗では推奨外で、学習も遅い（推奨の数字は ✅ 13775728、学習の遅さは推測）
- 来店コンバージョンは対象にならない前提で設計し、「診断」ページで対象になったら使う（✅ 6100636）
- 経路検索・通話ボタンのクリックは「ボタンを押した数」。少数だと値の付け方ひとつで入札が大きく動く。最初は「サブ」で数だけ見る → 値を決めてから「メイン」へ（手順は推測。メイン／サブの仕組みは 06）
- 電話は転送番号＋通話時間で数える。タップ計測は誤タップが混ざる（T6 4-4）
- 半径を小さくしすぎると表示が途切れる・出ない（✅ 1722043）。最小 1 km
- 「所在地やインタレスト」のままだと遠方の関心だけの人に出る。来店型なら「所在地」を検討（04、23）
- 配信が出ないときは、入札より先に品質（広告の関連性・LP）を手当てする（01 参照）
