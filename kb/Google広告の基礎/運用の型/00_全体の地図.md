# 型00 全体の地図（運用型広告の運用の原理と型）

- 位置づけ: 知識ベース「Google広告の基礎」の中核になる体系の入口。既存の 28・35・36・37（運用の型）は手順と点検表の集まりで、「なぜその順か」「どう決めるか」の背骨が弱かった。この体系は、運用型広告の定義から出発して、判断の規則までを 1 本の論理でつなぐ。手順の細部は写さず、既存メモの番号へ送る
- 作成日: 2026-11-17。材料は知識ベースの 00〜37、ロジックツリー L1〜L4、tips T1〜T7。既存メモは変更していない
- 対象: 検索キャンペーンを中心に、P-MAX・デマンド ジェネレーション・動画・ショッピングにも当てはまる形で書いた。数値のしきい値は検索が基準で、ほかの種類に固有の値は断って書く

## この体系が答える問い

運用型広告の「運用」とは何をする仕事か。何を、どの順で、いつ、どれだけの確かさで決めるのか。その答えを、慣習や経験則の寄せ集めではなく、定義と式から導けるか。

## 中心の考え方（10 行）

1. 運用型広告は**競り・可変・帰還**の 3 条件で定義される。この 3 つがそろうと、「決めて放置」より「差を見て直し続ける輪」が必ず上回る。その輪を回す仕事が運用である（型01）
2. 自動化で輪は二重になった。内側は機械（オークション 1 回ごと）、外側は人（日〜四半期）。人に残るのは、目的を決める・媒体の外の情報を持ち込む・機械の出力を確かめる・中身そのものを変える、の 4 つ（型01）
3. 最大にすべきは管理画面の成果数ではなく**増分利益**。利益が最大になるのは、平均ではなく**限界**の獲得単価が損益分岐に等しい点（型02）
4. 輪は 6 工程で、**症状は下流に出て、原因は上流にある**。速さの違う 3 つの輪（事故・改善・目的）が重なる（型03）
5. 数字を読み誤らせる源は学習・遅れ・振れ・周期の 4 つ。判断してよいのは、**確定・評価窓・件数**の 3 条件がそろったときだけ（型04）
6. 差 δ を言うには 1 期間に約 15.7 ÷ δ² 件。月 30 件のアカウントで成果数から言えるのは「2 倍か半分か」だけ。**件数が、できる運用を決める**（型04）
7. 運用者が変えられるものは、機械のどの入力口に入るかで 6 類に分かれる: **教える・渡す・囲う・換える・束ねる・事業を変える**（型05）
8. アカウントは常に 9 状態のどれか 1 つにあり、8 つの問いに順に答えれば決まる。**状態が、打ってよい手と打ってはいけない手を決める**（型06）
9. 打ち手の順は**計測 → 目的と成果の定義 → 絞る → 素材 → 構成 → 入札・予算 → 広げる**。上流を変えると下流をやり直すことになる、という依存関係から 1 本に決まる。入札は「効率と量の取り合いの線」の上を動くだけで、線を動かすのは素材と事業だから、入札は最後になる（型07）
10. 判断の質は結果ではなく手続きで保つ。変える前に仮説・判定の指標・待つ期間・戻す条件を書き、結果を**効いた・効かなかった・判定不能**に分けて残す（型11）

## §3 章のつながり

```
型01 定義 ──→ 型02 目的関数 ──────────────┐
  │（輪・境界）      │（BE・T・q・ι）        │
  ▼                  ▼                        ▼
型03 制御の輪 ──→ 型04 時間の法則 ──→ 型06 状態の判定 ──→ 型07 優先順位 ──→ 型08 規則集
  │（工程・3 つの輪）  │（W・L・P・件数）    ▲（何が読めるか）    ▲（何から直すか）      │
  │                    │                     │                    │                      │
  │                  型05 操作できるもの ────┴────────────────────┘                      │
  │                  （6 類: 何を変えられるか）                                           │
  ▼                                                                                       ▼
型09 段階 ←──── 状態の遷移 ──── 型10 問題解決 ──→ L1〜L4（原因の一覧）        型12 例題（全部を通す）
  │                                                                                       ▲
  └────────────→ 型11 判断の質（記録・検証・合意・AI と人）───────────────────────────────┘
```

- **正本の章**は 型01〜04・06・07 である（定義、式、状態、順序をここで決める）。型05・08〜12 は正本の定義を使う章で、食い違ったら正本が正
- 読む順: 初めてなら 型01 → 02 → 03 → 04 → 06 → 07 の順（ここまでが背骨）。そのあと 型12 の例題を 1 つ通してから、型05・08〜11 を必要なときに引く
- 急ぐとき: この章の「中心の考え方」→ 型06§2 の決定木 → 型07§2-3 の順序 → 型04§7・§8 の表、の 4 か所だけで骨格はつかめる

## §8 使うときの注意

1. **数値は検索キャンペーンが基準**である。P-MAX・デマンド ジェネレーション・動画に固有の待つ期間・刻み・日予算の倍数は、断って書いた所（型04§10、付録 C の裁定 13・18）を見る
2. **β ＝ 0.7（閾35）は出典の無い仮置き**で、多くの判断（平均の線 β × BE、縮める線、増やす採算）がこれに依る。費用と成果の確定した組がたまったら、最初に置き直す（規定-16）
3. **式は最低線**である（ポアソン分布の近似。周期・外乱・件数のばらつきの大きさは入っていない）。実際に要る件数は、式の値より多い（付録 A §5）
4. **例題と数値例の数字は、すべて仮定**である。構造を示すためのもので、目安の数字として引用しない
5. 確認日（2026-11-16〜17）から 30〜90 日たったら、〔公式〕の事実は取り直す。日付で古くなる仕様変更は付録 D の第 4 部
6. 既存メモには顧客や社内の事情が出る箇所があるが、この体系には人名・社名・実案件の数字を書いていない。外に出すときも、既存メモの側の扱いに従う

## §9 更新の決まり

- 定義・式・状態・順序を変えるときは、正本の章（型01〜04・06・07）を先に直し、付録 A・B を合わせ、そのあとほかの章を合わせる
- しきい値を変えるときは、付録 B の表と、その値を使う規則（付録 B の「使う章と規則 ID」）を同時に直す。変えた理由は付録 C に裁定として残す
- 自分のアカウントの記録で置き直した値（C、L、β、過渡の長さ、確からしさの目安）は、体系の正本ではなくアカウントごとの記録に置く（型11§5）
- 知識ベースの側が裏取りで直されたら、付録 B §7 の対応表から該当する章を引いて合わせる
- **数字を変えたら `94_付録E_検算.py` を流す**（式・早見表・例題の数字を検算する。通らないまま残さない）
- **〔公式〕の根拠は `rules.csv` の id で引く**（`R-入札-081` の形）。既存メモの節番号だけで引かない。裏取りで既存メモが直っても、id で引いていれば付録 B §7 から追える。節番号は id と併記してよい
