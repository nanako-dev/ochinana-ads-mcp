## 4. 開発者トークンと Google Ads API の件（A 担当の整理）

前提: 利用者は Google 広告の開発者トークンを持っている。手元の API の認証（OAuth の更新トークン）が切れている。2026-11-17 に取得した公式ページだけで整理した。

**1. 2026 年に何が変わったか（確定）**
- 開発者トークンは 2026-09-09 に廃止された。原文は "Developer tokens were sunset on September 9, 2026"（developer-token）。廃止一覧（deprecations）も同じ日付。告知の Ads Developer Blog は 2026-09-10 付（"A new onboarding experience for Google Ads API developers"）。
- API のアクセス段階（テスト／エクスプローラー／ベーシック／スタンダード）は、トークンではなく **Google Cloud プロジェクト** に付く。どのプロジェクトかは、OAuth のユーザー認証なら OAuth クライアント ID を持つプロジェクト、サービス アカウントならそのアカウントを持つプロジェクト（developer-token）。
- 移し方: 廃止前 90 日の API 呼び出しの記録から、そのトークンで使われたプロジェクトに同じ段階を付けた。90 日使われていなかったプロジェクトの段階は取り消された（developer-token）。
- ヘッダーの `developer-token` は送ってもよいが無視される（"optional and ignored by the API servers"）。将来のメジャー版で、トークンを送ると拒否する予定（developer-token）。
- ブログは「既存のコードは変更なしで動く」と書く。
- MCC の API センターは過去の情報を見るだけの場所になった。段階の申請は Cloud Console の「Google Ads API 概要（Overview）」で行う。保留中のベーシック申請は閉じられた（閉じられたら Overview から出し直す）。スタンダード申請は通常どおり審査される。
- 段階（access-levels）:
  - テスト: テスト アカウントだけ、1 日 15,000 操作。API を有効にすると自動で付く。
  - エクスプローラー: 本番は 1 日 2,880 操作、テストは 15,000 操作。Overview から申請し、多くは自動で審査される。アカウント作成・ユーザー管理・プランニング（KeywordPlanIdeaService、ReachPlanService、AudienceInsightsService など）・請求のサービスは使えない。
  - ベーシック: 1 日 15,000 操作。エクスプローラーから申請し、**Cloud プロジェクトのブランド確認が前提**。数分で自動審査。
  - スタンダード: 操作数は無制限。手動の監査があり、目安は 10 営業日。
  - 「1 日」は直前 24 時間の移動窓で数える。
- 既知の不具合（developer-token）:
  - 2026-09-09 以降に Console でベーシック・エクスプローラーへ上げたプロジェクトが、本番で AUTHORIZATION_ERROR になることがある。回避は新しいプロジェクトでエクスプローラーを申請すること。
  - 無料トライアルのプロジェクトや、請求アカウントが停止・無効のプロジェクトは、申請が却下されることがある。回避は有料化、または請求を戻すこと。

**2. 「トークン自体が無効になったのか」への答え**
- トークンの文字列はもうアクセスの判定に使われない。「無効になった」というより「意味を持たなくなった」。
- 本番のアカウントを呼べるかどうかは、**手元の OAuth クライアントがある Cloud プロジェクトの段階** だけで決まる。
- 利用者の場合、廃止前 90 日（だいたい 2026-06-11〜09-09）に、そのトークンとその OAuth クライアントで API を呼んでいたかが分かれ目になる。
  - 認証が切れていて呼んでいなかったなら、段階は移っていない可能性がある。
  - そのときテストの段階のプロジェクトで本番アカウントを呼ぶと、v25 は `CLOUD_PROJECT_NOT_APPROVED_FOR_PRODUCTION`、v24 以前は `ACTION_NOT_PERMITTED` になる（common-errors、developer-token）。

**3. 更新トークンが切れた件（OAuth の取り直しで直る部分）**
- 公式の common-errors: OAuth 同意画面が「外部（External）」で、公開ステータスが「テスト（Testing）」のプロジェクトでは、更新トークンは **7 日で失効** し、`invalid_grant` になる。対処は公開ステータスを「本番環境（In production）」に変えること。
- identity/oauth2 の失効条件:
  - 上の 7 日。ただしスコープが name・email・openid だけなら例外。
  - 6 か月使っていない。
  - ユーザーがアクセスを取り消した。
  - 1 つの OAuth クライアント ID につき Google アカウントあたり 100 本の上限。超えると一番古いトークンが警告なしで無効になる。
  - Gmail スコープを含む場合のパスワード変更。
  - 時間制限つきのアクセスが切れた。
  - 管理者の制限（admin_policy_enforced）、または組織のセッション時間の上限。
- 公開ステータスを本番に変えたあと、テスト中に出た更新トークンも延びるかは、公式に書かれていない。Google Ads API フォーラムのアドバイザーは「新しい認証情報（更新トークン）を作り直す」よう答えている（第三者扱い）。**実務では本番に変えてから更新トークンを取り直す**。
- OAuth クライアントは、Google Ads API を有効にして段階を取ったのと同じ Cloud プロジェクトで作る（oauth/overview）。
- 認証に使う Google アカウントは、Google 広告のアカウントにアクセスできる必要がある。できないと `NOT_ADS_USER` になる。
- MCC 経由で呼ぶなら `login-customer-id` に MCC の ID（ハイフンなし）を入れる。入れないと `USER_PERMISSION_DENIED` になる（common-errors）。

**4. やる順番（公式の記述にもとづく。0 円でできる確認から）**
1. MCC の［API センター］でトークンの段階を見る（過去の情報として残っている）。
2. 手元のツールの `client_id` が属する Cloud プロジェクトを特定し、Cloud Console の「Google Ads API 概要」でそのプロジェクトの段階を見る。1 と同じ段階かを確かめる。
3. 段階がテストなら、Overview からエクスプローラーを申請する（多くは自動審査）。
   - 本番を 1 日 2,880 操作で使える。小さなアカウントのレポート取得には足りる見込み〔推測〕。
   - API でキーワード プランナー（KeywordPlanIdeaService）を使うなら、エクスプローラーでは使えないのでベーシックが要る。ベーシックはブランド確認が前提。
   - 申請が通ったのに本番で AUTHORIZATION_ERROR が出たら、既知の不具合。新しいプロジェクトでエクスプローラーを申請し直す。
   - 無料トライアルのプロジェクトなら、先に請求を有効にする。
4. OAuth 同意画面の公開ステータスを見る。「テスト」なら「本番環境」に変え、更新トークンを取り直す。7 日ごとに切れる症状なら、ほぼこれが原因。
5. コードとクライアント ライブラリを、トークンなしで呼べる版に上げる。`developer-token` のヘッダーは今は無視されるが、将来のメジャー版で拒否される。
6. Cloud プロジェクトの IAM で、オーナー・編集者のメール アドレスを最新にする。必須のサービス告知（MSA）はそこへ届く。

**5. 確認できなかったこと**
- 公開ステータスを本番に変えたあと、テスト中に出た更新トークンが 7 日を超えて使えるか（公式に記載なし）。
- 廃止前 90 日の窓の正確な開始日（「90 日」とだけ書かれている）。
- トークンを拒否し始めるメジャー版の番号と時期。
