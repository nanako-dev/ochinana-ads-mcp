## 1. 監査の進め方

### 1-1. 目的を先に確かめる

監査は目的で見る深さが変わる【実務家: Brad（Adalysis）、2026-07】（T5-96）。最初の打ち合わせで次の 5 つを文字で残す。

| 確かめること | 例 | なぜ要るか |
|---|---|---|
| 監査の種類 | トラブル対応／定期点検／引き継ぎ／新規提案の前の精査 | トラブル対応なら「いつから・何が」に絞る。定期点検なら全章 |
| 事業の成果 | 売上・有効リード・来店。最重要の成果は何か | 媒体の「コンバージョン」が事業の成果と同じとは限らない（06§4） |
| 損益の線 | 許容できる獲得単価・目標の広告費用対効果、利益率 | 目標が実績や損益から離れていないかを判断する（T2§2、26§9） |
| キャンペーンごとの役割 | 指名の防衛、新規獲得、再来訪の回収、認知 | 役割が違うものを同じ獲得単価で裁かないため（28§6-1） |
| 触ってよい範囲 | 読むだけか、事故だけは直してよいか | 引き継ぎ直後は原則「読むだけ」（28§2-2）。例外は事故の止血 |

### 1-2. 見る順番とその理由

点検表の章（A〜O）は依頼どおりの並びにしているが、**実際に見る順番は下の 4 段**にする。理由は 1 つで、上の段が壊れていると下の段の数字が読めないから（28§0、T5-97）。

| 段 | 章 | 理由 |
|---|---|---|
| 1 段目: 数字の土台 | A 計測 → N のうちアカウントの安全・停止の有無 | 成果の数え方が壊れていれば、獲得単価も入札の良し悪しも全部意味がない。自動入札は壊れた成果を教師データにして動く（00§4-4） |
| 2 段目: お金の流れ方 | B 入札 → C 予算と制限 → H 自動化の設定 → O 変更履歴 | 何が「人の判断」で、何が「機械や自動適用の判断」かを先に分ける。変更履歴を見ないと、数字の折れ点の原因を取り違える |
| 3 段目: 何に出しているか | D 構成 → E 検索語句 → I 地域・オーディエンス → K/L/M 種類別 | 無駄な配信と取り合いを見つける |
| 4 段目: 出した後 | F 広告文 → G アセット → J LP | 表示されてからクリック・成果に変わる部分。上が直っていないと評価できない |

- 実務家の順番は書き手で違う（Karooya は計測が最初、Optmyzr は構成が最初。T5-97・T5-100）。このメモは 28§1-1 と同じく計測を最初に置く
- 予算の増額の提案は最後に出す。無駄を直してからお金を足す（T2-4-3、28§5-2）

### 1-6. 結果のまとめ方（重大度の付け方）

点検表の「重大度」は**問題があったときの既定**。状況で上げ下げしてよいが、変えたら理由を書く。

| 重大度 | 意味 | 付ける条件【このメモ】 | 期限の目安 |
|---|---|---|---|
| **即**（すぐ直す） | 今もお金か計測が壊れ続けている | 計測の故障・二重計上、予算の桁違い、リンク切れ、ポリシー違反の放置、アカウントの安全（権限・2 段階認証）、関係ない検索への大きな費用 | 当日〜1 週間 |

| **整**（整理する） | 今すぐ損はしていないが、放置すると判断を誤る・事故の元 | 命名、不要な一時停止の残骸、使っていないリスト、アセットの不足 | 1 か月以内 |

- 「即」は 1 回の監査で 3〜5 件に絞る。全部を一度に直すと、何が効いたか分からず学習も揺れる（T2-3-5、28§1-3）

## 3. アカウントの大きさで変える

### 3-1. 少額・少量のアカウント向けの短い版（30 項目）

対象の目安【このメモ】: 月の費用 50 万円未満、または月の成果 30 件未満。**選び方**: 「お金か計測が今壊れている」項目と「少量だと特に効く」項目を優先し、量がないと判断できない項目（アセット別の成績、属性の除外、テスト）は外した。

少額・少量での読み方の注意:
- 成果が 0 件でも「3 の法則」（n クリックで 0 件なら、本当の成果率の 95% 上限は約 3÷n）で幅を見る（、28§6-1）。100 クリック 0 件でも本当の率が 3% ある可能性は残る
- 「様」（様子見）が多くなるのは正常。様子見の項目には**再判定の日付**を書く
- 30 件未満なら、獲得単価ではなく、クリック数・検索語句の中身・手前の行動の率で見る（02§15、28§3-3）

## 4. 監査結果の報告の型

### 4-1. 見出しの順

1. **要約（1 ページ）**: 監査の目的・期間・見た範囲／結論 3 行／「即」の件数と見込める影響／うまくいっている点（T5-119）
2. **前提**: データの期間、外した直近の日数（成果の遅れ）、使った権限、見られなかったもの（例: CRM の件数がない）
3. **計測の状態**（A）: 数字を信じてよいかを最初に言う。信じられないなら、後の章の数字は「暫定」と明記
4. **すぐ直す（即）**: 1 件ずつ、4-2 の型で
5. **確かめる（確）**: 誰に何を聞くか、いつまでに
6. **整理する（整）**: まとめて 1 表
7. **様子見（様）**: 再判定の日付つき
8. **直す順番と日程**: 束ねて週 1 回など。直した後の評価日（2 週間か 2 サイクルの長い方。02§4）
9. **付録**: 点検表（はい・いいえ・該当なし）、書き出しのファイル名、出典

### 4-2. 1 件の指摘の書き方（事実 → 影響 → 直し方 → 確かめ方）

| 欄 | 書くこと | 書き方の注意 |
|---|---|---|
| 番号・重大度 | 点検表の番号（例 A09）と 即／確／整／様 | 重大度を変えたら理由 |
| 事実 | 画面・期間・数字。誰が見ても同じになる書き方 | 推測を混ぜない。スクリーンショットか書き出しの場所 |
| 影響 | 何が起きているか、起きうるか。金額か件数で | 見込みは幅で書く。「Google の公表」「実務家の目安」「このメモの推測」を分ける |
| 直し方 | 具体的な操作。誰がやるか（権限） | 1 件 1 操作。まとめて直すなら順番 |
| 確かめ方 | 直した後に何を見れば効いたと言えるか、いつ見るか | 評価の指標と日付を先に決める。学習中の期間を外す |

記入例【このメモ】:

> **A09（即）カスタム目標に「資料ダウンロード」が入っている**
> 事実: キャンペーン「非指名_一般」の目標はカスタム目標「問い合わせ＋資料」で、サブに設定した「資料ダウンロード」を含む（[設定] > [目標]、2026-11-17 確認）。過去 30 日の「コンバージョン」列 48 件のうち 31 件が資料ダウンロード。
> 影響: 【公式】カスタム目標のアクションはサブでも入札に使われる（15:4-30）。入札は資料ダウンロードの取りやすい検索に寄っている可能性がある。問い合わせだけの獲得単価は、表示の約 2.8 倍（48÷17）。
> 直し方: カスタム目標から資料ダウンロードを外す（管理者権限）。目標値は問い合わせの実績で置き直す。数字が下がって見えることを事前に伝える。
> 確かめ方: 変更日から「学習中」が消えるまで（最長 7 日）を外し、その後 2 週間の問い合わせの件数と獲得単価、台帳の有効リードを変更前 4 週と比べる。

## 5. 監査でやってはいけないこと

| やってはいけないこと | なぜか（根拠） | 代わりにやること |
|---|---|---|
| データが少ないのに「効いていない」「止めるべき」と断定する | 件数が少ないと偶然の揺れが大きい。50 クリック 0 件でも本当の率が 6% ありうる（、28§6-6）。【公式】評価は落ち着いた後の 2 サイクルか 2 週間の長い方（02§4） | 「様」にして再判定の日付を書く。幅（3 の法則・信頼区間）で書く |
| 最適化スコアを成果の指標として扱う | 【公式】スコアは設定の見込みの推定で、品質スコアにも使われない。提案を却下してもスコアは上がる（9061546、13§4-1）。提案は Google の仮説で、事業の目標ではない（T2-11-9） | 提案は 1 つずつ、事業の成果で評価する |
| 「広告の有効性」の評価を上げることを目的にする | 評価が高くても成果が出るとは限らない（T3-12-14）。【公式】RSA は増えた表示・クリック・成果で評価する（28§6-3） | 成果で評価し、有効性は不足の手がかりに使う |
| 1 つの指標だけで判断する | CPL が下がっても成約率がもっと下がることがある（T1-11-12）。ブランドを除外すると P-MAX の ROAS は下がるのが想定内（T3-12-15） | 費用 → 成果数 → 獲得単価 → CVR → CTR → クリック単価の順に並べる（T2-11-2）。台帳の有効リードと並べる |
| 計測を確かめずに入札・構成を直す | 壊れた教師データに合わせて入札が動く（00§4-4、28§1-3） | A 章を最初に終える |
| 直近の数日を含めて期間を比べる | 成果の遅れで直近が悪く見える（L3§0-2）。【公式】IS とオークション分析は約 3 日遅れ（2544985） | 遅れの日数ぶん両方の期間から外す |
| 監査で見つけたことを一度に全部直す | 何が効いたか分からず、学習も揺れる（T2-3-5、T2-12-5） | 「即」から 3〜5 件。束ねて週 1 回 |
| 前任の設定を、理由を聞かずに「間違い」と書く | 意図的な設定かもしれない（T6 9-4） | 「確」にして理由を聞く |
| オークション分析から「競合が高く入札している」と言い切る | オークション分析は競合の入札額や予算を示さない（T1-11-15） | 「重複率・上位掲載率が上がった」という事実まで書く |
| 仕様の変更を運用の失敗と読む | 2026-06-01 の曜日スケジュールの予算配分、2026-08-17 の予算で制限された目標型の入札は仕様の変化（C09、B14） | 変更履歴・仕様の年表と折れ点を並べる |
| 実務家の目安を公式の基準として書く | 「予算 20% ルール」は公式ではない。【公式】予算と目標の変更では「学習中」は出ない（14:66、28§5-2 △） | 誰の主張かを書き、自分のアカウントで確かめる |
| 業界平均の CTR・CVR・獲得単価を合否の基準にする | 業種・地域・意図・成果の定義で大きく違う（28§0） | 自分のアカウントの通常の揺れと、損益の線で判断する |
| 監査のためにテスト送信して、そのまま成果に残す | 入札の学習が汚れる（06§7） | テストの成果は、データの除外か調整で扱う（06§14） |

### 5-1. よくある思い込みと実際（監査の場面）

| 思い込み | 実際 | 根拠 |
|---|---|---|
| サブにした成果は入札に使われない | カスタム目標に入れるとサブでも使われる | 15:4-30 ✅ |
| 自動適用をオンにすると予算も勝手に上がる | 【公式】自動適用で予算は上がらない | 10279006 ✅ |
| 「予算による制限」が出ていれば増額すべき | 最大化系はもともと制限になる。ランク由来の損失なら予算ではない | 14:73 ✅、T5-106 |
| 検索キャンペーンの言語の設定で配信を絞れる | 【公式】検索では言語は自動で決まり、古い設定は使われない | 14:230 ✅ |
| 必須の文言は見出し 3 に固定しておけば出る | 【公式】見出し 3・説明文 2 の固定は出ないことがある。URL の拡張がオンなら固定自体が使われないことがある | 15:1-13 ✅、AIMax§2 |
| 除外キーワードは表記ゆれまで止まる | 【公式】除外は類似パターンに広がらない | 15§8 の 6 位 ✅ |
| 変更履歴にすべての変更が出る | 【公式】Google の担当者の変更や一部のアカウント設定は出ないことがある | 19888 ✅（28§2-2） |

### 5-2. 判断の型（監査の結論の出し方）【このメモ】

1. 計測（A）は信じられるか → いいえなら、ほかの章の指摘はすべて「暫定」にして、計測の直しだけを「即」にする
2. お金が今、明らかに無駄になっているか（C01・D05・E02・H05・J01） → はいなら「即」
3. 件数は判断に足りるか（B02、3 の法則） → いいえなら「様」。再判定の日付を書く
4. 意図した設定か分からない → 「確」。誰に聞くかを書く
5. 上のどれでもない → 「整」。まとめて 1 か月以内
