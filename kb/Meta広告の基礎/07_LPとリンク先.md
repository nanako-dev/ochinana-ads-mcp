## 0. 先に結論（この章で一番効く 12 点）

1. **Meta には Google の「ランディング ページの利便性」に当たる、LP を直接採点する公開の指標が無い。** 近いのは関連度診断の**コンバージョン率ランキング**（クリック後の体験を見る。01 の関連度診断の節）。Meta の LP の規定は「審査（却下するか）」と「配信の最適化（LPV・成果の見込み）」の 2 つの経路で効く〔推測。公式の部品は §3・§8〕
2. **LP の規定は 3 つの文書に分かれている。** ①広告規定の［関連度］「広告で宣伝する商品およびサービスは、ランディングページで宣伝しているものと一致する必要があります」✅ ②広告ポリシーの基本チェックリスト「リンク先が適切に機能している」「邪魔なコンテンツ（ポップアップ広告など）が含まれていない」「広告の量とサイトのコンテンツの均衡」「確実にアクセスでき、広告の内容と関連性のあるリンク先」✅ ③コミュニティ規定の［スパム］の**クローキング・誤解を招くリンク・欺瞞的なリダイレクト・ランディングページでの欺瞞的な機能・なりすまし**✅（F07-04〜06）
3. **審査はリンク先も見る。** 広告規定は「広告に関連付けられたランディングページやその他のリンク先」も審査の対象になりうると書く ✅（F07-04、34§1）
4. **「ログインしないと見られない LP」を名指しで禁じる公式の文は見つからなかった** ❓。ただしチェックリストの「確実にアクセスでき」と、LPV への最適化の利用要件「正常に機能するウェブページ」は、ログインの壁の LP を想定していない〔推測〕
5. **欺瞞的なリダイレクトは禁止**: 「期待するランディングページのコンテンツを見る条件としてアクションを要求し、完了後に URL のドメイン名が変わる」か「利用者のアクションなく実質的に別のドメインに自動でリダイレクトする」サイト ✅（F07-05）。計測のためのリダイレクトそのものを禁じる文は無いが、Meta は「ピクセル実行回数の重複は、リダイレクトによって生じる場合があります」と書く ✅（F07-22）
6. **Facebook・Instagram のアプリの外部リンクは、広告もオーガニックも既定でアプリ内ブラウザーで開く。** 利用者はシステムのブラウザーで開くことも選べる。Meta はアプリ内ブラウザーで見られたサイトの内容と行動を広告の改善に使うことがあり、止めたいサイトは robots.txt で `meta-externalads` を Disallow にする ✅（F07-07）
7. **ランディングページビュー（LPV）は「広告のリンクのクリック後に、リンク先のウェブページ・モバイルアプリ・ショップを読み込んだとき」。アプリ内ブラウザーで開いたとき、またはピクセルがあるときにトラッキングし、一部は統計モデルで推定** ✅（F07-08、F07-09）
8. **2025 年 6 月以降、インスタントエクスペリエンスは LPV に数えない** ✅（F07-09、F07-12）。△ 同じヘルプの別ページ「インスタントエクスペリエンスの指標について」は、インスタントエクスペリエンスの中で URL を読み込みピクセルが PageView・PixelInitialized・ViewContent を実行すると LPV に数える、と書く（F07-14）
9. **［ウェブサイトのリンク先を最適化］をオンにすると、Meta がホーム・商品ページ・コレクションページなどから行き先を選ぶ**（売上・ウェブサイト・シングル画像または動画のとき）✅（F07-03、04§6-1）。**LP の比較をしたい広告ではオフにする**〔推測〕
10. **公開後に URL パラメーターを変えると、広告セットが情報収集期間に戻る可能性がある** ✅（F07-21）。LP の差し替え・UTM の直しは配信中に軽くやらない
11. **読み込み速度について、Meta の広告向けの「何秒以内」という公式の数字は見つからなかった** ❓。公式に書かれているのは、クローラーが「数秒以内にクロールできるように」（F07-16）、インスタントエクスペリエンスは「標準的なモバイルウェブよりも最大で 15 倍速く読み込めます」（Meta の主張、F07-15）、LPV は読み込み完了で数える（F07-08）まで
12. **LPV への最適化は「サイトの特定のページのトラフィックを増やす」ならリンククリックより勧められ、コンバージョンに最適化して週 50 件に届かないときの代わりにもなる** ✅〔公式の推奨〕（F07-10）

## 2. リンク先の種類と選び方

### 2-1. リンク先とは ✅〔仕様〕（F07-01）

- リンク先は「顧客が広告の CTA をタップまたはクリックした後に誘導される場所」
- 例: ウェブサイト、アプリ、ウェブサイトとアプリ、電話、メッセージアプリ、Instagram プロフィール、Facebook ページ、インスタントエクスペリエンス、Facebook イベント
- 選べるリンク先は、広告セットで選んだ**コンバージョンの場所**と、広告のフォーマット・クリエイティブで決まる。「すべてのコンバージョンの場所がすべてのリンク先に対応しているわけではありません」
- リンク先を選ばないと、エラー **#2061015**（必須フィールドが入力されていない）で公開できない場合がある

| 場合 | 決まり（F07-01） |
|---|---|
| 目的がエンゲージメント | ［リンク先］を出すには、関連する CTA を選ぶ |
| 目的が売上、場所がウェブサイト | ［メインのリンク先］のドロップダウンで選ぶ。［パーソナライズされたリンク先］の機能も使える |
| 場所がメッセージのリンク先 | リンク先とコンバージョンの場所が同じ。広告で設定し直す必要は無い |
| カルーセル | カードごとに画像・動画・リンク先を選ぶ。最後のカードにページのプロフィール写真と［もっと見る］の CTA を出すなら、その URL を［リンク先］に入れる |
| コレクション | ほとんどの場合リンク先はインスタントエクスペリエンス。インスタントエクスペリエンスの作成時に必須のリンク先を入れるので、広告で選ぶ必要は無い |

### 2-2. メインのリンク先とパーソナライズされたリンク先 ✅〔仕様〕（F07-02）

- 目的が売上、コンバージョンの場所がウェブサイトのキャンペーンでは、広告の［リンク先］に［メインのリンク先］と［パーソナライズされたリンク先］が出る
- **メインのリンク先**: CTA を押したときの誘導先。ウェブサイト・インスタントエクスペリエンス・Facebook イベント
- **パーソナライズされたリンク先**: 「コンバージョンにつながる可能性が最も高い体験に誘導したり、顧客が簡単にビジネスに連絡したりできる手段を追加」する任意の機能。**ショップ、ウェブサイトのリンク先を最適化、ブラウザーアドオン、商品の閲覧**
- 「これらの機能の一部はデフォルトでオンになっている場合があり」、どれがオンかは［パーソナライズされたリンク先］の［編集］で確かめ、切り替え・プレビューできる
- 「この製品や機能はまだご利用いただけない場合があります」（段階的）

### 2-3. ブラウザーアドオン（例: インスタントフォームのアドオン）✅〔仕様〕（F07-19）

- 目的をリード、ウェブサイトのコンバージョンに最適化したとき、［リンク先］の［ブラウザーのアドオン］で［インスタントフォーム］を選べる
- 広告は **Facebook モバイルアプリにだけ配信**され、タップするとアプリ内ブラウザーでサイトが開く。フォームは**サイトの初回スクロール時にだけポップアップ**し、押さなければ最小化してフッターに移る
- 前提: Meta ピクセルの設定と、ウェブサイトの標準イベントかカスタムイベント
- ［結果］列はアドオンのリード（Meta リード）とウェブサイトフォームのリードの合計。内訳で分けられる
- ❓ ブラウザーアドオンの他の種類（電話など）の一覧はヘルプの本文で確かめていない（検索結果の抜粋に［通話］がある）

**運用の判断への効き方**
- アドオンは「サイトの上に Meta のフォームを重ねる」形。**LP の上にポップアップを出す**ことになるので、LP の A/B の結果（フォームの通過率）が Meta のフォームに食われる〔推測〕。LP を比べる期間はアドオンを両方でそろえる
- GA4 にはアドオンのリードが出ない（25§3 #15）

### 2-4. 運用の判断への効き方（リンク先の選び方）

| 問い | 選ぶもの〔推測〕 | 理由（公式の部品） |
|---|---|---|
| サイトが遅い・スマホに向かない、まず反応を見たい | インスタントエクスペリエンス（全画面、モバイル） | 「瞬時に読み込まれ」（F07-12）。ただし LPV に数えない・サイトのピクセルの外（§5） |
| サイトで成果を測り、最適化したい | ウェブサイト | ピクセル・CAPI の成果が最適化に使える（06） |
| LP そのものを比べたい | ウェブサイト＋リンク先の最適化オフ＋ブラウザーアドオンをそろえる | §6 |
| 商品数が多い EC | 売上でパーソナライズされたリンク先の［商品の閲覧］［ショップ］を検討 | F07-02（中身は 21） |

## 3. リンク先の要件と審査

### 3-1. 審査の対象とタイミング ✅〔仕様〕（F07-04、34§1）

- 広告規定: 審査は配信前に自動で行い、通常 24 時間以内。配信が始まった後に再審査を受けることもある。「画像、動画、テキスト、ターゲット設定、広告に関連付けられたランディングページやその他のリンク先といった個別の構成要素も審査対象になることがあります」
- 「弊社のポリシーには違反していないものの、品質が低い広告はパフォーマンスへの影響が生じる場合があります」（却下ではなく配信の不利）
- 再審査を起こす編集はターゲット・クリエイティブ・最適化・課金対象イベント。**リンク先の URL の変更がこのどれに入るかは、取得した本文に明記が無い** ❓〔推測ではクリエイティブの一部〕

### 3-2. 広告ポリシーの基本チェックリスト（ウェブサイト広告）✅〔公式の推奨〕（F07-06）

「ウェブサイト広告をウェブサイトにリンクする場合は、以下のことを確認」:

| 項目 | 中身 |
|---|---|
| 機能 | リンク先が適切に機能している |
| 中身 | 性的内容を示唆するコンテンツ、ショッキングなコンテンツ、誤解を招くコンテンツ、**邪魔なコンテンツ（ポップアップ広告など）**が含まれていない |
| 広告の量 | 広告の量とサイトのコンテンツの均衡が取れている |
| アクセス | **確実にアクセスでき**、広告の内容と関連性のあるリンク先になっている |
| 関連のポリシー | 「低品質または邪魔なコンテンツ、システムの回避」についての広告ポリシー |

- この表は 34§2-8 の M50 と同じ出典。34 は「却下の理由」として書き、この章は「LP を作る前の要件」として使う

### 3-3. 関連度: 広告と LP の一致 ✅〔仕様〕（F07-04）

広告規定の［製品別およびフォーマット別のポリシー］→［関連度］:
- 「広告には、宣伝する会社、製品、サービス、ブランドが明記されている必要があります」
- 「テキスト、画像、その他のメディアなど、広告の構成要素はすべて、宣伝する商品またはサービスに関連するものである必要があります」
- 「**広告で宣伝する商品およびサービスは、ランディングページで宣伝しているものと一致する必要があります**」

**運用の判断への効き方**
- 1 本の LP で複数の商品を宣伝するとき、広告の商品が LP の**ファーストビューに無い**と、一致の判断が危うくなりうる〔推測。公式は「一致」とだけ書き、位置は書かない〕
- ウェブサイトのリンク先の最適化（§6-1）で Meta がホームやコレクションページを選ぶと、「広告の商品」と「着いたページ」が一致しない場面がありうる。審査との関係は ❓

### 3-4. スパムのコミュニティ規定（リンク先に関わる部分）✅〔仕様〕（F07-05）

広告規定は［ビジネスアセットに影響する広告ポリシー］で「広告は、スパムに関するコミュニティ規定に準拠する必要があります」と書く（F07-04）。そのスパムの規定で「欺瞞的または誤解を招く URL やドメイン、アプリをシェアすること」として禁止されるもの:

| 名前 | 定義（要旨） | LP の運用で当たりうる場面〔推測〕 |
|---|---|---|

### 3-5. ログインの壁・会員限定の LP ❓

- 公式の文で「ログインを求める LP は不可」と名指しする記述は、今回読んだ広告規定・チェックリスト・スパムの規定には無い ❓
- 近い記述: チェックリストの「確実にアクセスでき」（F07-06）、LPV への最適化の利用要件「正常に機能するウェブページ、または Facebook か Instagram 上のショップ」（F07-09）、クローラーの「数秒以内にクロールできるように」（F07-16）

- 確かめ方: 審査の結果（却下の理由の文言）、アプリ内ブラウザーでログインの状態が保たれるかを自社のサイトで見る

### 3-8. LP の差し替えと学習

## 6. Advantage+ のリンク先の最適化と LP の A/B

### 6-1. ウェブサイトのリンク先の最適化 ✅〔仕様〕（F07-03、04§6-1）

- オンにすると「コンバージョンにつながる可能性が最も高いと Meta が判断した URL に基づいて」、ホームページ・商品ページ・コレクションページ・別のページに誘導しうる
- 使える条件: 目的が売上 → 広告セットのコンバージョンの場所がウェブサイト → 広告のフォーマットがシングル画像または動画、ウェブサイト URL を入れると「［ウェブサイトのリンク先を最適化］が有効になりました」（［パーソナライズされたリンク先］の中）
- 広告の［リンク先］→［パーソナライズされたリンク先］→［編集］で、いつでもオン・オフ
- 「アップデートされた広告体験を段階的に導入しています」
- 旧い「プリフェッチ（先読み）」のヘルプの URL（1514372351922333、2017 年の Meta の発表がリンクしていた）は、今はこのページに転送される（2026-11-24 にブラウザで確認）。広告のリンク先の先読みの今の仕様は ❓

### 6-2. LP の A/B を Meta でやる道（3 つ）

| 道 | やり方 | 長所 | 短所 | 出典 |
|---|---|---|---|---|
| ①Meta の A/B テスト | 広告の URL だけを変えた 2 つのバージョンを A/B テスト（変数は 1 つ）。同じ人が両方を見ないように分ける | 人単位で分かれ、Meta の結果の単価で勝ちを出す。信頼性 65% 以上 | Meta の結果の単価で比べるので、LP の CVR そのものではない〔推測〕。件数が要る | 26§4 |
| ②同じ広告セットに URL 違いの広告を 2 本 | 広告ごとにリンク先を変える | 作りが簡単 | 配信が勝ちそうな広告に寄るので、等分にならない〔推測〕。比較の信頼性は Meta が保証しない | 04§6-5（構成の推測） |
| ③LPO ツール（サイト側で振り分け） | 広告は 1 本、サイトで A・B に分ける | 媒体の配信に影響されにくい。広告の学習を分けない〔推測〕 | 計測は LPO ツール・GA4 側。Meta の最適化はどちらの LP の成果も同じ広告の成果として学ぶ〔推測〕 | — |

- Meta のヘルプは手動でオン・オフを切り替える略式のテストを勧めない（26§4-4）
- 〔推測〕①は「この LP に連れて行くと Meta の配信全体の CPA がどうなるか」、③は「来た人の CVR がどう違うか」を答える。問いが違う

### 6-3. LP の A/B を壊すもの

| 壊すもの | 何が起きるか | 印 |
|---|---|---|
| ウェブサイトのリンク先の最適化 | Meta が行き先を選ぶので、A・B の URL の比較が崩れる | ✅ 機能（F07-03）／〔推測〕効き方 |
| ブラウザーアドオン（インスタントフォーム） | LP の初回スクロールで Meta のフォームが出て、LP のフォームの通過率が変わる | ✅ 機能（F07-19）／〔推測〕 |
| Advantage+ クリエイティブのエンハンス（「ウェブサイトの概要」など、リンク先の URL から要点を取って広告に出す） | 広告側の見え方がバージョンで変わる | ✅ 機能（M-アセット-051）／〔推測〕 |
| 配信中の URL パラメーターの変更 | 情報収集期間に戻る可能性 | ✅（F07-21） |
| LPO ツールのリダイレクト型の振り分け | 読み込みが遅れ LPV が減る、ピクセルの重複、UTM・`fbclid` の欠落 | ✅ 重複（F07-22）／〔推測〕 |
| クローラー・審査にだけ A を出す設計 | クローキング（保全性システムに異なるコンテンツを提示）と見なされうる | ✅ 定義（F07-05）／〔推測〕当てはめ |

### 6-4. LPO ツールと Meta のクローラー（推測を含む）

- Meta の審査はリンク先も見る（F07-04）。FacebookExternalHit は完全性のチェックで robots.txt を迂回することがある（F07-16）
- スパムの規定のクローキングは「**意図的に**」保全性システムに違うものを見せて「**ポリシーを回避しようとする**」こと（F07-05）。〔推測〕A・B が同じ商品・同じ主張で、来た人を無作為に分けているだけなら、定義の「回避」には当たりにくい。ただし B だけに強い表現を置くと、審査で見られないまま配信される形になり、却下・制限の危険がある（34§0 と同じ考え）
- 〔推測〕安全な形: ①A・B の主張の強さをそろえる ②クローラーを特別扱いしない（どの訪問にも同じ振り分けの規則）③B を広告の審査の対象にしたいなら、B を別の広告の URL にして ① の道で比べる
- ❓ Meta のクローラーに LP の A/B のどちらを見せるべきかの公式の記述は無い（Google は G07§7 で扱う）

### 6-5. 運用の判断への効き方

- **LP を比べる期間は、リンク先の最適化・ブラウザーアドオン・ウェブサイトの概要などの自動の機能を、両方の版で同じにそろえる**（できればオフ）〔推測〕
- **A/B の判定は「Meta の結果の単価（①）」と「LP の CVR（③）」を混ぜない**〔推測〕。報告ではどちらの問いの答えかを書く
- **少額なら ③ のほうが早く差が出る**ことが多い〔推測〕。Meta の A/B テストは広告セットが分かれて件数が半分になる（26§4、§10）

### 7-1. Meta の公式に書かれていること

| LPV の定義 | クリック後にリンク先を「読み込んだとき」に数える。読み込む前に離れた回数は LPV とリンククリックの差で分かる | ✅ | F07-08 |
| LPV への最適化 | 「広告をクリックしてリンク先のウェブサイトを完全に読み込む可能性が高いと予測される利用者」に優先して出す | ✅ | F07-09 |

### 7-2. どう測るか〔推測〕（部品は公式）

| 見るもの | どこで | 読み方 |
|---|---|---|
| LPV ÷ リンククリック | 広告マネージャ（L2 LNK-02） | 読み込む前に離れた人の裏返し（F07-08）。配置・LP ごとに比べ、急に下がった週を探す |
| LPV への最適化の結果の単価 | 広告マネージャ | 同じ予算で LPV が取れなくなったら、LP の読み込みを疑う |
| 実測の速度 | PageSpeed Insights・Core Web Vitals（Google の道具。基準値は G07§2-1） | Meta の基準ではないが、速さの共通の物差し |
| アプリ内ブラウザーでの体感 | 実機で Facebook・Instagram のアプリから開く | §4-3 |

### 7-3. 運用の判断への効き方

- **速さは「審査」でなく「LPV と成果の数」として効く**〔推測〕。LPV ÷ リンククリックが同じ配置で他の LP より明らかに低いなら、速さか中継のリダイレクトを先に直す
- **LP を直したときは LPV ÷ リンククリックの前後を比べる**（25§4-4 の 2 つの率の記録）
- Google の Core Web Vitals を満たすことは Meta の配信の条件ではないが、読み込み完了の率（LPV）を上げる方向には働く〔推測〕

## 8. ランディングページビュー（LPV）の指標の定義

### 8-1. 定義 ✅〔仕様〕（F07-08、F07-09、F07-11）

| 項目 | 中身 | 出典 |
|---|---|---|
| 発生 | 利用者が広告のリンクをクリックした後、広告のリンク先の**ウェブページ・モバイルアプリ・Facebook や Instagram のショップ**を読み込んだとき | F07-09 |
| 「ランディングページ」とは | 広告の作成時に選んだリンク先 | F07-09 |
| トラッキングの条件 | 利用者が Meta のテクノロジーで**アプリ内ブラウザーを使ってリンク先のウェブページにアクセスした場合**、または**リンク先のウェブページに Meta ピクセルが実装されている場合** | F07-08 |
| 計算 | 広告がクリックされた結果としてウェブページが読み込まれたときに数える | F07-08 |
| 推定 | データが一部しかない・不足しているため直接数えられないとき、一部に統計モデルを使う。「この指標は推定値である場合があります」 | F07-08、F07-09 |
| リンククリックとの違い | LPV は「正常に読み込まれた回数」、リンククリックは「広告上のリンクがクリックされた回数」 | F07-11 |
| 合わない理由 | 「リンククリック後に、ウェブページが完全に読み込まれていない、またはアプリが開かなかった」「ランディングページに誘導しない広告の作成時に、リンククリックのリンク先を複数指定した」 | F07-11 |
| 2025 年の変更 | 2025 年 7 月から、ピクセル共有に課題のある広告主も LPV を使える。2025 年 6 月以降、インスタントエクスペリエンスは LPV に数えない | F07-09 |
| 関連の指標 | ランディングページビューの単価、リンククリック、CPC（リンククリックの単価）、CTR（リンククリックスルー率） | F07-08、F07-11 |

### 8-2. LPV への最適化 ✅〔仕様〕〔公式の推奨〕（F07-09、F07-10）

- 「広告セットをランディングページビューに最適化すると、広告をクリックしてリンク先のウェブサイトを完全に読み込む可能性が高いと予測される利用者に広告が優先的に表示されるようになります」「トラフィックの質を向上させるのに有効な方法」
- 利用要件: 「正常に機能するウェブページ、または Facebook か Instagram 上のショップ」
- 使い分け（ベストプラクティス）:

| 目的 | Meta の推奨 |
|---|---|
| サイトの特定のページのトラフィックを増やす | リンククリックより LPV への最適化 |
| コンバージョンを増やす | まずコンバージョンに最適化。ただし週およそ 50 件以上が要る。届かないなら LPV への最適化が効果的な選択肢になりうる。ファネル下部のイベント（購入など）をピクセルに設定していない場合にも使える |
| Facebook ページや動画へ誘導する形式（クーポン・Messenger など） | LPV ではなく、Facebook ページへのアクセス数の最大化 |

- 対象の広告アカウントでは、LPV についての推奨が最適化スコアに出る。最適化スコアは実際・今後のパフォーマンスを表さず、保証しない（F07-09、F07-10）

### 8-3. △ と ❓

- △ **ピクセルの要否**: 「ウェブサイトランディングページビュー指標」はアプリ内ブラウザー**または**ピクセルでトラッキングと書く（F07-08）。「インスタントエクスペリエンスの指標について」はインスタントエクスペリエンスから先の LPV に「ピクセルを作成してインストールし、キャンペーンの作成時に選択する必要」と書く（F07-14）。既存のロジックツリー L2 LNK-02 は「ピクセルが LP に無ければ数えられない」と書く（§12 で報告）
- ❓ アプリ内ブラウザーでピクセルの無いページの LPV を、Meta が何をもって「読み込み完了」と判定するか（ページの load のイベントか）は書かれていない
- ❓ システムのブラウザー（利用者が外のブラウザーで開いた場合）でピクセルが無いときに数えるかは、F07-08 の文の範囲では数えない読みになる〔推測〕

### 8-4. 運用の判断への効き方

- **LPV の率（LPV ÷ リンククリック）は、LP の速さ・リダイレクト・誤クリックの面の比率の 3 つで動く**（L2 LNK-02・03）。配置の内訳で見て、面の構成の変化と LP の変化を分ける〔推測〕
- **LPV は推定を含む**（F07-08）。小さな差（数 %）で LP の良し悪しを決めない〔推測〕
- **トラフィックの目的で LP の検証をするなら、最適化は LPV、行き先はウェブサイト**（インスタントエクスペリエンスは数えない、F07-09）。04§6-5 の「LP ごとに広告を分け、広告セットは 1 つ」と組み合わせる

## 10. 少額・少量のアカウントでの注意

- **LP の A/B を Meta の A/B テスト（①）でやると、件数が半分ずつになり 65% に届きにくい**（26§4）。少額ならサイト側の振り分け（③）で LP の CVR を比べ、Meta 側は 1 本の広告で学習を分けない〔推測〕
- **URL パラメーター・リンク先の差し替えで情報収集期間に戻る損が大きい**（F07-21）。LP の改修は URL を変えずに中身を差し替える形を選ぶ〔推測〕。ただし表現の強化は審査の危険（§3-8）
- **件数が週 50 件に届かないなら LPV への最適化も選択肢**と Meta は書く（F07-10）。ただし LPV に最適化すると「読み込みまで行く人」に寄り、成果まで行く人とは限らない（L2 CPC-上-06 の注意）。LP の検証の期間だけ、と決めて使う〔推測〕
- **少額では LPV の率の小さな差は推定の揺れ**（F07-08）。週の LPV が数十なら、率の 1 割の差は判断に使わない〔推測〕

## 11. 判断の型

| 症状・問い | 最初に見るところ | 次の手 |
|---|---|---|
| リンククリックは多いのに LPV が少ない | LPV ÷ リンククリックの推移、配置の内訳、リダイレクトの数、ピクセル | 速さ・中継を直す。誤クリックの面なら最適化を LPV 以上に（L2 LNK-02・03） |
| LPV が急に 0 | 行き先をインスタントエクスペリエンスにしたか（2025-06 から数えない）、ピクセル | 行き先を確かめる（F07-09） |
| LP の A/B で LPO ツールと Meta の数字が逆 | リンク先の最適化・アドオン・ウェブサイトの概要がオンか、比べている問いが違うか | 自動の機能をそろえ、問いを分ける（§6） |
| LP を差し替えたら却下 | 差し替えた表現、スパムの 7 種、一致 | 34§5 の直し方 |
| 却下は無いが配信が細い | 品質（F07-04）、コンバージョン率ランキング | クリック後の体験を直す（01） |
| 会員向けの広告で CVR が低い | ログインの壁、アプリ内ブラウザーでのログインの状態 | ログイン前に内容が分かるページへ（§3-5、§4-3） |
| サイトが遅く、すぐに直せない | インスタントエクスペリエンスを試す | 測り方の違いを報告に書く（§5-5） |
| サイトの内容を Meta に使わせたくない | robots.txt | `meta-externalads` を Disallow（F07-07）。審査のクロールは止まらない〔推測〕 |
| Google の「LP の利便性」を Meta でも見たい | 関連度診断 | Meta に同じ指標は無い。コンバージョン率ランキングと LPV の率で見る（§1） |

## 13. よくある思い込みと実際

| 思い込み | 実際 | 印と出典 | 効く場面 |
|---|---|---|---|
| Meta にも LP の利便性の評価がある | 公開の LP の指標は無い。クリック後はコンバージョン率ランキング | ✅ 01／§1 | 改善の優先 |
| LP の速さは Meta の審査に関係する | 秒数の基準は公式に無い。速さは LPV と成果の数で効く | ❓／〔推測〕 | LP の改善 |
| LP は Safari と Chrome で確かめれば十分 | 既定はアプリ内ブラウザー | ✅ F07-07 | 入稿前の確認 |
| インスタントエクスペリエンスも LPV に数える | 2025-06 から数えない（別のページに △） | ✅ F07-09／△ F07-14 | トラフィックの目的 |
| LPV はピクセルが無いと出ない | アプリ内ブラウザーで開いた分は数える | ✅ F07-08 | 計測 |
| リダイレクトは計測のためなら自由 | 別ドメインへの自動のリダイレクトは欺瞞的なリダイレクト。重複の発火も起きうる | ✅ F07-05、F07-22 | 計測の中継 |
| 離脱防止のポップアップは自由 | 関係のないポップアップは「トラッピング」として禁止。邪魔なポップアップもチェックリストで不可 | ✅ F07-05、F07-06 | LP の作り |
| ログインの壁の LP は禁止と明記されている | 名指しの記述は見つからない。「確実にアクセスでき」の要件はある | ❓ F07-06 | 会員サイト |
| URL 違いの広告を 2 本並べれば LP の A/B になる | 配信が偏る。Meta は手動の略式テストを勧めない | 〔推測〕・26§4-4 | 検証の設計 |
| リンク先の最適化は LP の A/B と両立する | Meta が行き先を選ぶので比較が崩れる | ✅ 機能 F07-03／〔推測〕 | LPO |
| robots.txt で meta-externalads を止めれば Meta はサイトを見ない | 広告の改善に使わない指示。完全性のチェックのクロールは robots.txt を迂回しうる | ✅ F07-07、F07-16 | データの方針 |
| インスタントエクスペリエンスは 15 倍速いので常に良い | Meta の主張で条件の記載なし。LPV に数えず、サイトの成果は先のサイトで決まる | ✅ 主張 F07-15／〔推測〕 | 形式の選択 |
