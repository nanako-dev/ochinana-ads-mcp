## 0. 先に結論（この章で一番効く 10 点）

1. **広告の「名義」は広告ごとに選ぶ層で、Facebook ページ・Instagram アカウント・Threads のプロフィール・WhatsApp の名義の 4 つがある**。広告マネージャでは広告レベルの［名義］で選ぶ。Instagram と Threads の広告には、作成の内部でページの ID も使うが、**ページの情報は Instagram・Threads の広告のどこにも出ない** ✅〔仕様〕（D:Create Instagram ads、D:Threads Ads Creation、H:272348126756182）
2. **Instagram アカウントが無くても、Facebook ページを Instagram 広告の発信元にできる**。開発者文書の言い方では「ページを裏付けにした影の Instagram アカウント」（Page-backed Instagram account、PBIA）で、ページと同じ名前・プロフィール写真で出る。**ただしその名義ではコメントに返信できず、投稿もできない**（コメントの閲覧・削除はできる）✅〔仕様〕（H:272348126756182、H:1603906456518352、D:Set Up Instagram Accounts With Pages）
3. **逆に「ページなし」で出せるのは Instagram の配置だけ**。API では Instagram のプロアカウントを Instagram ログインでつなぎ、`publisher_platforms` を `instagram` だけにして、クリエイティブに `instagram_user_id` を入れ `page_id` を入れない。Facebook など他のプラットフォームを含めると広告の作成でエラーになる。広告マネージャの手順は［名義］でページをリンクすることから始まり、ページなしの手順はヘルプに無い ❓。Instagram アプリから初めて宣伝するときは、Facebook の広告アカウントにつながず「Facebook と Instagram を分けて」使う道がある ✅〔仕様〕（D:Set Up Instagram Accounts Without Pages、H:841305768920698、H:272348126756182）
4. **Instagram アカウントの持ち方は 3 通り**（ビジネスポートフォリオに入れたアカウント＝推奨、ページにつないだアカウント、PBIA）。ページにつないだアカウントは、**ページの「広告主」以上の権限があれば Instagram 側の権限なしで広告にできる**が、そのページ以外と組み合わせられない。1 ページにつなげる Instagram アカウントは 1 つ、PBIA も 1 つ ✅〔仕様〕（D:Set Up Instagram Accounts With Pages・On Business Manager）
5. **Threads の名義は 3 種＋ネイティブ**。Instagram と同じユーザーネームの Threads アカウント、Instagram が裏付けの Threads アカウント、ページが裏付けの Threads アカウント（2026-04-21 から）。**2026-09 から、ユーザーネームの一致が要らなくなり、Instagram を運用していないビジネスも Threads のプロフィールで直接出せる**（段階的）。Threads のプロフィールが無ければ Instagram、それも無ければページが使われる ✅〔仕様〕（D:Threads Ads Guides、H:615196104221050、H:655859553779869）
6. **Threads のプロフィールを持たずに Instagram やページで出した Threads 広告は、返信への返信・削除・非表示ができない**。API の返信の管理（2026-03-25〜）も、**Instagram が裏付け・ページが裏付けの Threads アカウントの広告と、投稿の宣伝（ブースト）・Advantage+ カタログ広告では使えない**。使えても**直接の返信だけ・文字の返信だけ** ✅〔仕様〕（H:615196104221050、D:Reply Moderation）
7. **既存の投稿を広告にする**: 広告マネージャで［広告設定］→［既存の投稿を使用］。**投稿 ID は URL からコピーした番号を使わず、ページの投稿一覧の［ID］列の番号を使う**。Instagram ストーリーズは**アクティブなものだけ**（アーカイブ・ハイライトは不可）。**広告の側で電話番号などを変えると元の投稿も変わる** ✅〔仕様〕（H:374756690038600）
8. **著作権のある音楽やフィルターなどインタラクティブな要素を含む投稿は広告にできない**。Instagram の投稿はフィードの写真・動画・カルーセル・リール、アクティブなストーリーズ、商品タグ付きの投稿が対象で、IGTV は不可。**既存の Threads のオーガニック投稿は広告にできない**（Facebook・Instagram の投稿を Threads に出すことは 2026-04-21 から可）✅〔仕様〕（D:Use Posts as Instagram Ads、D:Promote Existing Posts as Threads Ads）。△ ただしヘルプの Threads の「利用できない機能」の表は［Instagram の投稿を宣伝する］を非対応に挙げる（§5-5）
9. **投稿の宣伝（ブースト）も広告で、請求書でも広告として出る**。ただし目的・配置・ターゲット・クリエイティブの選択肢が狭く、**ヘルプはブーストの最適化を「ページへのいいね！・コメント・シェア・ブランドの認知」に限ると書く**（同じ記事の別の段落は「問い合わせ・ウェブサイトへのアクセス」の目標も挙げる △）。**iOS の Instagram アプリで残高を足すと、Apple のサービス料 30% がかかることがある**（instagram.com なら避けられる）✅〔仕様〕（H:317083072148603、H:841305768920698）
10. **Facebook の広告のコメントは、ページに設定した「単語のブロック」と「不適切な言葉のフィルター」が広告にも効く**（ページから広告へ拡大適用）。Instagram の広告の投稿は API で読む・隠す・消す・返信でき、**既存の投稿から作った広告ではオーガニックと広告のコメントが一緒に返る**。ストーリーズと Advantage+ カタログ広告ではコメントの管理が使えない ✅〔仕様〕（H:297350055160110、D:Post Moderation）

## 1. Google との対比（短く）

| 論点 | Google 広告 | Meta 広告（この章） |
|---|---|---|
| 広告に出る「出し手」 | 名義の層は無い。検索・P-MAX・デマンド ジェネレーションでは「ビジネス名」アセット（半角 25・全角 12）とロゴ（`../Google広告の基礎/12_デマンドジェネレーション.md`、`10_PMAX.md`）。広告主の確認の名前は広告の透明性センターに出る | 広告ごとに選ぶ**名義**（ページ・Instagram・Threads・WhatsApp）。名前とプロフィール写真がそのまま広告の頭に出る（§2） |
| 名義の持ち物 | アカウントとは別の資産は要らない（YouTube の動画広告は動画をチャンネルに置く） | ページや Instagram は**ビジネスポートフォリオの資産**で、広告アカウントとは別に権限を渡す（27§2〜§3） |
| 既存のオーガニックの投稿を広告に | YouTube の動画を広告に使う道はあるが、投稿の「宣伝」の仕組みは知識ベースに無い ❓ | 既存の投稿を使用・投稿の宣伝（ブースト）・投稿 ID（`object_story_id`・`source_instagram_media_id`）（§5・§6） |
| 広告へのコメント | 検索・ディスプレイの広告にはコメント欄が無い。YouTube の動画広告にはコメントが付く（G11） | Facebook・Instagram・Threads の広告はすべて「投稿」で、コメント・返信が付く。管理の手段は名義の種類で変わる（§7） |
| 名義の変更 | ビジネス名アセットの差し替え | ページ名・ユーザーネームの変更は資産の側で行い、PBIA とページ裏付けの Threads は自動で追随する（§9） |

**取り違えやすい点**: Google の運用者は「広告アカウント＝出し手」と考えがちだが、Meta では**広告アカウント（お金と配信の器）と名義（ページ・Instagram）は別の資産**で、別々に権限を渡す。代理店の広告アカウントから依頼主のページの名義で出すのがふつうで、ページの側の権限が無いと公開が止まる（04§3-2）。

## 2. 名義の種類と組み合わせ

### 2-1. 4 つの名義 ✅〔仕様〕（H:272348126756182、H:615196104221050、D:Create Instagram ads、D:Threads Ads Guides、D:WhatsApp identity）

| 名義 | 何に出るか | API の項目 | ないとき |
|---|---|---|---|
| Facebook ページ | Facebook・Messenger・Audience Network の広告。Instagram・Threads・WhatsApp の広告でも内部で使う | `object_story_spec.page_id`（読み出しでは `actor_id`＝ページ ID） | Facebook の配置には出せない（§3） |
| Instagram アカウント | Instagram の広告（フィード・ストーリーズ・発見・リール・発見ホーム・検索結果） | `object_story_spec.instagram_user_id`（「Instagram actor ID」） | ページを発信元にする（PBIA。§4-3） |
| Threads のプロフィール | Threads フィード | `threads_user_id`（`object_story_spec` の中か、リクエストの最上位） | Instagram、それも無ければページが使われる（§2-3） |
| WhatsApp の名義 | WhatsApp ステータス | `wamo_whatsapp_identity_spec`（`wamo_whatsapp_identity_id` か `whatsapp_phone_number`。両方なら同じ WhatsApp ビジネスプロフィールに属すこと） | 指定しなければ**ページの名義が既定**（`PAGE_BACKED`）。指定しないと一部の広告が WhatsApp ステータスに出ないことがある |

- 広告マネージャでは、広告レベルの**［名義］**でページ → Instagram アカウント → Threads アカウントの順に選ぶ。Instagram の欄には、リンクしたページが Instagram 広告の発信元として自動で選ばれ、Instagram アカウントを足すなら［アカウントをリンク］✅（H:272348126756182）
- **Instagram・Threads の広告には「ページの ID」が要るが、ページの情報は広告のどこにも出ない**。クリエイティブを作ると、ページに**未公開の投稿**ができる（ページの「宣伝できる投稿」の一覧から見える）✅（D:Create Instagram ads、D:Threads Ads Creation）
- WhatsApp ステータスの配置は **Instagram ストーリーズも選んでいるときだけ**使え、ステータスだけのキャンペーンは今は不可。形式はシングル画像・シングル動画 ✅（D:WhatsApp identity。05§10-2・66 と同じ）

### 2-2. Instagram の名義の 3 通り（API の言い方）✅〔仕様〕（D:Create Instagram ads、D:Set Up Instagram Accounts With Pages・On Business Manager）

| 種類 | 作り方 | 広告に使う条件 |
|---|---|---|
| ビジネスポートフォリオの Instagram アカウント（**推奨**） | Instagram のビジネスアカウントを作り、ビジネスポートフォリオでユーザーネームとパスワードで所有を申請 → 広告アカウントを割り当てる | 割り当てた広告アカウントで広告を出せる人は、その Instagram でも広告を出せる |
| ページにつないだ Instagram アカウント（Page-connected） | Instagram のビジネスアカウント（プロフィール画像あり・非公開でない）を Facebook ページにつなぐ。「小さなビジネス向けの簡単な方法」 | ページの `advertiser` 以上の権限があれば、**Instagram 側の権限は要らない**。クリエイティブの `page_id` はそのページでなければならない |
| ページが裏付けの Instagram アカウント（PBIA、影のアカウント） | API で `POST /<PAGE_ID>/page_backed_instagram_accounts`（ページの `ADVERTISER`・`MANAGER`・`CONTENT_CREATOR` のどれか） | ページと同じ名前・写真。ログインできない。§4-3 |

### 2-3. Threads の名義 ✅〔仕様〕（D:Threads Ads Guides、D:Threads Ads Creation、H:615196104221050、H:655859553779869、H:1140692603898291）

| 種類 | 中身 | 条件・期限 |
|---|---|---|
| Instagram に関連付いた Threads アカウント | 同じビジネスポートフォリオに**同じユーザーネームの Instagram アカウント**がある | **2026-01-29 より前に作った Threads アカウントは自動でポートフォリオに入った**。それ以降に作ったものは手で追加する。クリエイティブの `instagram_user_id` は同じユーザーネームの Instagram |
| Instagram が裏付けの Threads アカウント | Instagram アカウントが、そのために作った Threads アカウントの代わりに広告を出す（API で作る影のアカウント。ログインできない） | `POST /<IG_USER_ID>/instagram_backed_threads_user`。既にあれば既存の ID が返る |
| ページが裏付けの Threads アカウント | ページが、そのために作った Threads アカウントの代わりに広告を出す。**ページの名前とプロフィール写真を写し、変わると追随する** | **2026-04-21 から**（D:OCC 2026）。`POST /<PAGE_ID>/page_backed_threads_accounts`。ページの `ADVERTISER` 以上。ページの Instagram アカウントが Instagram 広告を出せること |
| ネイティブの Threads プロフィール | 自分の公開の Threads プロフィール | **2026-09 から、Threads と Instagram のユーザーネームの一致が不要に**。Instagram を運用していないビジネスも Threads のプロフィールで直接出せる（段階的）（H:615196104221050、H:655859553779869） |

- 1 つの Instagram アカウントにつなげるのは、関連付いた Threads アカウント 1 つと、Instagram が裏付けの Threads アカウント 1 つ。1 つのページにつなげるのは、ページが裏付けの Threads アカウント 1 つ ✅（D:Threads Ads Guides）
- 広告マネージャで Threads のプロフィールが既定で使われるのは、**公開の Threads プロフィールがあり、同じビジネスポートフォリオに Instagram プロフィールかページがあって、利用者に広告のアクセス許可がある**とき。自動で入らなければ［名義］の［Threads アカウント］で選ぶ ✅（H:615196104221050）
- **Threads のプロフィールが無いとき**: Instagram のプロフィールがあればそれが既定、無ければページ。複数あるなら［名義］で選び、［Threads アカウント］の下に［Instagram アカウントを使用］か［Facebook ページを使用］が出る ✅（H:615196104221050）
- **Meta Business Suite で Threads 広告を出す・Threads アカウントを管理するには、同じポートフォリオの Instagram と Threads のユーザーネームの一致が要る** ✅（H:615196104221050。広告マネージャとは条件が違う）
- **広告を出す Threads プロフィールにはプロフィール写真が要る**。無いと Threads に配信されない ✅（H:655859553779869）
- Threads の配置の条件: △ **開発者文書は「Threads の `threads_stream` を選ぶには Instagram の `stream`（フィード）も選ぶ」と書く**。**ヘルプは「Instagram フィードか Facebook フィードのどちらか 1 つと一緒に選ぶ。両方は要らない」と書く**（H:615196104221050、H:655859553779869 ／ D:Threads Ads Creation）。管理画面ではヘルプの書き方、API では開発者文書の書き方と読むのが無難〔推測〕。既存の `M-配置-002` は開発者文書の書き方
- Threads 広告で使える目的: ヘルプは「すべての目的が Threads に対応、一部のコンバージョンの場所とパフォーマンス目標は非対応」と書き、非対応の表を持つ（例: トラフィックのメッセージアプリ・プロフィールへのアクセス・通話、リードのインスタントフォーム、エンゲージメントのイベントへの参加）✅（H:655859553779869）。△ 開発者文書の対応表は `OUTCOME_AWARENESS`・`OUTCOME_TRAFFIC`・`OUTCOME_ENGAGEMENT`・`OUTCOME_SALES` の 4 つだけを挙げる（D:Threads Ads Creation。2026-02-17 のアプリ広告の対応〔D:OCC 2026〕も表に反映されていない）
- Threads の配信量: 「テストと学習のあいだ、Threads の広告の量を意図して低く保っている」✅（D:Threads Ads Guides、D:Threads Ads Insights）

### 2-4. 名義ごとの「できる・できない」早見表 ✅〔仕様〕（§2-1〜§2-3、§4、§7 の出典を合わせた表）

| 名義の持ち方 | Instagram／Threads の配置に出せる | Facebook の配置に出せる | 名義で投稿できる | 名義でコメントに返信 | コメントの閲覧・削除 |
|---|---|---|---|---|---|
| ページ＋ポートフォリオの Instagram | ✅ | ✅ | ✅（アプリ） | ✅（アプリか API） | ✅ |
| ページ＋ページにつないだ Instagram | ✅ | ✅ | ✅（アプリ） | ✅（アプリか API） | ✅ |
| ページだけ（PBIA） | ✅（ページの名前と写真） | ✅ | **できない** | **できない** | ✅（広告マネージャか API） |
| Instagram だけ（ページなし、API の道） | Instagram だけ | **できない**（エラー） | ✅（アプリ） | ❓（D に記載なし。Instagram のアプリからは可能と読める〔推測〕） | ❓ |

### 2-5. 運用の判断への効き方

- **API で入稿する道具を作るときは、`page_id` と `instagram_user_id` の組み合わせの決まり（ページにつないだ Instagram はそのページとだけ、PBIA もそのページとだけ）を入力の点検に入れる**〔推測〕（✅ の決まりから）

## 3. ページなしで出せるか

### 3-1. 道ごとの答え ✅〔仕様〕（D:Set Up Instagram Accounts Without Pages、H:272348126756182、H:841305768920698、H:793315701035887、H:615196104221050）

| 道 | ページなしで出せるか | 条件 |
|---|---|---|
| 広告マネージャ | **記載なし** ❓。ヘルプの手順は「広告レベルでは、まず［名義］で Facebook ページをリンクする必要があります」から始まる | ページなしの手順はヘルプに無い |
| Marketing API（Instagram API with Instagram Login でつないだ依頼主） | **できる。ただし Instagram の配置だけ** | 下の §3-2 |
| Instagram アプリ・instagram.com からの宣伝 | **できる**（Instagram のプロアカウントが要る） | 初めて宣伝するとき、リンクする広告アカウントを選ぶよう求められ、**既存の Facebook 広告アカウントを選ぶか、Facebook と Instagram を分けて使う**かを選べる |
| Threads 広告 | Threads のプロフィールが無くても出せる（Instagram かページを使う）。2026-09 からは Instagram が無くても Threads のプロフィールで直接（段階的） | §2-3 |
| Facebook ページの訪問広告・店舗所在地・イベント広告 | **できない**（ページそのものが宣伝の対象） | `promoted_object.page_id` が必須（D:Facebook Page Visit Ads。30 章） |

### 3-2. API でページなしの Instagram 広告を作る決まり ✅〔仕様〕（D:Set Up Instagram Accounts Without Pages）

- 依頼主は **Instagram のプロアカウント**を、Instagram ログインの統合（Instagram API with Unified Login）でアプリにつなぐ。設定は**広告アカウントと `ads_management` の権限**を求めること（［Create new configuration］の既定の設定に入っている）
- つなぐとき、依頼主は共有する Instagram のプロアカウントと広告アカウントを選び、アプリは**ビジネス統合システムユーザーのアクセストークン**を受け取る。以後のリクエストはすべてこのトークン
- ID の取得: `me/assigned_instagram_accounts`（Instagram）と `me/adaccounts`（広告アカウント）
- 広告セット: **`publisher_platforms` は `instagram` だけ**。`instagram_positions` で面を選べ、指定しなければ Instagram のすべての面に出る。**`facebook` など他を含めると、ページなしのクリエイティブを使う広告の作成でエラー**
- クリエイティブ: `object_story_spec` に `instagram_user_id` を入れ、**`page_id` を入れない**。**`object_story_spec` には `instagram_user_id` か `page_id` のどちらかが要り、どちらも無いと失敗**
- 既存の Instagram 投稿を使うなら、`instagram_user_id` と `source_instagram_media_id` を入れ、`object_id`（ページ ID）を入れない
- 読み出し: ページなしのクリエイティブでは `actor_id`・`object_id`・`page_id`・`effective_object_story_id` が返らない
- プレビュー（`generatepreviews`）のクリエイティブの指定にも `page_id` は要らない。作成後は、ほかの Instagram 広告と同じくインサイトの取得と `<AD_ID>/copies` での複製ができる

### 3-3. Instagram アプリからの宣伝で分かっていること ✅〔仕様〕（H:841305768920698、H:793315701035887、H:317083072148603）

- 宣伝した投稿は［発見］・ホームフィード・発見フィード・プロフィールフィード・ストーリーズに出る。**商品タグを含むフィード投稿も宣伝できる**
- アプリから宣伝すると、**オーディエンスと配置のオプションは自動で設定される**。instagram.com でもアプリと同じ機能が使える
- **iOS の Instagram アプリで広告アカウントに利用可能残高を足すと、合計支払い額（課税・地域の手数料の前）の 30% の Apple のサービス料がかかる場合がある**（受け取るのは Apple）。iOS でリールを宣伝するときは利用可能残高での支払いが要る。避けるには instagram.com を使う
- EU・EEA・スイスの利用者は、広告なしのサブスクリプションか低パーソナライズ広告の体験のアカウントセンターに入っていると、広告の機能が制限される
- 米国を拠点にする、または米国を狙う事業者が信用・雇用・住宅・社会問題・政治の広告を作るときは、［特別な広告カテゴリ］を選ぶ（23§10）
- 宣伝を出すと広告ポリシーで審査され、提出・審査開始・承認か却下・終了のときにお知らせが来る

### 3-4. 運用の判断への効き方

- **「ページを作りたくない」依頼主には、Instagram だけの配信になると先に伝える**。Facebook・Messenger・Audience Network、店舗所在地（30 章）、ページの訪問広告は使えない〔推測〕（§3-1 ✅ から）。Advantage+ 配置の前提（全配置に出して安く取る）も崩れる（01§9）
- **依頼主がアプリで「Facebook と分けて」宣伝を始めていたら、広告マネージャでの管理に移せるかを確かめる** ❓（移し方・移したときに過去の広告がどうなるかは今回の出典に無い）。引き継ぎの前に、依頼主の Instagram の［宣伝］の履歴と支払いの方法を聞く〔推測〕
- **iOS アプリで宣伝している依頼主は、30% の手数料を払っている可能性がある**。費用の点検で「残高の追加の経路」を確かめ、instagram.com か広告マネージャに寄せる〔推測〕（✅ の仕様から）

## 4. Instagram アカウントの使い方（ページの Instagram の代わりに）

### 4-1. 3 通りの比較 ✅〔仕様〕（D:Set Up Instagram Accounts With Pages の比較表）

| 要件 | ポートフォリオの Instagram | ページにつないだ Instagram | PBIA（ページが裏付け） |
|---|---|---|---|
| 広告主が Instagram アカウントを持つ必要 | ある | ある | **ない** |
| ビジネスポートフォリオの設定が要る | 要る | 要らない | 要らない |
| Facebook の画面での手作業 | 要る（ポートフォリオに Instagram を申請） | 要る（ページに Instagram をつなぐ） | 要らない |
| 投稿（メディア）を足せる | できる（アプリ） | できる（アプリ） | **できない** |
| その Instagram の名義でコメント | できる（アプリか Marketing API） | できる（アプリか Marketing API） | **できない** |
| 広告の投稿のコメントを API で読む・消す | できる | できる | できる |
| ユーザー所有の広告アカウントで出す | **できない** | できる | できる |
| ビジネス所有の広告アカウントで出す | できる | できる | できる |

### 4-2. ポートフォリオの Instagram（推奨）✅〔仕様〕（D:Set Up Instagram Accounts On Business Manager）

- 手順: ①Instagram のビジネスアカウントを作る ②ビジネスポートフォリオで所有を申請（**そのアカウントのユーザーネームとパスワードが要る**）③（任意）代理店をパートナーに割り当てる ④広告アカウントを Instagram に割り当てる ⑤ Instagram アカウントの ID を取る
- 広告アカウントの割り当ては API でもでき（`POST /<IG_USER_ID>/authorized_adaccounts`、ビジネスの `ADMIN` 以上）、割り当てられる広告アカウントは**そのビジネスが所有する**か、**Instagram を所有するビジネスが所有していて、自社のビジネスがアクセスできる**もの。**A 社の広告アカウントを B 社の Instagram に割り当てることはできない**（両方に管理者のアクセスがあっても）
- **Instagram アカウントから直接、人に権限を渡すことはできない**。Instagram につながるページかビジネスに権限を渡す。Instagram にリンクした広告アカウントで広告を出す権限のある人は、その Instagram でも広告を出せる
- 旧 `InstagramUserID` のエンドポイントは v22.0 で非推奨、**2025-04-21 に全バージョンで非推奨**。Instagram プラットフォームの `IGUserID` を使う
- 一覧の取得: `{business_id}/instagram_accounts`、`act_{adaccount_id}/instagram_accounts`、`{page_id}/instagram_accounts`（旧 Connection Objects では見えない）。`{ad_account_id}/connected_instagram_accounts`・`{business_id}/instagram_business_accounts` もある（D:Use Posts as Instagram Ads）

### 4-3. PBIA（ページを Instagram の名義にする）✅〔仕様〕（D:Set Up Instagram Accounts With Pages、H:272348126756182、H:1603906456518352）

- ヘルプの言い方: 「Instagram アカウントをお持ちでない場合でも、Facebook ページを Instagram 広告の発信元として使用して Instagram 広告を掲載できます」。勧める理由として「時間に余裕がない場合、ビジネス用の Instagram アカウントを設定する必要はありません」
- 開発者文書の言い方: 「Facebook ページのために広告を出しているように動くが、その広告を出すために影の Instagram アカウントを作る」。広告とオーガニックを別の Instagram アカウントで出したい広告主にも使える
- **1 ページに PBIA は 1 つ**。既にあれば作成の呼び出しは既存の ID を返す。ページにアクセスできる人は PBIA にもアクセスできる。広告アカウントを PBIA に割り当てる必要はない
- **名前とプロフィール写真はページと同じ。ページ名・写真を変えると影のアカウントも自動で変わる**（§9）
- **ログインして投稿を管理できない**。広告の投稿のコメントといいね！は、①クリエイティブの `instagram_permalink_url` で投稿を見る ②広告マネージャでコメントを見る・消す ③Post Moderation API で読む・消す、のどれか。**PBIA の名義で投稿・コメントはできない**

### 4-4. ページにつないだ Instagram ✅〔仕様〕（D:Set Up Instagram Accounts With Pages）

- Instagram のビジネスアカウントで、**プロフィール画像があり、非公開アカウントでない**こと
- つないだ後、ページの設定の画面でつながりは見えるが Instagram の ID は見えない。ID はページのアクセストークンで `GET /<PAGE_ID>/instagram_accounts`
- **ページの `advertiser` 以上の権限があれば、Instagram 側の権限なしで広告を出せる**。個人・ビジネスどちらの広告アカウントでも、アクセスがあれば使える
- クリエイティブには `instagram_user_id` と `page_id` を入れ、**ページにつないだ Instagram は、そのページの ID でしか使えない**

### 4-5. 運用の判断への効き方

- **代理店が依頼主の Instagram を「ユーザーネームとパスワードを預かって」ポートフォリオに申請するのは避ける**〔推測〕。申請にはパスワードが要る（✅）ので、依頼主のポートフォリオで申請してもらい、代理店にはパートナーとして資産を共有してもらう（27§3-4）
- **「広告用の Instagram を別に作る」かわりに PBIA を使える**が、名義で返信できないので、広告のコメントは「消す・隠すだけ」になる。問い合わせが来やすい広告ではメッセージの導線（63）を別に用意する〔推測〕
- **ユーザー所有の広告アカウント（個人の広告アカウント）から出している小さな依頼主は、ポートフォリオの Instagram を使えない**（✅）。ページにつなぐか PBIA にするか、ビジネス所有の広告アカウントへ移すかを選ぶ〔推測〕

## 5. 既存の投稿を広告にする

### 5-1. 広告マネージャでの手順と決まり ✅〔仕様〕（H:374756690038600）

1. 目的を選び、キャンペーンを設定する
2. 広告セットの［コンバージョン］で［コンバージョンの場所］を選ぶ: アプリ（アプリ広告）／電話（電話発信広告）／メッセージアプリ（メッセージ誘導広告）／**あなたの広告**（動画の視聴、投稿やイベントへのアクション）／ウェブサイト。**目的が認知度のときはこの欄が出ない**
3. 広告の［名義］で Facebook ページと Instagram アカウントを選ぶ
4. **［広告設定］のドロップダウンで［既存の投稿を使用］**
5. ［クリエイティブ］→［投稿を選択］
6. コールトゥアクションを選び、電話番号やウェブサイトのリンクなど、広告の種類に要る情報を足す

| 決まり | 中身 |
|---|---|
| 投稿 ID | **URL からコピーした投稿 ID は使わない**。ページ投稿で宣伝する投稿を見つけ、**［ID］列の投稿 ID**を使う |
| Instagram ストーリーズ | **アクティブなストーリーズだけ**選べる。アーカイブしたもの・ハイライトに足したものは選べない |
| 目的との相性 | 既存の投稿の中には、選んだ目的に対応しないものがある。**投稿に目標の違う CTA があると、その投稿で広告を作れない**（例: ［購入する］の CTA が付いた投稿は電話発信広告に使えない） |
| 広告の側で変えたもの | **電話番号の追加など広告の詳細を変えると、選んだ既存の投稿の情報も変わる**。投稿に CTA があれば［削除］で、作成中の広告と既存の投稿の両方から消せる（公開に CTA が要る広告では［削除］が出ない） |
| テキスト | 既存の投稿から作った広告はテキストを編集できない（`M-アセット-013`） |

### 5-2. API の項目 ✅〔仕様〕（D:Ad Creative、D:Use Posts as Instagram Ads、D:Create Instagram ads、D:Post-Processing）

| 項目 | 中身 |
|---|---|
| `object_story_id` | **Facebook ページの投稿の ID**。形は `<投稿の持ち主の ID>_<投稿の ID>`（ページなら `<PAGE_ID>_<POST_ID>`）。投稿に画像があれば **8 MB を超えない**こと。画像は広告アカウントの画像ライブラリに取り込まれる |
| `object_story_spec` | 広告を作るときに、ページの**未公開の投稿**を同時に作る指定。このとき `object_story_id` は null で、**`effective_object_story_id` は未公開・オーガニックを問わずその投稿の ID** |
| `source_instagram_media_id` | 広告に使う **Instagram の投稿の ID**（Instagram Graph API の media・stories のエンドポイントで取る）。作成済みのクリエイティブの元の投稿は `{ad_creative_id}/source_instagram_media_id` で分かる |
| `boost_eligibility_info` | Instagram の投稿が広告にできるか（ブーストできるか）を確かめる項目 |
| `is_instagram_eligible` | Facebook の投稿が Instagram の広告に使えるか。`true` なら作れる。「すべての Facebook の投稿が Instagram 広告として動くわけではない」 |
| 未公開の投稿の取り出し | `object_story_spec` で作った投稿は `/promotable_posts` に `include_inline=true` を付けると返る（`false` なら ID を返さない） |
| 投稿が消えたとき | 作成・編集の後処理で、クリエイティブが `WITH_ISSUES` になり、`issues_info` にエラー **1815869「Ad post is not available」**（広告に関連する Facebook の投稿が使えない。削除されたか、見る権限が無い） |

- Instagram の投稿を広告にするときの例は `object_id`（ページ ID）＋`instagram_user_id`＋`source_instagram_media_id`。Facebook の投稿を Instagram 広告にするときは `object_story_id`＋`instagram_user_id`（ページにつないだ Instagram か PBIA）✅
- Facebook の投稿を `instagram_user_id` 付きで宣伝し、広告セットに Facebook と Instagram の両方の配置があると、「Creative is missing DOF spec」などのエラーが出ることがある。直し方は `asset_feed_spec` に `"optimization_type": "DOF_MESSAGING_DESTINATION"` を足す ✅（D:Use Posts as Instagram Ads のトラブルシューティング。メッセージの CTA の例）

### 5-3. どの投稿が広告にできるか ✅〔仕様〕（D:Use Posts as Instagram Ads、D:Promote Existing Posts as Threads Ads、H:374756690038600）

| 元の投稿 | 広告にできるもの | できないもの |
|---|---|---|
| Instagram | フィードのシングル写真・動画・カルーセル・リール（タグ付きの写真・動画も可）、**アクティブなストーリーズ**、商品タグ付きのフィード画像・カルーセル・既存の動画 | **IGTV の投稿**、**著作権のある音楽やフィルターなどインタラクティブな要素を含む投稿**、アーカイブ・ハイライトのストーリーズ（ヘルプ） |
| Facebook | フィードの投稿・ストーリーズ（Instagram に出すなら `is_instagram_eligible` が `true` のもの） | 目標の違う CTA が付いた投稿（目的と合わない） |
| Threads | — | **既存の Threads のオーガニック投稿は広告にできない** |
| Facebook・Instagram の投稿を Threads に | 画像・動画・**画像だけの**カルーセル（2026-04-21 から） | パートナーシップ広告（ブランドコンテンツ）としての宣伝は Threads に非対応 |

- パートナー・クリエイターの投稿を広告にする条件（コード・許可・アーカイブした投稿の扱い・クリエイターの編集の禁止）は **67§3** にある。ここでは重ねない

### 5-4. 既存の投稿の広告の「エンゲージメント」の行き先 ✅〔仕様〕／❓

- **Threads に出した Facebook・Instagram の投稿の広告では、Threads の広告に付いたいいね！やコメントは元の投稿に戻らない** ✅（D:Promote Existing Posts as Threads Ads）

### 5-6. 運用の判断への効き方

- **反応のよいオーガニック投稿を広告にすると、社会的な証明（いいね・コメント）が残ったまま配信できる**。ただし広告の側で電話番号などを変えると元の投稿も変わる（✅）ので、「投稿を直さずに広告だけ変える」はできない〔推測〕
- **音楽付きのリールは広告にできないことがある**（著作権のある音楽 ✅）。オーガニックで流行の音源を使った投稿を「後で広告に回す」計画は立てない。広告に回す前提の投稿は、Meta のサウンドコレクションなど広告で使える音源で作る〔推測〕（音源の一覧は 03 の［音楽を追加］）
- **入稿の道具では、投稿 ID は［ID］列の値を使う**（URL の番号は使わない ✅）。API なら `<PAGE_ID>_<POST_ID>` の形を確かめる
- **配信中の広告の元の投稿を消すと、広告が `WITH_ISSUES` になる**（エラー 1815869 ✅）。ページの投稿の整理をする担当に、広告に使っている投稿の一覧を渡す〔推測〕

## 6. 投稿の宣伝（ブースト）と広告マネージャの広告

### 6-1. 何が違うか ✅〔仕様〕（H:317083072148603）

- **投稿の宣伝**＝Facebook ページや Instagram アカウントで公開済みの既存のコンテンツ（投稿・ストーリーズ・リール動画など）から作った広告。「Facebook・Messenger・Instagram の投稿でより多くの利用者にリーチする最も簡単な方法」
- **投稿の宣伝も有料の広告**。「より広範なオーディエンスにシェアするための予算が必要だから」。**請求書では、投稿の宣伝は広告として出る**
- 宣伝で決めるもの: 目標（問い合わせ・エンゲージメント・ウェブサイトへのアクセスなど）、広告テキスト（既存のテキストのまま、または**複数のテキストのバリエーションを足して Meta に出し分けさせる**）、開始日と終了日（または予算を使い切るまで）、予算、配置
- Meta Business Suite で投稿の宣伝を**日時指定**できる
- 新しい投稿を作るとき、［公開］の代わりに［宣伝］を押すこともできる

| 比べる点 | 投稿の宣伝 | 広告マネージャ・Business Suite の広告 |
|---|---|---|
| 最適化 | **ページへのいいね！・コメント・シェア・全体的なブランドの認知だけ**（△ 同じ記事は「ウェブサイトクリック、ページのエンゲージメント、ローカルビジネスの宣伝にフォーカスできる」とも書き、目標の例に「問い合わせ・ウェブサイトへのアクセス」を挙げる） | アプリのインストール、ウェブサイトのコンバージョン、動画の再生、ショップの注文など。目的は「リード」「アプリの宣伝」「売上」なども |
| 配置 | チェックボックスで Facebook（モバイル・デスクトップのフィード）と Instagram を選ぶ | 右側広告枠、Messenger、Instagram ストーリーズ、WhatsApp ステータス、Audience Network などから選べる |
| クリエイティブ | 既存の投稿のまま | カルーセル、説明の追加、特定の曜日・時間帯で予算を増やす、など |
| ターゲット | 趣味・関心、年齢、性別 | 重なるオーディエンスの種類、類似オーディエンス、Advantage+ クリエイティブなど。詳細ターゲット設定の一部は広告マネージャだけ |

- 使い分け（Meta の言い方）: ページでのエンゲージメントやブランドの認知を高めたいなら投稿の宣伝が最適、高度な広告の種類は Business Suite か広告マネージャで ✅〔公式の推奨〕
- 2026-03 から、Facebook フィードの配置に［Facebook の友達］タブが入る ✅（同じ記事の注）

### 6-2. Instagram からの宣伝の 5 つの道 ✅〔仕様〕（H:793315701035887、H:841305768920698）

### 6-4. 運用の判断への効き方

## 7. 広告へのコメント・返信の管理

### 7-1. Facebook の広告 ✅〔仕様〕〔公式の推奨〕（H:297350055160110）

- ブランドは Facebook に出る広告のコメントをモデレーションできる。「一部の機能は、特定の地域のみで段階的にリリース」
- **単語のブロック**と**不適切な言葉のフィルター**を有効にすると、その単語・言葉を含むコメントが**非表示**になる。**機能はページ単位で設定し、ページから広告へ拡大適用される**。不適切な言葉のフィルターは強さを変えられ、**ページが公開するすべての広告に効く**
- 受信箱のコメントのモデレーションの道具で、特定の単語を含む投稿・コメントをブロックできる。**絵文字にも対応**し、文字と同じく扱われる
- Meta の推奨（ベストプラクティス）:
  1. 否定的・好意的なコメントのどちらにもできるだけ対応する
  2. 不適切な言葉のフィルターを有効にする
  3. 受信箱のコメントのモデレーションの道具で特定の単語をブロックする
  4. ページ設定・広告マネージャ・サードパーティの API パートナーの道具で**定期的に**コメントを見る
  5. 非表示になったコメントを見直し、そのまま・表示・削除を決める
  6. コミュニティ規定に違反しそうなコメントを報告し、スパムを続ける利用者をブロックする

### 7-2. Instagram の広告 ✅〔仕様〕（D:Post Moderation、D:Set Up Instagram Accounts With Pages）

- **`instagram_user_id` 付きのクリエイティブは、その Instagram アカウントに 1 つの投稿（Instagram Stream post）を作る**。API でその投稿にアクセスし、コメントを足す・見る・一部を消すことができる
- クリエイティブには `instagram_permalink_url`（投稿の URL。ウェブで見るので、［広告］表示や CTA が無く、複数画像のカルーセルも出ない＝実際の見え方とは違う）と `effective_instagram_media_id` がある
- コメントの種類: **オーガニック**（オーガニックの投稿へのコメント）と**非オーガニック**（広告のメディアへのコメント）
  - **既存の投稿を宣伝・ブーストした広告**: `effective_instagram_media_id` でも `source_instagram_media_id` でも、`/comments` は**両方**を返す
  - それ以外の広告: `effective_instagram_media_id` は**非オーガニックだけ**
  - 配置アセットカスタマイズなど複数のメディアを持つ広告は、`/ordered_comments`（Instagram の表示順。全メディアのコメントを含みうる）
- Instagram Graph API でできること: コメントの作成・読み取り・**非表示と再表示**・削除（追加の権限が要る）
- **使えない場面**: Instagram ストーリーズ（コメントのできる投稿ではない）、**Advantage+ カタログ広告**（テンプレートのクリエイティブでは `effective_instagram_media_id` が働かない）。年齢制限のあるメディアとコメントは今は取得できない（文書は Graph API の方法を使うよう書く）
- **PBIA の広告**: 名義でコメントできない。コメントは広告マネージャか API で見る・消す（§4-3）

### 7-3. Threads の広告 ✅〔仕様〕（D:Reply Moderation、H:615196104221050、D:OCC 2026）

- **2026-03-25 から、Threads 広告の返信を見る・隠す・返信できる**（D:OCC 2026）
- **Threads のプロフィールを持たず、Instagram かページで出した Threads 広告では、コメントへの返信・削除・非表示ができない**（「現時点では」）（H:615196104221050）

| API の決まり | 中身 |
|---|---|
| 対応する広告 | シングル画像、シングル動画、カルーセル、配置アセットカスタマイズ、静的な投稿、既存の投稿 |
| **対応しない広告** | **Advantage+ カタログ広告、ブーストした投稿、Instagram が裏付け・ページが裏付けの Threads アカウントが作った広告** |
| 取れる・返せる範囲 | **広告のメディアへの直接の返信だけ**。返信への返信（入れ子）は取得も返信もできない |
| 返信の形 | **文字だけ**。画像・動画・カルーセルの返信は不可 |
| 権限 | 広告を持つ広告アカウントの `ads_read`（メディアと返信の読み取り）、`ads_management`（隠す・返信） |
| 読む | `GET /{media-id}`（`caption`・`like_count`・`reply_count`・`share_count`・`quote_count`・`repost_count`・`hide_status` など）、`GET /{media-id}/replies` |
| 隠す・戻す | `POST /{reply-id}/manage_reply`、`hide=true`／`false`。**隠すと公開の表示から消えるが、削除はされない**。状態は `hide_status` の `HUSHED`／`UNHUSHED` |
| 返信する | `POST /{reply-id}/add_reply`、`text` が必須 |
| 削除 | API の文書に削除の手段は書かれていない ❓ |

### 7-4. Advantage+ クリエイティブの「関連の高いコメント」

- 成果を上げそうなコメントを広告の下に目立たせる機能は 03（関連の高いコメント、`inline_comment`）と 31§5 にある。批判的なコメントが選ばれない保証は書かれていない ❓（03 の記述）。ここでは重ねない

### 7-5. 運用の判断への効き方

- **広告の前に、ページの「単語のブロック」と「不適切な言葉のフィルター」を設定する**。ページ単位の設定が広告にも効く（✅）ので、広告ごとに設定する手間は無い。薬機法・景品表示法に触れる言葉（「治る」「痩せる」など）を依頼主と一緒に一覧にして入れる〔推測〕
- **名義ごとに「誰が・どこで・何時までにコメントを見るか」を決める**: Facebook はページの受信箱か広告マネージャ、Instagram は Instagram のアプリか API、Threads は Threads のプロフィールがあるときだけ。PBIA と Threads のプロフィールなしの広告は返信できないので、問い合わせは別の導線へ〔推測〕（§2-4 ✅ から）
- **Threads の返信は「隠す」で、消すのではない**（✅）。報告書に「削除した」と書かない
- **API で自動のモデレーションを組むなら、Advantage+ カタログ広告・ストーリーズ・ブーストの広告は対象外**（✅）。点検の表に「コメントを自動で見られない広告」の行を作る〔推測〕
- **既存の投稿から作った Instagram 広告は、オーガニックのコメントと混ざる**（✅）。依頼主の SNS 担当とコメントの担当を分けていると、二重に対応したり漏れたりする〔推測〕

### 9-2. 公式で確かめられなかったこと ❓

- **Facebook ページの名前の変更の手順・審査・回数や間隔の制限**: ビジネスヘルプセンターの検索（「ページの名前を変更」）では該当の記事が出ず、Facebook ヘルプセンター（facebook.com/help）の検索はログインなしでは結果が出なかった。**第三者の記事は「変更はリクエストして審査される」「一定の期間は戻せない」と書くが、日数は記事によって違う**〔実務家・仮説〕。判断の根拠にしない。確かめ方: ログインした状態で Facebook ヘルプセンターの「Facebook ページの名前を変更する」を読む
- **Instagram のユーザーネーム・表示名を変えたときの、配信中の広告・Threads の関連付けへの影響** ❓。Instagram に関連付いた Threads アカウントが「同じユーザーネーム」を条件にしていたことから、2026-09 の変更が届いていないアカウントでは関連付けが外れるおそれがある〔推測〕
- **名義をあるページから別のページへ差し替えたとき、過去の広告の反応（いいね・コメント）や関連度診断が引き継がれるか** ❓
- ページの名前の変更が広告の審査（ページの名前とランディングページの一致など）にどう効くか ❓（34 の審査の章にも記載なし）

### 9-3. 運用の判断への効き方

- **ブランド名を変える依頼主は、ページ名の変更を広告の切り替えより先に終わらせる**〔推測〕。PBIA とページ裏付けの Threads は自動で追随する（✅）が、ページ名の変更そのものに審査があるかは ❓ なので、日程に余裕を取る
- **配信中の広告の名義は差し替えず、新しい名義の広告を足して古いものを止める**〔推測〕。クリエイティブの変更は大幅な編集（✅）で、どちらにしても学習はやり直しになる。差し替えると過去の反応がどうなるか ❓ なので、比べられる形を残す
- **ページを消す前に、そのページで作ったオーディエンスを使っている広告セットを洗い出す**（新しい広告セットに使えなくなる ✅）

## 10. 判断の型

### 10-1. 名義を決める問い（新しい依頼主）〔推測。各分岐の根拠は ✅ の仕様〕

```
Facebook ページはあるか？
├─ ない → Instagram のプロアカウントはあるか？
│    ├─ ある → Instagram だけで出す（API のページなしの道か、アプリの宣伝）。Facebook・店舗所在地・ページの訪問は不可（§3）
│    │          → 全配置に出したいなら、ページを作って Instagram をつなぐ
│    └─ ない → ページを作る（店舗があるなら店舗ページの構造も＝30 章）
└─ ある → Instagram アカウントはあるか？
     ├─ ない → PBIA で Instagram に出す（返信できない）。返信が要るなら Instagram を作ってつなぐ（§4）
     └─ ある → ポートフォリオに入れる（推奨）か、ページにつなぐ。
                 → 広告アカウントはユーザー所有か？ 所有ならポートフォリオの Instagram は使えない（§2-4）
Threads に出すか？（既定で入る）
├─ 返信の管理が要る → Threads のプロフィールを作り、ポートフォリオに入れる（2026-01-29 以降は手で追加）
└─ 要らない → Instagram かページの名義で出る（返信・削除・非表示は不可）
```

### 10-2. 「この投稿を広告にしたい」と言われたら

| 問い | 見る所 |
|---|---|

| 音楽・フィルター・IGTV か | 著作権のある音楽・インタラクティブな要素・IGTV は不可（§5-3） |
| ストーリーズなら、まだアクティブか | アーカイブ・ハイライトは不可（§5-1） |
| 投稿に CTA が付いているか | 目的と違う CTA なら、その目的の広告にできない（§5-1） |

## 12. よくある思い込みと実際

| 思い込み | 実際 | 根拠 |
|---|---|---|
| Instagram に広告を出すには Instagram アカウントが要る | ページを発信元にできる（PBIA）。ただし名義で返信・投稿はできない | §4-3 ✅ |
| ページが無くても広告マネージャで全配置に出せる | ページなしで出せるのは Instagram の配置だけ（API）。広告マネージャの手順はページのリンクから始まる | §3 ✅ |
| Google と同じく、広告アカウントの権限があれば誰の名前でも出せる | 名義（ページ・Instagram）は別の資産で、ページの「広告主」以上の権限などが別に要る | §2・§4 ✅、27§3 |
| Instagram と Threads の広告にはページの名前も出る | ページの ID は内部で使うが、ページの情報は Instagram・Threads の広告のどこにも出ない | §2-1 ✅ |
| Threads のオーガニック投稿もブーストできる | 既存の Threads のオーガニック投稿は広告にできない | §5-3 ✅ |
| Threads 広告の返信はいつでも管理できる | Threads のプロフィールが無いと返信・削除・非表示とも不可。API はブースト・Advantage+ カタログ・影の Threads アカウントに使えない | §7-3 ✅ |
| Threads の返信を「削除」した | API でできるのは「隠す」（削除されない） | §7-3 ✅ |
| 投稿 ID はブラウザの URL の番号 | URL からコピーした ID は使わず、ページ投稿の［ID］列の値。API は `<PAGE_ID>_<POST_ID>` | §5-1・§5-2 ✅ |
| 既存の投稿から作った広告の電話番号を変えても、元の投稿は変わらない | 元の投稿の情報も変わる | §5-1 ✅ |
| ブーストは広告ではないので、広告の数字や請求とは別 | ブーストも広告で、請求書でも広告として出る。審査も受ける | §6-1 ✅ |
| ブーストでも購入に最適化できる | ヘルプはブーストの最適化をいいね！・コメント・シェア・認知に限ると書く（同じ記事の目標の例とは △） | §6-1 ✅／△ |
| インスタのアプリで宣伝すれば手数料は同じ | iOS のアプリで残高を足すと Apple のサービス料 30% がかかることがある | §3-3 ✅ |
| 広告のコメントのフィルターは広告ごとに設定する | ページ単位の単語のブロック・不適切な言葉のフィルターが、ページの広告すべてに効く | §7-1 ✅ |
| ストーリーズ広告のコメントも API で管理できる | ストーリーズはコメントのできる投稿ではなく、管理の対象外 | §7-2 ✅ |
| 音楽付きのリールもあとから広告にできる | 著作権のある音楽やフィルターを含む投稿は広告にできない | §5-3 ✅ |
