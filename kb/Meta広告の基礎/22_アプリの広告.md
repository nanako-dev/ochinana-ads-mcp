## 0. 先に結論（この章で一番効く 12 点）

1. **アプリを Meta for Developers に登録し、広告アカウントをアプリにリンクしないと、インストールに最適化できない。** 登録しなくても「アプリの宣伝」の広告は出せるが、**自動でリンククリックに最適化**される ✅〔仕様〕本文（F22-01）
2. **インストール・アプリイベント・価値に最適化するには、Facebook SDK を入れてアプリイベントを足すか、MMP にリンクする。** 測るのにも SDK（か MMP・API）が要る ✅〔仕様〕本文（F22-01・F22-04）
3. **Advantage+ アプリキャンペーンのパフォーマンス目標は 4 つ**: アプリのインストール数・リンククリック数・アプリイベント数・コンバージョン値の最大化（価値は［購入］だけ、入札は最小単価だけ）。ターゲットは国・言語・OS だけで、性別・興味関心・カスタムオーディエンスの追加・類似は使えない ✅〔仕様〕本文（F22-02・F22-03）
4. **一度に最大 50 点の画像・動画・プレイアブル・インスタントエクスペリエンスを上げられ、テキストと見出しは最大 5 件。** 月に数回クリエイティブを更新し、入札価格上限は設定しないのが推奨 ✅〔仕様〕〔公式の推奨〕本文（F22-02・F22-05）
5. **iOS 14 以降用キャンペーンは、アトリビューションの手法を AEM か SKAdNetwork から選ぶ。** 各キャンペーンは最適化 1 種類、**アプリあたり最大 24 キャンペーン**（同じページの配信ステータスの説明は「手動キャンペーンが 18 件」△）。購入方法はオークションだけ ✅〔仕様〕本文（F22-06）
6. **SKAdNetwork の結果は少なくとも 24 時間遅れ、キャンペーン単位の集計で届く。** 広告セット・広告の内訳は統計モデル（1 広告セット・1 広告なら使わない）。1・7・28 日のクリックとビューの窓は使えず、A/B テストはキャンペーン単位だけ ✅〔仕様〕本文（F22-07）
7. **AEM を手法にした iOS 14 以降用キャンペーンは、ほぼリアルタイムで報告され、アプリイベントの最適化では 7 日クリックの窓と Audience Network を使える。** 2024-10-09 から MMP に AEM のレポートを送る ✅〔仕様〕本文（F22-08・F22-09）
8. **価値の最適化（アプリ）の要件は「過去 7 日に値のあるアプリ内購入 15 件以上」。** アプリ内の広告インプレッションの価値は「過去 28 日に 2 種類以上の値で 15 件以上」。イベントマネージャで［コンバージョン値の最大化］をオンにし、要件を満たしてから使えるまで数週間かかる場合がある ✅〔仕様〕本文（F22-10）
9. **価値の最適化の最適化ウィンドウは 1 日・7 日・28 日クリックから選ぶ。28 日はアプリ内購入だけ。** 最初のテストは 3 週間以上、週 50 件以上を目指し、最初は ROAS 目標なし ✅〔仕様〕〔公式の推奨〕本文（F22-11・F22-12）
10. **アプリのイベント名は 1,000 種類まで、1 イベントの項目（パラメータ）は 25 まで、名前は 2〜40 文字の英数字、値は 100 文字まで。** カスタムイベントは広告レポートで「その他のモバイルアプリアクション」にまとめられる。MMP と SDK の両方で同じイベントを送ると二重に数える ✅〔仕様〕本文（F22-13）
11. **ディープリンクは計測には使わない。** ヘルプは「7 日分のデータしか入手できない」「クリックしか確認できない」と書き、MMP を勧める。後で入れた人をアプリ内の決まった画面に送る「ディファード（遅延）ディープリンク」は SDK が要り、iOS の SKAdNetwork キャンペーンでは API で付けられない ✅〔仕様〕本文（F22-14・F22-15）
12. **アプリのインストールの重複は「直近 90 日で 1 回だけ」帰属させる。** 最初のインストールを残し、後は捨てる（経路を問わない）。CAPI for App Events ではインストールの重複除外を自分で組む必要は無い ✅〔仕様〕本文（F22-16、`24§4-5`）

## 2. 仕組みの全体像

### 2-1. 部品 ✅〔仕様〕本文（F22-04・F22-01）

開発者文書「Overview」が挙げる部品:

| 部品 | 役目 |
|---|---|
| 広告キャンペーン | 目的「アプリの宣伝」（旧「アプリのインストール」。名前が変わっても動作は同じ）で作る。Marketing API か広告マネージャ |
| アプリ | Meta for Developers に登録し、ビジネスポートフォリオと広告アカウントにつなぐ。登録しないとリンククリックに最適化される |
| アプリイベント | アプリの中の行動を記録する（SDK・コード不要のイベント設定ツール・API・MMP） |
| App Ads Helper | 最新のインストールイベント、アプリイベントとディープリンクの動作を確かめる道具 |
| Meta Business SDK・コンバージョン API・パートナー連携 | アプリのインストール以外の目的（売上など）でアプリのイベントを使うときに要る |

- 広告アカウントをアプリにリンクするのは、アプリの開発者か、登録したアプリの管理者権限を持つ人。［アプリダッシュボード］→ アプリ →［アプリ設定］→［詳細設定］✅〔仕様〕本文（F22-01）
- アプリの設定を終えた直後は**リンククリック（`LINK_CLICK`）にしか最適化できない**。インストールや購入、D2・D7 の定着（インストールから 2 日・7 日後にまた開く）に最適化するにはイベントを足す ✅〔仕様〕本文（F22-17）

### 2-3. 目的ごとのアプリの最適化（広告セットのリファレンスの ODAX 表）✅〔仕様〕本文（F22-19）

| 目的 | コンバージョンの場所 | 選べる最適化（API） |
|---|---|---|
| アプリの宣伝（Advantage+ でない） | — | `LINK_CLICKS`・`APP_INSTALLS`・`APP_INSTALLS_AND_OFFSITE_CONVERSIONS`（アプリイベント）・`VALUE` |
| アプリの宣伝（Advantage+、表では AAA） | — | `APP_INSTALLS`・`APP_INSTALLS_AND_OFFSITE_CONVERSIONS`・`VALUE` |

### 2-4. 運用の判断への効き方

- **最初の 1 週間で「アプリの登録 → 広告アカウントのリンク → SDK か MMP → イベントの確認（App Ads Helper）」を終わらせる。** どれかが抜けると、広告は出ても**リンククリック**に最適化されたまま回る（気づきにくい）
- **カルーセルで素材を 2 枚しか用意しないと作れない。** アプリは 3 枚から
- **既存の利用者への広告（再エンゲージメント）は、Advantage+ アプリキャンペーンでは作れない。** 売上・リード・エンゲージメントの目的でリンク先をアプリにし、AEM の対象か確かめる（§6-4）

### 2-5. Google との違い

Google はアプリ キャンペーンが「種類」で、インストールとエンゲージメントが別の種類。Meta は目的「アプリの宣伝」でインストール側だけを持ち、エンゲージメントは他の目的（コンバージョンの場所＝アプリ）に散らばる。

## 3. Advantage+ アプリキャンペーン

### 3-1. 何か ✅〔仕様〕本文（F22-02、`13§4-4`）

- 旧名は Automated App Ads（AAA）。今は Advantage+ カタログ広告と統合され、「アプリのインストール数を最大化するための最も効果的な手法として設計」。Meta AI が**入札戦略・ターゲット・広告の配置**を自動で最適化
- 開発者文書は「キャンペーン・広告セットの作り方に変更は無く、動的な機能はクリエイティブにだけ入る」と書き、商品セット（`product_set_id`）を広告のクリエイティブに入れてカタログ広告にできる ✅〔仕様〕本文（F22-20）
- 旧 AAC（`smart_promotion_type=SMART_APP_PROMOTION`）は v25.0 から全バージョンで作れない、v26.0 で編集できない。移行は同じ ID のままだけ（`04§6-3`、`13§15`）

### 3-2. できること・できないこと ✅〔仕様〕本文（F22-02）

| できる | 決まり |
|---|---|
| 広告の一括作成 | 1 つの広告セットで、**一度に最大 50 点**の広告。複製は不要 |
| クリエイティブ | アップロードできる数に制限なし。**一度に最大 50 件**の画像・動画・プレイアブル・インスタントエクスペリエンス。**テキストと見出しは最大 5 件**。カタログから画像を選べる |
| 配置 | Advantage+ 配置（Facebook・Messenger・Instagram・Audience Network） |
| オーディエンス | 国・言語・アプリストアの組み合わせ。キャンペーンどうしが同じオーディエンスを奪い合わない作り |
| キャンペーンの数 | 宣伝するアプリごとに「いくつでも必要な数だけ」（例: 1 つは登録完了、1 つはカートへの追加）。ただし **SKAdNetwork と AEM のキャンペーンの制限は引き続き適用**（§5-3） |
| 最適化 | インストール・アプリイベント・価値 |
| 入札 | 最小単価（入札価格上限の追加は任意） |
| レポートの内訳 | 年齢・性別・年齢と性別・国・インプレッションデバイス・プラットフォーム・プラットフォームとデバイス・配置。Android 向けなら指定マーケット地域（DMA） |

| できない | 代わり |
|---|---|
| 性別・利用者層・興味関心・行動・**カスタムオーディエンスの追加**・**類似オーディエンス** | 国・言語・OS はキャンペーンで指定できる。アカウントの広告設定で最低年齢・地域の追加と除外。アプリ広告設定でカスタムオーディエンスの除外、アプリのアトリビューションの設定 |
| トラフィック・エンゲージメント・リード・売上の目的のモバイルアプリのエンゲージメント広告 | ふつうのキャンペーンで作る |
| 特定の配置のインサイト | 配置の選択を作成時に変えられないため。内訳の「配置」は見られる |

- ティーンには使えない（最低年齢を自動で調整）（`23` の 388 行）

### 3-3. パフォーマンス目標（4 つ）✅〔仕様〕本文（F22-03・F22-05）

| パフォーマンス目標 | 最適化とターゲット | 主な KPI | 注 |
|---|---|---|---|
| アプリのインストール数の最大化 | インストールへの最適化と幅広いターゲット | インストール単価 | — |
| リンククリック数の最大化 | リンククリックと任意のターゲット | リンククリックの単価 | — |
| アプリイベント数の最大化 | アプリイベントの最適化と任意のターゲット | イベント単価 | — |
| コンバージョン値の最大化 | 価値の最適化と任意のターゲット | 広告費用対効果 | **最適化イベントは［購入］だけ、入札は［最小単価］だけ** |

- 「国、言語、オペレーティングシステムは同じまま、パフォーマンス目標だけを変更してテスト」を推奨 ✅〔公式の推奨〕本文（F22-03）

### 3-4. ベストプラクティス ✅〔公式の推奨〕本文（F22-05）

- 入札: **最小単価で、入札価格上限は設定しない**。上限はコストを抑えるが、長く回すほど広告の機会と結果の数を制限しうる
- クリエイティブ: 一度に最大 50 点。**数多く上げ、月に数回更新して広告疲れを防ぐ**。プレイアブル・インスタントエクスペリエンスも使う
- 情報収集期間中は変更しない
- 同じオーディエンスに Advantage+ アプリキャンペーンを同時に配信しない（重複で配信効率が落ちる）
- 適しているかを確かめるには、まず制限付きの設定と Advantage+ オンの設定で A/B テスト

### 3-5. 運用の判断への効き方

- **「誰に出すか」を細かく決めたい依頼は、Advantage+ アプリキャンペーンでは叶わない。** カスタムオーディエンスの追加も類似も使えない。除外（既存の利用者を外す）はアプリ広告設定で
- **キャンペーンを分ける軸は「最適化イベント」と「国」。** 同じ国を複数のキャンペーンで狙わない（重複）。iOS 14 以降用では数の上限もある（§5-3）
- **素材の量と更新の頻度が運用の中心。** 50 点まで一度に入り、月に数回の更新が推奨。Google の G22 の「アセットを上限まで入れる」と同じ方向

### 3-6. Google との違い

Google のアプリ キャンペーンは広告グループ単位でアセットを分け、目標単価で入札する。Meta の Advantage+ アプリキャンペーンは広告セット 1 つに素材を集め、上限なしの最小単価が推奨の基本。

## 4. アプリのイベント

### 4-1. 3 種類と、送る方法 ✅〔仕様〕本文（F22-21・F22-13）

| 種類 | 中身 |
|---|---|
| 自動で記録されるイベント | SDK がインストール・アプリのセッション・アプリ内購入を自動で記録 |
| 標準イベント | Meta が用意した名前（購入、カートに追加、レベル達成など） |
| カスタムイベント | アプリ独自の名前 |

- 1 つのイベントは `name`（必須）・`valueToSum`（任意。同じ名前の値を合算）・`parameters`（任意）でできる
- 送る方法: Facebook SDK（iOS・Android・Unity）、コード不要のイベント設定ツール（イベントマネージャで画面の要素を選んでイベントにする）、App Events API（サーバーから）、MMP からサーバー間で、CAPI for App Events（`24§4-5`）
- **SDK か API か**（FAQ）: SDK は手間が少なく、アプリの版・名前・利用時間・セッション数などを自動で付け、Android の広告 ID・IDFA の取得と広告トラッキングの制限を扱う。ただし**イベントを足すにはアプリの新しい版を出す**必要がある。API は版を出さずに足せるが、広告トラッキングの制限と ID の取得を自分で扱い、利用の指標は自動で付かない ✅〔仕様〕本文（F22-13）
- サーバーからまとめて送るときは、`X-Forwarded-For` ヘッダーで端末の IP を送る ✅〔仕様〕本文（F22-22）

### 4-2. 上限 ✅〔仕様〕本文（F22-13・F22-21）

| 項目 | 上限 |
|---|---|
| イベント名の種類 | **1,000**（超えると新しい種類は記録されず、`100 Invalid parameter` のエラー。古いイベントは無効化できる。**削除はできない**） |
| 1 イベントの項目（パラメータ） | **25**（呼び出しごとではなく、そのイベント名の全部の呼び出しで） |
| イベント名・項目名 | **2〜40 文字の英数字** |
| 項目の値 | **100 文字**まで |
| イベントの量 | 上限なし |

- 上限を超える典型: レベルごとに別のイベント名（Level Achieved 1、2…）を作る。1 つのイベント「レベル達成」に項目 `level` を付けるのが正しい ✅〔公式の推奨〕本文（F22-13）
- **広告レポートに出るのは標準イベントだけ。** カスタムイベントは「その他のモバイルアプリアクション」にまとめられ、内訳が出ない ✅〔仕様〕本文（F22-13）
- よくある誤り（FAQ）: 購入の通貨・値を付け忘れる、小数点の位置、小数点にカンマ、平均の注文額を決め打ちで入れる ✅〔仕様〕本文（F22-13）

### 4-3. 自動のアプリ内購入の記録 ✅〔仕様〕本文（F22-13）

- Android は SDK 4.36 以上、iOS は 3.22 以上で、アプリダッシュボードの設定をオンにする
- 記録されるのは**チェックアウト開始・購入・購入のキャンセル**。製品 ID・数量・合計額・通貨・商品名・説明が自動で付く
- すでに購入を自分で記録しているなら、オンにすると二重に数えうる（自分の記録を止める）
- アプリ内購入（ストアの課金）だけで、それ以外の購入には使えない

### 4-4. MMP と SDK の併用 ✅〔仕様〕本文（F22-13・F22-23）

- MMP を使っているなら、MMP にイベントをサーバー間で Meta へ送ってもらえる
- MMP の SDK と Facebook SDK の両方を入れてよいが、**同じイベントを両方から送ると二重に数える**
- インストールだけ MMP から、ほかのイベントは Facebook SDK から、という分け方は可
- 開発者文書は、生涯価値の計算などで第三者を使いたいなら、Meta が提携する MMP（Meta ビジネスパートナーの測定の分野）を使えると書く。Meta が推奨するのは SDK での計測 ✅〔仕様〕本文（F22-23）
- CAPI for App Events では、SDK・MMP・App Events API の既存の連携との重複を、`event_id` と `event_name` で除く（ウェブと同じ）。インストールは除外の仕組みが既にあり、**直近 90 日で 1 回**だけ帰属 ✅〔仕様〕本文（F22-16）
- ❓ Meta の公式ページで、提携する MMP の名前（AppsFlyer・Adjust など）の一覧は今回読めていない。`24` の 152 行はパートナー連携の例として AppsFlyer・Adjust・Segment を挙げる。確かめ方: Meta の Business Partner Directory（solutions-explorer の measurement）

### 4-5. CAPI for App Events で今回足したこと（項目の表は `24§4-5`）✅〔仕様〕本文（F22-16）

- `campaign_ids`: Facebook のリンクをクリックしたときに外向きの URL かディープリンク（アプリの AEM 用）に付く、暗号化された文字列。モバイルアプリのエンゲージメントのキャンペーンでディープリンクから渡る
- `custom_vendor_id`: 広告主か MMP が作った端末の ID（MMP の予備の ID を含む）。Apple の IDFV は `vendor_id` に入れる。既存の ID をこの欄に移すときは値・形式・大文字小文字を変えない
- `install_referrer`: 第三者のインストールリファラー（今は Android だけ）

### 4-6. 運用の判断への効き方

- **イベント名の設計は最初に決める。** 1,000 種類の上限と、削除できないことがあるので、「レベル 1」「レベル 2」を別のイベントにしない
- **最適化に使うイベントは標準イベントを優先する**〔推測〕。カスタムイベントはレポートで内訳が出ない。ただしアプリイベントの最適化のヘルプは「カスタムイベントを標準イベントにマッチングしているなら、カスタムイベントに直接最適化を推奨」と書く（§7-1）。レポートの見やすさと最適化の精度のどちらを取るか決める
- **MMP を入れたら、二重送信を最初に点検する**（MMP の管理画面で Meta への送信イベントの一覧と、Facebook SDK の自動記録を照らす）

## 5. iOS の扱い（iOS 14.5 以降）

### 5-1. 2 つのアトリビューションの手法 ✅〔仕様〕本文（F22-08・F22-24）

iOS 14.5 以降の端末を狙うアプリの宣伝キャンペーン（「iOS 14 以降用キャンペーン」）は、キャンペーンのアトリビューションの手法として **AEM か SKAdNetwork** を選ぶ。

| 項目 | AEM（Meta） | SKAdNetwork（Apple） |
|---|---|---|
| 報告の速さ | ほぼリアルタイム | **少なくとも 24 時間の遅延**。結果は起きた時点ではなく Meta に届いた時点で報告 |
| 範囲 | Meta のテクノロジーの中だけ | 複数の広告ネットワークをまたいで帰属 |
| インストールの窓 | クリックから 1 日・7 日・28 日（ヘルプ 1356268495231843） | アプリの商品ページへ送る広告をクリックし、**30 日以内**にインストール |
| インストール後のイベントの窓 | クリックから 1 日か 7 日 | SKAN の版で日数が違う |
| 設定 | アプリが AEM の対象かを確かめる | イベントマネージャで SKAdNetwork のイベントを設定 |
| アプリイベントの最適化 | 7 日クリックのアトリビューション設定で、Audience Network にも配信できる | 最適化したいイベントをイベントマネージャの SKAdNetwork のイベント設定に足す |
| 価値の最適化 | ［コンバージョン値の最大化］をオンにする必要は無い | SKAdNetwork のイベント設定で［コンバージョン値の最大化］をオンにする |
| レポートを受け取れないもの | SKAdNetwork のレポート | 1・7・28 日のクリックとビューの窓 |

- 2024-10-09 から、Meta は MMP に AEM のレポートを送る（識別情報の削除・差分プライバシー・集計の後）。全 MMP で使えるようにしたが、統合の時期は MMP ごとに違う ✅〔仕様〕本文（F22-09）
- SKAdNetwork を手法にできないときは、AEM で iOS 14 以降用キャンペーンを作れる（SKAdNetwork のレポートは受け取れない）✅〔仕様〕本文（F22-25）
- 第三者の測定（MMP）は SKAdNetwork のレポートしか出さないことがある。広告マネージャの［アトリビューション設定の比較］で Meta の帰属と SKAdNetwork を並べられる ✅〔仕様〕本文（F22-09）

### 5-2. SKAdNetwork の詳細 ✅〔仕様〕本文（F22-07・F22-25・F22-26）

- **版**: iOS 16.1 以降の端末で、iOS SDK 16.1 以降で作った Meta のアプリ上に広告が出たときは SKAN 4.0。それより前は以前の版。**SKAN 4.0 のサポートは段階的に導入**（「現時点ではご利用になれない場合があります」）
- **細かいコンバージョン値**: イベントマネージャで設定する**最大 63 件**の個別かバンドルのアプリイベント（以前の版はこれだけ）
- **粗いコンバージョン値**（4.0 で追加）: 高・中・低のラベル。Facebook SDK を使い、細かい値のイベントが **3 件以下**で粗い値のイベントが無いと、優先度の順に高・中・低が自動で作られる（3 件なら高・中・低、2 件なら高・中、1 件なら高）。3 件より多いか 0 件なら自動では作られない
- **ポストバック**: 1 つ目（細かい値）は広告マネージャに入る。1 つ目の粗い値と、2・3 つ目のポストバックは広告マネージャに入らず、**2・3 つ目は Insights API で粗い値として**出る。SDK で粗い値を自動で対応づけられるなら、1 つ目の窓の分は細かい値として報告される
- **統計モデル**: SKAN はキャンペーン単位で集計を返す。広告セット・広告の単位はモデルで補いうる。**キャンペーンが 1 広告か 1 広告セットならモデルは使わない**。広告に複数のクリエイティブの要素があると、クリエイティブ単位のレポートは無い
- **A/B テストはキャンペーン単位だけ**
- これらの制限は SKAN の報告を使うキャンペーンのインストールとアプリイベントに適用。インプレッション・リンククリック・AEM のキャンペーンには適用しない。Android と iOS 13 以前は SKAN のデータを使わない
- MMP を使うなら、SKAN 4.0 に対応しているかを MMP に確かめ、MMP の画面でイベントを設定し、イベントマネージャで SKAN を設定する。CAPI か App Events API なら、Apple の文書で 4.0 を入れてからイベントマネージャで設定する
- 開発者文書（Audience Network の SKAdNetwork のページ）: Info.plist の `SKAdNetworkItems` に SKAdNetwork の ID を足す（`v9wttpbfk9.skadnetwork`、`n38lu8286q.skadnetwork`）。これは**Audience Network で収益化する側（パブリッシャー）**の設定で、Audience Network SDK 6.21.0 以上、Xcode 26 以降 ✅〔仕様〕要約（F22-27）

### 5-3. iOS 14 以降用キャンペーンの制限 ✅〔仕様〕本文（F22-06）

| 項目 | 決まり |
|---|---|
| 最適化 | 各キャンペーンは最適化 1 種類 |
| キャンペーンの数 | **アプリあたり最大 24 件** |
| 広告セット | Advantage+ アプリキャンペーンは、固定された最適化の選択肢がある広告セット 1 つだけ |
| 互換性 | iOS 14 以降のキャンペーンを回す広告アカウントで、iOS 13.7 以前と Android 向けも回せる |
| Advantage+ | iOS 14.5 以降では Advantage+ のみ。手動の設定はサポートされない |
| 購入方法 | オークションだけ（予約購入は不可） |
| 入札 | 最小単価（入札価格上限は任意）。平均目標達成単価上限なら、広告セットを **3 日以上**回す |
| Advantage+ キャンペーン予算 | **最大 5 つの広告セット** |
| 配信ステータス | 「上限を更新中」＝アプリ ID あたりの手動キャンペーンが **18 件**に制限、オフにすると枠が空く。「上限のため保留」＝上限に達し、既存を止めるまで新しいものは配信されない |

- △ 同じページの中で「アプリあたり最大 24 件」と「アプリ ID あたりの手動キャンペーンが 18 件」が並ぶ。手動（Advantage+ でない）キャンペーンの枠が 18 で、全体が 24 と読めるが、ページは関係を書いていない ❓。確かめ方: 広告マネージャの配信ステータスの表示
- 推奨（同じページ）: 地域・製品カテゴリ・言語・利用者あたり平均収益でまとめる。**複数のキャンペーンで同じ国を狙わない**。クリエイティブのテストは Android か iOS 13.7 以前向けのキャンペーンで行い、勝ったものを iOS 14 以降用に使う。**広告セットにクリエイティブを最大 6 つ**。既存のカタログを使い、アプリが AEM の対象であることを確かめる ✅〔公式の推奨〕本文（F22-06）

### 5-4. iOS 14.5 以降でのオーディエンスとリンクの制限 ✅〔仕様〕本文（F22-28・F22-15・F22-24）

- iOS 14 以降に更新した端末が増えると、アプリアクティビティ・ウェブサイトのカスタムオーディエンス、アプリのつながりのオーディエンスが小さくなりうる。代わりに幅広いターゲット・ターゲット設定の拡大を勧める
- API（`POST /{ad-account-id}/adsets`）では、iOS 14.5 の SKAdNetwork キャンペーンで**モバイルアプリのカスタムオーディエンスを含める**ことはサポートされない。新しい iOS 14.5 のアプリのインストールのキャンペーンでは、**アプリのつながりのターゲット**は使えない
- iOS 14 の更新で、**SKAdNetwork キャンペーンでは API（`POST /{ad-id}`）でディファードディープリンクを付けられない**

### 5-5. 運用の判断への効き方

- **iOS は「AEM か SKAN か」をキャンペーンを作る前に決める。** 速く・細かく見たいなら AEM、MMP と同じ物差しで他の媒体と比べたいなら SKAN〔推測〕。両方の数字は広告マネージャで並べられる
- **SKAN の数字で広告セット・広告を比べない。** モデルで補った数字。比べたいなら 1 キャンペーン 1 広告セットにする（モデルが使われない）か、Android で比べる（Meta の推奨もクリエイティブのテストは Android か iOS 13.7 以前）
- **キャンペーンの数は 24（△ 18）まで。同じ国を複数で狙わない。** 国ごと・最適化ごとに分けすぎると上限と重複に同時にかかる。G22 の「iOS は 1 アプリ 8 キャンペーン以下を推奨」と方向は同じ（Meta は上限、Google は推奨）
- **開始と停止の直後は、AEM と SKAN の数字が大きくずれる。** ヘルプは数日待ってから比べるよう書く（§9-2）

### 5-6. Google との違い

Google も iOS は SKAdNetwork と ODM（端末上の計測）で測り、キャンペーン数を絞ることを勧める（G22 §5-1）。Meta は SKAN のほかに AEM という自前の手法を選べ、AEM では 7 日クリックの窓とリアルタイムに近い報告が使える。Google にこの「キャンペーンごとに手法を選ぶ」作りは無い。

## 6. ディープリンク

### 6-1. 何か ✅〔仕様〕本文（F22-14・F22-29・F22-30）

- ディープリンク＝アプリの中の特定のコンテンツへ直接行くリンク。広告をタップした動機と最初の画面がそろうので、使ってもらいやすい
- **ディファード（遅延）ディープリンク**＝アプリをストアで入れた後に、決まった画面へ送る。**まだアプリを入れていない人を狙うなら必須**、入れた人だけなら不要
- 前提: インストールのトラッキングをオンにする。ディファードディープリンクには **Facebook SDK（iOS・Android）** と**広告主 ID の収集**が要る
- **iOS ではディープリンクは広告とだけ動く**（アプリの招待などには使えない）
- ディファードディープリンクを広告に足せるのは、**目的がアプリのインストール（アプリの宣伝）のとき**。広告マネージャで新しい広告セットの［広告クリエイティブ］にディープリンクか App Links のメタデータの URL を入れる

### 6-2. iOS と Android の作り方 ✅〔仕様〕本文（F22-29・F22-30・F22-31）

| | iOS | Android |
|---|---|---|
| ウェブのリンクで開く | Universal Links（Apple の手順で関連ドメインに対応）。そのうえで AEM のためのコードを足す | Android App Links。前提を満たせば追加の作業は無く、サイトの URL を広告とカタログで使える |
| 独自の URL スキーム | アプリダッシュボードの［設定］→［iOS］に URL スキームの接尾辞（`://` 無し。**iOS 16 未満では要件でない**）と App Store ID | ［設定］→［Android］にクラス名（起動の Activity） |
| ディファード | SDK の App Links（`fetchDeferredAppLink`） | SDK の `AppLinkData.fetchDeferredAppLinkData` |
| GDPR の対応で自動初期化を切っているとき | 同意の後に自動初期化を戻してから遅延リンクを取る | 同じ |
| 確かめ方 | App Ads Helper | 同じ |

- AEM（アプリ）を使うには、Universal Links に対応し、アプリのデリゲートで SDK に URL を渡す（SDK v14.0.0 以降は `application(_:continue:)`、v13.2.0 以前は `application(_:open:options:)`）。再エンゲージメントの広告のディープリンクの URL は、**コールドスタートでも SDK に届く**ようにする ✅〔仕様〕本文（F22-08）
- カタログの商品のディープリンクは App Links の仕様でフィードに入れる（`applink.ios_url`・`applink.android_url` など）。フィードの情報がクローラーの App Links より優先。iPhone・iPad の情報は iOS 全体と違うときだけ入れる ✅〔仕様〕本文（F22-32、`21`）
- App Links を使う前に、その URL がスクレイプされているかを `?type=og&scrape=true&id=<APP_LINK>` で確かめる ✅〔仕様〕本文（F22-18）

### 6-3. 計測にディープリンクを使わない ✅〔仕様〕本文（F22-15）

ヘルプ「測定にディープリンクの使用が推奨されない理由」:

- ディープリンクでの計測は、アプリのインストールやアプリイベントへの広告の帰属を正しく把握できない
- **7 日分のデータしか入手できず**、それより長い窓を測れない
- **クリックしか確認できない**（見ただけで後から入れた人は分からない）
- 端末をまたぐ行動（iPhone で入れて iPad で初めて起動）を追えない
- 最適化するには結果のデータが要る。MMP 経由の App Events API か Facebook SDK で集める。**ディープリンクのトラッキングだけでは最適化は成功しない**

### 6-4. 運用の判断への効き方

- **アプリを入れていない人に「商品の画面」から見せたいなら、ディファードディープリンクを SDK で入れる。** 入れていないと、ストアから戻った人はアプリのトップに着く
- **iOS の SKAN キャンペーンで API からディファードディープリンクを付ける運用は組まない**（できない）
- **ディープリンクの URL パラメータで成果を数える独自の計測は、Meta の帰属と合わない前提で扱う。** 7 日・クリックだけの数字になる

### 6-5. Google との違い

Google はエンゲージメント キャンペーンの前提条件にディープリンク（Universal Link・App Link）を置く（G22 §1-1）。Meta はディープリンクを「体験をよくするもの」とし、計測の手段ではないとはっきり書く。

## 7. アプリイベントの最適化と価値の最適化の条件

### 7-1. アプリイベントの最適化 ✅〔仕様〕本文（F22-33）

- 1 つのアプリの宣伝キャンペーンで、インストールとアプリ内の行動の両方を増やせる（例: ゲームでレベル達成に最適化）
- 前提: Facebook SDK を入れているか MMP にリンクしている、標準かカスタムのアプリイベントを設定している、アプリが **AEM か SKAdNetwork の対象**
- **すべての標準イベントが最適化に使えるわけではない**（使えるイベントの一覧は Meta for Developers のページ）
- **カスタムイベントにも最適化できる**が、アプリの宣伝で**カスタムイベントの値には最適化できない**（値のパラメータが使えないため）
- カスタムイベントを標準イベントに対応づけているなら、**対応づけた標準イベントではなくカスタムイベントに直接最適化することを推奨**（配信のモデルがよい、名前がそのまま使える、設定が簡単）
- iOS 14 以降用: AEM を手法にするなら 7 日クリックのアトリビューション設定で Audience Network にも出せる。SKAN なら最適化するイベントを SKAN のイベント設定に足す。iOS の SDK を使っているなら **8.0 以降**に更新する
- △ 同じページの文「iOS 用 Facebook SDK のバージョン 8.0 以上を使用する場合は、iOS 14 以降を対象とし、合算イベント測定を使用するアプリの宣伝キャンペーンでは、Facebook SDK の要件はありません」は、「SDK 8.0 以上が要る」と「SDK の要件は無い」が同じ文の中にあり、意味が取りにくい（翻訳の崩れの可能性）。`06§8-2`（B-07・B-06）は「AEM がアプリの宣伝（インストール）キャンペーンにも広がり、SKAdNetwork 用のイベント設定なしで出せる」と書く。英語版で確かめる ❓
- 最適化を使うなら、すべてのコンバージョンイベントを送る。機密性の高い利用者データは送らない

### 7-2. 価値の最適化（コンバージョン値の最大化）の要件 ✅〔仕様〕本文（F22-10・F22-11）

| 最適化 | 要件 |
|---|---|
| アプリ内購入の値 | **過去 7 日に、値のあるアプリ内購入が 15 件以上** |
| アプリ内の広告インプレッションの値 | **過去 28 日に、2 種類以上の値のアプリ内広告インプレッションが 15 件以上**（Android・iOS でオープンベータ） |
| 共通 | CAPI・ピクセル・Facebook SDK・MMP などの連携がアクティブ。値と通貨を送るイベント。イベントマネージャでアプリイベントを設定し、［コンバージョン値の最大化］をオン |
| iOS 14.5 以降 | SKAN の手法なら SKAN のイベント設定で［コンバージョン値の最大化］をオン。AEM で送るイベントはオンにしなくてよい |

- 要件を満たしても、**使えるようになるまで数週間かかる場合がある**。広告マネージャで件数がしきい値を満たして見えても、データが一部しかないイベントは数えられないことがある ✅〔仕様〕本文（F22-10）
- 参考（ウェブ）: 過去 14 日に 5 種類以上の値で 100 件以上を推奨。pLTV は週 100 件・過去 28 日に 5 種類以上の値 ✅〔仕様〕本文（F22-10）
- 「コンバージョン値の最大化は、アプリの宣伝キャンペーンを購入金額に最適化するために使える。その他の最適化はすべて、売上の目的のウェブキャンペーンでしか利用できません」（pLTV・利益の最適化はウェブの売上だけ、と読める）✅〔仕様〕本文（F22-12）

### 7-3. 最適化ウィンドウ（アプリの価値の最適化）✅〔仕様〕〔公式の推奨〕本文（F22-11）

| 選ぶ窓 | 向く場面（ヘルプ） |
|---|---|
| クリックから 1 日 | 1 日目以降の ROAS を主に見たい（短期のコンバージョン） |
| クリックから 7 日 | 7 日目以降の ROAS を主に見たい（1 週間以内のコンバージョン） |
| クリックから 28 日（**アプリ内購入だけ**） | 14 日目以降の ROAS を重視し、アプリが 7 日目以降に意味のある価値を生む |

- コンバージョンイベントはアプリ内購入（iOS・Android）か、アプリ内の広告インプレッション（オープンベータ。広告収入のアプリ向け）
- ROAS 目標を置ける

### 7-4. 価値の最適化のベストプラクティス ✅〔公式の推奨〕本文（F22-12）

- 最初のテストは**少なくとも 3 週間**、**週 50 件以上**（pLTV は 100 件以上）
- 最適化するイベントのシグナルのカバー率を、イベントマネージャで確かめる
- **最初は ROAS 目標なし**でテストし、その後に足す
- パフォーマンスのピークは**通常 2 週間後**
- 結果の単価は高くなりうる。特に情報収集期間（通常 1 週間以上）は、件数に最適化したときより件数が少なくなりうる。急いで判断しない
- カスタムイベントの値を最大化するなら、そのカスタムイベントがイベントマネージャで審査されていることを確かめる
- pLTV は、コンバージョンイベントから**最大 7 日後**に送る値。5 つ以上の異なる（負でない）値を含む検証済みのモデルが要る。統合とモデルの学習に約 2 週間

### 7-5. 運用の判断への効き方

- **価値の最適化に入る前に「過去 7 日に値のある購入 15 件」を数える。** 届かないなら、アプリイベント（購入）の最適化で件数を貯める（G22 の「1 日 10 人に満たないなら手前の行動」と同じ考え）
- **最初の 3 週間は ROAS 目標を置かない。** 置くのは基準ができてから
- **28 日の窓はアプリ内購入の、長く課金するアプリだけ。** 広告収入のアプリ（広告インプレッションの値）は 1 日か 7 日
- **カスタムイベントの値は、アプリの宣伝では最大化できない。** 値の最適化は購入（とアプリ内の広告インプレッション）で組む

### 7-6. Google との違い

Google の目標広告費用対効果（アプリ）は 1 日 10 件・30 日 300 件の条件（G22 の分担先 14）。Meta のアプリの価値の最適化は「過去 7 日に 15 件」で、件数は少ないが期間が短い。どちらも「件数の多い手前のイベントから始めて、貯まったら価値へ」の順は同じ。

## 8. オーディエンス（アプリ）

### 8-1. アプリのカスタムオーディエンス ✅〔仕様〕本文（F22-28）

- アプリのイベントで作る（例:「直近 10 日にレベル 8 を通過」「直近 8 日に使ったが購入していない」）
- 保持期間（`retention_days`）は **1〜180 日**。期間内にまた条件のイベントを起こすと、その日から期間が延びる
- iOS 14.5 の制限は §5-4
- Advantage+ アプリキャンペーンでは**含める**ことはできず、アプリ広告設定で**除外**に使う（§3-2）

### 8-2. 運用の判断への効き方

- **既存の利用者を新規獲得のキャンペーンから外すには、アプリ広告設定でカスタムオーディエンスを除外する**〔仕様〕。広告セットで除外を探しても Advantage+ アプリキャンペーンには無い
- **再エンゲージメント（戻ってきてほしい人）は、売上・エンゲージメントなどの目的でアプリのカスタムオーディエンスを使う。** iOS では小さくなる前提（§5-4）

## 9. 計測の遅れと数字の違い

### 9-1. 遅れ ✅〔仕様〕本文（F22-07・F22-09・F22-12、`00§9-3`）

| 何が | 遅れ |
|---|---|
| SKAdNetwork の結果 | **少なくとも 24 時間**。届いた時点で報告。SKAN 4.0 の更新でさらに遅れうる |
| AEM（iOS 14 以降用） | ほぼリアルタイム |
| pLTV の値 | コンバージョンイベントから最大 7 日後に送る |
| 価値の最適化が使えるようになるまで | 要件を満たしてから数週間かかる場合がある |
| 価値の最適化の成果のピーク | 通常 2 週間後 |

- `00§9-3` は SKAN の結果が「届くまで 24 時間〜60 日」と書く（S-60 の抜粋）。今回読んだヘルプの本文は「少なくとも 24 時間」で、上限の日数は書いていない ❓

### 9-2. AEM と SKAN の数字が違う理由（ヘルプの列挙）✅〔仕様〕本文（F22-09）

1. 報告の遅延（AEM はほぼリアルタイム、SKAN は 24 時間以上）
2. シングルチャネルとクロスチャネル（AEM は Meta の中、SKAN は複数のネットワーク）
3. アトリビューションの窓の違い（§5-1 の表）
4. イベントの設定の違い（同じ名前でも別々に設定していれば違う。SDK の iOS の設定とそろえる）
5. AEM の対象外のイベント
6. キャンペーンの開始・停止の直後（SKAN の遅延。**数日待ってから比べる**）
7. コンバージョン数が少ない
8. 統合の方法の違い

### 9-3. App Events API の帰属の説明（古い記述）△

- 開発者文書 App Events API の `attribution` エンドポイントの説明は、「広告のクリックから 30 日以内」のインストールと、「**広告マネージャは 1 日ビュー・28 日クリック**」と書く ✅〔仕様〕本文（F22-22）
- 今の広告マネージャのアトリビューション設定の既定は「クリック後 7 日・ビュー後 1 日」（`00§9-4`、`06`）。App Events API の説明は古い既定のまま残っていると読む △

### 9-4. 運用の判断への効き方

- **SKAN のキャンペーンは、始めて 2〜3 日で判断しない。** 少なくとも 24 時間遅れ、開始直後は数字が大きくずれる（ヘルプ）
- **MMP の数字と広告マネージャの数字は、まず窓と手法をそろえて比べる。** ［アトリビューション設定の比較］で SKAN の列を出す
- **件数が少ないうちは AEM と SKAN の差が大きい**（ヘルプが明記）。差だけで計測の故障と決めない

## 13. 少額・少量のアカウントでの注意

- **まずインストールの最大化か、件数の多いアプリイベントから。** 価値の最適化は「過去 7 日に 15 件」、学習は週 50 件（`00§6`）。少額では価値の最適化に届くまで時間がかかる
- **iOS は AEM の 1 キャンペーンから始める**〔推測〕。SKAN は遅れとモデルで少額だと判断材料が薄い。キャンペーン数の上限にもかかりにくい
- **クリエイティブのテストは Android で**（Meta の推奨。§5-3）。iOS 14 以降用キャンペーンの広告セットのクリエイティブは 6 つまでが推奨
- **入札価格上限は置かない**（推奨）。上限を置くと少額ではさらに配信が細る
- **評価は 7 日単位、価値の最適化は 3 週間**（推奨）

## 14. 判断の型

| 状況 | 最初に見る | 打ち手の順 |
|---|---|---|
| アプリを新しく出す | アプリの登録・広告アカウントのリンク・SDK か MMP・イベントの確認 | 登録とリンク → SDK（自動のアプリ内購入の記録）→ App Ads Helper で確認 → Advantage+ アプリキャンペーンのインストールの最大化 → 素材 50 点まで |
| インストールは取れるが課金が増えない | 購入のイベントの件数（過去 7 日） | 購入のアプリイベントの最適化で別キャンペーン → 7 日に 15 件以上で価値の最適化（ROAS 目標なしで 3 週間）→ 基準ができたら ROAS 目標 |
| iOS の数字が MMP と合わない | 手法（AEM か SKAN）、窓、開始からの日数、件数 | ［アトリビューション設定の比較］で SKAN の列 → 数日待つ → イベントの設定を SDK とそろえる → AEM の対象外のイベントを確かめる |
| iOS のキャンペーンが配信されない | 配信ステータス（上限を更新中・上限のため保留） | 使っていないキャンペーンを止めて枠を空ける → 国の重複をまとめる |
| 価値の最適化が選べない | 過去 7 日の値のある購入、イベントマネージャの設定、SKAN の設定 | 件数が足りなければ購入の最適化で貯める → 設定をオン → 数週間待つ |
| 商品の画面へ送りたい | ディファードディープリンク、SDK、カタログの applink | SDK でディファードを入れる → フィードに applink → App Ads Helper で確認（SKAN の API では付けられない） |
